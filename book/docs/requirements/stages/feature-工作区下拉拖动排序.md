# 工作区下拉拖动排序专项

工作区下拉面板内支持拖动工作区行更换顺序。现状：工作区列表顺序 = `workspaces` 数组顺序，落盘与展示同序（StoredWorkspace 注释「workspaces 数组顺序即下拉展示序（不做工作区排序）」即本次修订对象），但没有任何调整顺序的手段——新建工作区恒追加数组末尾，创建即定序（2026-09-21 用户裁决：工作区下拉框允许拖动更换顺序）。落盘 schema 零变更：数组顺序本来就是持久化事实，缺的只是 reorder 通道与拖拽手势。

- 交互定稿：下拉展开后按住工作区行拖动，行间实时插入指示，放下即提交完整顺序生效并持久化；「全部会话」是固定首位的视野哨兵项——不可拖、不可落（不属于排序集合，PRD 4.8）；有过滤词时暂停拖拽（过滤视图是子集，子序重排语义含混，宁缺勿滥——与会话列表「视野内拖拽调全序相对位」的既有语义划清界限，工作区列表短、无过滤拖拽需求）；右键操作条展开行（重命名/删除按钮为交互后代起点）不可作为拖拽起点，与手势原点追踪既有惯例一致
- 手势体系：与会话列表拖拽排序同一族（HTML5 DnD、面板级事件委托、中点 before/after 判定、插入线 2px 墨级伪元素不推挤、源行 opacity 降格、原生整行快照拖影零自绘、瞬态不进 store/IPC/落盘）；dataTransfer 清空默认后只写应用自定义 MIME（`application/x-msb-workspace`），拖影越界不构成导航或文本投放；dragend 在源元素上恒达，列表外/Esc 取消全覆盖零残留。实现形态（泛化 useSessionDragReorder 为共享 hook 还是平行小 hook）在开发计划定稿，不强行抽共享导致两会话/工作区两套行语义耦合
- 提交契约：drop 生成一次**完整工作区 id 全序**提交（无位移/拖回原位短路零 IPC），主进程整单校验拒绝制——与 sessions:reorder 同口径：id 格式非法、重复、缺项、多项或未知任一不满足整单拒绝、磁盘顺序不变，界面回主进程事实顺序 + 失败反馈（不静默）
- 纯元数据语义：重排只改 workspaces 数组顺序（即下拉展示序、移动弹层目标列同序跟随），不动 activeWorkspaceId、激活会话、lastActiveSessionId 与会话归属，零编排回调、不触碰分区与页面运行状态；新增通道 `workspaces:reorder`（会话域 19 → 20，全 invoke 零推送——工作区仅主窗左栏操作，与既有工作区五通道同性质）
- renderer store：镜像侧 reorderWorkspaces 动作对齐 reorderSessions 既有模式——本地全序校验、无变化短路零 IPC、乐观换序、失败重拉主进程权威顺序
- 视觉：下拉面板行内插入指示与拖拽降格沿用会话列表定稿语言（全灰阶、琥珀零参与——纯结构操作），细节经 impeccable 复核定稿并落 DESIGN.md「工作区切换框」条目
- 契约方向（详细通道与校验在开发计划定稿）：`ReorderWorkspacesPayload { ids: string[] }`，校验常量复用 WORKSPACE_ID_RE；schema v4 不动（数组顺序即持久化顺序）
- 范围外：键盘 ↑↓ 重排、显式拖拽把手、跨下拉/移动弹层拖动、工作区拖入会话列表等跨面板语义、「全部会话」参与排序
- 本期不做：工作区顺序的独立撤销（重排即落盘，无历史栈）；移动弹层内拖动排序（目标列序随下拉序自动一致，无需单独能力）
