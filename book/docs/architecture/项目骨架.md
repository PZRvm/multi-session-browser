# 项目骨架与目录结构说明

> 多会话测试浏览器（multi-session-browser）：面向软件测试人员的 Electron 桌面工具。左侧管理多个完全隔离的浏览器会话（Cookie/缓存/登录态互不影响），右侧是 Chrome 式浏览区，每个会话可独立唤起 DevTools。
>
> 本文档描述仓库的目录结构、`src/` 各子目录的职责，以及每个源码文件的作用。需求依据见 `book/docs/requirements/PRD.md`，工作约定见根目录 `AGENTS.md`，设计系统见 `DESIGN.md`。

## 一、技术栈与三进程结构

- **Electron 42.11.7 + electron-vite + TypeScript**，包管理只用 npm（勿用 pnpm/yarn）
- **主进程**（`src/main/`）：Node 环境，负责窗口创建、会话/浏览器状态机、持久化、IPC handler
- **预加载桥**（`src/preload/`）：contextBridge，向 renderer 暴露白名单 `window.api`
- **渲染进程**（`src/renderer/`）：React 19 + antd 6 + zustand 5 的纯 UI，禁止直接访问 Node/Electron API
- **契约层**（`src/shared/`）：三进程共用的类型、通道名、键位表与运行时守卫——跨进程通信的单源，改动需三方同步

数据流单向：主进程是唯一事实源（Tab 列表、会话、外观均由主进程持有并推送快照），renderer 只是镜像 + 发命令；界面文案经 `src/shared/i18n/` 字典单源管理（zh-CN 源语言 + en-US，新增语言走注册表扩展入口，见 3.5 节）。

## 四、关键横切约定（读代码前先知道）

1. **IPC 边界**：renderer 一切经 `window.api` 白名单；通道名单源 `src/shared/`；主进程 handler 一律先过运行时守卫再进业务。
2. **会话隔离是生命线**：每会话独立分区 `persist:sess-<id>`，禁止共享；浏览器嵌入用 WebContentsView（BrowserView 已废弃勿用）；DevTools 挂具体 webContents 与会话强绑定。
3. **窗口作用域**：主窗浏览区固定 `'main'`，独立窗口各有 windowId；快照按作用域构建并定向推送，命令按 `event.sender` 来源窗口路由。
4. **运行时验证隔离**：一切手动验证/冒烟必须设 `MSB_USER_DATA=<临时目录>`（见 `src/main/index.ts` 头部注释的事故背景）。
5. **验证手段**：无测试框架；`npm run typecheck` + `npm run lint` 必过，行为验证走 `npm run dev` + CDP 脚本（历阶段惯例）。
6. **文案取词**（阶段六）：用户可见文案一律经 `src/shared/i18n/` 字典（范围线见其头注）——renderer 组件用 `useT()`、store 无组件上下文用 `DICTIONARIES[useI18nStore.getState().language]`、主进程构造期用 `t()`（main/i18n.ts）；en 字典缺键即编译失败，开发注释与 console 日志保持中文不入字典。
