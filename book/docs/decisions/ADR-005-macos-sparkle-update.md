# ADR-005：macOS 更新采用 Sparkle

## Status

Accepted：用户指定迁移 Sparkle，并在 2026-11-14 原型证实取消会清缓存后，明确接受“应用未退出时可稍后安装；普通退出取消，重新打开需重新下载”。生产接入已落盘，验收仍由计划跟踪，尚未完成平台门禁。

## Context

现有 Squirrel.Mac 无法安装临时签名包；个人开源维护者暂不购买 Apple Developer 证书。要求保留主进程控制、原生日志与确认、录制和严格保存门禁，Windows 保留现有更新器。

两个现成 Electron 桥接库的默认行为分别存在自动下载和准备失败后继续重启的问题。官方 Sparkle 可自行生成 EdDSA 密钥，但原生安装器在 ready 后可能随普通退出安装。SDK 取消后清理已下载更新，无法沿用原先的重开恢复缓存要求。

独立探针使用官方 2.10.1、随机测试 appId、临时密钥和真实两个版本。Cocoa、Electron 45.3.0 arm64 和 Rosetta x64 已验证下载、取消、签名拒绝、模拟保存拒绝以及真实替换重启；取消完成事件与退出时序已在七场景原型通过；产品隔离打包测试进度见计划。

## Decision

Mac 采用固定版本的官方 Sparkle 与项目控制的 Node-API / Objective-C 桥接，下载、验签和安装仍由官方引擎承担。主进程独占桥接，renderer 继续使用现有窄更新 IPC，不获得路径、URL、原生回调或密钥。

检查时保留 user-driver 的版本回复，直到用户明确下载；ready 后保留安装回复，只有录制检查和严格保存成功才提交 Install。普通退出时提交 Skip，并等待更新周期取消完成再退出；进程内“稍后”不提交 Dismiss 或 Skip，继续持有 ready。退出清理后重开按 available 重新下载，不伪装保留缓存。

版本日志继续由唯一 Markdown 生成；Mac appcast 引用对应版本资源，Windows 清单与 Release 正文使用同一正文。EdDSA 公钥固定打入应用，私钥仅用于签署归档；不把免费更新签名描述成 Apple 公证。

## Consequences

免费密钥可以验证更新包来源，仍需面对未公证应用首次分发的系统限制。项目增加原生构建、两架构验证及公私钥维护；测试密钥与正式密钥隔离。

本决定只替代 ADR-004 中的 Mac 更新引擎选择，保留其主进程所有权、严格保存和禁用策略。既有恢复集时序 R1 不因换引擎而关闭，仍阻断真实数据安装验收与发布。
