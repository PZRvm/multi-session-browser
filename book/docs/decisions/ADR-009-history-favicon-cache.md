# ADR-009：历史图标沿会话获取并缓存

状态：Accepted，2026-11-16。

## 背景

历史只保存 favicon URL，建议子窗使用默认 Session，无法继承网页会话的 Cookie、代理与缓存。用户要求提高启动后图标的成功率，最终失败使用搜索图标。

## 决定

保留应用界面与网页分区分离。主进程按可信 sender 解析会话，从真实历史取得图标地址，通过对应 Session.fetch 获取，失败尝试页面 origin/favicon.ico；子窗接收 data URL。图标缓存保存到对应分区的 `History Favicons/`，不修改历史 schema、不调用第三方图标服务，也不把应用子窗切入网页分区。

## 结果与代价

同会话网络身份保持一致；缓存可跨重启复用，随分区删除，克隆时按既有分区复制携带。新增缓存体积、并发、超时、取消和异步回填的维护成本。缓存是派生数据，写入失败仍可显示本次图片；无法获取或解码时显示 SearchOutlined。

历史检索与键盘状态机仍属于 renderer。主进程在既有 suggest-show/data 字段中补入图片数据，不新增共享 IPC 通道；旧子窗契约注释中的“只做承载”描述应结合本 ADR 的图标补全增量理解。

后续审查修复：根图标失败后允许沿同会话取得历史页面的link图标，页面索引和图片分别限制128项并落于该会话缓存目录；下载和缓存单图上限为256KiB。主进程使用禁止联网、无preload的sandbox工具分区执行实际图片解码和DOMParser，只有解码成功的图片才缓存。工具空闲销毁；网页Cookie/代理只在原会话的fetch中使用，解析器不获得凭据或网络能力。
