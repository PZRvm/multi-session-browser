# 历史图标体积上限修正

分级：M。仅调整现有图标服务的体积限制，需要边界回归；不改变会话网络身份、IPC 或缓存 schema。沿用 feature/history-favicon 分支。

## Step 0

背景：SCRM 声明的有效 PNG 为 96,024 字节，超过原 64 KiB 上限，重复搜索仍被拒绝。用户确认允许更大的图标，但保留合理上限。

范围：将单图上限改为 256 KiB，下载长度校验、流式校验、data URL 与读盘校验继续由 MAX_BYTES 派生。排除：缩图、页面图标发现、null 历史补全、其他缓存审查后续和界面调整。没有新增权限或提示。

要求：96,024 字节和恰好 256 KiB 的有效图片可缓存，第二次命中内存、重启命中磁盘；超过上限 1 字节的图片仍拒绝。每会话 128 项、4 路并发、超时和失败冷却不变。

## Phase 1 / 2

根因证据见 [SCRM 排查](../notes/issue/2026-11/2026-11-16-SCRM站点图标无法缓存.md)。MAX_DATA_LENGTH 从 MAX_BYTES 计算，改一处即可同步网络与缓存验证。影响为单会话图片数据理论上限从 8 MiB 提升为 32 MiB（不含 Base64 和 JSON 开销）；不取消容量限制。

改动文件：historyIcons.ts 的常量，history-icons-regression.mjs 的接受/拒绝边界用例。先用新用例复现旧上限失败，再改常量；用真实站点响应复验。
