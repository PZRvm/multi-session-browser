# 删除会话原生确认框 开发计划

> 创建时间：2026-09-18 18:25:49（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/feature-删除会话原生确认框.md`（交互口径与两项用户裁决——三处同规、取消为默认——已冻结；PRD 3.1.2/3.1.3/3.1.5/4.10 与验收 30 已先行落库）  
> 执行模式：直通  
> 实施范围：删除会话、批量关闭选中会话、删除工作区三处二次确认从渲染层 `modal.confirm`+overlay 悬挂登记迁到主进程 `dialog.showMessageBox` 原生对话框（新开 dialog 域 1 条 invoke 通道，i18n 零新增）；输入类渲染层弹层（打开测试地址、移动到工作区、批量移动、重命名）不动  
> 目标结果：三处删除确认弹原生框，弹框期间右侧浏览器区内容全程可见不变白；「取消」为安全默认（Enter/Esc=取消）；弹框文案随界面语言、明暗随应用主题；确认后的删除执行链路（级联/分区销毁/整单拒绝反馈）零变化  
> 当前进度：步骤 1—4 均未开始

## 1. 当前基线

- **变白根因（本计划要消除的缺陷）**：三个确认框均为渲染层 antd `modal.confirm`——`SessionRow.tsx:187-207`（删除会话）、`SessionPanel.tsx:222-252`（批量关闭选中）、`WorkspaceSwitcher.tsx:164-191`（删除工作区）。WebContentsView 是 renderer DOM 之上的原生层，弹层开启经 `openOverlay()/closeOverlay()`（`stores/ui.ts` overlayDepth 计数）收起页面视图换弹层可见性，代价即用户截图：弹框存续期间浏览器区整片变白。
- **overlay 登记其余消费者（保留不动）**：`SessionPanel.tsx` 的 urlModal（L201-207）、批量移动弹层；`WorkspaceSwitcher.tsx:147-152` 的重命名弹层与下拉面板本身。三确认框迁走后登记机制与这些消费者无耦合。
- **主进程原生对话框先例（本计划逐段对齐）**：`src/main/browser/permissions.ts:117-197` 摄像头权限两处 `dialog.showMessageBox`——标题/正文/细节/按钮文案全部经主进程 `t()`（`src/main/i18n.ts` 语言态模块：boot 注入 + settings:set-language 推进 + 语言变更回调）从 shared 字典取词。触发源在 renderer 时需经 invoke 通道（permissions 是主进程内部直调，无通道）。
- **i18n 零新增可行（键全部已在 zh/en 双语字典）**：`sessions.sessionRow.deleteConfirm.{title,content}`（zh-CN/sessions.ts:39-42）、`sessions.batchBar.closeConfirm.{title,content}`（L74-78）、`sessions.workspaceSwitcher.deleteConfirm.{title,prefix,withSessions,empty}`（en-US 对应位 L34/L67/L110）、按钮 `sessions.shared.delete`（'删除'）与 `common.cancel`（'取消'，common.ts:8）。工作区正文的 prefix+条件拼接逻辑从 renderer（WorkspaceSwitcher L170-174）等价搬到主进程 handler。`DictKey`（shared/i18n/index.ts:63，点路径联合类型）主进程可直用；`TParams = Record<string, string | number>`（L65）支持 `{name}`/`{n}` 插值。
- **通道与守卫现状**：sessions 域 19 条通道（`shared/sessions.ts` SESSIONS_CHANNELS，头注 L40-44 有增量记录惯例）本计划不动；新开独立 dialog 域 1 条 invoke。入参守卫与失败日志收口在 `src/main/ipc-utils.ts`（`isRecord`/`logFailureAsync(channel, payload, run, tag)`）；业务错误键 `errors.invalidSessionParams` 已在字典（main t() 可取）。
- **preload api 域结构**：五域（appearance/sessions/browser/omniboxSuggest/settings，`src/preload/index.ts:72-326` + `index.d.ts` Window.api 声明），新增第六域 `dialog`，两文件签名必须一致。
- **主进程装配点**：`src/main/index.ts:355` `registerSessionIpc({...})` 等 register* 调用集中在 IPC 注册区；新 `registerDialogIpc()` 无 deps，邻近插入一行。
- **renderer modal 消费点（迁移后待清理）**：`SessionRow.tsx:131`、`SessionPanel.tsx:42`、`WorkspaceSwitcher.tsx:38` 三处 `App.useApp()` 解构——`modal` 迁走后删除、`message` 保留（行内失败反馈仍用）。
- **删除执行链路（零变化）**：删除会话 `removeSession`→sessions:delete→主进程 `onDeleted` 级联切换+分区销毁（index.ts:359-371）；批量关闭 `deleteSessions`→sessions:delete-batch 整单拒绝制；删除工作区 `deleteWorkspace`→workspaces:delete（会话降级未分组）。本计划只换「确认」一环。
- **版本与验证**：Electron ^39、React 19、zustand 5、antd 6；验证 = `npm run typecheck` / `npm run lint` / `npm run build` + `npm run dev`（`MSB_USER_DATA` 隔离目录，永不触碰用户真实数据）手动链路。

## 2. 范围边界

### 2.1 本阶段必须完成

- 契约：新文件 `src/shared/dialog.ts`——`DIALOG_CHANNELS.confirmDestructive = 'dialog:confirm-destructive'`、`ConfirmKind` 三值白名单（'session-delete' | 'sessions-batch-close' | 'workspace-delete'）、`ConfirmDestructivePayload { kind; name?; count? }`；preload `api.dialog.confirmDestructive(payload): Promise<boolean>` 两文件对齐。
- 主进程：新文件 `src/main/dialogs.ts` `registerDialogIpc()`——入参守卫（isRecord + kind 白名单 + 按 kind 校验 name/count）→ 主进程 t() 复用既有键组装标题/正文/按钮 → `dialog.showMessageBox(sender 窗口, { type: 'warning', message: 标题, detail: 正文, buttons: [取消, 删除], defaultId: 0, cancelId: 0, noLink: true })` → 返回 `response === 1`；`index.ts` 装配接线。
- renderer：三调用点迁移——确认改走 `window.api.dialog.confirmDestructive`，返回 true 才执行既有删除动作；`openOverlay/closeOverlay` 三处调用与 `modal` 解构移除；SessionPanel 的 `confirmOpen` 状态删除、Esc 守卫条件修正、防重入 ref；`stores/ui.ts` 头注释补「破坏性确认走主进程原生框不参与登记」例外。
- 文档：`book/docs/architecture/项目骨架.md` 增两新文件行 + preload/三组件行同步；`book/notes/summary/2026-11/legacy-process.md` 当前阶段行；验收文档落 `book/notes/summary/`。

### 2.2 本阶段明确不做

- 输入类渲染层弹层（打开测试地址、移动到工作区、批量移动、会话重命名、工作区重命名）的原生化或视觉调整——原生对话框无输入/选择能力，维持 Modal+overlay 既有机制（弹框期间页面视图收起为该类弹层的已知代价）。
- 自绘无边框子窗口模拟主题色确认框、原生弹框 checkbox（不再询问）、按钮主题色注入——PRD 4.10 明示不做。
- 批量关闭确认的独立文案重构（复用 `batchBar.closeConfirm.*` 既有键）。
- 独立窗口内的确认场景（独立窗口无左栏会话列表与工作区切换框，三入口均在主窗）。

### 2.3 本阶段数据原则

- 确认通道是纯 UI 辅通道：主进程只弹框返回 boolean，不落盘、不触碰会话快照、不触碰分区；删除执行仍由既有 sessions:delete / sessions:delete-batch / workspaces:delete 闭环，确认与执行两段解耦。
- 返回值语义诚实：`true` 仅当用户按下确认按钮；取消按钮、Esc、关闭弹框、sender 窗口缺失一律 `false`；入参守卫失败按 ipc-utils 惯例抛 `t('errors.invalidSessionParams')`（renderer catch 后视为取消并 console 告警），不伪造确认结果。
- 文案语言 = 主进程语言态（settings 语言缓存 → main i18n），与界面语言单源同步，不经 IPC 传字符串。

### 2.4 契约核对（编码前冻结）

1. **dialog 域新契约**：`DIALOG_CHANNELS.confirmDestructive = 'dialog:confirm-destructive'`（dialog 域第 1 条，全 invoke）；`ConfirmKind` 白名单三值；`ConfirmDestructivePayload { kind: ConfirmKind; name?: string; count?: number }`——session-delete 必填 name、sessions-batch-close 必填 count、workspace-delete 必填 name+count（多传不拒、缺传抛错）；返回 `Promise<boolean>`。需同步：`src/shared/dialog.ts`（新建，头注释指向本计划）、`src/preload/index.ts`、`src/preload/index.d.ts`。
2. **文案单源**：主进程 t() 复用既有键（清单见基线第 4 条），i18n 字典零新增零删除零改名；shared 字典 `dialogs` 命名空间（摄像头权限）不动——破坏性确认的文案留在 sessions 命名空间原位（与 main 消费 errors 命名空间同先例）。需同步：无（本条为冻结声明）。
3. **交互语义偏离声明（对渲染层版惯例）**：①Enter=取消（用户裁决 2026-09-18，原渲染层 Enter=删除）；②批量关闭「整单拒绝保持弹框开启」→ 原生弹框一次性确认，确认后 deleteBatch 失败走行内 `message.error`（`batchBar.closeConfirm.failed` 键已在），用户可从入口再次发起；③原生框视觉次序（buttons 数组到屏幕左右的映射）macOS 与 Windows 存在平台差异，以 `defaultId/cancelId` 语义为准绳，dev 实测核对视觉次序。需同步：无文档冲突（PRD 4.10/feature 文档已按此口径落库）。
4. **overlay 登记边界收窄**：破坏性确认不再属于「可能延伸到右区的 portal 弹层」范畴（原生层之上的系统弹框无遮挡问题），`stores/ui.ts` 头注释补例外说明，防止后续照旧给确认框套登记。需同步：`src/renderer/src/stores/ui.ts`（注释级）。
5. **骨架基线**：PRD 与 feature 文档已先行落库（2026-09-18），实现与之冲突时以 steps 文档为准回改实现；`book/docs/architecture/项目骨架.md` 与 `book/notes/summary/2026-11/legacy-process.md` 的同步任务列入步骤 4。

完成标志：`src/shared/dialog.ts` 落库且 `npm run typecheck` 0 错误；`grep -rn "dialog:confirm-destructive" src/` 仅命中 shared 常量定义；preload 两文件 `confirmDestructive` 签名一致；`grep -n "modal.confirm" src/renderer/src/components/SessionRow.tsx src/renderer/src/components/SessionPanel.tsx src/renderer/src/components/WorkspaceSwitcher.tsx` 零命中。
