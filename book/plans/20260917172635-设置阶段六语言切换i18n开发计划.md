## 2. 范围边界

- **i18n 基建**：`src/shared/i18n/` 语言注册表（SUPPORTED_LANGUAGES 单源：code/label，默认 zh-CN）+ 按域命名的双语字典（zh-CN 为源语言与类型来源；en-US 逐命名空间受 `Dictionary['ns']` 类型完备性约束——缺键即编译失败，typecheck 成为「无缺译」硬门禁）+ `createT` 取词纯函数（点路径 + `{n}` 插值）。**不引入 i18next 等第三方库**（键类型安全由 TS 原生达成，字典体量小、无复数/日期格式化需求，与 themeSystems 配置单源哲学一致）。
- **扩展入口（用户裁决）**：新增语言 = 新建 `locales/<code>/` 七命名空间文件（逐个受类型约束）+ 注册表加一条 + renderer antd locale 映射加一条，**零组件/零主进程业务改动**；扩展方法写入 `book/docs/architecture/项目骨架.md`。
- **主进程语言态与双语化**：`src/main/i18n.ts` 语言态模块；`installChineseMenu` 参数化为 `installAppMenu(t)` 并在语言变更时重建；摄像头对话框、用户可见 IPC 报错、BLANK_TITLE、设置窗标题经字典取词；启动时从 settings.json 读语言（先于菜单安装，initHomepageCache 先例）；四处建窗 query 增 `lang` 首帧注入。
- **renderer i18n 基建**：`stores/i18n.ts`（求值期 bootstrap 读 query 定首帧语言；init 订阅 settings:changed + 拉取快照；setLanguage 经新通道并按主进程返回权威回填；建议子窗角色同样订阅，解决懒建池语言滞后）；`useT()` hook（订阅 language，切换全组件重渲染）；App.tsx 与 SettingsWindow.tsx ConfigProvider locale 动态化。
- **设置项点亮**：PaneGeneral 语言行从展示态改受控下拉（中/英切换即时生效并持久化，changed 全窗推送同步所有壳层）。

### 2.2 本阶段明确不做

- 第三种语言实装（注册表与字典架构留扩展入口，加语言属后续增量）。
- 被测网页、DevTools 原生 UI、Chromium 右键菜单的语言控制（随 OS，不随应用设置）。
- 主进程开发日志与告警（store/settings 中文告警等）双语化——开发面文案保持中文（用户可见面才入字典，范围线见 2.3）。
- 日期/数字本地化格式、复数规则（现无消费场景）。
- 恢复出厂执行（阶段七；本阶段仅本地化两步确认 UI 文案与确认词）。
- sessions.json / 分区数据 / preferences.json 任何触碰（语言仅入 settings.json）。

### 2.3 本阶段数据原则

- **入字典的范围线**：用户可见文案 = renderer 全部 UI 文案（含 aria/title）、原生菜单、原生对话框、跨 IPC 上浮显示的报错、空白 Tab 标题、窗口标题；**开发注释与 console 告警保持中文不入字典**——两侧边界在 shared/i18n/index.ts 头注写明。
- 语言切换即时生效以主进程快照为权威：setLanguage 成功返回值回填，失败保持旧语言不回滚半态；changed 推送到达前各窗不自行改语言。
- settings.json 坏值/缺键语言键 → 回退默认 zh-CN + 中文告警，不升 version、不丢其他键（homepage 先例）；存量用户文件零迁移。
- en 字典缺键 = 编译错误（类型约束），不允许「回退中文」静默缺译；插值占位符 `{n}` 在字典值内声明，缺失参数如实渲染原文占位符（可巡检发现）。
- 一切运行时验证/冒烟必须 `MSB_USER_DATA=<临时目录>` 隔离，不触真实用户数据。

## 6. 可并行步骤分析

### 6.1 依赖关系

| 步骤 | 前置依赖 | 可与谁并行 | 说明 |
| ---- | -------- | ---------- | ---- |

| 步骤 3 | 步骤 1（契约/基建）；端到端验收需步骤 2 handler | 步骤 2 | 文件集 = src/renderer/**；波次内各做各的基建，端到端语言切换验收等两步齐后由主会话统跑 |
| 步骤 4 | 步骤 2 + 步骤 3（t 机制/store/主进程语言态就绪） | 簇 A/B/C 互并行 | 三簇组件文件集与命名空间文件对均不相交 |
| 步骤 5 | 步骤 4 | 无（串行） | 巡检对象是全量抽取后的终态 |
| 步骤 6 | 步骤 5 | 无（串行收尾） | 骨架终稿 + 验收 + 审查 |

### 6.2 并行波次

- **波次 1（串行先行）**：步骤 1。理由：通道契约、字典架构与命名空间正交划分若不稳，后续全返工。
- **波次 2（可并行，2 agents）**：步骤 2 ∥ 步骤 3。理由：main/renderer 文件集不相交，双方只读消费步骤 1 冻结的 shared/i18n 基建；行为依赖（setLanguage 链路）在等齐后由主会话统验。
- **波次 3（可并行，3 agents）**：步骤 4 三簇。理由：簇文件集与命名空间文件对双重不相交；每簇工作量（≈10 文件抽取 + 双语字典）远超并行重建成本。
- **波次 4（收尾，独占）**：步骤 5 → 步骤 6。理由：巡检与文档收尾对象是终态，主会话亲自执行。

### 6.3 并行门槛

- 波次 2：两步骤文件集不相交（src/main vs src/renderer）✓；主进程双语化（≈8 文件 + 三命名空间对）与 renderer 基建（store/hook/两 ConfigProvider/语言行）各预计 ≥1 小时 ✓。
- 波次 3：三簇组件集与命名空间对均不相交 ✓；每簇 8—13 文件 ✓。common 命名空间与骨架文档为共享文件，簇 agent 只读/不碰（见红线），不构成交集。

### 6.4 不可并行的红线

- **同一字典文件**：任何两 agent 不得写同一命名空间文件对（zh+en 同理）；common 键集步骤 1 冻结，波次 3 簇只读，缺词上报主会话收口。
- **同一骨架文档**：book/docs/architecture/项目骨架.md 归主会话（步骤 1 增条目、步骤 6 终稿），簇 agent 禁改——步骤 4 骨架同步并入收尾的显式偏离已在 5.4.5 声明。
- **shared 契约三件套**（shared/settings.ts / preload/index.ts / index.d.ts）只在步骤 1 冻结期修改，后续步骤只读。
- **依赖未冻结契约的步骤必须等待**：步骤 3/4 不得提前于步骤 1 的字典架构开工。
- **互相破坏验收基线**：步骤 5 巡检期间禁一切代码改动以外的并行实现；code-review 修复轮与巡检修复不得同时进行。

- 簇 agent 对「注释里中文是否入字典」按 2.3 范围线执行：只抽用户可见文案，注释保留。
