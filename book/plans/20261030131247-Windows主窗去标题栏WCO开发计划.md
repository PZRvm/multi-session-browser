# 阶段开发计划：Windows 主窗去标题栏（WCO 窗口控制右上角）

> 创建时间：2026-10-30 13:12:47（Asia/Shanghai）
> 需求来源：`book/notes/learn/2026-10/20261030130138-Windows主窗去标题栏窗口控制右上角.md`（调研报告，四条待确认假设已获用户逐条确认）
> 执行模式：直通
> 实施范围：仅 Windows 主窗——去系统标题栏、系统窗口控制按钮（WCO）浮于右上角、Tab 栏避让 WCO 区。mac/Linux 与一切子窗形态零改动；不新增自绘按钮、不新增 IPC、不动板头与页内标题。
> 目标结果：Windows 主窗无系统标题条，右上角为系统原生最小化/最大化/关闭按钮（Win11 Snap Layouts 可用），Tab 再多也不与按钮区重叠；窗口拖动/双击最大化如常；亮暗主题下按钮配色跟随；`npm run build:win` 打包安装后一切成立（含 #42409 兜底验证）。
> 当前进度：步骤 4 / 4，阶段已完成（观感手验 8 步随验收文档 book/notes/summary/20261030131247-…/20261030134409-阶段验收.md 人工执行）

## 1. 当前基线

- 主窗建窗 `src/main/index.ts:208-224`：仅 darwin 分支配 `titleBarStyle: 'hidden'` + `trafficLightPosition: { x: 14, y: 12 }`（三灯定位板头左端）；win32/linux 无窗体配置、保持系统框（198-207 行注释"Windows/Linux 不携带 query、保持系统框原形态（平台惯例沿用）"——本阶段该表述修订）。macOS 关窗重开走 `activate → createWindow`（664-669 行），重建时现取外观快照（190 行注释）。
- 显示链 `src/main/index.ts:214/229-231`：`show: false` + `ready-to-show` 才 `win.show()`——正是 Electron [#42409](https://github.com/electron/electron/issues/42409) 竞态面（`show:false` + `titleBarOverlay` + 打包后 `loadFile` 时 ready-to-show 有概率不触发；28/33/37/38 版本均有报告，修复入 43.7.4+，本项目 Electron 39.8.10 未含）。官方 workaround：`did-finish-load` 兜底 + 只显一次标志。
- 主题链 `src/main/appearance.ts`：`syncSnapshot`（258-281 行）全窗循环 `setBackgroundColor`；构造注入的 `onResolvedThemeChanged` 回调（131/139/277-280 行）由 `index.ts:115-121` 桥接 registry 同步 WebContentsView 兜底底色——WCO 配色同步的现成挂点（overlay 色只随亮暗翻转，不随主题色三系，与该回调粒度恰好一致；建窗初值沿 217 行 `getAppearanceBackgroundColor` 现取快照先例）。
- Tab 栏 `src/renderer/src/assets/app.css:2098-2125`：`.chrome-tabs` 高 40px、`padding: 6px 10px 0`、空白区 `app-region: drag`（恒生效）；Tab 溢出靠 flex 收缩（`.chrome-tab { min-width: 0 }`、`.chrome-tab-title { max-width: 180px; ellipsis }`），无横向滚动——Tab 多时排满栏右缘（与右上角 WCO 冲突的根源，也是避让的解法：右侧 padding 收窄可用宽，既有收缩机制自动在避让线内完成）。
- 色值三处对账：`--chrome-tabbar` 亮 `#dee1e6`（app.css:56）/ 暗 `#202124`（app.css:115），`--chrome-ink` 亮 `#3c4043` / 暗 `#e8eaed`，`DESIGN.md:30/42` colors 块同值。chrome-\* 族为全局常量不随主题色三系（琥珀/雾蓝/苔绿）。主进程当前无 chrome 族实色单源（窗口背景 `themeBoardBackground` 在 `src/shared/themeSystems.ts:298` 有单源先例，其头注 17-20 行（appearance.ts）即"app.css 与 shared 两处字面量改一处须同步另一处"的对账纪律）。
- 拖拽带：`.board-head`（app.css:264-268）与 `.chrome-tabs` 空白区 drag 恒生效，注释明确"Windows 冗余生效为无害增益，冻结现状不加门控"——Windows 去栏后自动升级为主拖拽区，零改动；drag 区双击最大化为 Windows 系统内建行为（[#15163](https://github.com/electron/electron/issues/15163) 反证无法单独禁用）。
- 40px 顶区对齐契约：`.board-head` 与 `.chrome-tabs` 均 40px、两线对齐（app.css:259-263/2107-2110 头注，2026-09-28 用户三裁决）——WCO overlay `height` 必须取 40 并登记耦合。
- 用户环境：Windows 11（build 26100），Snap Layouts 可实机验收。

## 2. 范围边界

### 2.1 本阶段必须完成

- 主进程 win32 主窗：`titleBarStyle: 'hidden'` + `titleBarOverlay: { height: 40, color, symbolColor }`（实色，色值经 shared 单源派生——[#48193](https://github.com/electron/electron/issues/48193) 透明色 hover 渲染 bug，禁透明）。
- `ready-to-show` + `did-finish-load` 双触发显示（只显一次标志；注释登记 43.7.4+ 升级后可移除）。
- 亮暗翻转时 `setTitleBarOverlay` 同步配色（沿 `onResolvedThemeChanged` 回调桥接，appearance.ts 不新增窗口形态知识）。
- `src/shared/themeSystems.ts` 新增 chrome 表面色派生（chrome-tabbar / chrome-ink 亮暗两值），app.css 与 DESIGN.md 对账注释。
- `.chrome-tabs` 右侧 padding 按 `env(titlebar-area-width, 100%)` 避让（fallback 后非 win32/独立窗计算恒为原 10px，天然平台门控、不新增 query）。
- DESIGN.md 增补主窗 Windows 窗体形态条目；`index.ts` 旧注释修订；`book/notes/summary/2026-11/legacy-process.md` 阶段行同步。
- `npm run typecheck` / `npm run lint` / `npm run build` 全绿；`npm run dev` 与 `npm run build:win` 打包安装双轨手验（#42409 在打包 loadFile 路径才易复现，dev 通过不算数）。

### 2.2 本阶段明确不做

- mac / Linux 零改动：darwin 分支、`winc=traffic` query、三灯定位不动；overlay 配置仅进 win32 分支；"mac 不动"验收手段为 diff 审查（本机无 mac，不承诺跨平台实机验证）。
- 一切子窗不动：独立窗口（tear-off）、设置窗、建议子窗、截图反馈/编辑窗、工作区 sheet 等保持各自既有窗体形态。
- 板头不动：Windows 页内标题「多会话测试浏览器」保留（用户确认假设 3），`.board-head` 与 `.traffic-spacer`/`windowTrafficControls` 门控不触碰。
- 不引入 Tab 横向滚动、Tab 列表压缩下拉等新溢出机制（既有 flex 收缩 + 省略已满足避让边界）。
- 不自绘窗口控制按钮、不新增 IPC 通道与 preload 面（WCO 按钮系统绘制，无需 renderer 感知）。
- 不增删源码文件、不改文件职责边界——`book/docs/architecture/项目骨架.md` 同步不适用（纯内部实现改动；themeSystems.ts 增导出仍属其"主题 token 单源"既有职责）。

### 2.3 本阶段数据原则

- 零落盘变化：无新增持久化键、无偏好迁移；overlay 配色纯运行期由亮暗态派生。
- 避让宽度一律消费浏览器维护的 `env(titlebar-area-width)`，禁止 JS 测量/缓存宽度后写入样式（防最大化/拖宽后的陈旧值）。

### 2.4 契约核对

1. **chrome 表面色主进程单源**：`src/shared/themeSystems.ts` 新增亮暗派生函数（chrome-tabbar 底色与 chrome-ink 符号色两组）；同步对账三处——themeSystems.ts（新单源）、app.css:56/115（token 字面量行加对账注释）、DESIGN.md:30/42（colors 块）。完成标志：三处四值（#dee1e6/#202124/#3c4043/#e8eaed）逐字一致且 `npm run typecheck` 通过。
2. **主窗窗体形态文档化**：DESIGN.md 增补条目（WCO 方案与来源裁决、overlay height=40 与顶区对齐契约耦合、配色对账、Tab 避让 env 机制、#42409 兜底与 43.7.4+ 升级移除条件）；`src/main/index.ts:198-207` 旧注释"Windows/Linux 保持系统框原形态"随之修订为 win32 WCO 表述（Linux 仍系统框）。完成标志：`grep -rn "保持系统框原形态" src/` 零命中（DESIGN.md 保留历史沿革记录不受此限）。
