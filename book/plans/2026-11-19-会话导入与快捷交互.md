# 会话导入与快捷交互开发计划

分级 **L**。导入修复涉及会话分区写入后的页面恢复与 webContents 生命周期，另外两项分别涉及地址栏和会话列表。首个实现提交的正文记录分级与验证方式。更新于 2026-11-19，已完成 Phase 6。macOS 验收通过，Windows 与 IndexedDB 既有兼容边界见验证记录。

## Step 0 · 需求简报

- **Chrome 导入**。从目标会话的右键菜单完成导入后，当前会话自动恢复浏览，首次输入地址即可命中新导入的历史，重建后的网页直接读取已成功导入的站点数据。用户无需切出再切回。导入非当前会话时保持眼前的会话，首次正常切入目标即可读取数据。
- **地址栏**。普通模式下，输入文字并看到行内 URL 补全后，按一次 Enter 直接在当前 Tab 打开完整目标。建议列表明确高亮的项目优先，搜索模式的 Enter 继续提交当前引擎的关键词。
- **会话列表**。双击行的非控件区域，进入该行原有的名称输入框。双击未选中的行时，沿用第一次单击的选中行为。保存、失焦与 Esc 沿用菜单重命名的处理。
- **范围边界**。导入只消费用户选定的 Chrome profile、类型和冲突裁决，处理结果按项报告。本轮范围包括导入完成后的恢复、localStorage 写入、Enter 提交和双击触发。分区和落盘格式、导入冲突语义、账号及浏览记录的授权范围、标签恢复模型、界面布局和产品发布均在范围外。

需求基线见 [PRD 3.1、3.2、3.9、4.11](../docs/requirements/PRD.md)。本次用户反馈修订了其中「未接受的行内后缀不参与 Enter 提交」的约定。

## Phase 1 · 现状与影响

| 功能 | 代码依据 | 风险 |
| --- | --- | --- |
| Chrome 导入 | [chromeImport/index.ts](../../src/main/browser/chromeImport/index.ts) 在 `runImportQuiesced` 内写入，在其返回后显示原生结果。[registry.ts](../../src/main/browser/registry.ts) 会关闭目标页面并清空运行时激活位，结束时调用 `switchSession`，后者异步准备代理和扩展后才挂载页面。 | 执行结果可能先于激活提交到达。此时 [SessionPanel.tsx](../../src/renderer/src/components/SessionPanel.tsx) 触发的历史重拉会经 [browser/ipc.ts](../../src/main/browser/ipc.ts) 按窗口解析运行时会话，可能因空激活位而被拒绝。同一会话恢复前后 ID 相同，[browser store](../../src/renderer/src/stores/browser.ts) 的快照更新也不会自动再拉历史。仅用激活位是否为空判断回切，还可能覆盖正在异步准备的其他会话。 |
| 地址栏 | 主窗和独立窗共用 [Toolbar.tsx](../../src/renderer/src/components/browser/Toolbar.tsx)。Enter 已处理高亮项，普通提交只读取已接受的补全；当前行内补全已经保存完整 `targetUrl`。 | 从展示文字重新分类会丢失原协议或 `www`，先设 React 状态再提交可能读到上一拍的草稿。 |
| 会话列表 | [SessionRow.tsx](../../src/renderer/src/components/SessionRow.tsx) 的行点击负责选中，右键菜单的 `rename` 复用 `startNameEdit`，行级暂无双击入口。 | 菜单按钮的两次点击即使各自阻止冒泡，双击仍是独立事件。编辑态重复触发会重置草稿，拖拽释放后也需验证事件边界。 |

导入时序是静态分析确认的竞争窗口。实施前用测试 profile 复现并分别观察分区写入、恢复快照、历史 IPC 和网页读值，确认用户遇到的是页面、历史还是两条链路同时失效。地址栏回归依据见[受控补全历史记录](../notes/learn/2026-11/20261106165837-受控地址栏补全需要保留完整目标与撤销状态.md)。

## Phase 2 · 设计

### 导入完成后恢复浏览

1. 在 `registry.ts` 复用现有关闭与恢复链。目标分区结束写入或还原后释放导入占用，通过可等待的内部激活路径，在已有分区上完成代理、扩展准备、Tab 恢复、view 挂载和快照发布。等待到会话恢复提交即可，网页网络加载沿用现有加载状态。普通切换调用方继续沿用现有入口。
2. 恢复前用最新的切换代号和主进程选中状态复核目标。用户已切走、清空选择或删除目标时结束自动恢复。把确认仍应恢复目标、接入异步激活和最终提交纳入同一切换代号的保护，避免导入回切盖过更新的选择。关闭失败、导入失败及部分成功同样收尾，保留原始错误和分项写入事实；已经写入但恢复失败时，用现有原生结果框如实呈现两者。
3. `chromeImport/index.ts` 的成功结果在应恢复的目标提交后返回，继续用原生结果框。由 `SessionPanel.tsx` 在历史项成功、且浏览区与侧栏仍属于导入目标时，调用 browser store 重拉一次当前窗口历史。回填继续验证请求代号和会话身份；导入后台目标时，允许其在下一次激活时走现有拉取。沿用现有 IPC 载荷及来源窗口权限，无需逐条广播导入历史。
4. 页面按既有恢复集还原 Tab 顺序、URL 和激活位。验收以网页读到新数据为准，重建过程按现有语义重新加载，页面内输入和运行态不属于恢复集。独立窗口按现有导入关闭和归并规则处理。

### localStorage 运行时写入

实测证实已使用的站点在页面重建和会话切换后仍读到旧值，重启应用才读到已写盘值。用户确认将 localStorage 写入链路纳入本轮。离线探测仍读取源 Chrome 固定副本和目标 LevelDB 副本。解码 Chromium 的 Latin1 与 UTF-16LE 格式，按第一方 HTTP/HTTPS 源和逻辑键归并。不支持的编码或来源按条计数，带顶层站点隔离的存储键保持原隔离边界。

执行期先静默目标会话。主进程创建只属于该分区的临时 WebContentsView，在请求阶段拦截全部网络访问。只有当前选定源的唯一 URL 能得到空白本地响应，响应禁用脚本和资源加载。通过 Chromium 的原生 localStorage 读回目标现值，逐键验证探测时的结果。发现用户提交后目标漂移时拒绝写入本类型，提示重新探测。所有源完成复核后才按裁决写入，通过同一个运行时读回确认。写入前保留受影响键的私有备份，类型内失败恢复已尝试过的源并核对结果。还原失败时保留备份并显示已有的失败信息。

### Enter 打开行内补全

在 `Toolbar.tsx` 保留输入法组合拦截。Enter 依次处理指定引擎模式、可见且已高亮的历史项、仍有效的行内补全、已接受的补全目标、普通原文提交。有效的行内补全直接把 `completion.targetUrl` 交给既有 `submitUrl`，复用作用域检查、待导航与失败反馈。Esc 或删除取消补全后，Enter 按当前原文处理。Tab 的引擎优先级、左右键当前的光标或补全行为、原生建议窗口和样式均沿用现状。

### 双击会话行

在 `SessionRow.tsx` 增加行级 `onDoubleClick`，对空闲编辑态、左键和非交互目标调用 `startNameEdit`。输入框、菜单按钮和拖拽过程排除在触发范围外。复用现有行内输入、焦点和 `renameSession` 校验与保存。单击、键盘 Enter/Space 选中和右键菜单继续使用既有入口。两个快捷交互新增的都是已有操作入口，可复用现有可访问名称与反馈。

## 实施顺序与验收

| 顺序 | 操作 | 通过标准 |
| --- | --- | --- |
| 1. 导入生效 | 在隔离数据目录搭建 Chrome 测试 profile。本地站点显示 Cookie 对应身份及 localStorage、IndexedDB 标记，历史用目标会话从未访问过的 URL。修复前记录失败场景，修复后从实际右键入口导入。 | 不切会话、不手动刷新，确认原生结果框后当前 Tab 自动恢复，网页读到已成功写入的数据，地址栏立即可搜到新 URL。分别覆盖历史单选、站点数据单选及组合、两种冲突裁决、取消、部分成功和失败。选中会话切走且下一会话尚在准备时，最终保留新选择；后台目标导入后首次切入生效，其他会话的网页与数据不受影响。恢复后 Tab 顺序、URL、激活位和目标分区正确。 |
| 2. 地址栏导航 | 主窗和独立窗分别输入有历史行内补全的短前缀，使用包含 `http://www.`、路径和查询参数的本地历史目标。 | 一次 Enter 只发起一次导航，地址完整。另测建议高亮优先、Esc 后以原文提交、无命中走默认搜索、指定引擎搜索、IME 候选确认、Tab/右方向键、空输入、无效 URL、切 Tab 或会话后无旧目标。 |
| 3. 双击重命名 | 双击已选和未选的会话行，分别测 Enter 保存、失焦保存及 Esc 取消。用菜单进入同一编辑态作对照。 | 正确目标行获得名称输入焦点，未选中行只发起一次切换，新名称重启后仍存在。单击和键盘仍可选中。双击菜单按钮、名称或备注输入框不会触发行重命名；拖拽重排和编辑中禁拖通过。 |

用 `npm run dev:agent` 和独立测试数据运行以上回归。测试包含可用平台及导入类型，Windows 或不兼容的 Chrome 数据类型如实登记。产品代码变更后运行 `npm run typecheck` 与 `npm run lint`。Phase 5 按[审查清单](../guidelines/review-checklist.md)检查会话隔离、恢复竞态与单次提交，发现项记入 issue。Phase 6 将验收证据、PRD 和设计约定的对应更新写回 book，重建索引。
