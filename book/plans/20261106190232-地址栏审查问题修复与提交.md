## 2. 范围边界

### 2.1 必须完成

- 未支持显式 URI 行内拒绝，包含 blob、view-source、magnet、无 `//` 自定义 URI；保留已认可的搜索运算符和合法主机端口例外。
- 合法显式 HTTP(S) 网址按 URL 语法放行下划线主机；无协议域名仍验证主机意图与语法。非法 IP/端口和网址中间真实 Tab 仍拒绝。
- 普通查询识别 U+3000/U+00A0 等空白，保留查询原文；不能把网址 Tab 防护变成外发查询。
- 菜单撤销/重做在主窗与独立窗地址栏中消费现有局部栈；其他壳输入、设置窗、被测网页和 DevTools 保持原生编辑。恢复 CSS 原换行，值不变。
- 完成命令、实际菜单回调、键盘、普通输入/网页表单和双窗口验证，书写回后提交中文 Clean Commit；提交 body 记录 L 级动机与证据。

### 2.2 明确不做

不改 partition、代理、登录态、持久化 schema、跨窗 Tab 生命周期和搜索模板；不清真实数据，不自动重载 Google 或改站点主题；不调整外观或引入依赖/通用编辑器。不把其他 legacy 审查算作当前五项。提交不包含主仓库未跟踪文档，不合并、不推送。

### 2.3 数据原则

分类纯本地，测试使用独立 userData。菜单命令只携带 undo/redo，不携带输入内容、Tab 或会话数据；renderer 不获得 invoke/send 权限。其他窗口由原生 webContents.undo/redo 执行。所有迟到命令按当前焦点消费，不保存命令供下次聚焦使用。

### 2.4 Phase 2 契约与设计

- 新 `shared/nativeEditing.ts` 定义单一 `native-editing:command` 推送和闭集 `undo | redo`；preload 仅暴露 `nativeEditing.onCommand`，过滤值并返回退订函数，无 renderer→main handler。
- 主进程菜单用明确 click 与原有平台加速键替代 undo/redo role。现取 focused webContents；只有 BrowserWindow 自己的 webContents 且通过现有 registry.resolveSenderScope 的主/独立壳才收到推送。网页、DevTools、设置/选择窗等走该 focused webContents 原生编辑。不能靠 URL 或 getAllWindows[0] 猜窗口。
- renderer 主/独立壳入口在 React 挂载前订阅；向当前 activeElement 派发 renderer 本地、可取消编辑事件。Toolbar 只在 input 仍聚焦、非组合态时消费事件并调用与 keydown 相同的局部栈操作。未消费时调用 document.execCommand，保留其他壳输入原生行为；无延迟焦点转移。
- Toolbar 的 DOM 监听用 layout effect 同步最新闭包并清理；撤销/重做共用一段操作。空栈幂等，不回退到旧原生栈；IME 期间交原生编辑。现有 scope/version、选区与完整目标快照不改所有权。
- 文件：addressInput.ts、Toolbar.tsx、app.css；新增 shared/nativeEditing.ts、renderer/nativeEditing.ts；修改 main/index.ts、preload/index.ts/index.d.ts、renderer/main.tsx。同步 PRD、骨架与 ADR-002。无新界面或可见文案，CSS 只恢复审查指出的换行；沿用 impeccable 已定工具栏视觉。
- 方案依据：Electron MenuItem role 会覆盖 click；显式菜单 callback 才能按焦点分流。避免执行任意 renderer JavaScript、模拟快捷键或扩展通用 IPC。见 [MenuItem](https://www.electronjs.org/docs/latest/api/menu-item)。
