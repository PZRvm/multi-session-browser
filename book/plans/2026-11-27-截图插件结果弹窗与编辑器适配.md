# 截图插件结果 Popover 与编辑器适配开发计划

分级 L。改动涉及 Electron 扩展剪贴板授权、截图来源校验和插件窗口归属。交互以本应用的内置截图功能为参照。 [任务分级](../guidelines/task-tiers.md) · [PRD §3.10.1、§3.12](../docs/requirements/PRD.md)

## Step 0 需求简报

| 项目 | 内容 |
| --- | --- |
| 背景 | 用户点击截图插件后，目前直接进入编辑。只想粘贴或保存原图时也要经过编辑器。 |
| 范围 | 自研截图插件的工具栏动作、工具栏 Popover 和编辑窗，覆盖普通 Chrome 与本应用。 |
| 排除 | 内置截图入口、录屏插件、第三方插件、整页和桌面截图、截图历史与公开发布。 |
| 边界 | 截取发起窗口中当前标签页的可视区。原图为 PNG，加载和导出使用每张图自己的 `captureId`。 |

点击插件即截图，把原图写入系统剪贴板，复制成功后显示可关闭的工具栏 Popover。工具栏 Popover 提供「下载图片」和「编辑图片」。只有用户点「编辑图片」才打开编辑器。编辑窗默认更大，大图首屏完整可见，工具与快捷键沿用内置编辑器。

普通 Chrome 从 157 起提供扩展 Service Worker 剪贴板写入，本机安装版本为 158。旧版离屏文档的复制命令有只产生 HTML 的情况。宿主使用 Electron 45.3.0，需单独验证后台写入和窗口边界。Chrome `storage.local` 的 10 MB 配额还可能被高分辨率 PNG 的 Base64 数据占满。 [Chrome 剪贴板文档](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers) · [Chromium 图片复制讨论](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/kSad7GEQFo0) · [Chrome 存储文档](https://developer.chrome.com/docs/extensions/reference/api/storage)

## Phase 2 设计

### 截图与工具栏 Popover

1. 工具栏 action 立即记录来源窗口和标签页，截取可视区并生成带 `captureId`、像素尺寸的原图。Chrome 采集期间监测来源窗口的活动标签切换和关闭，发生变更就丢弃该次结果并提示重试。Electron 采集具体标签页的 `webContents`。请求交错时按发起顺序提交剪贴板写入，跳过已失效的来源。
2. Chrome 在 Service Worker 通过 `navigator.clipboard.write()` 写入 `image/png`。Electron 沿受限扩展桥，由主进程复用内置截图的 PNG 剪贴板写法。宿主从本次截图动作绑定的目标取得 PNG，校验实际扩展发送者、`clipboardWrite` 声明、一次性点击授权、来源窗口与分区。授权在使用或失效后释放。 [内置截图主进程](../../src/main/browser/capture.ts) · [Electron Clipboard](https://www.electronjs.org/docs/latest/api/clipboard)
3. 普通 Chrome 在采集、复制和存储完成后，通过当前标签的 `chrome.action.openPopup` 打开原生工具栏 Popover。Electron 复用录屏插件所用的现有工具栏 Popover 承载，由后台一次性授权归还来源窗口和图标锚点。结果页通过明确的 `captureId` 取图。复制确认且原图可读后才显示「已复制到剪贴板」和两个按钮。按 Esc、点击外部或再次点击入口可以收起 Popover。点击编辑后加载独立编辑窗。使用插件现有主题和 i18n，新增简中、繁中和英文文案，键盘可按顺序访问两个按钮。 [Chrome Action API](https://developer.chrome.com/docs/extensions/reference/api/action) · [原生窗与截图交互规范](../../DESIGN.md)

| 操作或异常 | 预期 |
| --- | --- |
| 下载图片 | 下载本弹窗对应的原始 PNG，使用既有下载路径和同名避让。Chrome 按下载任务状态确认结果，Electron 使用现有落盘回执。弹窗仍可编辑或手动关闭。未确认落盘时只显示请求状态。 |
| 编辑图片 | 使用同一份原图打开独立编辑窗。打开期间防止重复点击，待编辑器收到并显示原图后关闭结果 Popover。打开或加载失败时保留可重试的结果 Popover。 |
| 手动关闭 | 结束本次结果交互，已在剪贴板的原图可继续粘贴。用户主动关闭后，迟到的开窗回调不得使弹窗恢复。 |
| 采集或剪贴板失败 | 显示实际失败。原图仍可用时保留下载和编辑入口，提示剪贴板写入失败。结果 Popover 创建失败且复制已完成时，保留剪贴板内容。 |

原图和续编图的 PNG 以 Blob 存入扩展自身的 IndexedDB，后台休眠后仍可按 ID 读取。旧 `capture:*` 条目按原 ID 兼容读取。结果页载入后持有原图。点编辑时续留交接快照，清理时暂时保护正在交接的原图，其余快照按现有 10 张上限裁剪。编辑窗载入后持有自己的快照，后续操作按本窗版本提交。快照与窗口归属限定在当前扩展和会话分区，原始下载和编辑产物各自使用对应版本。

### 编辑器

- 默认外窗目标为 **1440 × 960 逻辑像素**，按结果 Popover 所在显示器的可用区收敛。平台保留原生窗口边框和系统关闭键。
- 首次打开时，以工具栏和状态区之外的实际画布宽高计算 `min(1, 可用宽 / 图宽, 可用高 / 图高)`，等比居中。窗口尺寸变化时，自动适配状态继续保持整图可见。沿用插件的 ⌘/Ctrl+滚轮手动缩放，手动缩放后的溢出可滚动查看。
- 只调整 Stage 显示比例。指针命中、标注与裁剪沿用原图坐标，复制和下载保留原始像素尺寸，裁剪输出按选区尺寸。矩形、椭圆、箭头、画笔、双模式马赛克、文字输入、裁剪、撤销和重做直接复用现有工具。 [Konva 缩放实测记录](../notes/learn/2026-11/2026-11-11-插件画布缩放与原生提示.md)

## 实施顺序与验收

| 步骤 | 操作与通过条件 |
| --- | --- |
| 1. 确认平台能力 | 使用隔离配置验证本机 Chrome 普通扩展和 Electron 可后台写入真实 PNG，并用原生应用粘贴比对。Chrome 127–156 可以打开结果 Popover，后台复制不可用时显示提示，仍可下载和编辑。自动复制使用 Chrome 157 起提供的 API。 |
| 2. 接通工具栏 Popover | 触发真实插件按钮，先测到原图进入系统剪贴板，再观察结果 Popover。此时编辑器窗口计数为零。验证下载原图、编辑后关闭结果 Popover、Esc 或点击外部关闭。下载用 PNG 尺寸与像素对账。 |
| 3. 接通编辑器适配 | 用小图、超宽图、竖长图、4K / 高 DPI 图检查首屏四边可见。覆盖小屏、缩窗和手动放大。标注、裁剪、马赛克遮挡与输出尺寸都要在缩放后对账。 |
| 4. 验证失败和隔离 | 覆盖无活动页、权限拒绝、空图、存储失败、弹窗与编辑器加载失败及下载失败。两窗用不同标记页面快速截图，中途切标签或会话，再分别下载和编辑，核对窗口、剪贴板提交顺序和成品。验证普通网页、未获本次授权的扩展调用及失效来源被拒绝。 |
| 5. 回归与打包验证 | 执行 `npm run typecheck`、`npm run lint`、`node extensions/build.mjs` 和更新后的真机检查。在 macOS 与 Windows 分别记录普通 Chrome、Electron 主窗和独立窗结果，覆盖亮暗、三语和内置截图回归。截图任务只运行截图用例。Electron 调试用 `npm run dev:agent` 与隔离数据目录。使用同 ID 的测试包验证覆盖安装，再核对结果页、编辑器及语言资源已包含在 CRX。 |
