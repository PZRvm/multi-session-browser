# 地址栏交互与 Chrome 站点数据导入 开发计划

> 创建时间：2026-10-28 11:20:40（Asia/Shanghai）
> 需求来源：`book/docs/requirements/stages/feature-地址栏下拉融合与新会话空输入.md`；技术依据为 `book/notes/learn/2026-10/20261028105514-Chrome登录态与站点存储导入可行性.md`，并纳入用户本轮范围与冲突裁决
> 执行模式：波次
> 实施范围：地址栏与历史建议无缝融合、新建会话不残留旧输入、Chrome 本机 Cookie 文件读取与 Mac 授权解密、兼容格式的 IndexedDB 完整快照导入；不做 Chrome 扩展与 sessionStorage
> 目标结果：主窗和独立窗地址栏交互一致；所选 profile 的受支持 Cookie / IndexedDB 只进入目标会话；冲突可选以 Chrome 或当前会话为准，失败与不支持如实反馈，QQ 邮箱登录结果有独立验证记录
> 当前进度：步骤 0 / 7，阶段尚未开始；本文件为开发计划，不表示解密、文件兼容性或登录态迁移已经验证

## 1. 当前基线

- **代码基线**：当前检出 `main@a6e306f`，工作区无源码改动；本轮写计划前 `npm run typecheck`、`npm run lint` 均通过。最近真实计划为 `book/plans/20261027150209-工作区右键菜单原生化开发计划.md`；其功能已完成。本阶段体量大于该直通专项，按完整版编排。
- **版本与依赖**：`package.json` 声明 Electron `^39.2.6`；前序隔离实验实测本机 Electron **39.8.10 / Chromium 142.0.7444.265**。已有 `classic-level`，`historySource.ts` 已使用内置 `node:sqlite`；未安装 Dexie、Chrome 导出扩展或 Cookie 解密原生模块。新增依赖不是本计划前提。
- **地址栏显示**：`src/renderer/src/components/browser/Toolbar.tsx` 中，显示优先级为 `draft ?? pendingShown ?? mainUrl`；`draft`、`pending`、建议高亮/关闭状态保存在复用组件中。`pending` 有 Tab 判据，`draft` 没有明确的会话/Tab 归属。它们是待复现核对的污染入口，尚不能仅凭代码认定用户残留文本的唯一根因。
- **窗口与历史**：主窗 `components/BrowserFrame.tsx`、独立窗 `components/IndependentWindowFrame.tsx` 均复用 Toolbar。`stores/browser.ts` 已在快照会话漂移时清空历史镜像，并用拉取代号拒绝旧历史回填；修复优先限定地址栏本地瞬态，不以清除用户历史或重建浏览页解决。
- **几何与视觉**：`src/shared/omniboxSuggest.ts` 的 `SUGGEST_PANEL_GAP = 6`、边框合计 2、行高 30、最大高度 298，与 `app.css` 对应。输入框四角 14px，建议面板四角 8px；主进程 `browser/omniboxSuggest.ts` 将面板独立 clamp 到显示器工作区。`useOmniboxSuggestWindow.ts` 管锚点、show/hide 与鼠标回推，子窗不夺焦、页面保持可见。
- **主页现状**：`manager.ts:newUserTab` 使用设置中的主页，`persistence.ts` 的首 Tab 兜底复用该方法；PRD 3.8.2、验收 27 明确新会话首 Tab 也加载主页。修复空输入必须区分“旧会话残留”和“新会话自身真实 URL”。
- **Chrome 导入现状**：`src/shared/chromeImport.ts` 仅含 `history / localStorage`、3 条 invoke 通道；`ChromeImportResolution` 只有 `localStoragePolicy`。`index.ts` 暂存计划 TTL 为 60 秒，历史保留内存条目，localStorage 只暂存统计、执行时重读源目录。新增类型需要固定所确认的数据快照，不能继续依赖统计与源数据始终不变的假设。
- **执行入口与原生界面**：实际前端编排在 `components/SessionPanel.tsx:openImportChrome`，不是 SessionRow。它调用 `chrome-import-select` sheet → dry-run → 可选冲突 sheet → execute；默认策略 `session`。`shared/dialog.ts` 的冲突字段只表达 localStorage 键数/站点数，选择窗高度按两条内容行计算；`workspacePickerWindow.ts` 负责守卫和原生窗口，`WorkspacePickerWindow.tsx` 负责表单展示。不能只扩 scope 枚举而遗漏表单、计数、尺寸、守卫和结果文案。
- **目标分区**：`registry.ts` 的分区路径解析与 `runImportQuiesced` 可复用。当前静默窗口关闭该会话全部 webContents、finally 恢复激活画面；它是否足以释放 IndexedDB 及后台存储句柄尚未验证。同引擎的 `clonePartition` 整分区复制不等于 Chrome 跨版本导入的兼容性证据。
- **能力证据**：前序临时分区实验验证过 Electron Cookie API 写 HttpOnly、同分区同源新页面读取 IndexedDB 的 Blob/Date；没有验证真实 Chrome 密钥读取、真实 Cookie 解密、跨版本 IndexedDB 文件复制或 QQ 邮箱完整登录迁移。
- **文档差异**：`book/docs/requirements/PRD.md` 3.9、验收 36 与 DESIGN 导入条目仍只允许历史/localStorage；DESIGN 地址栏条目仍记载 6px 间距。`book/docs/architecture/项目骨架.md` 的相关职责与通道说明也需随实现同步。规划时不把这些未来变更写成已交付事实。

## 2. 范围边界

### 2.1 本阶段必须完成

- 建议展开时输入框下角取消圆角，面板上角为直角并贴住输入框，接缝无空隙、双线和分离底色；收起后输入框恢复四角圆角。主窗/独立窗、亮暗、缩放和窗口移动均覆盖。
- 新建会话不继承旧会话的网址草稿、搜索词、待导航文本、错误状态和历史建议；地址栏瞬态明确绑定当前窗口中的会话与 Tab，迟到异步回复不污染新作用域。
- 保持主页语义：主页留空时新会话地址栏为空；设置主页时先清除旧输入，页面导航后只展示该新会话自己的 URL，不改写主页配置、不长期隐藏真实地址。
- Cookie：直接读取默认 Chrome 用户目录中所选 profile。支持有效明文记录；Mac 支持经系统授权获得密钥并解密已验证格式，再通过目标分区 Cookie API 写入。保留普通 Cookie 的作用域和受支持属性，明确过期、无法解密、格式不支持、分区 Cookie 等结果。
- IndexedDB：先证明兼容性，再支持已验证布局和版本的完整站点存储快照，包含对应 Blob 等关联数据；目标冲突支持完整保留/替换，替换范围在原生裁决框内可见。
- 沿用会话级一次二选一的冲突交互：同次导入按类型汇总后，由用户选择「以 Chrome 为准 / 以当前会话为准」。localStorage/Cookie 按受支持记录处置；IndexedDB 按已冻结的独立站点快照处置。
- 保留历史/localStorage 原能力、原生模态与结果框、三语言、会话隔离、恢复画面和失败还原；落实取消/过期的临时资源清理。
- 至少有受支持的 Mac Cookie 解密正例和 IndexedDB 文件迁移正例。全部禁用或全部报“不支持”不能代替该能力交付。

### 2.2 本阶段明确不做

- Chrome 扩展、扩展导出包、持续同步、自定义 Chrome 目录、其他浏览器导入：后续另立项。
- sessionStorage 导入、标签页 namespace 迁移、页面早期注入与标签页运行态持久化：本阶段排除。
- Windows 应用绑定加密的绕过、提权或向 Chrome 注入；本期也不新增 Windows DPAPI 专用依赖。非 Mac 平台先支持有效明文，其他加密记录明确不支持，后续另评原生平台适配。
- 任意 Chrome/Electron 版本之间的通用 IndexedDB 转换、原始 LevelDB 记录拼接、行级数据库合并、无法识别的 storage bucket 格式、不可迁移密钥对象的无损承诺。
- 修改源 Chrome 数据或关闭其加密保护、强制结束用户 Chrome 进程、共享 profile/partition、导出密码、保证所有网站免登录。
- 重做历史搜索排序、会话管理、设置窗口、代理或 DevTools。保留现有页面和会话，不通过清空环境修复地址栏。

### 2.3 本阶段数据原则

- 所有运行时验证强制使用 `MSB_USER_DATA` 临时目录。源侧先用专用 Chrome 测试 profile/合成库；真实 Chrome 只在用户显式导入动作中只读访问。QQ 邮箱操作由用户完成登录验证，不收集密码，不读取邮件内容。
- 仅读取勾选内容，源路径由主进程探测白名单解析；renderer 不提交任意文件路径、不接收 Cookie 原值、密钥或 IndexedDB 内容。新 Cookie/IndexedDB 文件快照要求源 Chrome 已退出或存在可靠一致快照证据；旧两类单独导入不无故增加此限制。
- 本项目不另建业务加密格式。有效明文可直接导入；Chrome 已加密值须先解密，不能把密文当作 Cookie 原值。钥匙串访问走系统允许的授权路径，不记录密钥/Cookie 值，不将已解密 Cookie 输出到临时文件。
- 源快照在 dry-run 后固定，执行只消费主进程暂存的同一份数据；取消、TTL、失败与退出清理快照。临时目录限当前用户访问。还原失败时保留必要备份并明确报告，不能误清唯一恢复副本。
- 原则为**类型间可部分完成，类型内失败可还原**：历史/localStorage 保持现有语义；Cookie 回滚本次变更记录，IndexedDB 回滚本类型本次变更的快照及必要元数据。还原失败单独报告，不把它等同普通导入失败，也不继续写同一损坏目标。
- 统计有单位且只反映真正结果。Cookie 未支持/解密失败不可算成功；IndexedDB 的站点数不能冒充记录数；失败回滚后的写入不能留在“新增成功”计数中。
- “以 Chrome 为准”不意味着清空目标会话；IndexedDB 独立快照单位内可能被移除的目标专有数据，必须在冲突摘要中说明。其他站点、其他类型和其他会话保持不变。

## 3. 开始编码前的契约核对

步骤 1 形成技术证据，步骤 2 冻结以下契约。完成之前不分派并行实现。

1. **权威需求与设计修订**：同步唯一 `book/docs/requirements/PRD.md` 3.2.1、3.8.2 相关说明、3.9 与验收 27/36：旧输入清理不改变主页；导入扩四类；记录级合并与 IndexedDB 快照替换分开描述；Mac 受支持格式与其他平台加密限制如实注明。DESIGN 地址栏间距与导入两行/单类型冲突的旧约定一并修订，视觉实施走 impeccable scoped 流程。PRODUCT 只增已确认的范围事实，修正本次涉及的 PRD 引用，不清理无关历史文档。
2. **建议子窗度量与可呈现状态**：`SUGGEST_PANEL_GAP` 变为 0；接缝处不重复绘边，`SUGGEST_PANEL_BORDER` 随实际剩余边框重新确定，行高与最大高度原则上保持。CSS、共享常量、主进程 bounds 和 DESIGN 四处对账。当前 show/hide 七通道可保留；若主进程因空间不足拒绝展示，复用 show 的结果返回 `canPresent`，preload 两处同步，shell 以当前有效请求的结果决定融合态。旧回复不得复活已关闭/已切换的建议。
3. **输入作用域**：地址栏编辑、pending、错误定时器、建议选中/抑制状态都归属 `(sessionId, activeTabId)`，窗口由 renderer 实例天然限定；scope 漂移当拍不显示旧值。异步导航提交须在回填前核对发起 scope。优先在地址栏局部组织状态，不以重新挂载整个 BrowserFrame/Toolbar 破坏录屏等不相干订阅。确需抽文件时由步骤 2 定名，随后更新骨架。
4. **导入类型与载荷**：`CHROME_IMPORT_SCOPES` 扩为 `history / localStorage / cookies / indexedDB`，保留 `ChromeImportPolicy = 'chrome' | 'session'`；resolution 从仅 `localStoragePolicy` 收敛为同次导入的 `policy`，默认保持现有 `session`。内部生产者/消费者同版本同步迁移，不新增永久双字段来源。dry-run/result 必须有计数单位 `records / sites`、支持/跳过/失败数与闭集原因码；结果区分 `done / partial / skipped / failed / unsupported`，不能把未实现模块占位成 done。
5. **暂存生命周期**：新增 `chrome-import:cancel`，导入域由 3 条变为 4 条 invoke，preload 增 cancel。planId 一次消费、绑定发起 shell/目标会话/profile/scopes；`prepare` 产物由主进程持有，renderer 只拿统计和标识。60 秒确认 TTL 从准备完成后开始，不能包含用户处理钥匙串授权的等待；任务超时、系统授权拒绝、父窗关闭与已有 sheet 60 秒兜底分别处理，终止后不得后台继续写入。复核目标存在性及占用，目标冲突在静默窗口内重新核对，改变则返回重做探测，不能按旧摘要扩大写入。
6. **Cookie 引擎**：源侧读取 SQLite schema/版本、明文或已识别密文、域名校验前缀与时间字段；Mac Keychain helper 为异步、固定参数、无 shell 拼接的系统调用或等价原生接口，输出只进主进程内存。目标 via `Session.cookies`，普通 Cookie 身份、host-only/domain、path、过期、Secure/HttpOnly/SameSite 有对照表。同名不同 path 不混淆；不支持的 CHIPS 等不能降成普通 Cookie。会话 Cookie 仅导入源快照中实际存在者，不伪造过期时间。
7. **IndexedDB 单位与兼容性**：步骤 1 冻结最小可验证支持矩阵，至少包括 Chrome/目标 Chromium 版本、后端、路径布局、站点及默认 bucket 解析、关联 Blob、目标重开读写与回滚。以同一底层库不可分割的站点快照为裁决单位，不能在一个 LevelDB 内混合两侧记录；不同值或无法可靠判同按冲突处理。路径由受控清单生成，拒绝逃逸/符号链接；不得复制整个 QuotaManager 覆盖其他站点，若依赖元数据必须给出精准映射和备份还原证据。
8. **原生 sheet 与 i18n**：`shared/dialog.ts`、main picker、`WorkspacePickerWindow.tsx` 将单 localStorage 摘要改成按类型、单位的摘要数组；冲突上下文用 planId 从主进程暂存取权威数据，不让 renderer 自报破坏范围。选择窗勾选行按实际 scope 数计算高度，能力提示为简短事实；新增三语字典键覆盖 Cookie/IndexedDB、授权/文件占用/不支持/部分成功/还原失败/快照替换语义。不新增 renderer Modal/message/notification。
9. **模块契约与并行写入归属**：步骤 2 定义只在主进程使用的引擎接口：`prepare`（源快照/探测）、`apply`（静默目标内按 policy 执行并提供还原）、`dispose`（清理）；具体类型在新 `chromeImport/types.ts`。源数据不进入 shared。步骤 3/4/5 不得改共同装配、字典、骨架；主会话在并行波验收时统一同步骨架，避免多 agent 同写文档。

完成标志：步骤 1 的正例与失败边界有证据，以上类型/IPC/文档口径已落笔，`npm run typecheck`、`npm run lint` 通过；未接入模块不在正常界面宣告可用。

## 5. 分步实施

### 步骤 1：复现地址栏问题并验证文件导入技术路径

1. 使用隔离 `MSB_USER_DATA` 的 `npm run dev`，复现未提交草稿/已提交待导航/建议展开期间新建会话，以及配置主页场景，记录实际残留来源与异步时序；同时核对旧历史晚到是否已被现有 token 守卫挡住。
2. 用专用 Chrome 测试 profile 写入已知 Cookie（含 HttpOnly、host-only、不同 path、过期和实际可落盘的会话 Cookie）。验证源数据库位置/版本、Mac 系统钥匙串访问允许与拒绝、受支持密文解密及域名校验；只记录计数、格式和结果，不记录真实密钥或 Cookie 值。验证非 Mac/未知格式按不支持反馈。
3. 在专用源库写入含对象仓库、索引、Blob/Date/ArrayBuffer 的 IndexedDB。源 Chrome 完全退出后复制，验证目标分区在 webContents 关闭后是否仍有数据库/后台存储句柄；证明受支持快照可进入隔离目标、再次读写和重启均正确。另做已有库回滚、不同版本/布局拒绝样本，不复制整个 QuotaManager。
4. 将格式/版本/静默机制/冲突单位与正反例写入本计划关联验收目录的技术验证记录，并在调研报告补证据。探针仅用临时文件，不引入测试框架、不遗留产品调试分支。若无法得到可靠的 Mac 解密或 IndexedDB 正例，先定位该前提，不进入依赖它的实现；地址栏可继续独立复现，不能把导入目标改成全部不支持后勾选完成。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 隔离场景有可复核的残留复现/排除证据；技术记录至少包含一个 Mac 受支持解密正例、拒绝授权反例、一个 IndexedDB 文件迁移并重启读写正例及还原正例。真实账号授权弹窗尚未由用户处理的，明确记为待操作，不能伪造通过。

### 步骤 2：冻结共享契约、原生界面规则与模块边界

1. 按第 3 节落 shared、preload 两文件及主进程内部 `types.ts`；新增 cancel 通道接口与原因码、统计单位，约定引擎 apply/rollback 责任。保留默认 `session`，迁移全部内部调用的策略字段，保证类型检查通过；新能力在引擎接入前不可选/不可执行，不用成功占位。
2. 将步骤 1 的平台/格式支持矩阵写进 PRD 3.9 与验收；同步主页和输入清空口径、IndexedDB 完整替换例外、DESIGN 两个相关条目。执行 UI 调整前使用 impeccable scoped polish/clarify，保留原生承载与灰阶语系；具体颜色/边框/圆角以其产出对账。
3. 明确步骤 3/4/5 各自文件清单和不许触碰的公共文件；新增文件职责与共享桥职责变化在本步同步 `book/docs/architecture/项目骨架.md`，保留计划尚未完成的表述。主会话维护共同文档、避免 agent 同写。

验收：`npm run typecheck`、`npm run lint` 通过；四 scope/四导入通道、统一 policy、按单位统计与 show 返回类型在 shared/preload/main/renderer 生产者消费者对齐；PRD/DESIGN 与步骤 1 证据一致，新增骨架条目对应已创建文件，未实现功能不显示可用。

### 步骤 3：实现地址栏融合与输入状态隔离

1. 按 impeccable 定稿仅调整 Toolbar 地址栏及建议样式：展开后输入框下角/面板上角归零，间距归零、底色/侧边框连续、接缝无重复线；关闭还原。同步共享 border/gap、子窗高度和定位，保留 30px 行高、检索规则、原生子窗不夺焦与页面可见。
2. 将 draft、pending、invalid 定时器、建议选中/抑制态绑定当前会话/Tab，scope 改变即使输入仍聚焦也不显示旧值。处理旧 navigate Promise 晚到、异步 show 回执、子窗鼠标回推、快速切换与卸载；无匹配、失焦、Esc、关闭 Tab、零会话和 HTML 全屏收口一致。
3. 保持默认空白与已配置主页的既有导航语义。除非步骤 1 证明 store 历史守卫存在漏洞，否则不改其镜像机制。屏幕边缘下方空间不足时，保持锚定并缩短高度；无可呈现区域时拒绝显示并恢复输入框形态，不独立移位造成融合错开。
4. 主会话在本波合并验收时同步本步骤文件职责变化与 DESIGN 最终度量到骨架/设计文档；执行者只提交变更清单，不与其他实现者同改骨架。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 主窗/独立窗、亮暗、不同缩放与靠屏幕边缘截图证明接缝连续，收起还原；输入旧草稿后建会话、导航在途切换、A/B/A 快切均不串文本或建议；主页设置保持，旧会话页面/历史仍在；输入法 Enter、方向键、鼠标点选、Esc/失焦全过，页面无白屏。

### 步骤 4：实现 Cookie 源读取、Mac 解密与目标写入还原

1. 在 `cookieSource.ts` / `cookieCrypto.ts` 实现只读 SQLite 映射、有效明文与已验证密文分支、系统授权拒绝/超时、版本/前缀/域名校验、时间和受支持属性映射。Keychain helper 异步运行，参数固定、不经 shell 拼接；值与密钥只留主进程内存，异常信息脱敏。
2. 在 `cookies.ts` 按内部接口实现目标比较、policy 写入与精确回滚；同名不同 path/host-only 不串改，目标缺失直接新增，冲突整条采用所选来源。跳过过期，未知格式/CHIPS/不能读取的记录独立统计；不能把密文写入当成功或给会话 Cookie 伪造持久期限。
3. 保存本次要修改记录的原状态；API 或 flush 失败时撤销已新增记录、恢复原记录并验证同名旁路记录不变。只回滚该类型该次变更，不通过清空全部 Cookie 达成。归还的结果必须描述还原是否成功。
4. 不改共享契约/装配/字典/骨架；向主会话提交新增职责和样本结果，主会话在本波完成前同步骨架。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 隔离目标下，已知值 Cookie 导入后服务器能收到预期凭据；HttpOnly/Secure/SameSite/host-only/path/过期映射与两种冲突选择正确；中途注入失败后目标与执行前一致，其他会话为空/原样；授权拒绝、未知密文、非 Mac 加密记录均有真实失败/不支持计数且日志无凭据值。

### 步骤 5：实现 IndexedDB 完整快照、冲突与失败还原

1. 在 `indexedDb.ts` 实现步骤 1 确认的源布局、版本与站点/bucket 枚举、关联文件清单及兼容性判据；只读取所选 profile 受控目录。拒绝未知格式、路径逃逸/链接、缺失 Blob、未静默写入源，不能只检查目录存在就判可用。
2. 目标对不存在单位新增；存在且无法可靠判同则形成站点快照冲突，按 policy 保留或整体替换。`session` 保留该快照完整目标数据，`chrome` 只替换确认的快照单位，保留其他站点和其他存储类型；统计单位固定为 sites。
3. 写入前可靠收尾目标后台句柄并备份完整受影响快照/必要元数据，使用受控暂存与替换过程；复制/校验/重开失败还原，本类型内不留已成功站点的半次提交。需要配额或 bucket 元数据时仅操作经探针证明的映射，禁止整库覆盖目标元数据；不可靠时拒绝导入该布局。
4. 不改公共装配/字典/骨架；主会话验收时统一同步文件职责与最终支持矩阵。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 下快照中的对象仓库/主键/索引/Blob/Date/ArrayBuffer 重开及重启后正确，导入后可继续写入；两种冲突选择有目标专有数据对照；其他站点、其他类型、其他会话不变；缺文件/版本不兼容/模拟复制失败能拒绝或还原，不能静默建空库后报成功。

### 步骤 6：集成源快照、四类原生导入与生命周期

1. `sourceSnapshot.ts` 与 `chromeImport/index.ts` 落固定源副本、planId 资源拥有者、cancel/TTL/退出清理和主进程白名单守卫。新类型选择后校验源与目标的可靠静默；不把 LOCK 文件存在本身视为“进程运行”的充分证据，不主动关用户 Chrome。保证执行只消费已确认源，目标冲突变化则重做准备。
2. 将三个引擎与既有历史源接入，localStorage 支持读取固定副本并保留记录级合并；目标 Session/路径只经 registry 注入，不用直接复制 Cookie 库。跨类型分项执行与还原结果汇总，恢复会话、代理/DevTools 绑定及历史重拉链不回归。cancel 只清尚未执行的计划，不在写盘中途制造假取消。
3. 更新 SessionPanel、shared/dialog、main picker 与 WorkspacePickerWindow：四类型选择、按类型单位的权威摘要、一次 policy 选择、IndexedDB 替换影响、加载锁定与取消。让已有 sheet 60 秒兜底和准备授权等待协作，不出现窗口超时关闭后后台仍写数据；弹层期间网页保持可见。
4. 三语同步字典和原生结果框：完整成功/部分成功/不支持/失败/还原失败分别显示真实计数，不把 cookies/indexedDB 错误误标成 localStorage。结束后关闭匹配请求的加载 sheet、清理临时资源，历史成功仍及时重拉。主会话同步本步骤骨架、DESIGN/PRD 的最终度量/通道/行为。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 真实原生入口完成历史单选/LS 单选/新增类型单选/四选、无冲突/两种裁决、取消/TTL/源文件变化/目标变化、会话删除/克隆/切换/关父窗与授权拒绝等矩阵；确认前目标零写入，确认后只写目标，未勾选类型未读取；所有反馈原生、计数单位正确，取消及过期无临时数据残留。

### 步骤 7：全量验收、结构化审查与文档收尾

1. 主会话亲自运行 `npm run typecheck`、`npm run lint`、`npm run build`，以及 `npm run dev` 隔离手动回归：地址栏完整矩阵、四类型导入、重启、历史隔离、工作区/克隆/删除、独立窗口/拖拽、F12、设置主页/语言/外观及录制中工具栏行为。Windows 可执行场景实际抽验，无法运行的跨平台项如实列出，不以 Mac 结果代替。
2. 真实登录验收使用用户明确选择的 Chrome profile 与 QQ 邮箱等样本；用户处理系统授权和必要的登录操作，只核对状态/请求，不保存账号凭据或邮件。分别记录 Cookie 读/解密/写入/发送、IndexedDB 数据读写和站点认证结果。未完成真实样本则保持对应验收项未完成，不能把“计数非零”当免登录通过。
3. 使用项目 `code-review` 技能按八项清单独立审查，清单写 `book/notes/issue/`；审查者只记录。主会话处理阻断问题并复验受影响场景，未解决项明确保留。同步唯一 PRD、PRODUCT、DESIGN、`book/docs/architecture/项目骨架.md`、steps 状态、报告新增证据及 `book/notes/summary/2026-11/legacy-process.md`，只对账本阶段相关事实。
4. 在 `book/notes/summary/20261028112040-地址栏交互与Chrome站点数据导入开发计划/` 落技术验证记录、最终阶段验收与完整手动步骤（入口→操作→预期→实测/待测），证据不含 Cookie/密钥。逐项勾 Todo 和退出清单；若还有必须完成的正例/手动项，不把阶段标为完成。

验收：三条检查命令全绿；八项审查及阻断问题有闭环证据；每项退出清单可查，骨架与 `src/` 实际结构一致、共享契约/原生界面/i18n 对齐，验收文档存在，计划 Todo 与 process 同进度；真实站点验证结果明确区分通过、失败与待操作。

## 6. 可并行步骤分析

### 6.1 依赖关系

| 步骤 | 前置依赖 | 可与谁并行     | 说明                                                     |
| ---- | -------- | -------------- | -------------------------------------------------------- |
| 1    | 无       | 无（串行）     | 决定解密、文件格式与静默机制是否有正例，结果决定后续接口 |
| 2    | 1        | 无（串行）     | 共享类型、桥、模块接口与文档口径先冻结                   |
| 3    | 2        | 4、5           | 地址栏/建议几何文件与两个导入引擎文件不相交              |
| 4    | 2        | 3、5           | 限 Cookie 专属三个模块，依赖冻结内部接口                 |
| 5    | 2        | 3、4           | 限 IndexedDB 模块，依赖步骤 1 的兼容矩阵                 |
| 6    | 3、4、5  | 无（串行）     | 装配/原生 picker/字典/registry 有共同写入面              |
| 7    | 6        | 无（串行收尾） | 全量回归、审查结论处置与最终文档需交叉验证               |

### 6.2 并行波次

- **波次 A**：步骤 1，主会话串行验证。前提不通过不推进依赖部分。
- **波次 B**：步骤 2，主会话独占契约与文档冻结。
- **波次 C**：步骤 3 / 4 / 5 同批并行；最多 3 个实现 agent，与主会话合计不超过当前 4 个并发槽。主会话负责公共文档同步与每个结果的检查。
- **波次 D**：步骤 6，主会话独占集成，其他实现者退出写入后开始。
- **波次 E**：步骤 7，主会话执行检查和手动验证，完成后发起一次只读审查，处理结论后收尾。

### 6.3 并行门槛

仅波次 C 达门槛：三个文件集合分离，均包含多状态实现与行为验证，预计各超过约 5 分钟。骨架、字典、shared、preload、主装配和 process 由主会话独占，不纳入并行 agent 写入清单；若步骤 2 无法冻结互斥写集，则主会话将相交部分移入步骤 6，或顺序完成该步骤，不为并行强拆接口。其余波次存在数据/契约/验收依赖，保持串行。

### 6.4 不可并行的红线

- 不允许两个 agent 同改 Toolbar/app.css、共享类型、preload、registry、导入 index、picker、字典或共同文档。
- Cookie/IndexedDB 未通过技术正例，不可按假定格式并行实现；未冻结接口不得开工。
- 多个 dev 实例不得共用 `MSB_USER_DATA`、Chrome 源测试 profile 或目标分区目录；严禁一个进程写、另一个复制同一库。使用各自临时目录且只有主会话维护最终验收基线。
- 系统钥匙串/真实 Chrome/QQ 邮箱验证与集成验收由主会话统一调度，不由多个 agent 同时操作。需要交叉核对的回滚结果与真实登录状态不可自报即通过。

## 7. 建议询问 Agent 的方式与次数

### 7.1 分组建议

| 用途      | Agent 类型                | 建议时机                             | 并行数量     | 次数                          |
| --------- | ------------------------- | ------------------------------------ | ------------ | ----------------------------- |
| 调研      | Explore 类只读探索        | 步骤 1 某一技术前提需要独立核对时    | 最多 1       | 0—1 次                        |
| 实现      | general-purpose           | 步骤 2 验收后，步骤 3/4/5 各一名     | 最多 3       | 3 次                          |
| 审查      | general-purpose，只读审查 | 步骤 6 接通、主会话完成步骤 7 检查后 | 1            | 1 次；修复后定向复审最多 1 次 |
| 测试/收尾 | 主会话直接执行            | 每波检查点与步骤 7                   | 不占并行预算 | 0 次                          |

常规 4 次，含可选探索与定向复审**总上限 6 次**（≤12）。每次重建上下文都有成本，不为小问题反复开 agent；小修和集成由主会话完成。若槽位不足，分两批等待，不超并发数，不将协作任务创建为用户侧新聊天。

### 7.2 每次询问的约定

- prompt 必须自包含：本计划完整路径、步骤编号、完整任务与验收、依赖已通过证据、允许文件清单、公共文件禁止清单。执行时按 `subagent-execute-plan/assets/subagent-prompt-template.md` 组装；工具没有 Explore 标签时，以只读职责表达，不假造工具类型。
- 明确源数据和目标目录隔离；Cookie 值/系统密钥不进回复。实现者提交新增文件职责和未测项，不自行改共同文档，不自行宣告全阶段完成。
- 实现类 agent 返回后，主会话亲自执行 `npm run typecheck`、`npm run lint`，核对接口与行为；自述测试只作为线索。
- 步骤 3/4/5 的派发注明“待步骤 1、2 验收后再发起”；步骤 6 不提前开始。审查只写清单不修实现，修复后的定向复审等待对应复验通过。

## 10. 主要风险与控制

| 风险                                       | 控制方式                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Mac 钥匙串访问被拒或打包后身份变化         | 步骤 1 验证允许/拒绝；步骤 4 主进程异步授权，步骤 7 记录 dev/打包验证边界，不输出密钥            |
| 把 Windows“无法通用离线解密”误讲成未加密   | PRD/能力提示明确双平台都可能加密，本期不支持的记录如实分类                                       |
| 源 Chrome 活库复制或目标后台句柄仍活跃     | 步骤 1 给可靠静默证据，步骤 6 控制快照；不把关页面或有 LOCK 文件等同已具备正确结论               |
| IndexedDB 内部格式、Blob、配额元数据不兼容 | 已验证矩阵 + 关联文件清单 + 重启读写正例；未知格式拒绝，禁止原始记录拼接和整库 QuotaManager 覆盖 |
| 用户选择后源/目标变化，冲突范围扩大        | 固定源暂存；静默窗口内复核目标，变化重做探测，不偷偷套旧摘要                                     |
| 类型部分成功但回滚/计数失真                | 分类型结果与还原状态，Cookie/IDB 本次变更可还原；失败注入核验真实盘面                            |
| 快照替换丢掉目标单位内独有数据             | 原生裁决摘要明确整份替换单位和影响；默认保持 session，其他站点/类型不动                          |
| 地址栏状态复用或迟到 IPC 污染新会话        | scope 所有权与异步代号共同判定，快切/待导航/鼠标回推/定时器矩阵验证                              |
| 屏幕 clamp 导致面板脱离输入框              | 共享度量、锚定向下收窄与可呈现回执；无空间不独立移位，DPI/贴边实测                               |
| 误把数据写入成功等同 QQ 邮箱认证通过       | 分开记录解密、写入、发送与站点认证，用户操作真实账号，不读取邮件或记录凭据                       |
| 并行实现改同一字典、骨架或装配             | 波次 C 文件白名单，公共文件主会话独占，合波后亲自检查                                            |
