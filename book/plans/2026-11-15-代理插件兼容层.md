# 代理插件兼容层

分级：L。涉及 per-Session 代理边界、特权 IPC、配置所有权与持久化。分支 `plan/extension-lifecycle-and-proxy`，先完成[扩展删除回收](2026-11-15-扩展运行时删除回收.md)。用户已授权实施，并明确内置手动配置优先，清除后交给插件。

## Step 0

背景：用户要求实际验证是否需要。固定 SwitchyOmega 2.5.20 三轮真实加载，proxy.settings.set 回调无错却仍 DIRECT，真实请求走源站；同会话内置代理正向对照确实走代理，B 仍 DIRECT。证据、固定哈希和官方参考见[实测报告](../notes/learn/2026-11/2026-11-15-扩展回收与代理兼容实测.md)。

目标体验：用户在固定代理插件选择配置，当前会话新请求真实按其规则代理；切换、恢复、卸载和失败时控制权可解释。不能只有页面打开/对象存在/回调无错。普通网页和其他分区无法更改该会话代理。

范围：shims/preload-guard 与 session SW/frame 可信身份、browser/proxy 控制事实、必要的内部类型/持久化记录和 UI 状态反馈、固定插件实际主要流程。若需修改持久化形态先设计迁移；界面改动先走 impeccable。不写第二套直接 setProxy 的旁路引擎。

排除：Chrome 全量扩展 API 兼容、会话跨分区代理同步、任意跨会话控制、绕过网页人机验证、将用户登录/凭据纳入诊断、换掉现有依赖/浏览器引擎与发布新版本。PAC/自动切换不能因现有内置代理只支持 HTTP/SOCKS5 就悄悄删出插件验收范围。

## Phase 1：分析

Electron 提供 Session.setProxy，但不承诺完整 Chrome 扩展 API；当前 chrome.proxy/settings 对象已存在，原生 types.ChromeSetting.set/clear 报未支持。须在 chrome 对象冻结前补真实桥，不能仅做 if (!chrome.proxy) 分支。现有 browser/proxy 引擎掌握生效配置、凭据、连接关闭与探测恢复，应扩展单源仲裁，避免会话重激活用旧内置配置覆盖插件。

固定 SwitchyOmega options.html 第三轮已显示设置项（前两轮采样偏早，不作 UI 故障结论）；本轮尚未证明其完整 UI/后台主要操作可用，需在原版主要操作路径调查实际依赖。若牵涉 contextMenus/其他 API，应单独记录并经设计收敛范围，不私改插件原版或换简单样本结项。

## Phase 2：设计与待定决策

拟定架构：原生扩展身份 + 已加载且具 proxy 权限 → 有界 ChromeSetting 操作 → 按 Session 串行代理控制器 → Electron.setProxy/连接清理 → 权威状态/get/onChange。持久化和操作失败不报假成功；frame 与 SW 共用处理器，网页伪报 ID 被拒绝。get 返回实际配置与真实 levelOfControl，clear/卸载按已定优先权恢复下一来源。

编码前必须定稿：

1. 内置手动代理与代理插件谁优先；多个插件如何争用。建议显式手动配置优先；这是建议，尚待产品决策，不写成既定事实。须设计与 Chrome levelOfControl 语义一致的反馈，不能把应用手动设置伪报成其他扩展或系统策略。
2. regular/incognito scope、set/get/clear/onChange/onProxyError、callback/Promise 的支持边界和错误约定；不支持值明确失败，不映射成假直连。
3. fixed_servers、direct、system、PAC URL/内联 PAC、auto_detect 的映射。SwitchyOmega 自动切换依赖 PAC，先做隔离可行性验证；下载源、大小、超时、重定向和脚本交给 Chromium 网络执行的边界需定。不可在主进程 eval 不可信 PAC。
4. 重启、卸载、删除、升级/回滚、克隆、更新准备屏障与代理“检测”的恢复语义；不将一次临时探测永久覆盖插件配置。
5. 插件声明的权限、来源与配置敏感字段的保留/日志规则；授权不能用 renderer payload 自报 ID。

计划在上述产品冲突或外部 API 不确定时停留设计门禁。当前只需准备计划，无需在本轮选定优先权。

## Phase 4 验收门禁

- 不以 API 对象或回调为准：HTTP/HTTPS 与支持的 SOCKS/PAC 规则必须由本地源站/代理记录证明路由；错误端口、认证失败、断网与超时如实失败。
- A 设置只改 A，B 与其他窗口会话不变；页面/子 frame/未授权扩展/伪报 ID 拒绝，卸载后旧调用拒绝。
- set/get/clear/onChange 的控制权、顺序和结果一致；多个同时设置、手动配置/插件冲突按已确认规则判定，失败不通知假成功。
- 会话重激活、应用重启、克隆、更新准备、临时代理检测后恢复和卸载不悄悄覆盖有效值；永久删除不重建目录。
- SwitchyOmega 原版固定版本与普通 Chrome 对照主要操作，不修改 manifest/不换样本规避；PAC 和未支持 API 明确列结果。
- Mac 实测并预留 Windows 实机矩阵；各平台缺设备则保持待测，不能以 Node mock 或编译代替。

## Phase 2 定稿（2026-11-15）

用户确认内置非空手动配置优先；清除后选取仍已加载且声明 proxy 权限的插件记录，按可信安装清单 generation 仲裁（最近安装/显式升级优先），同序以扩展ID稳定决胜。手动覆盖时 get 返回 not_controllable，不伪装为系统策略。插件仍可保存待生效配置，get/onChange 如实返回当前有效值；clear/卸载移除自己的控制记录并恢复下一来源。

支持 regular；incognito scope 明确拒绝。支持 ChromeSetting set/get/clear/onChange、callback/Promise，错误 callback 的 runtime.lastError 仅在回调栈内可见。onProxyError 对收到的代理网络错误进行受限通知，不把请求失败解释为设置调用失败。fixed_servers 的 HTTP/HTTPS/SOCKS4/5、direct/system/auto_detect、PAC HTTP(S) URL及内联 data 以严格结构/大小/URL/端口白名单映射；不在 Node eval PAC。两种 PAC 已通过真实 Session.setProxy 和请求实测。

扩展设置独立存 userData/extensions/proxy-settings.json v1，保留已有 sessions.json 形态。文件严格验证、原子写、按全局事务锁提交，native 应用失败不提交；落盘失败回退旧有效配置。browser/proxy 持有唯一有效配置合成与原生应用点；启动/激活、卸载、临时检测恢复与删除通过该单源。删除回收先屏蔽插件请求，dropSession 清设置。普通关闭/重启保留记录。隐私：代理/PAC 内容不进 console，记录只写私有 userData；来源为原生 Session/frame/SW、已加载扩展与 proxy 权限，不采用 payload ID。

文件范围：browser/proxy.ts 与新纯配置/存储模块、extensions/shims/preload-guard/management、main装配、测试与书籍。暂不增加设置 UI；既有插件通过 get/levelOfControl/onChange 读取状态。仅实现接入必需的协议，不扩 Chrome 全量 API。

Phase 2 通过，进入 Phase 3；固定原版主要流程和修复后回归尚未通过。


强制 PAC 补充：固定 SwitchyOmega 会发送 mandatory:true，Electron 公共 ProxyConfig 无此字段，不能静默丢弃。对 mandatory PAC，URL先按大小/超时/重定向约束读取并物化为内联脚本，原函数在 Chromium 内执行并为合法结果附带本次应用随机尾标；宿主 webRequest 只在 resolveProxy 含当前尾标时放行，解析失败、超时或配置代号变化一律取消。不会在 Node 执行 PAC。默认无代理与非 mandatory PAC 不加该守卫；显式 DIRECT 是带尾标的合法结果。尾标为不可解析的 .invalid 代理，不成为外部数据出口。需实测坏脚本/超时绝不触达源站，再将此路径记通过。原版自动切换/失败行为仍是Phase4门禁。


Phase 4 诊断发现原版 MV2 background.html 的 Electron 原生 contextIsolation=false；现有宿主桥无条件调用 contextBridge，导致 preload 在后台页抛错，browserAction 等兼容 API 未安装，原版后台未完成初始化。此为代理插件必要接入路径，不改变被测网页/普通窗口的隔离选项。生成器针对原生已受限扩展来源的非隔离上下文使用直接主世界桥与库 electronContext，安装后仍删除临时 electron 能力；隔离 frame/SW 继续 contextBridge。精确锚点和双路径需独立回归，禁止向网站扩大注入范围。


临时关闭回归发现：直接杀 MV2 background webContents 后仍保留加载登记，会让其后续 IPC 绑定失效。close/clone/import 增加可恢复的 suspend：先检查录制、暂停特权桥和新挂载、排空并卸载原生实例，保留引擎与全局包/设置；同分区激活显式 resume 重载，再同步有效代理才导航。管理层不能替用户激活暂停分区。代理事务用同一队列排空，复制不与旧设置写入交错。此路径不设置永久 retired；失败不继续复制，尝试恢复后报告原错。需真实关闭再打开原版后台验证。

## 结项（2026-11-16）

根因是代理切换屏障取消了 chrome-extension 资源，限制屏障到 HTTP(S)/WS(S) 后关闭重开通过；并非用延长等待解决。启动缺失的持久控制扩展阻断网络；全局卸载同时覆盖暂停/未激活分区记录。更新准备屏障在异步身份清单读取后复验。
