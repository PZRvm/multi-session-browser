# Tab 栏分隔线与栏内拖动排序 开发计划

> 创建时间：2026-09-18 14:09:03（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/feature-tab栏分隔线与栏内拖动排序.md`（交互规格与复用面已冻结；PRD 3.2.2 两条验收条目已同步落库）  
> 执行模式：直通  
> 实施范围：Tab 栏非活动 Tab 间竖直分隔线（纯 CSS + chrome token）+ 同窗口作用域内 Tab 拖拽重排（TabItem 指针手势状态机扩展第四态 + reorder-tabs 全序提交命令链 + manager 重排原语）；不做跨窗重排、不做 HTML5 DnD、不做延迟换位  
> 目标结果：Tab 栏内水平拖动 Tab 实时换位、释放生效且事实源即主进程；重排中拖离 Tab 栏矩形自动升级为既有拖出手势（升级前先提交已发生位移）；非活动相邻 Tab 间呈现分隔线、选中 Tab 两侧无线，亮暗双主题  
> 当前进度：步骤 1—4 均未开始

## 1. 当前基线

- **手势现状**：`TabStrip.tsx` 的 TabItem 已持指针捕获手势状态机（`idle → armed → dragging`，5px 触发阈值，`DRAG_ENGAGE_RADIUS_PX`；指针捕获保证窗外 move/up 送达——当初弃用 HTML5 DnD 的两段视觉问题见组件头注）。`dragging` 态经 `store.dragStart` 上报主进程开 16ms 光标轮询（tear-off 链）；释放经 `store.dragEnd` 取回四态裁决。Esc 放回、rejected 回弹、吞随尾 click 的防御均已内聚 TabItem。
- **重排可复用面（steps 文档已冻结）**：① 插入位中点判定算法——TabStrip 悬停指示器 effect 既有（按 dragCursorX 对各 Tab 中点算 index）；② Map 按位重排——`manager.ts` `moveTabToWindow` 内部段（delete + set 调整迭代序 + insertIndex 钳制，阶段 10）；③ 全序提交口径——会话列表先例 `useSessionDragReorder.ts`（drop 生成完整新序一次提交、无位移短路零 IPC、失败回调反馈）+ `sessions.ts` reorder handler（当前全部 id 无重复全序、整单校验整单拒绝，L450-465 一带）。
- **命令链现状**：浏览器域 25 条通道（19 命令 + 6 推送，注册日志 `ipc.ts` 头注与 console 两处同步维护）；命令一律 `requireScope`（主窗零会话拒绝）+ 结构守卫 + 返回该窗作用域快照（switchTab 等 12 条先例）；preload `index.ts` / `index.d.ts` 三处对齐惯例。
- **tabs 序事实源**：主进程 `manager.ts` 的 `tabs` Map 迭代序即快照顺序（`buildSnapshot` 直接按迭代输出）；renderer `stores/browser.ts` 是快照纯镜像（`applySnapshot` 守卫按 windowId/sessionId 分流），本地瞬态先例有 `draggingTabId`（乐观置位 + 快照自愈清理）。Tab 列表不持久化（重启回单 Tab，PRD 3.6.4 口径）。
- **视觉 token 现状**：chrome 区 token（`--chrome-tabbar` / `--chrome-tab-active` / `--chrome-tab-insert` 等）是 app.css 全局常量族（亮色定义 + 暗色 `[data-theme]` 覆盖，约 L57-132），**不经 themeSystems 注入**（`themeSystems.ts` L274 注释明确 chrome-* 全族不随主题系统）；DESIGN.md 载有 chrome token 清单（L30-51 一带）。既有 `.chrome-tab` / `.chrome-tab.active` / `.dragging` / `.drag-rejected` 类系在 app.css L1749 起。
- **Tab 栏矩形已知**：主进程 `dragging.ts` 已持各窗 TabStrip 视口矩形缓存（report-tabstrip-rect 通道，2026-09-25 修订）——renderer 侧同源的栏矩形可由 TabStrip 根容器 `getBoundingClientRect` 现取，无需新通道。
- **文档现状**：PRD 3.2.2 两条验收已落（2026-09-18 修订标注）；steps 功能文档已冻结交互口径与"本期不做"；`book/docs/architecture/项目骨架.md` 载有 `useSessionDragReorder.ts` 等手势 hook 职责行（新增 hook 文件须同步，见 L168 惯例）。
- **版本**：Electron ^39.2.6、React ^19.2.1、zustand ^5.0.15；验证 = typecheck / lint / build + `npm run dev`（`MSB_USER_DATA` 隔离）。

## 2. 范围边界

### 2.1 本阶段必须完成

- 契约：`shared/browser.ts` 增 `reorderTabs: 'browser:reorder-tabs'` 命令通道（浏览器域 25→26，总 32→33 两处计数同步）+ `ReorderTabsPayload { ids: string[] }`；preload `api.browser.reorderTabs(payload): Promise<BrowserSnapshot>`，`index.d.ts` 同步。
- 主进程：manager 提取 Map 按位重排共用私有函数（`moveTabToWindow` 与新原语共用）+ `TabManager` 基面增 `reorderTabs(ids, windowId): BrowserSnapshot`（全序校验：集合与该窗作用域 tabs id 完全一致且无重复，不匹配整单 no-op 返回原快照；`emitChange` 推送）；ipc 增 reorder-tabs handler（requireScope + ids 结构守卫 + 全序校验，整单拒绝抛错回传）。
- renderer：`stores/browser.ts` 增 `reorderTabs(ids)` 动作（IPC 返回快照经 `applySnapshot`，失败保持原状）；新增 `browser/useTabReorder.ts` hook（本地拖拽序瞬态 + 中点换位判定 + 提交/短路/失败回滚 + 升级 tear-off 前的位移提交，入参全量 tabs——与 `useSessionDragReorder` 对称）；TabItem 手势状态机扩展第四态 `reordering`（水平位移主导且光标在栏矩形内进入；拖离栏矩形先提交当前序再走既有 `engageDrag` 上报链；释放即提交新序）。
- 视觉：app.css 增 `--chrome-tab-separator` token（亮暗两处，Chrome 灰系发丝线）+ 分隔线规则（`.chrome-tab:not(.active) + .chrome-tab:not(.active)` 相邻选择器，左边框形态）+ 重排拖动中的让位视觉；**动手前走 impeccable 技能 scoped 命令定稿**（AGENTS.md 界面设计规则），定稿结论补 DESIGN.md chrome token 清单一行。
- 文档：`book/docs/architecture/项目骨架.md` 增 `browser/useTabReorder.ts` 职责行 + TabStrip 职责描述补重排；`book/notes/summary/2026-11/legacy-process.md` 状态行同步。

### 2.2 本阶段明确不做

- 跨窗口拖拽重排（跨窗走既有 tear-off / moveTabToWindow 插入位语义，重排仅限本窗口作用域——steps 文档已冻结）。
- HTML5 DnD 引擎（Tab 区有"窗外释放两段视觉"的弃用决策，重排必须共用指针捕获手势体系）。
- 重排持久化（Tab 列表不持久化口径不变）、延迟换位策略、重排动效曲线定制（跟手换位视觉以 impeccable 定稿为准，实测手感不佳再调）。
- F11/菜单等与本功能无关的入口；分隔线随 hover 变色、阴影渐变（DESIGN 视觉语系禁止）。

### 2.3 本阶段数据原则

- tabs 顺序唯一事实源 = 主进程 `tabs` Map 迭代序：renderer 重排全程为本地瞬态（拖拽中乐观预览序、拖动 id 半透明），提交即一次完整全序覆盖；主进程全序校验不匹配整单拒绝，renderer 失败回滚本地预览序（快照未变即自然回滚，失败回调作视觉反馈——对齐 `useSessionDragReorder` 先例）。
- 诚实性：无位移/拖回原位短路零 IPC；重排命令只做纯序变更（url/title/loading 等字段不动，快照现读）；重排不落盘、不新增持久化字段。
- 升级 tear-off 时先提交已发生位移（主进程序与新窗 tear-off 起点一致），后上报 dragStart——两段提交的中间态对外不可见（快照推送顺序自然保证）。

### 2.4 契约核对（编码前冻结）

1. **通道扩展（浏览器域 25 → 26：命令 20 + 推送 6）**：`BROWSER_CHANNELS` 增 `reorderTabs: 'browser:reorder-tabs'`；`ReorderTabsPayload { ids: string[] }`（该窗作用域全部 Tab id 的无重复全序）；`shared/browser.ts` 头注释增一行指向本计划。需同步：`src/shared/browser.ts`。
2. **命令语义**：ipc 层 `requireScope` + ids 数组结构守卫（每项 string、非空、有上限——取 `TAB_COUNT_MAX` 类常量或沿用快照 tabs 量级防御性封顶）；主进程全序校验（集合与该窗快照 tabs id 完全一致、无重复），不匹配整单拒绝抛中文错误（`errors.reorderDuplicateIds` 类先例文案入 i18n 字典，zh/en 双语）；成功返回该窗作用域 `BrowserSnapshot`。需同步：`src/main/browser/ipc.ts`、`src/main/browser/manager.ts`、`src/shared/i18n/locales/{zh-CN,en-US}/`。
3. **preload 三处对齐**：`api.browser.reorderTabs(payload: ReorderTabsPayload): Promise<BrowserSnapshot>`；`index.d.ts` 同步。
4. **视觉 token 契约**：`--chrome-tab-separator` 为 chrome 常量族新成员（app.css 亮暗两处定义，不经 themeSystems）；具体色值与让位动效以 impeccable 定稿为准，定稿后补 DESIGN.md 清单。
5. **文档基线**：PRD 3.2.2 与 steps 文档已先行落库（2026-09-18），本计划不再重复修订；实现与之冲突时以 steps 文档为准回改实现。

完成标志：shared 通道与类型落库且 `npm run typecheck` 0 错误；`grep -rn "browser:reorder-tabs" src/` 仅命中 `src/shared/browser.ts`；preload 两文件签名一致；ipc 注册日志与头注计数为 33 / 26。

## 3. 分步实施

### 步骤 1：契约冻结 + 分隔线视觉定稿（shared / preload / impeccable / DESIGN）

任务：

1. `src/shared/browser.ts`：增 `reorderTabs` 通道与 `ReorderTabsPayload` 类型，头注释补修订行（指向本计划）。
2. `src/preload/index.ts` + `index.d.ts`：增 `reorderTabs` 方法（两处签名一致）。
3. 走 impeccable 技能 scoped 命令（polish 路径）定稿三件视觉：分隔线色值（亮暗，Chrome 灰系发丝线）、选中 Tab 两侧无线的呈现形态（相邻选择器边界情况：选中项居中/居首/居尾/连续多项）、重排拖动中的让位视觉（拖动 Tab 半透明跟手 + 其余 Tab 换位方式）。
4. 按定稿落 app.css：`--chrome-tab-separator` token（亮暗两处）+ 分隔线规则 + 让位视觉类系；DESIGN.md chrome token 清单补一行（注明 2026-09-18 增、出处本计划）。

验收：`npm run typecheck` 通过；`npm run dev` 中 Tab 栏呈现分隔线——选中 Tab 左右两侧无线（选中项居中/居首/居尾三态目视），亮暗两主题各验一遍（外观切换经板头三段）；拖动预览尚未实现（本步骤仅静态视觉）。

### 步骤 2：主进程重排原语与命令链（manager / ipc / i18n）

任务：

1. `src/main/browser/manager.ts`：从 `moveTabToWindow` 提取 Map 按位重排共用私有函数（入参：目标序描述；`moveTabToWindow` 改调用共用函数，行为零变化）；`TabManager` 基面增 `reorderTabs(ids: string[], windowId): BrowserSnapshot`——全序校验（scopedTabIds 集合与 ids 集合一致、无重复，不匹配返回原快照不动）、按新序重排 Map、`emitChange`、返回该窗快照。
2. `src/main/browser/ipc.ts`：增 reorder-tabs handler——`requireScope` + 结构守卫（数组、每项 string、量级封顶）+ 委托 manager（校验不匹配抛中文错误，对齐 sessions reorder 整单拒绝口径）；注册日志与头注计数 32→33 / 25→26 两处同步。
3. `src/shared/i18n/locales/zh-CN/errors.ts` 与 `en-US/errors.ts`：增整单拒绝文案键（zh/en 双语并行，不写组件内字面量）。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 启动日志见「33 条通道：浏览器域 26」；临时经 DevTools console 调 `window.api.browser.reorderTabs`（乱序全序）可观察到 Tab 顺序变化、短缺/含未知 id 的载荷被拒（错误提示为字典文案）——验证后复原顺序。

### 步骤 3：renderer 手势扩展与重排 hook（TabStrip / useTabReorder / store）

任务：

1. 新建 `src/renderer/src/components/browser/useTabReorder.ts`：本地拖拽序瞬态（预览序 + 拖动 id）、中点换位判定（复用悬停指示器同源算法）、`commit()`（无位移短路零 IPC；有位移发 `reorderTabs` 全序）、失败回滚与回调、`commitIfMoved()`（升级 tear-off 前的位移提交）；入参恒为全量 tabs（该窗作用域快照）。
2. `src/renderer/src/stores/browser.ts`：增 `reorderTabs(ids)` 动作（IPC 返回快照走 `applySnapshot`，失败 console 告警保持原状）。
3. `TabStrip.tsx` TabItem 手势状态机扩展第四态 `reordering`：过 5px 阈值后水平位移主导（|dx|>|dy|）且光标在 TabStrip 根容器矩形内 → 重排模式（本地预览序渲染 + 让位视觉类）；重排中光标离开栏矩形 → 先 `commitIfMoved()` 再走既有 `engageDrag`（tear-off 链，主进程轮询/虚影/裁决照旧）；栏内释放 → `commit()` + 吞随尾 click；Esc → 放回原位（清预览序零 IPC）。`dragging`（tear-off）与 `reordering` 两态互斥不回落。
4. 边界自查：0/1 Tab 不可达；关闭钮/新建钮不参与（既有 closest 守卫覆盖）；HTML 全屏期间无 Tab 栏自然无入口；快照推送（导航/加载态变化）到达时若正在重排——预览序以拖动 id 为锚合并（拖动中其他字段照快照更新，序保持本地预览，释放提交全序覆盖）。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 手动链路：①栏内水平拖动实时换位、释放后顺序保持且刷新（切 Tab 往返）不回跳；②拖回原位释放零副作用；③栏内拖几位移开后垂直拖离栏区 → 新独立窗口建立、源栏 Tab 序与拖动所见一致；④拖离栏区但落回源窗栏上 → 既有 stayed 放回语义不变；⑤重排后关闭中间 Tab，邻位补位规则不受重排影响。
