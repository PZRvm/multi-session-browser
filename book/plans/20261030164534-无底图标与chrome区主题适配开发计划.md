# 阶段开发计划：无底图标与 chrome 区主题适配

> 创建时间：2026-10-30 16:45:34（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/feature-关于页无底图标与chrome区主题适配.md`  
> 执行模式：直通  
> 实施范围：样式三件套——关于页与 Windows 板头换用去底透明 logo；chrome 表面族（Tab 栏 / 工具栏底色族）从全局常量改为随主题色三系；Windows WCO overlay 配色随系。不动窗体形态与 40px 顶区几何、不动 chrome 墨族 / veil 全局常量、不动 build/ 图标、零落盘变化。  
> 目标结果：设置-关于页显示无底板全彩品牌图形（跨平台一致）；琥珀 / 雾蓝 / 苔绿三系 × 昼夜下右侧 Tab 栏与工具栏底色随系同族换色（雾蓝锚定现值观感不变），Windows 右上角 WCO 按钮区底色同步随系；Windows 主窗板头左上角显示无底 icon；`npm run typecheck` / `npm run lint` / `npm run build` 全绿，`npm run build:win` 安装态复验通过。  
> 当前进度：步骤 1—4 均未开始

## 1. 当前基线

- 图标资产：`resources/` 现存去底图两枚——`logo-windows-transparent.png`（1024×1024 RGBA，提交 0a3d6c4「Windows 图标换去底透明版」引入的全彩品牌图形：琥珀前景窗 + 灰阶层叠窗口 + 深灰描线，约 88.8% 全透明像素；代码零引用，仅作 `build/icon-win.ico` 源稿，electron-builder.yml `!resources/logo-*.png` 将 logo-* 排除出包）与 `logo-multi-session-browser-v2.png`（非现品牌定稿）。关于页现用 `resources/icon.png`（512px 带米色圆角底板）：`PaneAbout.tsx:5` 导入、`:51` 渲染，`.settings-about-icon` 64px（app.css:1865 起，注释「圆角已在图标资产内烘焙」——换去底图后该表述失效）。
- chrome 表面族现状：`--chrome-tabbar/-toolbar/-line/-tab-separator/-surface/-tab-active/-omnibox-bg/-tabbar-drag-target` 为全局常量、不随主题三系（app.css 亮色块 56-87 行、暗色块 119-140 行，块头注明言「chrome-\* 全族：全局常量，不随主题系统——右区恒中性灰阶」）；冷灰值（#dee1e6/#f1f3f4 族）恰与雾蓝板面同色温——即用户所述「只给雾蓝做了适配」。`themeCssVariables` 不含 chrome 族（themeSystems.ts:262-265 未收录清单）；WCO overlay 消费 `chromeTabbarSurface(resolved)`（themeSystems.ts:307，仅随亮暗不随三系）。
- DESIGN.md 契约冲突（本阶段须修订）：151 行「右侧……完全交给 Chrome 的原生灰阶语法……板面语言不得越界」、176 行「对页使用 Chrome 自己的亮暗灰阶——两个色域始终不互通」、210 行 The Accent Stays On The Board Rule——三处共同规定右侧恒中性灰阶。
- 外观链：`onResolvedThemeChanged` 仅亮暗翻转触发、themeColor 变化不触发（appearance.ts:136-147 定义、285-288 通知点，138 行注释明言）——WCO overlay 随系必须扩此回调语义。`changed` 广播快照已含 themeColor（appearance.ts:48-54 snapshotEquals），主窗 / 设置窗 renderer effect 收到后 `applyThemeTokens` 全量重注入（theme.ts:24-31 逐条 setProperty），新增 token 映射自动生效、renderer 注入链零改动。
- Windows 主窗形态：WCO 专项（计划 20261030131247，已完成）后 win32 无系统标题条、右上角系统 overlay 三钮（index.ts:248-257，overlay height=40 与顶区对齐契约强耦）、Tab 栏右侧 `env(titlebar-area-width)` 避让（app.css:2124-2131）；左上角板头（`.board-head` 40px，SessionPanel.tsx:214-222）非 darwin 分支渲染纯文字标题「多会话测试浏览器」。建窗 query 形态单源：`winc=traffic` 仅 darwin 主窗携带（index.ts:307/315 两分支），renderer 侧 `windowTrafficControls` 消费（stores/browser.ts:251-257，不经 navigator 推断平台）；独立窗 / 设置窗 / 子窗不带 winc。
- 顶区对齐契约不动项：板头与 Tab 栏均 40px（app.css:259-268/2107-2112）、trafficLightPosition y=12、WCO overlay height=40——本阶段零几何改动。
- 无测试框架；验证手段 typecheck + lint + `npm run dev` 手动验证（AGENTS.md）；视觉改动须走 $impeccable scoped 流程（AGENTS.md 界面设计规则）。

## 2. 范围边界

### 2.1 本阶段必须完成

- 需求记录文档落盘与三件套实现：①关于页换去底 logo（跨平台同一资产）；②chrome 表面族 token 化随三系（含 WCO overlay 随系）；③Windows 主窗板头左上角去底 icon。
- DESIGN.md 双世界色域原则三处修订 + Colors 块 chrome 条目主题化注记（先文档后代码）。
- `themeSystems.ts` 表面 token 扩充（三系 × 昼夜显式落值 + 派生规则登记）；app.css 缺省值对账改写；WCO 单源对账注释升级。
- 主进程外观回调扩义（亮暗或 themeColor 任一变化即通知）与建窗 overlay 初值随系。
- $impeccable scoped 流程两段：动手前起步定值（步骤 1/2 内）+ 实现后复核收口（步骤 4）。
- 三系 × 昼夜对比度矩阵记录；dev 手验；`npm run build:win` 安装态复验；process.md / 验收文档落盘。

### 2.2 本阶段明确不做

- macOS 板头不加 icon（左上角已有原生三灯，用户仅要求 Windows）；Linux 零改动（系统框保留，winc 不注入）。
- 独立窗（tear-off）/ 设置窗 / 建议子窗 / 截图窗窗体形态零改动（独立窗 chrome 表面随系为 CSS token 自然生效，属配色非窗体形态）。
- chrome 墨族与 veil 族（`--chrome-ink/-ink-dim/-disabled/-error` 及各 veil、`--chrome-tab-insert`）维持全局常量——近中性墨在三系表面上对比度均成立（步骤 4 矩阵验证），不做全族主题化；若复核暴露真缺陷仅微调对应表面明度，不扩 token 面。
- `build/` 图标（icon-win.ico / icon.icns / icon.ico）与 dock / 任务栏图标不动（0a3d6c4 已定稿）。
- 不改 40px 顶区几何、Tab 避让机制、trafficLightPosition；不新增 IPC 通道与 preload 暴露面（winc 为建窗 query 既有形态，非新通道）。
- 不增删源码文件、不改文件职责边界——`book/docs/architecture/项目骨架.md` 同步不适用（纯内部实现 + 资产改名；themeSystems.ts 扩导出仍属其「主题 token 单源」既有职责）。

### 2.3 本阶段数据原则

- 零落盘变化：无新增偏好键、无迁移；存量 themeColor 偏好直接驱动新 chrome 表面值。
- 雾蓝系 chrome 表面值锚定现值（#dee1e6/#f1f3f4/#202124/#292a2d 族）——「已适配」的现状即定稿；琥珀 / 苔绿按同明度异色相同法推导，不引入新阶梯结构。
- 色值全部显式落值 `themeSystems.ts`（禁运行时算色字符串拼接），派生规则注释逐条可复算（themeSystems.ts 既有派生规则区先例）；`chromeSurface`/`chromeOmniboxBg` 亮态三系恒 #ffffff（对齐 confirmCardBg「亮恒白」先例），暗态随系。

### 2.4 契约核对

1. **DESIGN.md 双世界色域原则修订**（编码前冻结）：151/176/210 三处从「右侧恒中性灰阶 / 色域不互通」修订为「chrome 表面底色随主题三系整套切换（配置单源同 board 族，`src/shared/themeSystems.ts`），强调色信号仍不出板（Accent rule 保留）」；Colors 块 chrome 条目加 theme-systems 注（块值 = 琥珀系快照，三系值见单源）。完成标志：三处修订落盘且 Colors 琥珀快照与 themeSystems.ts 琥珀系值逐字一致。
2. **chrome 表面族单源升级**：从「themeSystems.ts 两函数 + app.css 字面量 + DESIGN Colors」三处对账（WCO 专项建立）升级为「`ThemeModeTokens` 显式值（随系）+ app.css 琥珀缺省（对账基准）+ DESIGN Colors 琥珀快照」；`chromeTabbarSurface` 签名扩为 `(id, resolved)`、头注对账表述同步；app.css chrome 块头注「全局常量不随主题系统」表述退役，改 board 族同款「缺省值 = 琥珀系，运行时注入覆盖」注记；`themeCssVariables` 未收录清单（themeSystems.ts:262-265）删去 chrome 表面族、保留墨族 / veil / error。完成标志：三处琥珀系值逐字一致 + `npm run typecheck` 通过。
3. **外观回调扩义**（主进程内部契约，非 IPC 面、preload 零涉）：`onResolvedThemeChanged` 扩为亮暗或 themeColor 任一变化即通知（携带二元组、按对去重，lastNotifiedResolvedTheme 扩为对字段）；registry 兜底消费解构只取 resolvedTheme（`browserViewFallbackBackground` 仍仅随亮暗——页面画布中性底不随系，注释登记裁定）；index.ts overlay 消费随系。完成标志：typecheck 通过 + dev 切系时 WCO overlay 即时换色。
4. **建窗 query 值域扩展**：`winc` 增值 `'wco'`（仅 win32 主窗，index.ts dev/loadFile 两分支同注；darwin 仍 'traffic'，二者互斥），renderer 侧 `windowTrafficControls` 旁增同源消费（stores/browser.ts 单源纪律）。完成标志：query 注入平台互斥成立、grep winc 无散落引用。

## 3. 分步实施

### 步骤 1：图标资产统一与两处落位（关于页 / Windows 板头）

任务：

1. 落盘需求记录 `book/docs/requirements/stages/feature-关于页无底图标与chrome区主题适配.md`（本计划需求来源，三条需求 + 截图判读）。
2. `git mv resources/logo-windows-transparent.png resources/logo-transparent.png`：跨平台共用的品牌去底源稿，Windows 专名退役；仍匹配 `logo-*` 打包排除模式（electron-builder.yml 注释核对，无需改配置）。
3. `PaneAbout.tsx:5` 导入改 `logo-transparent.png`；app.css `.settings-about-icon` 注释修订（「圆角已在图标资产内烘焙」表述随底板退役）；尺寸初稿维持 64px。
4. Windows 板头 icon：`index.ts` 建窗 query win32 分支增 `winc: 'wco'`（dev / loadFile 两处，紧邻 darwin traffic 注释同款登记）；`stores/browser.ts` 增 `windowBrandMark`（`winc === 'wco'`，头注对齐 windowTrafficControls 单源纪律）；`SessionPanel.tsx` board-title 分支标题文本前置 `<img>`（仅 windowBrandMark 渲染、alt 空 + aria-hidden、draggable={false}——favicon 拖拽源阻断先例 TabStrip.tsx:362）；app.css 增 `.board-title-icon`（16px、与标题 gap 沿用 .board-title 既有 6px、40px 行内垂直居中）。
5. $impeccable scoped 起步（context.mjs --target 相关组件 + critique 现状）：定稿关于页无底图 64px 观感（去底板后视觉重量变化，尺寸 / 下距可微调）与板头 16px 落位（对齐基线、亮暗两态）；结论落本步骤证据。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev`（Windows）——设置-关于页显示无底板全彩品牌图形、产品名 / 版本行版式如旧；主窗板头左上角 16px 无底 icon 与标题同行协调、亮暗两态各验；独立窗与设置窗无 icon；mac 形态不受影响（diff 审查：darwin 分支与 winc=traffic 零触碰；关于页无平台分支天然一致）；impeccable scoped 结论留痕。

### 步骤 2：chrome 表面族主题化——契约修订与 token 单源（先文档后代码）

任务：

1. DESIGN.md 三处原则修订 + Colors 块 chrome 注记（契约核对 1；先于代码）。
2. `themeSystems.ts`：`ThemeModeTokens` 增 `chromeTabbar / chromeToolbar / chromeLine / chromeTabSeparator / chromeSurface / chromeOmniboxBg / chromeTabbarDragTarget` 七 token（三系 × 昼夜显式落值）；`chromeTabActive` 记派生规则 ≡ chromeToolbar（不另设配置键，themeCssVariables 直接映射）；接口注释与头注派生规则区登记推导法（雾蓝 = 现值锚定，琥珀 / 苔绿同明度异色相，逐条可复算）；`themeCssVariables` 增八条映射（七 token + tab-active 别名）。
3. 色值初稿经 $impeccable scoped 流程定稿（critique 现状截图 + 色阶推导；亮态表面恒白项按 2.3 数据原则落）。
4. app.css :root / 暗色块 chrome 族字面量改写为琥珀系缺省值（对账基准），块头注退役「全局常量」表述改 board 族同款注记（契约核对 2）。

验收：`npm run typecheck` 通过；三系 × 昼夜表面值逐条对派生规则可复算（人工核对留痕）；app.css 缺省与 themeSystems 琥珀系、DESIGN Colors 琥珀快照三处逐字一致；`npm run dev` 切三系 × 昼夜 Tab 栏 / 工具栏底色即时同族换色、雾蓝观感与改动前一致（截图比对）。

### 步骤 3：主进程主题链随系（WCO overlay + 回调扩义）

任务：

1. `appearance.ts`：回调扩义为（resolvedTheme, themeColor）二元组通知、按对去重（`lastNotifiedResolvedTheme` 扩为对字段），构造注入类型与头注修订（「themeColor 变化不触发」表述退役）；`createAppearanceController` 签名与 index.ts 消费端同步。
2. `themeSystems.ts` `chromeTabbarSurface(id, resolved)` 签名扩参与头注升级；`chromeOverlaySymbol` 维持仅随亮暗（墨族全局，注释登记）。
3. `index.ts`：createWindow overlay 初值两处传 `appearance.themeColor`；回调消费处 `setTitleBarOverlay` 随系（既有 try-catch 防护与「不阻断主题切换」语义维持）；registry 兜底消费解构只取 resolvedTheme（`browserViewFallbackBackground` 零改动 + 裁定注释）。
4. 全链核对：设置窗切主题 → changed 广播 → 主窗 renderer 重注入与 WCO overlay 换色两通道同源快照、无先后错帧。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev`（Windows）——设置-外观切琥珀 / 雾蓝 / 苔绿时主窗右上角 WCO 按钮区底色与 Tab 栏同步即时换色（雾蓝恒现观感）；亮暗翻转仍即时同步；WebContentsView 兜底底色仍只随亮暗；独立窗无 overlay 无异常。

### 步骤 4：视觉复核、对比度矩阵与打包验收

1. $impeccable scoped 复核：三系 × 昼夜 chrome 区全观感（Tab 栏 / 工具栏 / 地址框 / Tab 分隔线 / 悬停蒙版 / 拖拽落点高亮）+ 关于页 + 板头 icon 一并过检；缺陷一批修完、至多一轮复核收口（有界通过纪律）。

3. dev 手验清单：三系 × 昼夜主窗与独立窗 Tab 栏 + 工具栏观感一致；地址框聚焦 / 悬停态；Tab 悬停 / 按压 / 拖入高亮在新底色上可辨；板头 icon 亮暗两态；拖拽 tear-off 独立窗表面随系。

5. `book/notes/summary/2026-11/legacy-process.md` 阶段行落盘；需求记录文档补「执行记录」节；`book/notes/summary/20261030164534-无底图标与chrome区主题适配开发计划/` 验收文档落盘。
