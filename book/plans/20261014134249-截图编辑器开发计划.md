# 截图编辑器 开发计划（快速截图与快速录屏专项·编辑器增量）

> 创建时间：2026-10-14 13:42:49（Asia/Shanghai）  
> 需求来源：`book/notes/learn/2026-10/20261014130059-截图编辑器.md`（调研定稿，用户两轮批复全部假设）；功能族 `book/docs/requirements/stages/feature-快速截图与快速录屏.md`（快速截图线增量）  
> 执行模式：波次  
> 实施范围：截图反馈条「编辑」入口（**最右端**、copied/saved 态显示）→ 独立编辑子窗（settings 窗形态先例）内 react-konva 六件标注工具（矩形/椭圆/箭头＝三档粗细+换色，马赛克＝拖框区域+块径三档，裁剪＝暗遮罩+确认+标注随选区保留，文本＝换色+字号档+微信系字体栈）→ 窗内「复制到剪贴板」「下载」两产出 icon（成功窗内 inline 反馈、**不自动关窗、关窗仅手动且无确认**）。不做：画笔/序号/高亮工具、涂抹式打码、马赛克模糊变体、撤销重做以外的图层管理、编辑内容持久化  
> 目标结果：截图后反馈条点「编辑」打开编辑子窗，六件工具全部可用（Retina 屏马赛克块径正确无暗边），复制/下载产出编辑后成品（下载命名复用单源链、单槽回写换新 captureId），编辑期并发由 captureId 对账如实报「截图已过期」；三命令全绿，PRD 3.10.1/DESIGN/骨架/process 同步  
> 当前进度：步骤 1—8 均未开始

## 1. 当前基线

- **反馈条现状（HEAD = 713e08e capture-feedback-close）**：`src/renderer/src/components/browser/CaptureFeedbackWindow.tsx` 三态（copied/saved/danger）纯展示子窗（role=capture-feedback，`useT` i18n，lang 建窗注入 + settings:changed 推送）；按钮回程 `feedback-action` 判别联合（download / dismiss 携内容指纹），主进程 handler 按 action 分支校验（sender 白名单 `resolveOwnerOf` + kind 枚举 + text 非空 ≤2000）后经 `sendToHost` 定向转发宿主 shell。「编辑」action 按同门接入。
- **单槽缓存与落盘单源**：`src/main/browser/capture.ts` 模块级 `lastCapture`（captureId + PNG Buffer + sessionName；新截图整体覆盖、退出即失）；`saveLastCapture` 经 `serializeSave` 串行链 + `src/main/browser/downloadNaming.ts`（`fileExists`/`formatDownloadStamp`/`resolveUniqueDownloadPath`/`sanitizeDownloadNameSegment`）落系统下载目录——编辑图下载与「截图已过期」对账语义全部复用，不另建第二套命名。

- **渲染端多角色分流**：`src/renderer/src/main.tsx` 按 query role 分流（settings / omnibox-suggest / workspace-picker / capture-feedback 四先例），`bootstrapLanguage` 求值期同步执行；懒加载分包有先例（构建产物 SettingsWindow 独立 chunk）。
- **契约现状**：`src/shared/capture.ts` `CAPTURE_CHANNELS` 现有 14 通道（截图面 9：capture/saveLast/request/showFeedback/hideFeedback/feedbackData/feedbackAction/downloadRequest/dismissRequest；录屏面 5）；preload `api.capture` 命名空间与 `index.d.ts` 同步暴露。编辑器新增通道与角色常量在此单源扩。

- 反馈条入口：编辑链接式钮置于**条最右端**（「下载」钮右侧）、copied 与 saved 两态显示（danger 不显示）+ i18n `browser.capture.edit` 三语 + CSS。

- 视觉与文档：impeccable new-work 轮定稿编辑窗视觉；PRD 3.10.1 编辑小节 + 验收条目、DESIGN.md 编辑器段、`book/docs/architecture/项目骨架.md` 新文件条目、`book/notes/summary/2026-11/legacy-process.md` 阶段行。

### 2.2 本阶段明确不做

- 画笔、序号标注、高亮笔等其余微信工具（架构留扩展位：工具枚举可扩）。
- 涂抹式画笔打码、马赛克的高斯模糊变体（只做拖框区域像素化）。
- 编辑内容持久化与会话数据落盘（编辑态窗内自持，关窗即弃——用户裁决无确认直接关）。
- 编辑器快捷键、全屏覆盖形态（用户裁决独立子窗）、多图/多 Tab 编辑。
- 编辑窗自动关窗与宿主反馈条联动（用户裁决：不自动关窗、结果反馈窗内 inline、宿主反馈条不随动）。

### 2.3 本阶段数据原则

- **单槽 = 最近一次成品**：edit-copy / edit-download 均回写单槽并**换新 captureId**（旧引用自然过期，与既有 save-last 语义同构）；复制动作才写系统剪贴板，下载动作只落盘不碰剪贴板。
- **过期如实报**：编辑窗产出时 captureId 对账失败在窗内如实报「截图已过期」（i18n），不伪造成功、不静默丢弃。
- **诚实性**：空槽（无截图）、坏 dataUrl（解码失败）如实报错；编辑全程零分区触达、不写任何会话数据。
- 编辑图下载命名锚定发起截图时会话名（sessionName 随单槽保留），复用唯一路径序号不覆盖既有文件。

## 6. 可并行步骤分析

### 6.1 依赖关系

| 步骤 | 前置依赖 | 可与谁并行 | 说明 |
| ---- | -------- | ---------- | ---- |
| 步骤 1 | 无 | 无（串行先行） | 契约冻结（shared + preload 类型 + i18n 键）是一切并行的前提 |
| 步骤 2 | 步骤 1 | 步骤 3、4 | 只碰 main.tsx + 空壳组件 + package.json |
| 步骤 3 | 步骤 1 | 步骤 2、4 | 只碰 main/browser 两文件 + index.ts |
| 步骤 4 | 步骤 1 | 步骤 2、3 | 只碰 CaptureFeedbackWindow.tsx + app.css 反馈条段 + 核对 i18n |
| 步骤 5 | 步骤 1、2 | 无（编辑器大块内部串行） | 依赖分流壳与 preload 类型；编辑器本体单线程推进 |
| 步骤 6 | 步骤 5 | 无 | 工具条/产出钮建立在 Stage 组件结构上 |
| 步骤 7 | 步骤 6 | 无 | 视觉轮需功能完整面 |
| 步骤 8 | 步骤 1—7 | 无（收尾独占） | 全量验收 + 文档 + 审查 |

### 6.2 并行波次

- **波次 1（串行先行）**：步骤 1。理由：通道/类型/键位冻结后，三路实现才不互踩契约。
- **波次 2（可并行）**：步骤 2、3、4。理由：文件集合互不相交（renderer 分流壳 / 主进程窗与 handler / 反馈条入口），接口已冻结；步骤 4 的按钮发送在类型层即可编译，运行时联调与步骤 3 同批验收。
- **波次 3**：步骤 5 → 步骤 6（编辑器本体，同一实现链串行）。理由：6 依赖 5 的 Stage 组件结构，拆给两个 agent 会互相等待反而慢。
- **波次 4（收尾独占）**：步骤 7、8。理由：视觉轮与全量验收需要完整功能面。

### 6.3 并行门槛

波次 2 三步骤文件集不相交且各自工作量 > 5 分钟，达标开并行；波次 3 两步骤存在组件结构依赖，不达标合并为串行链，理由如上。

### 6.4 不可并行的红线

- 步骤 3 与步骤 4 都涉编辑入口链路，但步骤 3 独占 `src/main/browser/capture.ts`（edit 分支在 handler 内做），步骤 4 只碰渲染层——**步骤 4 禁止改 capture.ts**，否则与步骤 3 冲突。
- 步骤 5/6 禁止回改步骤 2 的 main.tsx 分流结构（新增文件承载，避免与壳层互踩）。
- 所有波次内禁止改 `src/shared/capture.ts`（契约已冻结，改动归步骤 1 重开）。
- 结果需交叉验证的组合（步骤 3×4 的入口联调、步骤 5×6 的导出链）不得各自验收了事，统一并入下一批次验收。

## 7. 建议询问 Agent 的方式与次数

### 7.1 分组建议

| 用途 | Agent 类型 | 建议时机 | 并行数量 | 次数 |
| ---- | ---------- | -------- | -------- | ---- |
| 调研 | 不需要 | — | — | 0 次（调研报告已定稿，现状本轮已核实） |
| 实现 | general-purpose | 波次 2：A=步骤 3、B=步骤 2+4；波次 3：C=步骤 5+6 | 波次 2 并行 2 个；波次 3 单个 | 共 3 次 |
| 审查 | code-review 技能（主会话执行） | 步骤 8 | — | 1 轮 |
| 测试/收尾 | 主会话直接执行 | 波次 4 | 不并行 | 0 次 |

全阶段 agent 询问总次数上限：4 次。控制原因：编辑器本体（波次 3）是强上下文大块（设计语系/坑点基线/i18n 规则多），拆碎重建成本高于串行；波次 2 三块各自独立且契约冻结，是唯一明确划算的并行点。

### 7.2 每次询问的约定

- prompt 自包含：引用本计划路径 + 步骤编号 + 该步骤「验收」标准 + 只允许触碰的文件范围 + 禁止清单（含 §6.4 红线与「禁改 shared/capture.ts」）。
- 实现类 agent 返回后由主会话亲自跑 `npm run typecheck`/`npm run lint` 验收，不信任 agent 自述。
- 波次 3 的 agent 须附调研报告路径（坑点基线：Pixelate pixelRatio:1 / 文本 IME / 分包）与 DESIGN.md 相关段。
- 依赖前序波次的询问，待其步骤验收后再发起。
