# 浏览器区兜底底色随主题 开发计划

> 创建时间：2026-09-25 00:33:58（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/feature-应用外观三模式.md`（「切换应覆盖应用壳、Electron 原生界面和原生 DevTools」）——2026-09-25 用户反馈实测 www.google.com 疑似未跟随黑夜模式，CDP 隔离实例调查确认被测页面 `prefers-color-scheme` 管线已完整生效（三态跟随 + 活传播 + google 黑夜首屏暗色渲染成功），浏览器区唯一未覆盖点为 WebContentsView 兜底底色写死白色  
> 执行模式：直通  
> 实施范围：只做 WebContentsView 页面首帧前兜底底色随主题——建视图时现取 + 主题翻转时同步存量视图；不碰页面画布默认色、不注入样式、零新增 IPC 通道  
> 目标结果：黑夜模式下新建会话/新建 Tab/新导航的首帧前不再闪白底；主题翻转后存量视图的下次导航兜底色即随新主题  
> 当前进度：步骤 1—4 均未开始

## 1. 当前基线

- 外观域管线已生效：`src/main/appearance.ts` 在 init/setMode/setThemeColor/resetToDefaults 均设置 `nativeTheme.themeSource`，Electron 将其传播至全部 webContents（含 WebContentsView 与原生 DevTools）；`syncSnapshot` 循环 `BrowserWindow.getAllWindows()` 逐窗 `setBackgroundColor`（窗底色建窗注入 + 翻转全覆盖）。2026-09-25 CDP 隔离实例实测：会话页 `matchMedia('(prefers-color-scheme: dark)')` 三态跟随且切换未刷新即翻转（活传播）、黑夜下全新导航 google.com 首屏完整暗色（body 背景 rgb(34,36,42)）。
- 唯一缺口：`src/main/browser/manager.ts` `newTab` 创建 WebContentsView 后写死 `view.setBackgroundColor('#ffffff')`（注释「页面加载前兜底白底，防透明闪烁」）——不按主题取值；且 `syncSnapshot` 的广播链只触达 BrowserWindow 与 renderer webContents，无任何路径更新存量视图底色，主题翻转后老 Tab 下次导航仍以旧色兜底首帧。
- DevTools 为原生受管（`wc.devToolsWebContents`，manager 不自建视图），随 nativeTheme 自行亮暗，无自管底色需要处理。
- 装配结构：`src/main/browser/registry.ts` 以 `managers: Map<string, TearOffTabManager>` 持全部会话 manager（`ensureManager` 创建时注入 `partition`/`getHomepageUrl` 等 opts）；`createAppearanceController()` 现为零参工厂（`src/main/index.ts:81`），主进程侧无外观变化回调出口；`createIndependentWindows` 已有 `getBackgroundColor` 现取 dep 先例可对齐。
- 契约现状：chrome surface 色值目前只在 renderer 侧（`app.css` chrome-\* token：亮 surface `#ffffff` / 暗 surface `#202124`，与 `DESIGN.md` Chrome 色板同值）；主进程不读 CSS，需要 shared 单源落点。`src/shared/browser.ts` 为浏览器域契约单源（BROWSER_CHANNELS、WINDOW_ID_MAIN 等）。

## 2. 范围边界

### 2.1 本阶段必须完成

- `src/shared/browser.ts` 增兜底底色单源：常量对（亮 `#ffffff` / 暗 `#202124`，chrome surface 族）+ 取值函数（`'light' | 'dark'` → 色值），头注释写明与 `app.css` chrome-surface、`DESIGN.md` Chrome 色板的对账关系。
- `manager.ts`：建视图底色改现取（opts 增 `getFallbackBackground` dep）；`TearOffTabManager` 增 `applyFallbackBackground(color)` 遍历存量视图更新。
- `registry.ts`：创建参数增同名 dep 透传 `ensureManager`；registry 面增 `applyFallbackBackground(color)` 聚合方法（迭代 `managers` 全集）。
- `appearance.ts` + `index.ts`：`createAppearanceController` 增可选 dep `onResolvedThemeChanged`（resolvedTheme 变化去重后调用，init 期也发）；index 注入回调经 `registry?.` 空值守卫桥接到 registry 聚合方法。
- 文档同步：`book/docs/requirements/PRD.md` 3.4、`DESIGN.md` Chrome 色板条目、`book/docs/architecture/项目骨架.md`（manager.ts / registry.ts / appearance.ts / shared browser.ts 四行）。

### 2.2 本阶段明确不做

- 不向页面注入任何样式、不做强制暗色、不改 about:blank 与未设背景页面自身的画布默认色（Chromium 默认白——PRD 3.4 诚实性红线；空白页加载完成后的白底是页面画布行为，不属于兜底色管辖）。
- 不处理原生 DevTools 底色（原生受管，随 nativeTheme 已自行亮暗）。
- 零新增 IPC 通道、零 `preload/index.d.ts` 变更（纯主进程内聚，renderer 无感知）。
- 不做逐会话/逐标签/站点级底色偏好；主题色（themeColor）不参与右区兜底色（强调色不出板规则，右区恒灰阶，只随亮暗两态）。
- 不改被测页面偏好管线（`nativeTheme.themeSource` 已生效，本阶段不触碰）。

### 2.3 本阶段数据原则

- 兜底底色是壳层视觉派生值：随外观快照现取，不新增持久化键、不进 preferences.json。
- 不伪造：翻转即同步存量视图，不因广播时序残留旧色；验收观察条件（首帧窗口极短）如实记录，不以截图伪造不可捕捉的瞬间。

### 2.4 契约核对

1. **shared/browser.ts 增常量与取值函数**：`browserViewFallbackBackground(resolved: 'light' | 'dark')`——chrome surface 族色与 `app.css` chrome-surface token、`DESIGN.md` Chrome 色板三处对账（字面量改一处须同步其余两处，对齐 appearance.ts 头注的 board 底色对账惯例）。需同步文档：`DESIGN.md` Chrome 色板条目补对账句。
2. **PRD 3.4 补归属句**：「外观切换覆盖应用壳」明确含浏览器区 WebContentsView 页面首帧前兜底底色——随当前亮暗取 chrome surface 族色、切换即时同步；不改变页面画布默认色、不注入样式。
3. **createAppearanceController 增可选回调 dep**：向后兼容（现仅 index.ts 一处零参调用点），无 IPC/preload 契约变更。
4. **骨架同步**：`book/docs/architecture/项目骨架.md` 四行职责描述随步骤 2—3 落笔同步（无新增/删除文件）。

完成标志：契约常量落入 `src/shared/browser.ts` 且 `npm run typecheck` 0 错误；PRD/DESIGN/骨架三处文档落笔可 grep。

1. `src/shared/browser.ts` 增兜底底色常量对与 `browserViewFallbackBackground` 取值函数，头注释写明三处对账关系与「主进程不读 CSS」的同步义务。
2. `book/docs/requirements/PRD.md` 3.4 补兜底底色归属句（措辞见 2.4 契约点 2）。
3. `DESIGN.md` Chrome 色板条目（亮/暗 Chrome 行）补主进程建视图兜底底色对账句。
4. `book/docs/architecture/项目骨架.md` shared `browser.ts` 行补常量描述。

验收：`npm run typecheck` 0 错误；grep 确认 PRD 3.4、DESIGN、骨架三处均已落笔。

### 步骤 2：manager.ts 建视图现取 + 存量更新方法

任务：

1. `createTabManager` opts 增 `getFallbackBackground: () => string`（注释写明现取语义：newTab 为同步函数，不容 await，取色由注册表注入）。
2. `newTab` 内 `view.setBackgroundColor('#ffffff')` 改为 `opts.getFallbackBackground()`，原「页面加载前兜底白底」注释更新为随主题表述。
3. `TearOffTabManager` 接口与实现增 `applyFallbackBackground(color: string): void`——遍历 `tabs` 全集逐 view `setBackgroundColor`（含未挂载/悬挂态视图，防切换激活时以旧色兜底首帧；对 webContents 已销毁的视图调用安全无副作用）。

验收：`npm run typecheck`、`npm run lint` 通过；grep 确认 manager.ts 无写死 `'#ffffff'`。

### 步骤 3：registry 与 index.ts 接线（外观翻转触达存量视图）

任务：

1. `registry.ts`：创建参数增 `getFallbackBackground` 透传 `ensureManager`；`SessionBrowserRegistry` 接口增 `applyFallbackBackground(color: string): void`——迭代 `managers` 全集透传（空 Map no-op；对齐 destroySession 等既有聚合方法形态）。
2. `appearance.ts`：`createAppearanceController` 增可选 dep `onResolvedThemeChanged?: (resolved: ResolvedTheme) => void`；`syncSnapshot` 内与上次发布快照比较 resolvedTheme，变化即调用（init 首次也发——index 侧空值守卫兜住 registry 未建的启动窗口期；setThemeColor 不改亮暗故自然不触发）。
3. `index.ts`：registry 创建参数注入 `getFallbackBackground`（现取 `appearanceController.getSnapshot().resolvedTheme` 经步骤 1 函数派生，对齐 `createIndependentWindows` 的 `getBackgroundColor` 先例）；`createAppearanceController` 注入 `onResolvedThemeChanged` 回调 → `registry?.applyFallbackBackground(...)`。

验收：`npm run typecheck`、`npm run lint` 通过；grep 确认 index.ts 接线处无写死色值。
