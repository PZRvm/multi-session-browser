# 自研插件宿主集成（截图/录屏功能打通）

分级L：扩展兼容 preload 生成链改造 + 主进程截图/取流桥 + 隐藏窗生命周期，命中 always-L（特权 IPC 与 Session 级 preload）。

## Step 0（结构化需求简报）

| 项目 | 简报 |
| --- | --- |
| 背景 | 用户在宿主内成功导入 extensions/dist 的 screenshot.crx 与 recorder.crx，但功能不可用（普通 Chrome 15/15 通过）。静态实锤根因：electron-chrome-extensions 4.10.0 不提供 `tabs.captureVisibleTab`、`tabCapture`、`offscreen`、`runtime.getContexts`（产物 grep 全 0 命中），两插件核心链全部落空 |
| 使用者与场景 | 用户在宿主任意会话内点截图插件图标→编辑器→标注/复制/下载；点录屏 popup→开始/暂停/结束→MP4 |
| 需求输入 | 用户 2026-11-12 报障 + 两个 CRX；合并审查 M-1 已预言该集成缺口 |
| 影响范围 | src/main/extensions/{preload-guard 生成链,shims(新),dev-entry 装配}、index.ts 注入；不改两插件本体与第三方插件行为 |
| 排除项 | 不实现 Chrome 全量 offscreen 规范；不推翻库 4.10；不改协议 v1；Windows 不测 |
| 数据和权限 | shim IPC 仅扩展上下文 sender 可用（chrome-extension:// 前缀校验）；取流授权沿用 captureView.ts 的 setDisplayMediaRequestHandler 先例（请求方限定采集器） |
| 成功与失败 | 宿主内截图全链（点图标→编辑窗→标注→复制/下载）与录屏全状态机（开始/暂停/恢复/取消/结束→MP4 产物）可用；第三方四插件回归不破坏 |
| 回收与退出 | 证据归 book；shim 段与库 preload 同文件生成，升级库版本时断言失败即重新核验 |

## 根因清单（grep 库产物实锤）

| 插件依赖 | 库 4.10.0 | 宿主等价物 |
| --- | --- | --- |
| tabs.captureVisibleTab | ✗ | wc.capturePage() → dataURL |
| windows.create(popup) | ✓（有实现，待验） | — |
| downloads.download | ✓（preload 18 处，data: URL 待验） | 主进程直写兜底 |
| storage/runtime/onMessage/onChanged/action.onClicked | ✓ | — |
| runtime.getContexts | ✗ | 宿主登记态模拟 |
| tabCapture.getMediaStreamId | ✗ | 一次性 token + 授流登记 |
| offscreen.createDocument | ✗ | 宿主隐藏 BrowserWindow 加载扩展 offscreen.html |
| getUserMedia(chromeMediaSource:'tab') | ✗（Chromium 专属约束） | preload 拦截改写为 desktop 源 + setDisplayMediaRequestHandler 授目标 tab 流（captureView.ts 先例）；tab 音频无原生等价物，audio 开关在宿主内降级为无声（如实反馈，不假装） |

## 里程碑

- **M1 截图线**：preload-guard 生成链追加宿主 shim 段（chrome.tabs.captureVisibleTab 若缺则定义 → ipc）；主进程 shims 模块：`msb-ext-shim:capture-visible-tab`（sender 校验扩展上下文；库 windowId=BrowserWindow.id → 宿主 scope → manager.getActiveWebContents → capturePage）；验证 windows.create/downloads 实况，缺则补。验收：隔离实例点截图→编辑窗→标注→复制/下载。
- **M2 录屏线**：getContexts/offscreen/停启文档 shim + 隐藏采集窗生命周期（主进程登记）；tabCapture.getMediaStreamId token；offscreen 页 preload 拦截 getUserMedia 改写 tab 源→desktop 源，分区 session handler 按 token 授被录 tab 的流；状态机走插件自身实现（协议 v1 对齐，宿主只补环境）。验收：宿主内录屏全状态机 + MP4 产物 + 第三方四插件回归。
- **M3 回归**：第三方四插件（Cookie-Editor CRUD、翻译、Dark Reader、uBO）在 shim 加入后回归不破坏；production-plugins 自动检查若可复用则跑。

## 约束

- shim 通信仅经新增受控 IPC 通道，preload 白名单语义不放宽（通道专用、sender 双重校验：chrome-extension:// 前缀 + 目标 wc 存活）。
- 隐藏采集窗只加载插件自带 offscreen.html，不注入任何站点页面。
- 音频：Electron 无 tab 音频捕获路径，第一版录屏在宿主内 audio 关闭语义（如实降级并记录），不阻塞视频链。
