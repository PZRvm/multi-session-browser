## 2. 范围边界

### 2.1 本阶段必须完成

- **主进程每 Tab DevTools 生命周期**：F12 开 → 懒创建宿主 `WebContentsView`，经 `setDevToolsWebContents` + `openDevTools` 将该 Tab webContents 的原生 DevTools 嵌入宿主 view；关 → `closeDevTools()` + 摘除 view；关闭 Tab 时一并销毁；macOS 关窗重开时随 `attachToWindow` 重挂；DevTools 实例与所在 Tab 的 webContents 一对一强绑定（AGENTS.md 领域规则："DevTools 挂在具体 webContents 上"）
- **底部停靠布局**：内容区按 renderer 上报的页面/DevTools 双矩形切分；停靠区高度由可拖拽分隔条控制（Chrome 惯例）；拖拽比例是 renderer 内存态
- **F12/ESC 双侧快捷键**：页面聚焦走 manager 的 before-input-event、shell 聚焦走 renderer keydown，两侧共用键位表（F12/Escape 入表）；omnibox 编辑态 ESC 豁免；DevTools 自身聚焦时 F12 可关闭、ESC 不劫持（留给 DevTools 抽屉）
- **脚手架 F12 冲突解除**：移除 `optimizer.watchWindowShortcuts` 接线，dev 态 F12 归产品语义；prod 态 shell 防误刷新守卫（拦 Cmd/Ctrl+R、F5）由主窗口 before-input-event 自接管
- **每 Tab 数据隔离**：DevTools 的 Elements/Console/Network/Application 只反映所在 Tab 的 webContents 数据；切 Tab 时停靠区跟随（新激活 Tab 开则显示其 DevTools、关则收起），互不串扰
- **契约扩展**：`src/shared/browser.ts` 增 2 条通道 + `BrowserSnapshot.devtoolsOpen`；`browserShortcuts.ts` 增 F12/Escape；`preload` 增 2 方法
- **Toolbar 提示升级**：`.chrome-devtools-hint` 由静态 span 升级为可点开关按钮，状态如实跟随 devtoolsOpen
- **文档同步**：DESIGN.md、book/notes/summary/2026-11/legacy-process.md 同步 + `book/notes/summary/` 整链验收文档落盘

### 2.2 本阶段明确不做

- **会话与浏览器绑定**：`persist:sess-<id>` 每会话独立分区、切会话后 DevTools 跟随切换会话环境数据（PRD 3.3.2 的完整语义）——阶段 4。本阶段绑定粒度是 Tab，"当前会话的数据"在本阶段落地为"激活 Tab 的数据"（诚实性声明见 2.3）
- **DevTools 停靠方向切换**（右/左/独立窗口切换）：embedding 形态固定为底部停靠；`setDevToolsWebContents` 宿主形态下 DevTools 自带 dock 按钮不可用，属 Electron 固有限制，PRD 未要求
- **DevTools 开启状态与停靠比例持久化**：浏览器状态本就不持久化（阶段 2 原则：重启回单个新标签页），DevTools 随之复位
- **ESC 停止页面加载**（Chrome 在 DevTools 关闭态下的 ESC 行为）：PRD 只要求 ESC 关闭 DevTools；未开时 ESC 原样放行，推后续打磨
- **DevTools 原生能力改造**（换肤、面板裁剪、自定义传输）：PRD 5.3 明令"完全复用官方调试面板"，恒不做的红线
- **会话状态灯 loading 驱动**：阶段 2 既定修正，推迟阶段 4
- **二期调试辅助**（截图/弱网/UA/日志）：`book/docs/requirements/stages/step-09-测试辅助功能二期.md`
- 测试框架引入——沿用 typecheck + lint + 手动验证

### 2.3 本阶段数据原则

- **调试数据只读不造数**：Elements/Console/Network/Application 全部来自 Chromium DevTools 本体与所在 webContents，应用层不注入、不缓存、不伪造任何调试数据
- **状态真源**：devtoolsOpen 由主进程维护并随快照推送，renderer 纯镜像；停靠比例是 renderer 内存态，不进快照、不落盘
- **诚实语义**：浏览器仍是未绑定会话的单例（`persist:browse`），本阶段 DevTools 绑定的是激活 Tab；计划、代码注释与验收文案不得宣称"按会话隔离 DevTools"——会话级隔离是阶段 4 绑定后的自然结果（DevTools 挂在 Tab 的 webContents 上，届时零返工跟随）
- **DevTools 即原生**：不改造、不代理其内部 IPC、不缓存其数据
- 界面文案纯中文（本阶段新增文案仅：分隔条 aria-label、开关按钮 title/aria-label）

## 3. 开始编码前的契约核对

以下变更编码前必须冻结（依据 AGENTS.md：实现与设计冲突时先改文档；本节即本阶段的文档修订记录）：

> 2026-09-11 缺陷修订：真实设备模式验证发现，自建外部 DevTools WebContentsView 会让设备画面与被检查页面落入两套坐标系统，且关闭后存在复用已销毁 child view 的异常。按 PRD「完整原生 DevTools」优先级，契约改为 Electron/Chromium 受管 DevTools；删除 `setDevToolsBounds` 通道与双锚点布局。以下契约点已同步为修订后的当前事实，原实施过程保留在后续步骤与 `book/notes/summary/2026-11/legacy-process.md` 中作为历史记录。

> 2026-09-11 修复轮增补（用户授权）：复审发现 renderer 侧 closeDevTools 以「守卫读镜像态 + toggle」实现，存在毫秒级 TOCTOU 可把已关闭的 DevTools 误重开。通道 13 → 14 条，增 `closeDevTools: 'browser:close-devtools'`（无 payload，未开启时主进程原子 no-op），preload `api.browser` 增对应方法，renderer closeDevTools 直连该通道、不再走 toggle。

1. **`src/shared/browser.ts` 增补**（冻结载体，文件头注改为"修改需先修订本计划第 3 节"）：
   - `BROWSER_CHANNELS` 增 `toggleDevTools: 'browser:toggle-devtools'`、`closeDevTools: 'browser:close-devtools'`（通道 12 → 14 条）
   - `BrowserSnapshot` 增 `devtoolsOpen: boolean`（**激活 Tab** 的 DevTools 开关态；无激活 Tab 时恒 false）
   - 其余既有通道、类型、tab id 生成规则（主进程 `tab-<seq>`）零变更
2. **`src/shared/browserShortcuts.ts` 键位表扩展**：`BrowserShortcutId` 增 `'toggle-devtools' | 'close-devtools'`；key 联合类型增 `'F12' | 'Escape'`；表增 `{ id: 'toggle-devtools', key: 'F12' }`、`{ id: 'close-devtools', key: 'Escape' }`（多字符键无修饰分支天然覆盖二者，匹配函数零改动）；头注"明确不做"清单删除 F12/ESC 行，改记两条豁免规则：omnibox 编辑态 ESC 不关 DevTools（renderer 侧）、DevTools 自身 webContents 内 ESC 不劫持。
3. **`src/preload/index.d.ts` 归步骤 2 独占**：阶段 2 计划第 3 节的独占权随阶段 2 完成已释放，本阶段由本节接管；`api.browser` 增 `toggleDevTools(): Promise<BrowserSnapshot>`（修复轮增补：另有 `closeDevTools(): Promise<BrowserSnapshot>`，见上方修订记录），步骤 3 起不得再改该文件。
4. **`optimizer.watchWindowShortcuts` 移除声明（AGENTS.md 坑点正式处理，行为变化记录在案）**：dev 态 F12 不再打开 shell 自身的 Electron DevTools（归产品语义，shell 自身 DevTools 经 Alt 唤出菜单 View 可达，开发便利性损失已评估可接受）；dev 态 Ctrl+R 不再被脚手架接管（shell HMR 误触自愈：bounds 会重报）；prod 态 shell 防误刷新守卫由主窗口 before-input-event 自接管（拦 Cmd/Ctrl+R 与 F5）。收尾在 process.md 执行决策记录。
5. **DESIGN.md 三处待收尾落盘**：①「Chrome 框架」条目的 F12 提示改写为开关按钮实况（含 aria-pressed/title 规则）；②右区记录原生受管 DevTools 事实，停靠与设备模拟布局全部交回 Chromium；③「Not Yet In The World」章节按新边界改写（该节自注"阶段 3 前有效"）。

### 6.2 并行波次

- **波次 1（串行先行）**：步骤 1。理由：`setDevToolsWebContents` 嵌入路径若不可行需走退路，退路改变停靠布局契约，必须先出结论。
- **波次 2（串行）**：步骤 2。理由：契约 + 键位表 + preload 类型是后续全部并行的输入；体量小（<30 分钟）无并行对象。
- **波次 3（可并行）**：步骤 3、5。理由：都只消费波次 2 契约，`main/browser/manager.ts` 与 renderer 文件集合不相交；manager 生命周期管理与 renderer 双锚点布局各自都是 ≥40 分钟的实现量。
- **波次 4（可并行）**：步骤 4、6。理由：步骤 4（ipc.ts + preload/index.ts）与步骤 6（index.ts）文件不相交；步骤 4 另受步骤 3 约束、步骤 6 不依赖 manager。
- **波次 5（收尾，独占）**：步骤 7。理由：验收期间代码必须冻结，文档以验收结论为准。

### 6.3 并行门槛

- 波次 3：2 个步骤、文件不相交、各约 40—90 分钟——达标，开并行。
- 波次 4：2 个步骤、文件不相交、各约 15—40 分钟——达标开并行；若执行时判断步骤 4 不足 5 分钟工作量，由主会话亲自做、不开 agent。
- 波次 1、2、5：均单步骤，串行执行（无门槛问题）。

### 6.4 不可并行的红线

- `src/shared/browser.ts`、`src/shared/browserShortcuts.ts`、`src/preload/index.d.ts` 仅归步骤 2；其余步骤不得触碰（防契约漂移）

- 依赖冒烟结论的步骤 2 不得在步骤 1 验收前开工
