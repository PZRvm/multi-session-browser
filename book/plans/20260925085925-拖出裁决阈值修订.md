# 拖出裁决阈值修订 开发计划（契约修订记录）

> 创建时间：2026-09-25 08:59（Asia/Shanghai）
> 需求来源：用户反馈（2026-09-24）——"拖出去必须拖到软件外面才建新窗，希望只要拖离 Tab 栏区域即可建新窗"；方向与 Chrome 惯例一致（PRODUCT.md 设计原则背书），调研从略径直实施
> 执行模式：修订——阶段 9（`book/plans/20260913023538-阶段9拖出拖入手势开发计划.md` 第 3 节契约点 3）冻结的"四态裁决按窗口 bounds 命中"语义，本修订细化为"按 Tab 栏矩形命中"；阶段 10 的插入位 hint 机制（`book/plans/20260913200109-阶段10跨窗口转移与生命周期收尾开发计划.md` 第 3 节）不受影响、继续适用
> 当前进度：实现完成，待手动验收

## 1. 修订后的裁决契约（冻结）

1. **命中测试细化**：dragStart/dragEnd 裁决与悬停判定的命中单位从「窗口 bounds」改为「窗口 Tab 栏矩形」。Tab 栏矩形 = 该窗 renderer 经 `browser:report-tabstrip-rect` 上报的 TabStrip 根容器视口矩形（窗口内容坐标 DIP），主进程叠加 `getContentBounds()` 原点（现取，窗口移动自动跟随）换算屏幕矩形。
2. **四态裁决语义**（修订后）：
   - 释放点在某窗口 **Tab 栏矩形内**：源窗栏 → `stayed`（零副作用）；同会话窗栏 → `moved-window`（hint 插入，无 hint 回退末位——阶段 10 机制原样）；异会话窗栏 → `rejected`（源 Tab 原位回弹）
   - 释放点**离开一切 Tab 栏**（源窗/他窗内容区、工具栏、软件外空白）→ `moved-new-window`（落点建窗）——"拖离 Tab 栏即可拖出"，Chrome 对齐
   - Esc 显式取消 → `stayed`（不变）
3. **悬停反馈收窄**：`hoverWindowAt` 同步按 Tab 栏命中——拖拽中只有对准同会话他窗的 Tab 栏才有高亮与插入指示器（Chrome 对齐：可落的是 Tab 栏而非整窗）；他窗内容区无任何可落反馈，释放即建新窗。
4. **通道扩展（浏览器域 24 → 25：命令 19 + 推送 6）**：`reportTabstripRect: 'browser:report-tabstrip-rect'`，载荷 `TabstripRectPayload`（四 number 视口矩形，结构同 `SetBoundsPayload`）；ipc 层结构守卫（四有限 number，命令口径拒绝），零/负尺寸 = 清条目；作用域解析用 `resolveScope`（不要求激活会话——主窗零会话空态 Tab 栏仍在）。preload `api.browser.reportTabstripRect` 两处对齐。
5. **上报方**：TabStrip 根容器挂 `useRectObserver`（与内容锚点上报同骨架：挂载即报 + ResizeObserver + rAF 节流），fire-and-forget 失败静默；**卸载上报零矩形清条目**（HTML 全屏壳层隐藏等场景，防陈旧矩形让不可见栏参与裁决）。
6. **尽力而为语义与自愈**：矩形丢失/陈旧（新窗首帧未落等毫秒级窗口）的后果是该窗 Tab 栏不被命中——释放走建窗，TabStrip 重挂载/resize 即自愈，不阻断拖拽。控制器内矩形缓存条目不随窗口销毁清理：已销毁窗口不进候选集自然不被查询，Electron 窗口 id 单调不复用，无别名风险。
7. **PRD 修订**：`book/docs/requirements/PRD.md` 3.6.1 拖出条件由"拖到窗口外空白处释放"修订为"拖离 Tab 栏区域释放"（2026-09-25 修订，本文档即在库修订链；docs/ 不进版本库）。

## 2. 验收口径（手动，待跑）

- 拖 Tab 离开本窗 Tab 栏、在**本窗内容区/工具栏**上释放 → 建新独立窗口（核心诉求）
- 拖 Tab 到**软件外空白**释放 → 建新窗（原行为保持）
- 拖 Tab 对准**同会话他窗 Tab 栏**：悬停高亮 + 插入指示器，释放并入指定位
- 拖 Tab 到**同会话他窗内容区**：无高亮，释放 → 建新窗（不再并入）
- 拖 Tab 到**异会话窗 Tab 栏**释放 → 拒绝回弹；到异会话窗内容区释放 → 建新窗
- Esc 拖拽中放回源位；HTML 全屏中（Tab 栏已隐藏）无拖拽入口，退出全屏后 Tab 栏重挂载即重报矩形
- 主窗/独立窗互为源与目标各验一遍；多窗重叠时 Tab 栏命中按既有 tiebreak（聚焦序）裁决
