# 阶段 9 开发计划：拖出与拖入手势（独立窗口四）

> 创建时间：2026-09-13 02:35:38（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/step-09-独立窗口四-拖出拖入手势.md`（调研依据：`book/notes/learn/2026-09/20260912184016-标签页拖出独立窗口.md` 8.3 单元 D 方案 D1 与第 9 节 v2 定案；PRD 3.6.1 / 3.6.2 / 4.5 / 验收 14）  
> 执行模式：波次  
> 实施范围：交付 Tab 拖出/拖入手势全链——renderer HTML5 拖拽（dragstart/dragend + document dragover 保 dragend 触发）、主进程拖拽会话（光标轮询 + 同会话窗口命中 + 悬停高亮推送）、释放裁决（空白处→新窗口 / 同会话窗口含主窗口→并入其 Tab 栏 / 异会话→拒绝回弹）；移除临时右键入口。不做插入位置指示与视觉终稿、退出落盘归并（阶段 10）  
> 目标结果：任一 Tab（主窗口或独立窗口的 Tab 条）可被拖起——拖到窗外空白处释放即在落点附近成为新独立窗口；拖到同会话窗口（含主窗口激活会话浏览区）释放即并入其 Tab 栏末位并激活；拖到异会话窗口释放被拒绝、源 Tab 回弹原位不丢；拖拽全程有状态反馈（源 Tab 半透明、悬停目标窗高亮）；页面 webContents 原样迁移全程不重载；拖拽成为唯一 tear-off 入口（右键菜单退役）  
> 当前进度：步骤 1—6 均未开始

## 1. 当前基线

- **拖拽手势完全未实现**：`src/renderer/src/components/browser/TabStrip.tsx` 的 Tab 项只有 onClick/onKeyDown（:84-90），无 draggable 与任何 drag 事件；tear-off 唯一入口是临时右键菜单（:62-77 Dropdown contextMenu「移出到独立窗口」，:16 注释声明"阶段 9 拖拽手势替换入口"）+ overlay 登记块（:34-48）+ onMenuClick（:52-59，含 L3 修复的失败 message 反馈）。
- **tear-off 主进程链已交付，是拖出裁决的现成半成品**：`browser:tear-off-tab` handler（`src/main/browser/ipc.ts:199-206`，requireScope + requireTabId 守卫）→ `registry.tearOffTab`（`src/main/browser/registry.ts:702-728`：读会话名 → windows.createWindow → manager 迁移）→ `manager.tearOffTab`（`src/main/browser/manager.ts:400-425`：摘 view 保活 + 归属改写 + 源窗邻位补位 + 目标窗置激活位）。**缺口一**：只有"建新窗"路径，无并入既有窗口原语——tearOffTab 对目标窗只置激活位不挂 view（防白屏时序），若直接用于已就绪的目标窗会与该窗旧激活 view 双挂叠加（`activate` 的摘旧逻辑在 manager.ts:233-240，未被 tearOffTab 走到）。**缺口二**：建窗无落点定位（`src/main/browser/windows.ts:63-126` 仅默认 1024×720 居中系统默认位，无 x/y 参数）。
- **命中判定与窗口枚举的缺口**：windows.ts 无按会话枚举接口（仅 setTitleForSession 内部遍历 :138-142）；registry 不暴露 activeSessionId（`:138` 模块内变量）——拖拽命中主窗口需判"主窗激活会话 = 拖拽会话"（PRD 3.6.2）；无窗口聚焦序信息（多窗 bounds 重叠时无 tiebreak 依据，Electron 无 z 序 API）。
- **契约面**：`BROWSER_CHANNELS` 15 条（`src/shared/browser.ts:17-33`，13 命令 + 2 推送），无任何 tab-drag 通道；头注释（:1-12）指向阶段 7—8 计划第 3 节——本计划第 3 节即下一份修订记录；preload browser 13 方法 + 2 订阅（`src/preload/index.d.ts:44-60`）；ipc.ts 注册日志"15 条通道"（:208）。
- **可复用的同构机制**：ipc.ts 的 `windowForId` + stateChanged/focusAddress 定向推送（:33-48）是 dragHover 推送的现成模式；store 守卫按窗口模式分流（`src/renderer/src/stores/browser.ts:66-78`）与 `windowIdentity`（:45-57，独立窗口含自身 windowId）是拖拽态守卫的同构底座；TabStrip/Toolbar 主窗与独立窗共用，拖拽手势天然双形态生效。
- **平台事实（think-report 8.3 已核实）**：HTML5 dragover/drop 不跨窗口送达另一窗口的 DOM，跨窗命中只能主进程做——轮询 `screen.getCursorScreenPoint()`（约 16ms，仅拖拽期间）对全部同会话窗口 bounds 命中；dragend 触发依赖 dragstart 时对 document 注册 dragover preventDefault（社区通行技巧）；`getCursorScreenPoint` 与 `BrowserWindow.getBounds()` 同为 DIP 屏幕系，混合 DPI 下比较自洽；dragend 跨平台（macOS/Windows）行为属 Chromium 实现细节需实测——本机 macOS，Windows 为 build:win 目标平台、本环境无 Windows 机器。
- **合成输入限制（历阶段同口径）**：真实鼠标拖拽无法经 CDP 合成（阶段 4 起多次记录鼠标合成不可靠），本机亦无 cliclick 等合成鼠标工具；自动化路径 = CDP dispatchEvent 合成 DragEvent（Chromium 支持 `new DataTransfer()` 构造）驱动 renderer handler 全链 + `window.api` 直调主进程通道（阶段 7—8 步骤 3 冒烟先例）；真实手势（HTML5 drag 自然触发、窗外释放、Escape 取消）转人工清单。
- **审查遗留衔接（清单 20260912234627）**：L1/L2/L3/L5 已提前闭环；L4（registry 815 行职责增厚）维持观察——本阶段新增编排全部落独立 `dragging.ts`，registry 只增薄接口（getActiveSessionId / moveTabToWindow / tearOffTab 落点参数），不加深；是否拆分留阶段 10 视增长裁决。
- **流程硬约束**：一切运行时验证走 `MSB_USER_DATA` 隔离目录（`src/main/index.ts:22-39`，阶段 4 数据事故后强制）；拖拽视觉属既有界面视觉改动，走 impeccable scoped 路径（AGENTS.md）；阶段收尾走 code-review 技能。

## 2. 范围边界

### 2.1 本阶段必须完成

- renderer 拖拽手势：Tab 项 draggable、dragstart/dragend 处理（dragstart 时对 document 注册 dragover preventDefault 保 dragend 触发，dragend 后移除）、落点屏幕坐标上报（不读 dropEffect——冒烟定案，见契约点 2 修订注）。
- 主进程拖拽会话控制器 `src/main/browser/dragging.ts`：dragStart 开光标轮询（约 16ms，仅拖拽期存在）、同会话窗口命中、悬停变化经通道推送、单活动拖拽会话约束、60 秒过期兜底（防 dragend 丢失致轮询常驻）。
- 释放裁决四态：`stayed`（源窗上释放——含 Escape 取消——或会话/Tab 已失效）/ `moved-new-window`（空白处→落点附近建新窗）/ `moved-window`（并入同会话既有窗口，追加为末位 Tab 并激活，无双 view 叠加）/ `rejected`（异会话窗口或主窗激活会话不符，源 Tab 原位不丢）。
- manager 增 `moveTabToWindow` 原语（与 tearOffTab 同构、activate 收尾）；windows.ts 增 `listForSession` + 建窗落点参数 + 最近聚焦序；registry 增薄接口。
- 通道集变更：退役 `browser:tear-off-tab` IPC 面，新增 `browser:tab-drag-start` / `browser:tab-drag-end` / `browser:tab-drag-hover`（15 → 17 条）；preload 同步。
- 移除 TabStrip 临时右键菜单与 overlay 登记块（v2 定案 1：触发方式只做拖拽；ui store 的 overlayDepth 机制保留，SessionPanel 仍在用）。
- 拖拽视觉（impeccable scoped 路径定稿）：源 Tab 半透明、同会话窗口悬停高亮、拒绝回弹——chrome-\* 灰阶语义，琥珀不进右侧（DESIGN.md 色域纪律）。
- DESIGN.md（独立窗口条目补拖拽手势 + Not Yet 更新）、`src/shared/browser.ts` 头注释指向、`book/notes/summary/2026-11/legacy-process.md` 阶段 9 行、验收文档落盘。

### 2.2 本阶段明确不做

- 插入位置指示与目标 Tab 栏内精确定位（并入恒为末位追加并激活）+ 拖拽态视觉 impeccable 终稿——阶段 10（step-10 第 4 行）。
- 退出落盘归并（独立窗口中的 Tab 退出时按 URL 归并主窗口 session 列表）与重启不恢复独立窗口的收口强化（PRD 3.6.4 / 验收 17）——阶段 10；过渡期事实不变：独立窗口 Tab 退出不落盘、重启不恢复，如实接受不造假象。
- 多选批量拖（v2 定案 1：一次拖拽只移一个 Tab）；右键菜单入口的任何回归——用户定案不做；若 Windows dragend 实测不可靠，按 think-report 3.5 对冲条款与用户复议是否补菜单，不擅自加。
- 拖拽转移到异会话的任何宽容路径（一律拒绝，无确认弹窗、无跨会话转移）。
- registry L4 职责拆分（维持观察，阶段 10 视增长裁决）。
- PRD 验收 17 与 12—17 的总验收口径——归阶段 10 逐条收口（本阶段只对 14 与 12 的拖拽入口回归负责）。

### 2.3 本阶段数据原则

- 拖拽态是瞬态 UI 状态：不落盘、不进 `BrowserSnapshot`、不参与持久化上报（persistence 口径零变更，仍只绑 'main' 作用域快照）。
- 转移是 webContents 原样迁移：滚动/输入/登录态/分区/DevTools 绑定全保留；任何"重开同 URL"的伪迁移形态禁止（think-report 2.3 方案 B 否决先例）。
- 拒绝与取消零副作用：源 Tab 原位不丢、无双窗状态变化；裁决结果如实返回 renderer（五态不吞错、不静默降级）。
- 悬停推送只发同会话窗口（异会话窗口收不到任何拖拽推送）；悬停候选不含源窗口（源窗上方无高亮，释放即 stayed）。
- 落点定位失败（屏幕外/工作区外）回退默认位置建窗，不阻断 tear-off 主流程。

## 3. 开始编码前的契约核对

本阶段涉及共享契约和基准文档的以下变更，必须在编码前冻结并同步（依据 `AGENTS.md`：实现与设计文档冲突时先改文档；`src/shared/browser.ts:2-3` 头注释同款义务——修改前先修订本节）：

1. **通道集变更（15 → 17 条：命令 14 + 推送 3）**：退役 `browser:tear-off-tab`（v2 定案 1 拖拽替换入口后 renderer 无调用方；tear-off 编排不下沉消失——`registry.tearOffTab` 保留为主进程内部接口，dragging.ts 空白裁决复用。此为对阶段 7—8 计划"通道语义保留"表述的精确化：保留的是编排语义，IPC 暴露面随入口退役，消除死攻击面）；新增命令 `browser:tab-drag-start` / `browser:tab-drag-end` 与推送 `browser:tab-drag-hover`。需同步：`src/shared/browser.ts`、`src/preload/index.ts` + `index.d.ts`、`src/main/browser/ipc.ts`（注册日志 17 条）。
2. **payload 与返回值冻结**：`TabDragStartPayload = { id: string }`；`TabDragEndPayload = { id: string; screenX: number; screenY: number }`（**修订（步骤 1 冒烟定案 2026-09-13）**：不含 canceled 字段——两轮 CDP 探针实证合成路径下 `dropEffect`/`effectAllowed` setter 完全无效（监听器内外设置均读回 'none'）；真实路径分析中窗外空白释放、异窗释放、Escape 三者 dropEffect 同为 'none'（源窗文档的 dragover preventDefault 只覆盖自身），dropEffect 无法区分取消与释放。定案：一律坐标裁决——Escape 在源窗上方自然落 `stayed`，Escape 于空白处按释放处理建新窗，属 HTML5 拖拽通行代价的已知边界，DESIGN.md 与验收文档如实记录）；`TabDragHoverPayload = { sessionId: string; tabId: string; hoverWindowId: string | null }`（主进程→同会话全部窗口广播，各窗口与自身 windowId 比对画高亮；hoverWindowId 为 null 表示无悬停/拖拽结束清态）；`TabDragOutcome = 'moved-new-window' | 'moved-window' | 'stayed' | 'rejected'`（dragEnd handler 返回值，源 renderer 据此清态与触发回弹）。需同步：`src/shared/browser.ts`。
3. **拖拽会话语义冻结**：全局单活动拖拽会话（后到 dragStart 先广播清态再接管，告警日志）；命中集 = 该会话全部独立窗口 + 主窗口（仅当主窗激活会话 = 拖拽会话，PRD 3.6.2），排除 isMinimized 与已销毁窗口，多窗 bounds 重叠取最近聚焦者（windows.ts 维护聚焦序）；悬停候选 = 命中集减源窗口；裁决点 = dragEnd 上报坐标（合成 DragEvent 测试可控、macOS 冒烟验证），仅 (0,0) 陈旧形态（Windows 窗外释放坐标缺失的已知取值）径用最后一次轮询光标；**不以"零命中"作坐标无效判据（波次 3 检查点定案 2026-09-13）**——轮询点滞后最多一帧，快速甩出窗缘释放时轮询点仍可能落在源窗内，"零命中即改用轮询点复检"会把合法空白拖出误裁成 stayed；非 (0,0) 的平台坐标缺陷形态留 Windows 实测裁决，不为投机兜底牺牲正常路径；裁决点零命中即空白建窗；60 秒无 dragEnd 自动过期清态（广播 hoverWindowId: null + 告警）；dragEnd 对未知/已失效会话返回 'stayed'；dragEnd 时全量重验（Tab 仍在源窗、会话 manager 仍在注册表），失效即 'stayed' 不抛错。他应用窗口遮挡我方窗口属已知边界（Electron 无 z 序 API），如实记录不做原生探测。需同步：`src/shared/browser.ts` 头注释（语义摘要 + 指向本节）。
4. **入口替换**：TabStrip 右键菜单与 overlay 登记块整块退役，拖拽手势成为唯一 tear-off 入口；`TearOffTabPayload` 随 IPC 面一并移除，registry.tearOffTab 增可选落点参数 `{ x?, y? }`（内部接口，clamp 到目标屏工作区）。需同步：`src/shared/browser.ts` 注释、`TabStrip.tsx`。
5. **DESIGN.md**：收尾步骤统一同步（独立窗口条目补拖拽手势段：入口替换、五态裁决、视觉 token；Not Yet 章节改写为阶段 9 后有效——插入指示/退出归并留阶段 10）——编码期以本节为准，DESIGN.md 不阻塞编码。

完成标志：`src/shared/browser.ts` 与 `src/preload/index.{ts,d.ts}` 落笔后 `npm run typecheck` 0 错误（ipc/store/TabStrip 的消费缺口允许在步骤 2 内同步退役补齐——本阶段无跨步骤占位）；`grep -rn "tab-drag" src/` 仅命中 shared 常量与 preload 引用；`grep -rn "tear-off-tab" src/` 零命中（IPC 面退役干净，registry 内部编排不涉通道字符串）。
