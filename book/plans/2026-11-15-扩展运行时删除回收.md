# 扩展运行时删除回收

分级：L。触及 Session 分区、删除事务、扩展 IPC 与 webContents 生命周期。分支 `plan/extension-lifecycle-and-proxy`，基线 dev@6e47219。用户现已授权执行；当前完成设计并进入 Phase 3。

## Step 0

背景：用户要求验证是否需要处理。两轮真实应用均确认：A 元数据和目录已删，但 mounted/engine 残留，再安装新插件会对 A 加载并重新建立目录，见[实测报告](../notes/learn/2026-11/2026-11-15-扩展回收与代理兼容实测.md)。

目标体验：用户永久删除会话后，该会话插件停止且不再参与安装/升级/重挂载；其他会话、全局安装包和正常关窗/克隆不受误清理。失败不能反馈为已彻底删除。

范围：extensions/dev-entry、runtime/index/loader、shims/bridge、management，browser/registry、index/sessions 删除编排与必要类型、固定依赖补丁及诊断工具。按设计确定资源所有者后收窄文件，不借机重构其他模块。

排除：代理兼容实现、改变普通关闭语义、删除全局安装包、依赖大版本升级、会话 schema 泛化、界面重设计与正式发布。本轮不读取真实用户分区、不推 main。

数据/权限：仅永久删除的目标分区进入终止态，身份取主进程可信对象。永久失效会话不可再 fromPartition 以探测状态，不接受 renderer 自报路径。录制/采集先安全停止，再清会话；失败和超时保持可见。

## Phase 1：分析已取得的证据

- src/main/extensions/dev-entry.ts mounted、runtime/index.ts engines 只有登记，未提供删除协议；management.remountAll 枚举已删对象。
- registry.destroySession 删除分区却未撤销扩展挂载；当前 sessions.delete 先更新元数据、onDeleted 异步发起销毁，需核对失败回执与删除承诺，不能只给 Map.delete 加一行。
- 生命周期事件 session-gone 同时在永久删除和普通关闭出现，不能直接以该事件无条件永久回收。
- 依赖库持有 Session WeakMap、router/observer 和 app/session 监听，没有完整公开 dispose；需列清资源后定策略，禁止在不了解依赖状态时尝试同 Session 重构引擎。

## Phase 2：设计门禁与拟定接口

按资源所有权确定永久删除协议，拟定 terminatePartition(partition, session) 异步接口和分区 generation/终止屏障：先封锁新 mount/消息/采集，再取消或排空 pending mount；在 load、copy、清单回写等 await 后核对有效性；清 owned popup/offscreen/桥/token/监听、卸载扩展并移除宿主登记，最后才清分区目录。

remountAll 和安装清单结果只处理存活分区；永久删除后不因晚到的 copy/load/recordPartition 重新登记。全局包不删，目标分区副本按实际卸载完成后清理。普通关闭/克隆临时静默另走可恢复路径。

库资源需做一张建立/所有者/退出清单。若无法通过公开 API 完整停止资源，选择可复现的固定版本 dispose 补丁或保留封闭的终止对象；后一种必须明示残留边界，不声称“全部内存已释放”。不得只删除 Map 后重新构造同 Session。

删除成功回执与元数据提交、目录删除顺序需在设计中统一：故障前后都不得让分区重挂载，清理失败能被调用方获知；不静默吞错。具体回滚或保留待清理状态在编码前定稿。新模态/文案如确有需要复用原生反馈与 i18n，不新增 renderer Modal/toast。

## 实施步骤（设计门禁通过后）

1. 固化资源清单与永久删除/暂时关闭语义，必要时写 ADR；确定销毁故障/重试与调用方反馈。
2. 实现终止屏障、在途任务复验和异步回收，接入删除编排；management/清单写入不再触达终止分区。
3. 隔离应用完成正常、故障与竞态矩阵，回归插件与更新保存守卫。
4. Phase 5 按十一项清单正式审查，新问题先记录再独立修复；Phase 6 写回 issue/任务/计划/经验并刷新索引。

## Phase 4 验收门禁

- 删除 A 后再装、升级、卸载插件：A 不在 mounted/engine/分区清单有效登记中，未加载新插件，目录不会重建；B 功能正常，全局安装包保留。
- 人为阻塞 copy/load/recordPartition，在删除前后释放：晚到任务无重新登记、无新目录、无未处理拒绝。
- A 有 popup、offscreen、录制及在途 IPC 时删除：安全结束/拒绝，无目标错绑；资源监听与桥按清单退出。
- 关闭普通窗、切会话、克隆临时静默不触发永久终止；重启、冷缓存、双窗及不同分区同插件回归。
- 卸载/清盘/排空失败或超时：不伪报成功，不解开永久屏障，不循环重建分区；明确重试策略。
- node tools/browser-environment/{unit,initialization}.mjs、更新定向回归和 R1、typecheck/lint/build 通过；Mac 实测，Windows 未测单列。

## 执行设计定稿（2026-11-15）

资源清单：宿主 mounted、engines、pending、SW shim 监听/handler、offscreen/pending target、协议桥 target、原生已加载扩展、固定 preload、分区结果和副本。永久删除先同步 tombstone（分区字符串与 Session 弱引用），mounted 同步摘除；runtime 拒绝新 mount/resolve，在途 mount 全部排空后卸载扩展、注销 preload/SW shim，清宿主 engine/分区结果与副本。全局包保留。库内部 WeakMap/observer 无公开 disposer，本轮保留终止 Session 的不可重用状态，不承诺释放全部库内部内存；不加入未经验证的私有 dispose 补丁。

registry 注入 terminateExtensions，仅永久 destroy 调用；目标页面、popup/offscreen 及桥按分区结束，普通 close/clone 不触发 tombstone。终止超时保持屏障，不清盘不解封，重复 destroy 可继续清理。清理异常上抛；sessions 删除返回等待 onDeleted/onBatchDeleted 的 Promise，只有清理结束才返回 ok。元数据已提交删除时不恢复一个已终止会话；异常通过原生错误框和 invoke 拒绝如实告知残留，内部终止屏障保持，可再次清理。安装快照的旧分区调用亦被屏障拒绝。

实施补充：元数据提交前先验证录制空闲并排空/终止扩展，忙碌或排空失败保留原会话列表与网页数据；若此后 JSON 提交失败，插件终止态保持到重启，不伪造完全可用。元数据提交后的清盘失败仍如实回执/原生提示，不把终止会话恢复为可重挂载状态。
