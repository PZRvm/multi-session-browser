# 历史建议图标缓存

分级：L。触及会话网络分区和缓存生命周期。分支：`feature/history-favicon`。

## Step 0

背景：刚启动点击地址栏，历史建议大量显示灰圆点。当前只保存 favicon URL，由默认 Session 的弹窗重新加载；Chrome 导入记录没有 favicon URL。

范围：历史建议图标的获取、会话缓存、弹窗展示与删除/临时关闭时的取消。排除：Tab 栏图标、历史排序、Chrome 图标数据库导入、地址栏交互、代理策略和版本发布。

要求：列表立即显示；优先读本地缓存，再通过对应会话请求已记录图标，失败尝试站点 `/favicon.ico`；无地址的旧历史也可补取。加载中及最终失败均显示 `SearchOutlined`，图片恢复后替换。同会话共享缓存，异会话不共享。

边界：主进程从真实历史查出候选地址，不信任 renderer 提交的图标；只请求 HTTP(S)，不使用第三方 favicon 服务。下载限时、限体积、并发去重；失败短暂冷却。缓存为可丢弃派生数据，独立于历史 schema；删除会话封闭并排空请求，临时关闭取消请求后允许重建。无新增权限弹窗或结果提示。

## Phase 1：分析

已确认链路：manager 的 page-favicon-updated → history 存 URL → renderer 历史镜像 → suggest-show → 原生子窗 img。子窗使用默认分区，且失败状态不随 src 重置。

影响文件：新增 main/browser/historyIcons.ts；registry 接缓存生命周期和会话 fetch；ipc 在可信作用域加载真实历史；omniboxSuggest 窗口池异步更新图标并拒绝旧请求；OmniboxSuggestPanel 与局部 CSS 改搜索兜底。风险：默认分区误用、陈旧异步结果串会话、缓存无限增长、删除后回写、反复 hover 触发网络。

## Phase 2：设计

列表先推送空图标；窗口池为每次 show 保留数据身份，只给当前可见的同一份数据回填。主进程用 sender 解析会话，在真实历史中匹配 URL；图标服务按会话和候选 URL 去重。缓存存于对应分区目录内的 History Favicons，每会话至多 128 项；单图最多 256 KiB（初版 64 KiB，后续按[上限修正计划](2026-11-16-历史图标体积上限修正.md)调整），4 路并发，每次下载最多 4 秒，失败冷却 60 秒，缓存 7 天后尝试刷新、失败仍可用旧缓存。候选顺序：历史 favicon、页面 origin/favicon.ico；允许有体积限制的 image data URL。缓存不改变历史数据及共享 IPC 字段。

图片数据使用 data URL 通过现有 payload 传入子窗；子窗不再请求远程图标。按常见图片文件签名识别，兼容错误 MIME，拒绝 HTML。图片解码失败显示搜索图标；组件 key 包含 src，保证新图标可恢复。界面保持现有 16px 图标槽和行布局，搜索图标使用 chrome-ink-dim。impeccable polish：局部缺失/错误状态修复。
