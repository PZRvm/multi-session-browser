# DevTools 窗口记忆与脚本清理

分级 L：独立 UI 偏好持久化及会话销毁边界。沿用 `fix/devtools-undocked-device-mode`，基线 `3ae8f0f`。当前 Phase 6，本机交付完成。

## Step 0

背景：用户要求关闭上轮审查的窗口几何记忆待办，并明确删除已验收的历史图标与 DevTools 回归脚本。

范围：浮动工具窗口按来源 Session 记忆正常位置与尺寸，关闭重开及应用重启后恢复；原显示器移除时裁剪到可用工作区。删除两份指定脚本，把 build 恢复为 typecheck 加 electron-vite build。

排除：不改设备模拟、面板、会话跟随策略、应用版本、共享 IPC 或 sessions.json；不删除其他 scripts，不推送或合并。Windows/Linux 与物理键盘验收仍不得冒充已完成。

边界：坏 JSON、未知版本、非法矩形、无磁盘 Session 回退默认或内存；写失败不影响工具使用。最大化/最小化/全屏不污染正常矩形。并发写最后状态为准，退出等待已有写；永久删除会话时先停止并等完写入，禁止目录被迟到写重建。

## 分析与设计

`devtoolsWindowState.ts` 按 Session 弱引用缓存状态，独立文件置于该 Session.storagePath 下，格式 `{version:1,bounds:{x,y,width,height}}`。首次创建工具时同步读微型文件，移动/缩放只更新内存并合并异步原子写，沿用 atomicWriteJson。恢复时按匹配显示器 workArea 同时约束位置和大小。

`devtools.ts` 在原生窗口 move/resize 和关闭前保存 getNormalBounds，建立窗口时读取恢复值。registry 的报告 flush 同时等待 UI 偏好写；销毁 Session 先 retire 状态并等在途写。没有新增页面权限、桥或弹窗。

Phase 4 的真实删除夹具复现工具 WC 先销毁时视图 getter 为空，导致清理中断。修复范围补入缓存工具与设备子页的 WC 对象，关闭/迟到消息按 isDestroyed 判断；它直接支撑本轮删除封笔与窗口回收边界，不扩展面板能力。

验证在临时目录运行，覆盖重开/重启、不同 Session、不合法文件、屏幕移除、小工作区、并发与删除；真实隔离 Electron 核验恢复。用户验收后的两份脚本从仓库删除，历史报告保留当时证据，当前 ADR/骨架/报告注明已退役。
