## 2. 范围边界

### 2.1 本阶段必须完成

- **每会话独立分区的 TabManager**：`createTabManager` 参数化为 `{ sessionId, partition }`，partition 一律 `persist:sess-<id>`（AGENTS.md 领域规则，一会话一分区禁止共享）；新增主进程注册表 `src/main/browser/registry.ts` 管理全部会话级 manager 的生命周期。
- **点击会话右侧切换**：`sessions:set-active` 在主进程内原子触发浏览器切换（注册表摘旧挂新，视图级瞬时交换）；旧会话全部 webContents 保活（Tab、滚动、输入、登录态、DevTools 实例与抽屉态原样保留）。
- **切回无数据丢失**：会话间往返，Tab 列表、页面状态、DevTools 开关态完整保留（PRD 4.2）。
- **多账号同时在线互不踢线**：分区级 Cookie/存储隔离（PRD 4.1、验收标准 1），用例验证。
- **会话状态灯真实驱动**：主进程按"该会话任一 Tab loading"聚合状态，经新增推送通道同步 renderer；全量 map 推送 + 拉取通道兜底启动竞态。
- **pageTitle / lastUrl 持久化驱动**：激活 Tab 标题与 URL 变化 → 去抖写盘（schema version 2，`StoredSession.lastUrl`）；重启后首次激活该会话时自动重载上次打开页（PRD 3.1.4、验收标准 4）。
- **删除会话清分区数据**：销毁该会话全部 webContents → `clearStorageData()` → 删除 `userData/Partitions/sess-<id>` 目录；失败如实告警不静默。
- **零会话空态与入口禁用**：无会话时右侧呈现 Chrome 灰阶空态、浏览器命令全部守卫拒绝（「未选择会话」），renderer 控件禁用；空态设计按 AGENTS.md 走 impeccable 流程。
- **契约扩展与文档同步**：shared 两文件 + preload 两文件扩展；DESIGN.md（Not Yet 改写、空态条目、状态灯已驱动）、process.md 同步；`book/notes/summary/` 验收文档落盘；code-review 收尾。

### 2.2 本阶段明确不做

- **克隆会话、批量操作**（批量关闭/批量开 URL）：阶段 5（`book/docs/requirements/stages/step-05`）
- **会话拖出独立窗口**：阶段 6（`book/docs/requirements/stages/step-06`）
- **Tab 列表全量持久化**：重启只恢复每会话"上次打开页"单值（PRD 3.1.4 字面语义）；多 Tab 结构、历史栈跨重启保留留待后续阶段按需评估
- **后台会话懒销毁 / 内存上限策略**：一期定案 keep-alive（理由：瞬时切换与状态保真是 PRD 硬验收，懒销毁丢输入态与滚动位）；验收时记录实测内存，若发现不可接受记 process.md 留阶段 5+ 裁决
- **persist:browse 历史分区数据迁移或清理**：阶段 2/3 开发期遗留的本地数据，不属产品行为，不写任何迁移代码（开发者手动删 userData 即可）
- **Playwright**（AGENTS.md 坑点：会话隔离由 Electron 原生 partition 承担，勿引入）
- **二期功能**（截图/弱网/UA/独立代理/数据可视化/日志）：`book/docs/requirements/stages/step-09`
- **测试框架引入**——沿用 typecheck + lint + 手动验证

### 2.3 本阶段数据原则

- **隔离真源只有一个**：partition。一会话一分区（`persist:sess-<id>`），禁止任何形式的共享、复用或跨会话挂载；DevTools 随所在 Tab 的 webContents 走，天然随会话隔离（阶段 3 架构零返工兑现）。
- **状态不造假**：会话灯只由真实加载事件驱动（任一 Tab loading → 加载中）；pageTitle/lastUrl 只由真实导航与标题事件驱动；后台会话的真实状态如实推送，不因"看不见"而伪造 idle。
- **删除即彻底**：确认框承诺"全部本地数据不可恢复"——分区存储与目录必须真实清除；清除失败 console.warn 如实呈现，不静默降级。
- **快照防串台**：BrowserSnapshot 带 sessionId，renderer 丢弃与当前选中会话不符的过期快照；切换在主进程串行执行。
- **空态诚实**：无会话时右侧如实呈现空态，不保留任何"无主浏览器"假象（不出现无分区可归属的页面）。
- 界面文案纯中文（本阶段新增：空态文案、守卫错误「未选择会话」、空态 aria-label）。

## 5. 分步实施

### 步骤 1：多分区隔离与分区数据清除冒烟

## 7. 建议询问 Agent 的方式与次数

### 7.1 分组建议

| 用途 | Agent 类型 | 建议时机 | 并行数量 | 次数 |
| ---- | ---------- | -------- | -------- | ---- |
| 调研 | Explore（只读） | 仅当执行中发现代码与本计划基线不符 | 1 个 | 备用 1 次 |
| 实现 | general-purpose | 波次 3（步骤 3、4） | 2 个并行 | 1 轮 2 次 |

全阶段询问总次数上限：**6 次**（备用调研 1 + 实现 ≤4 + 审查 1，正常路径 5 次）。控制原因：本阶段文件面约 14 个文件，仅波次 3/4 的并行收益确定（文件零交集的大块）；过多并行会互相踩文件、合并冲突反而更慢。允许主会话亲自做小步骤，不为凑并行开 agent。实现类 agent 返回后由主会话亲自跑 `npm run typecheck` / `npm run lint`，不信任 agent 自述。

### 7.2 每次询问的约定

- prompt 必须自包含：引用本计划文件路径 + 具体步骤编号 + 该步骤"验收"标准原文 + 只允许触碰的文件范围（按第 4 节目录树标注）+ 禁止清单（范围外文件、禁用 BrowserView、禁碰契约文件与既有通道语义、一会话一分区红线、禁琥珀/box-shadow）；执行侧按 `subagent-execute-plan/assets/subagent-prompt-template.md` 组装
- 步骤 4 的空态设计子项：主会话先走 impeccable 技能产出设计约束稿，随 prompt 一并交给实现 agent（或主会话亲自实现该子项）；agent 不得绕过设计稿自创视觉

## 10. 主要风险与控制

| 风险 | 控制方式 |
| -------- | -------- |
| 多会话保活导致内存/进程数膨胀（每 webContents 一个渲染进程） | 一期定案 keep-alive（2.2 记录理由与回退条件）；步骤 7 用例 A/F 记录 5+ 会话实测内存；不可接受则记 process.md 留阶段 5+ 裁决懒销毁策略 |
| 切换瞬间 bounds 空窗/错位（新 manager 无缓存矩形） | 注册表全局 bounds 缓存 + setBounds 广播全部 manager + 新 manager 以缓存为 initialBounds；切换用缓存矩形即时挂入（步骤 3 任务 5） |
| 过期快照串台（快速连续切换时旧会话推送晚到） | BrowserSnapshot.sessionId + renderer applySnapshot 守卫丢弃不符快照；主进程切换串行（步骤 3/4） |
| 状态推送竞态（启动激活早于 renderer 订阅） | 全量 map 推送 + 先订阅后拉取（getStatuses 兜底），模式复用 browser store init 已验证方案（步骤 4 任务 2） |
| 分区清除不彻底或时序错误（webContents 存活时清除被覆写回盘） | 步骤 1 冒烟专门定序（销毁 → clearStorageData → fs.rm → 重启复查）；registry.destroySession 按结论实现；失败 console.warn 不静默（步骤 3 任务 3） |
| pageTitle/lastUrl 写盘频率过高（每次导航/标题事件触发全量 JSON 重写） | 仅值变化 + 约 500ms trailing 去抖 + 既有 mutateSnapshot 串行队列（步骤 3 任务 7） |
| schema v1→v2 迁移伤及既有数据 | 迁移只补 `lastUrl: ''`，其余校验/回退/去重逻辑零改动；步骤 5 验收用手写 v1 文件实测读出（含坏数据回退仍成立） |
| macOS 关窗重开 / resize 与会话切换交叠 | registry.attachToWindow 路由激活 manager；resize 经 setBounds 广播全 manager；用例 F 覆盖 |
| 范围蔓延（克隆/批量/独立窗口/Tab 全量持久化/懒销毁） | 2.2 明确不做清单 + 契约点显式声明 + code-review"作用域外改动"项拦截 |
