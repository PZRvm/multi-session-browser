# 阶段 10 开发计划：跨窗口转移与生命周期收尾（独立窗口五）

> 创建时间：2026-09-13 20:01:09（Asia/Shanghai）  
> 需求来源：`book/docs/requirements/stages/step-10-独立窗口五-跨窗口转移与生命周期收尾.md`（调研依据：PRD 3.6.4 / 4.5 / 验收 12—17；阶段 9 计划 2.2 对插入定位与退出归并的阶段 10 移交；阶段 9 计划第 1 节对 registry 拆分的阶段 10 裁决授权）  
> 执行模式：波次  
> 实施范围：独立窗口特性收官——① 拖入升级为插入位精确定位（悬停推送携带窗内光标坐标 + 目标窗上报插入位 + moveTabToWindow 按位插入，替换阶段 9 的「恒末位追加」）；② 退出落盘归并（任一作用域快照变化即重算「主窗在先 + 独立窗创建序」的归并 Tab 列表落盘，重启全部 Tab 回主窗恢复，独立窗不恢复）；③ 拖拽态视觉插入指示器走 impeccable 定稿，其余三态复核。不做：重启恢复独立窗口、页面运行态还原、多选批量拖、registry 拆分、Windows 平台实测（环境受限转人工）  
> 目标结果：拖 Tab 悬停同会话窗口时，目标窗 Tab 条出现 Chrome 式插入指示竖线并按光标位置实时移动，释放后 Tab 落在指示位（无上报回退末位）；任一时刻退出应用（含直接关窗、Cmd+Q），各会话散在独立窗口中的 Tab 全部按 URL 与顺序归并入该会话落盘 Tab 列表，重启后全部在主窗口对应会话下恢复且不重建独立窗口；用户主动关闭独立窗口仍销毁其 Tab 不归并（PRD 3.6.3）；PRD 验收 12—17 逐条对号通过  
> 当前进度：步骤 1—5 均未开始

## 1. 当前基线

- **跨窗口转移链主体已在阶段 9 交付**：主窗⇄独立窗双向、独立窗互转、异会话拒绝回弹、源窗转移空后自动关窗（集成真鼠标 11/11，验收文档 book/notes/summary/20260913023538-…/）。**缺口 = 并入恒末位**：`registry.moveTabToWindow`（`src/main/browser/registry.ts:748-765`）与 `manager.moveTabToWindow`（`src/main/browser/manager.ts:427-461`，activate 收尾）均无插入位参数；`TabDragOutcome` 注释明写「'moved-window'：并入同会话既有窗口（追加末位并激活）」（`src/shared/browser.ts:131-132`）；无任何插入指示 UI。
- **退出落盘只绑 'main' 作用域（本阶段核心缺口）**：`persistence.ts` 头注释「阶段 7—8 起接线只传入该会话 'main' 作用域快照——独立窗口 Tab 不参与落盘（过渡期事实，归并收口在阶段 10）」（`src/main/browser/persistence.ts:32-34`）；接线在 registry 的 manager.onSnapshotChanged（`registry.ts:348-350`：`if (snapshot.windowId === WINDOW_ID_MAIN) persistence.recordSnapshot(id, snapshot)`）。后果：独立窗口中的 Tab 退出不落盘、重启丢失——DESIGN.md:293 与 Not Yet（:341）已如实标注为过渡期行为。PRD 3.6.4 / 验收 17 要求归并恢复。
- **退出与关会话的时序口径（归并后必须翻转，见契约点 4）**：before-quit 先 `independentWindows.closeAll()` 再 `registry.flushPendingReports()`（`src/main/index.ts:294-298`），注释明确「上报只绑 'main' 作用域快照……关窗级联发出的非 main 快照不触发上报」——归并后该前提失效，先关窗会让级联清空触发归并收缩、冲刷写出缩水列表。closeSession 同构：先 `windows.closeAllForSession(id)`（`registry.ts:506`）后 `persistence.settleSession(id)`（`registry.ts:514`），克隆（close-then-copy）经此入口。
- **可复用的枚举与序信息**：windows.ts `listForSession`（`src/main/browser/windows.ts:210-214`，登记表 Map 迭代 = 创建序）与 `getFocusSeq`（:220-222，**主窗口不在登记表、序恒 0**——归并激活位不能依赖聚焦序）；manager `buildSnapshot(windowId)` 按窗口作用域过滤（`manager.ts:174-207`），`scopedTabIds(windowId)` = tabs Map（创建序）过滤序——**按位插入需 Map 重排（delete + 重新 set，直接 set 既有键不移动位序）**。
- **拖拽控制器现状**：`dragging.ts` 16ms 轮询 `pollOnce`（:303-318）驱动 `hoverWindowAt` 命中，`emitHover`（:98-105）载荷 `TabDragHoverPayload = { sessionId, tabId, hoverWindowId }` 无坐标信息；`DragSession`（:41-49）无插入位缓存；`adjudicateHit`（:230-240）调注入的 moveTabToWindow。悬停推送桥接按会话窗口全集定向发送（`src/main/browser/ipc.ts:98-105`）。
- **renderer 拖拽态现状**：指针捕获手势终版 + 跟随虚影 + 三态视觉（源半透明 / 整栏高亮 `drag-target` / 拒绝回弹）已在阶段 9 交付（`TabStrip.tsx:264-275`、`app.css` chrome-tab 系 token）；store 悬停推送归一化为「本窗口 id 或 null」（`src/renderer/src/stores/browser.ts:118-133`），无光标坐标、无被拖 Tab id 镜像（目标窗不知道拖的是谁）、无插入位字段。拖拽瞬态不进快照守卫链、不落盘（`stores/browser.ts:20-26`）。
- **契约面**：BROWSER_CHANNELS 17 条（14 命令 + 3 推送，`shared/browser.ts:21-39`）；头注释（:1-16）指向阶段 9 计划第 3 节——本计划第 3 节即下一份修订记录；ipc.ts 注册日志「17 条通道」（`ipc.ts:298`）；preload browser 15 方法 + 3 订阅（`src/preload/index.d.ts`）。落盘 schema v3（tabs/activeTabIndex）无需升级——归并列表是 v3 字段的取值口径变化，非结构变化。
- **阶段 9 遗留与本阶段裁决授权**：L2（registry tearOffTab 与 moveTabToWindow 作用域校验前导重复约 10 行，`registry.ts:724-726/753-757`）维持观察——本阶段触及 moveTabToWindow 签名，顺手收敛（契约点 5）；L3（dragStart 失败静默回位，Chrome 惯例语义自洽）裁决维持不动；registry 858 行职责增厚「是否拆分留阶段 10 视增长裁决」（阶段 9 计划第 1 节）——本计划裁决：不拆分，归并组合逻辑落 persistence（数据域），registry 只改接线与透传（净增个位数行）。
- **验证管道事实（阶段 9 已实证）**：CDP Input 域可合成真鼠标事件驱动指针手势全链（11/11）；落盘断言可直读隔离目录 sessions.json；冷重启可验恢复；全部运行时验证走 `MSB_USER_DATA` 隔离目录（阶段 4 数据事故后的强制流程）。本机无 Windows 机器，平台差异代码级核对 + 转人工（历阶段同口径）。

## 2. 范围边界

### 2.1 本阶段必须完成

- 插入位精确定位全链：悬停推送携带悬停窗内容坐标光标位 → 目标窗 renderer 按 TabStrip 布局计算插入位（Chrome 式中点判定）→ 经新命令上报主进程缓存 → dragEnd 裁决 moved-window 时按位插入；无上报/陈旧回退末位追加（既有行为兜底）。
- 插入指示器视觉（impeccable scoped 路径定稿）：悬停目标窗 Tab 条的插入位置竖线指示，chrome-\* 灰阶语义、双主题成对 token、琥珀不进右侧；既有三态（半透明/高亮/回弹）按「终稿」口径复核一遍，发现的问题一并定稿。
- 退出落盘归并：落盘恢复集从「仅 main 作用域」升级为「该会话全部作用域归并视图」（主窗 Tab 在先 + 独立窗 Tab 按登记表创建序），任一作用域快照变化即触发重算与去抖落盘（崩溃安全）；lastUrl/pageTitle/激活位口径见契约点 4；before-quit 与 closeSession 的时序翻转与封笔。
- 重启恢复收口：重启后独立窗口不恢复（现状即如此，windows.ts 登记表纯内存），各会话全部 Tab（含退出时在独立窗口中的）按 URL 与顺序在主窗口对应会话下恢复（applyRestore 既有机制天然承接，验证即可）。
- 通道集变更：新增 `browser:tab-drag-insert` 命令（17 → 18 条，命令 15 + 推送 3）；`TabDragHoverPayload` 增可选坐标字段；preload 同步。
- registry L2 前导顺手收敛（改动面已触及两函数）；registry 拆分裁决落档（不拆，理由见基线）。
- PRD 验收 12—17 逐条对号验收（对号表落验收文档）；DESIGN.md（拖拽手势条目补插入定位与归并、Not Yet 改写为阶段 10 后有效、:293 过渡期注收口）、`book/docs/architecture/项目骨架.md`（ipc.ts 18 通道、persistence 职责行）、`book/notes/summary/2026-11/legacy-process.md` 阶段 10 行、`src/shared/browser.ts` 头注释指向同步；验收文档落盘。

### 2.2 本阶段明确不做

- 重启恢复独立窗口本身（PRD 3.6.4 明确「重启后不恢复独立窗口」——这是需求不是缺口）；页面运行态还原（滚动/输入/登录态随迁移保活，恢复仍是 URL 级，阶段 6 口径不变）。
- 多选批量拖（阶段 9 用户定案不做，不复议）；拖拽转移到异会话的任何宽容路径（一律拒绝不变）。
- registry 模块拆分（裁决不拆，见契约点 5；若后续阶段增厚再议）。
- Windows 平台实机验证（本环境无 Windows 机器；contentBounds/光标坐标同为 DIP 屏幕系做代码级核对，实测转人工标注——历阶段同口径）。
- 应用打包（step-11）与二期测试辅助功能（step-12）；PRD 12—17 之外的一切新功能。

### 2.3 本阶段数据原则

- 归并是 URL 级：只并 URL 与顺序、激活位，运行态不还原不伪造；归并列表如实反映「主窗 + 当前存活独立窗」的 Tab 全集——用户主动关掉的独立窗 Tab 从落盘收缩（PRD 3.6.3 关窗即销毁不回主窗，落盘如实跟随），不做「退出前偷偷抢救」。
- lastUrl === tabs[activeTabIndex].url 不变式延续（persistence 既有 L5 守卫前提）；激活位与 pageTitle/lastUrl 取主窗口作用域激活 Tab（与会话列表现势一致），主窗 0 Tab 时取归并列表首项。
- 插入位 hint 是尽力而为的瞬态：只存在于拖拽窗口期（随 dragStart 建、随收尾清），不落盘、不进 BrowserSnapshot；无 hint 或 hint 陈旧一律如实回退末位，不伪造精确落位。
- 拖拽瞬态继续不进快照守卫链、不参与持久化上报（阶段 9 原则零变更）。
- 拒绝与取消零副作用不变；归并收缩/扩张的每次落盘都有真实事件源（快照变化），禁止无事件刷盘。

## 3. 开始编码前的契约核对

2026-11-06 增量契约：`browser:merge-to-main` 无载荷 invoke 与 preload `browser.mergeToMain(): Promise<OkResult>`，仅独立窗口可信 sender；批量原语与主窗激活规则见 `book/plans/20261106131016-独立窗口合并回主窗口开发计划.md` §2.4。

本阶段涉及共享契约和基准文档的以下变更，必须在编码前冻结并同步（依据 `AGENTS.md`：实现与设计文档冲突时先改文档；`src/shared/browser.ts:2-3` 头注释同款义务——修改前先修订本节）：

1. **通道集变更（17 → 18 条：命令 15 + 推送 3）**：新增命令 `browser:tab-drag-insert`（dragInsert）。payload `TabDragInsertPayload = { tabId: string; index: number }`，返回 `OkResult`；语义 = 目标窗对当前悬停的插入位尽力上报（index 为目标窗作用域 Tab 序列的插入位，0 = 最左，tabs.length = 末位之后）。主进程守卫：结构垃圾按命令口径拒绝（tabId string + index 有限非负整数，复用 ipc 守卫件）；通过结构守卫后按「hint 口径」处理——sender 解析出的 windowId 须等于当前活动拖拽会话的悬停窗且 tabId 匹配，否则**静默忽略返回 ok**（hint 是尽力而为通道，陈旧属设计内常态，不是错误）。需同步：`src/shared/browser.ts`、`src/preload/index.ts` + `index.d.ts`、`src/main/browser/ipc.ts`（注册日志 18 条）。
2. **悬停推送载荷扩展（向后兼容）**：`TabDragHoverPayload` 增可选 `cursorX?: number; cursorY?: number`——光标在**悬停窗内容坐标系**的位置（`win.getContentBounds()` 原点起算的 DIP，与 renderer CSS px 同值；主进程在 emitHover 前对当前悬停窗计算，hoverWindowId 为 null 的推送不携带）。各窗口 renderer 守卫逻辑不变（仍比对 hoverWindowId/会话），仅悬停落点本窗消费坐标。需同步：`src/shared/browser.ts`。
   **修订（阶段 10 执行期定案 2026-09-13）**：① 悬停推送不再「仅窗口变化时广播」——同窗内光标位移超 2px 亦重发（`HOVER_CURSOR_EMIT_DELTA_PX`，指示器随光标实时更新，静止零流量；同窗重发不清 hint，last-known 优先于末位回退）；② `TabDragEndPayload` 增可选 `canceled?: true`（Esc 放回显式携带，主进程一律 stayed 清场）——执行期实例实证：Esc 的坐标假想点（源窗内 +100,+100）在源窗与独立窗**重叠**时同时命中他窗，坐标裁决把取消误判成并入（Tab 被搬走）；与阶段 9「不读 dropEffect」冒烟定案不冲突（那是推断不可靠，这是显式键盘信号）。
3. **moveTabToWindow 插入位参数（主进程内部接口）**：`manager.moveTabToWindow(id, sourceWindowId, targetWindowId, insertIndex?)`——insertIndex 按目标窗作用域 Tab 序列计，缺省 = 末位（既有行为兜底）；实现须重排 tabs Map（delete + 重新 set，直接 set 既有键不移动位序——坑点写进实现注释）。registry.moveTabToWindow 透传；dragging.adjudicateHit 传入缓存的 hint。`TabDragOutcome` 注释同步修订（'moved-window' 不再恒「追加末位」，改为「按指示位插入并激活，无指示位时末位」）。需同步：`src/shared/browser.ts`（注释）、`manager.ts`、`registry.ts`。
4. **归并落盘语义冻结（主进程内部数据契约，schema v3 零变更）**：
   - 组合视图 = 主窗口作用域 tabs（在先）+ 该会话各独立窗口作用域 tabs（按 windows.ts 登记表创建序）；触发点 = 该会话**任一**作用域快照变化（registry 接线从「仅 main」放开）与窗口销毁级联（级联本身发空快照，天然覆盖）。
   - 激活位与 pageTitle/lastUrl 口径：仍取主窗口作用域激活 Tab（会话列表现势同源）；主窗 0 Tab（Tab 全部拖出的合法态）时取归并列表首项，保住 lastUrl === tabs[activeTabIndex].url 不变式。
   - **before-quit 时序翻转 + 封笔**：改为先 `flushPendingReports()`（此刻独立窗全部存活，冲刷捕获完整归并集）后 `independentWindows.closeAll()`；flushPendingReports 语义升级为「冲刷后封笔」（sealed 标志，此后 recordSnapshot 不再安排任何写盘）——否则关窗级联的收缩重算会在 500ms 去抖内抢写缩水列表。
   - **closeSession 冲刷前置**：settleSession 移到 closeAllForSession **之前**（捕获关窗前的完整归并集，克隆恢复集语义稳定为「克隆发起时刻的归并快照」）；关窗级联的后续收缩照常发生（源会话磁盘如实收缩——其独立窗 Tab 已销毁）。克隆目标的恢复集取 settle 时点 persistence 缓存值，不重读盘（执行时追踪 sessions.ts 克隆元数据路径接线，隔离用例实测）。
   - 需同步：`persistence.ts`（组合逻辑与 deps 改造）、`registry.ts`（接线）、`index.ts`（before-quit）、本计划第 5 节步骤 2。
5. **职责裁决与债务收敛**：归并组合逻辑落 persistence.ts（数据域单一出口），registry 仅注入枚举 dep（`listSessionSnapshots(id)`：该会话全部作用域快照，主窗在先、独立窗创建序）+ 改接线一行 + moveTabToWindow 透传——registry 不拆分（858 行维持，本阶段净增个位数行，裁决理由：编排职责未变，增厚的是 persistence 数据职责）；L2 前导重复顺手收敛（抽取共享的作用域解析前导，改动面已触及）；L3 维持观察不动。DESIGN.md / `book/docs/architecture/项目骨架.md` / process.md / shared 头注释收尾统一同步（编码期以本节为准，DESIGN.md 不阻塞编码）。
6. **页内查找通道扩展（修订 2026-09-14，通道 20 → 24：命令 18 + 推送 6；计划 book/plans/20260914162746-会话网页内查找开发计划.md 2.4 节）**：
   - 新增命令 `browser:find-start`（findStart）：payload `FindStartPayload = { text: string; forward?: boolean; findNext?: boolean }`，返回 `OkResult`；语义 = 对来源窗口作用域激活 Tab 的 webContents 调 `findInPage`（text 非空且 ≤ 200 字符守卫；forward 缺省 true、findNext 缺省 false——初搜传 findNext=true 自顶部起新会话，Enter/Shift+Enter 步进传 findNext=false 沿 forward 换向，Electron findInPage 官方语义）。
   - 新增命令 `browser:find-stop`（findStop）：payload `FindStopPayload = { action?: 'clearSelection' | 'keepSelection' }`（缺省 clearSelection），返回 `OkResult`；语义 = `stopFindInPage` 清高亮后对目标 webContents `focus()`——关栏焦点归还页面（Chrome 对齐）。
   - 新增推送 `browser:find-request`（findRequest）：无 payload；语义 = 页面聚焦态 Cmd/Ctrl+F 经 manager before-input-event 吞键后唤起来源窗口 shell 查找栏（focus-address 同构定向推送，registry 接线含会话归属守卫）。

## 10. 主要风险与控制

| 风险 | 控制方式 |
| -------- | -------- |
| before-quit 先关窗后冲刷：级联清空触发归并收缩、冲刷写出缩水列表（独立窗 Tab 退出丢失——正是本阶段要修的缺陷换形态复发） | 契约点 4 时序翻转（先冲刷后关窗）+ 冲刷后封笔（sealed）；步骤 2 冒烟⑦与步骤 4 套件⑦双实测 |
| 克隆（closeSession）窗口期归并竞态：settle 与关窗级联的收缩重写赛跑，克隆恢复集不确定 | settle 前置到关窗前 + 克隆恢复集取 settle 时点缓存不重读盘（契约点 4）；步骤 4 套件⑥实测对照 |
| tabs Map 重排坑：直接 set 既有键不移动位序，按位插入静默失效 | 契约点 3 写明 delete + 重新 set；步骤 2 冒烟②按位断言（0/中/末位）+ 其他窗口作用域顺序不扰动 |
| 插入 hint 陈旧/错窗：悬停切换后旧 hint 误用、异窗上报污染 | 悬停变化即清 hint + ipc 层 sender 窗 = 当前悬停窗强校验（不匹配静默忽略）+ 末位回退；步骤 4 用例② |
| 归并后恢复集膨胀：多窗多 Tab 重启全量 URL 恢复变慢 | URL 级恢复是既有口径（阶段 6），量级与会话 Tab 总数同阶；如实记录不改架构；若实测明显劣化留观察项 |
| renderer 指示器随 16ms 推送抖动/刷 IPC | store 只存最新坐标、上报仅 index 变化时发（计数断言）；指示器 DOM 单元素位移，不重排 Tab 列表 |
| 归并接线放开引入高频重算/写盘 | 去抖判据（tabsKey 指纹）沿用，无变化不写盘；组合成本 O(tabs) 与既有 buildSnapshot 同阶；步骤 2 冒烟③观察写盘频率 |
| 时序翻转破坏既有退出/克隆回归 | 步骤 4 复跑阶段 5 克隆用例 + 阶段 6/9 退出恢复用例；L5 不变式断言进套件 |
| Windows 平台 contentBounds/坐标形态未实测 | 代码级核对（同为 DIP 屏幕系）+ 环境受限转人工标注（历阶段同口径） |
| 契约未冻结即并行开工 | 波次红线（6.4）；步骤 2/3 发起以步骤 1 验收为前置 |
