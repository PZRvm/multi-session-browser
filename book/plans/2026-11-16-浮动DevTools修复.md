# 浮动 DevTools 修复

分级 L：涉及设备视图与 webContents 生命周期。分支 `fix/devtools-undocked-device-mode`，基于 dev `6c45905`。当前阶段：Phase 6，本机交付完成；平台验收与审查遗留单独记录。

## Step 0

背景：[排查报告](../notes/summary/2026-11/2026-11-16-浮动DevTools排查.md)确认原生浮动设备辅助页没有创建，按钮亮起但模拟未启用；DevTools 打开链接的专门事件也未接线。用户授权新分支修复。

范围：主进程浏览器域 DevTools 接入、原生设备辅助宿主、链接打开与必要的回归脚本。用户点击设备按钮后应看到原生设备工具栏，修改设备尺寸/UA/触摸应作用于该调试目标；资源链接应在原会话的窗口中打开新 Tab。

排除：不重写 DevTools 面板，不引入远程浏览器，不改变会话分区、共享 IPC 或持久化格式，不升级未验证的引擎版本，不重建被测页面，不改版本号或发布。R3 浮动窗是否自动跟随激活会话的产品策略不在本轮改变。

边界：只接收 Electron 内置设备辅助页；不允许任意网页伪装为设备宿主。来源页在等待期间关闭、重复开关、Dock side 往返、切 Tab/会话、跨窗口、应用退出都需避免遗留视图和迟到回调。权限不扩至页面；无新增渲染层提示或模态框。

## Phase 1：分析

- 项目入口：`src/main/browser/manager.ts` 的打开/关闭、激活/摘除和页面销毁路径；链接必须以来源 Tab 的 `windowId` 为准。
- 引擎路径：AdvancedApp 浮动设备 UI 需要 `device_mode_emulation_frame.html`；先用隔离实例验证公开 Electron 窗口/视图 API 能否承载，避免直接依赖私有前端对象。
- 风险：原生 DevTools 的 delegate 与普通页面不同；辅助页需要 opener 关联和 inspected-page bounds 布局；额外普通 BrowserWindow 可能不能正确呈现被测页面；不能仅让工具栏显示就判成功。

## Phase 2：设计

按两个可独立验证的工作包推进。

R1：用户已明确允许宿主兼容适配，官方面板保持原样。公开 `setDevToolsWebContents()` 自定义宿主能创建设备辅助页；安全 preload 在 DOMContentLoaded 时转发原生 `setInspectedPageBounds`、`setIsDocked` 和窗口动作，不加载私有前端模块、不重写面板。DevTools 视图停靠时与页面共享原浏览区，浮动时挂独立原生 BaseWindow；设备辅助页经严格白名单 `createWindow` 创建为原浏览区的 WebContentsView，页面置于其上并按原生 bounds 定位。全部使用来源会话的 Session。

文件：新增 `src/main/browser/devtools.ts` 和 `src/preload/devtoolsPreload.ts`，在 electron-vite preload 多入口登记；manager 的挂摘、布局与开关委托给兼容宿主，registry 通过 manager 摘除完整组合视图。关闭工具、所属 Tab、窗口、注销均清理两个辅助 webContents 与浮动窗口；原生关闭和 F12 都走同一关闭回调。新 IPC 只在专用 preload 与对应 DevTools webContents 的 `ipc-message` 间使用，校验主 frame、页面 URL、消息闭集和有限整数 bounds，不进入应用共享 API。用户看不到新的自绘面板。初始化失败以原生对话框反馈并恢复页面布局。

R2：独立完成链接事件。`manager.ts` 接收来源页面的 `devtools-open-url`，校验 URL 白名单、页面存活、窗口存活、更新准备和 manager 注销状态，向来源 manager/窗口新建 Tab。`registry.ts` 注入窗口是否仍属于当前会话的只读判断；后台 A 会话新 Tab 保留在 A，不能盖住前台 B 的 view。新的 Tab 激活通知经 registry 注入的回调沿现有生命周期订阅发送，覆盖录屏自动停止。无新 IPC、权限或反馈弹窗。脚本打包真实 manager 并用 Electron 事件夹具验证来源归属、拒绝路径和后台视图；另用真实隔离实例复验。
