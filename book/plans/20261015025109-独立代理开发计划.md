# 独立代理 开发计划（二期·单会话独立配置代理 IP）

## 2. 范围边界

### 2.1 本阶段必须完成

- 会话元数据增可空字段 `proxy`（协议 http/socks5 闭集 + host + 端口 1—65535 + 可选账号密码），落盘 schema v4→v5，v4 读取缺失静默补 null、类型错置 null 告警，写盘恒出 v5。
- `sessions:set-proxy`（保存/清除，null = 清除回直连，清除为合法语义对齐 set-note）与 `sessions:check-proxy`（按草稿值探测出口 IP，不经保存）两通道 + preload 两方法。
- 主进程代理引擎：分区首航前 `setProxy` 应用（proxyRules 映射 http→`host:port`、socks5→`socks5://host:port`，映射单源）、中途变更 `closeAllConnections` 收尾、切换/新建/克隆/重启恢复四路径 await、`app.on('login')` 代理认证反查供给凭据、克隆携带 proxy。
- 原生 sheet 新 kind `session-proxy`：协议/地址/端口/账号/密码表单 + 预填现值 + 检测按钮（三态文案：连不上代理/认证失败/探测失败）+ 保存/清除/取消。
- 会话行菜单「代理设置…」入口 + 行内「代理」徽标（仅已配置时渲染，Tooltip 显协议 host:port）。
- i18n 三语键族；PRD 3.5/4.11 扩围/新增 4.14 独立代理规则/验收 40；DESIGN、骨架、PRODUCT、README、process 同步；验收文档落盘。

### 2.2 本阶段明确不做

- PAC 脚本、auto_detect/WPAD、system 模式（ProxyConfig 余下三 mode）——二期范围按 PRD 3.5 即「单会话配置单独代理 IP」。
- 自定义 bypass 规则（Chromium 对 localhost/链路本地已有隐式旁路；内网测试环境诉求出现时另立增量）。
- WebRTC 真实 IP 防泄露策略（多 IP 测试的高级对抗场景，后续按需）。
- UA 自定义（二期另一列项，另行专项立项）。
- 改代理后自动刷新页面（对齐 Chrome 惯例：代理变更不重载，避免丢表单态；「生效确认」由检测按钮与刷新后的页面自行承担，PRD 4.14 写明）。
- 会话列表之外的位置显示代理态（独立窗口不渲染会话面板，无需另做）。

### 2.3 本阶段数据原则

- 探测结果如实呈现：检测返回什么显示什么，不伪造「代理生效」；超时/失败按真实原因分类文案。
- 账号密码明文落盘 `sessions.json`（与该文件本就承载的登录态数据同机同权），不做伪加密；PRD 4.14 如实声明存储位置，界面不宣称安全隔离。
- 代理配置是会话元数据，不触碰分区数据；删除会话连带清除（沿用整条删除链，无独立清理面）。
- 检测地址用常量单源，步骤 2 冒烟实测定稿（候选 `https://ip.3322.net` 纯文本 / `https://api.ip.sb/ip`，以国内网络实测可达为准），禁止散落字面量。

- **波次 1（串行先行）**：步骤 1。理由：五个文件（shared 两处 + store + preload 双件 + i18n 三语 + PRD）是其余步骤的共同地基，且 store v5 迁移必须先于步骤 2 的 handler 落盘路径。

### 6.3 并行门槛

波次 2 逐项自查：三个步骤的文件集合两两不相交（唯一共享点 i18n 键族已在波次 1 冻结，波内零写入）；三步均含实现 + 自验，预计各 ≥30 分钟。达门槛，开三路并行。波次 1、3 为单步骤串行，无并行对象。

- 步骤 1 必须独占先行：preload/index.d.ts 与 dialog.ts 被波次 2 全部三路消费，冻结前开工必然互相踩类型。

| 改代理后「看似未生效」（keep-alive 残留 + 不自动刷新） | 变更时 closeAllConnections 收尾；PRD 4.14 写明不自动刷新语义，检测按钮承担确认 |
