# 插件宿主兼容开发计划（会话1：宿主与安装）

分级L：涉及Session/WebContentsView生命周期、特权IPC、安装持久化与生产入口装配，命中always-L。本计划由独立会话执行，会话内只做宿主兼容线，不实现两个插件本体（会话2范围）。

## Step 0（结构化需求简报）

| 项目 | 约定 |
| --- | --- |
| 背景 | 前置验证macOS全量实证完成，协议v1已冻结（2026-11-10）；用户决策宿主功能与双插件拆两个会话并行开发，本会话承担宿主兼容线 |
| 使用者与场景 | 用户在本项目宿主内安装官方/自研插件、管理生命周期；会话2的截图/录屏插件以本线为宿主接入点 |
| 需求输入 | [协议v1](../docs/api/插件宿主协议草案.md)、前置验证工具与固定样本、前置审阅三项遗留（幂等复验/settle迁移/token生产化绑定） |
| 影响范围 | src/main/extensions下的runtime与install、src/main/index.ts、registry/manager、shared、preload、i18n、正式入口UI |
| 排除项 | 截图/录屏插件本体与会话2的编辑器复用改造、SwitchyOmega代理兼容层、商店公开发布、Windows实机（挂起） |
| 数据和权限 | 生产接入用正式Session；宿主生成不可预测target token并绑定扩展ID/窗口/Session/Tab/有效期；不降低sandbox |
| 成功与失败 | 以preflight工具回归与新增生产检查验收；契约变更必须与会话2同步后才能合入 |
| 回收与退出 | 证据与总结归book；固定样本与验证工具保留 |

## Phase 1 影响与风险

- 与会话2的接口只有协议v1与集成里程碑；不得替会话2实现插件逻辑，不碰 extensions/screenshot 与 extensions/recorder。
- 生产settle迁移（src/main/browser/recording/index.ts:161，现于落盘前推idle）在E接线时执行，改动前与会话2确认录屏状态机依赖。
- shared与preload是共享装配面，由本会话独占修改；编辑器复用改造目录由会话2独占，本会话不改。
- 引入electron-chrome-extensions与electron-chrome-web-store进正式依赖时，锁定版本与MIT许可记录进ADR/依赖说明。
- 审阅遗留三项在本线收敛：幂等/冲突复验与token绑定随E，settle迁移随D/E边界确认。

## Phase 2 设计（里程碑）

| 里程碑 | 内容 | 对会话2的意义 |
| --- | --- | --- |
| M1 | A：持久分区unpacked加载+action桥最小可用；B：unpacked/CRX验签安装与全局清单骨架 | 开放宿主端到端接入点 |
| M2 | A：完整生命周期（DevTools、多分区、导航/重载）；B：商店安装事务、升级/卸载、失败保留旧包 | 插件可走真实安装路径 |
| M3 | E：index.ts集中接线、preload/shared桥、i18n、正式入口UI；settle迁移；真实IPC幂等/冲突复验；token生产化绑定 | 插件正式入口可用 |
| M4 | preflight回归、根typecheck/lint/build、验收报告 | 双端共同验收；Windows恢复后补测 |

## 与会话2的协同

- 共享契约：协议v1（frozen）。任何字段/语义/错误码变更必须同步协议文件、check-protocol、check-schema与真实IPC夹具，并通知会话2；未同步的偏离不得合入。
- 文件边界：本会话独占src/main/extensions、src/main/index.ts、shared、preload、i18n；不碰extensions/{screenshot,recorder}与编辑器复用改造。
- 集成点：M1交付最小宿主后会话2做端到端；M3接线含插件正式入口。
- 建议本会话使用独立worktree/分支（从当前分支切出），合并顺序与会话2协调，避免同工作区并行写。
