# 双插件图标与编辑窗口修复

后续用户验收更正：顶部条确指系统标题栏，运行环境是普通 Chrome；本计划中 popup 无标签栏不代表去系统标题栏已完成。PiP/浮动已按用户要求删除，[后续调研与实施计划](2026-11-11-截图插件移除浮动与标题栏调研.md)为当前状态；该原生窗形需求仍受 Chrome API 限制，见[未满足项](../notes/issue/2026-11/20261111175817-Chrome截图窗标题栏限制与浮动移除审查.md)。以下保留本轮当时记录。

分级 L：跨截图、录屏两条功能线，修改共享编辑组件的显示适配。沿用当前 worktree，不修改宿主协议。

## Step 0

- 背景：用户反馈插件没有专属图标、截图编辑预览模糊、标题区位置不合适、录屏提示撑大或被弹窗裁切。
- 范围：`extensions/`、共享 `EditorWindow` 的可选缩放参数、插件检查脚本。
- 排除：宿主插件安装/运行时、媒体编码管线、会话隔离、IPC、原应用窗口形态、商店发布。
- 需求：每插件两张图标（彩色标识、工具栏线形图标）；预览在缩放后重绘且导出尺寸不变；无页内 Tab 栏，红绿灯在工具区上方；录屏提示浮在原生窗口层，显隐不改变面板布局且不被裁切。
- 边界：Chrome popup 保留系统窗口装饰；PiP 仍由页内手势进入、opener 保活。初始比例按来源 Tab 的 CSS 宽度与截图像素宽度计算，超出窗口滚动查看；缩放限制为初始比例的 0.25–4 倍，普通滚轮继续滚动。
- 权限与通知：不新增权限；动作结果沿用原行为；tooltip 使用浏览器原生 title，避免 DOM 浮层受窗口裁切。
- 建议采用：图标保持矢量源与确定性 PNG 派生；共享组件默认不开启滚轮缩放，原应用行为保持。

## Phase 1：影响与风险

现实现以 CSS zoom 放大 Konva 位图，无法补回重绘分辨率；PiP 生命周期脚本还重复维护缩放。编辑页继承 Electron 隐藏标题栏 query，造成工具行空白让位；PiP 三灯又插在工具行。录屏的绝对定位伪元素虽不在普通流内，却扩大 popup 可滚动边界，从而触发 Chrome 自动尺寸变化。

风险：缩放后标注坐标、文本与裁剪浮层必须使用同一比例；续编不能重置缩放；PiP 必须传递本窗快照和初始比例；浏览器 title 的延迟和位置由系统决定。

## Phase 2：设计

- 图标：各插件 `icons/icon.svg` 彩色标识、`icons/action.svg` 线形图标，派生 16/32/48/128 PNG，由 manifest 接入。几何图标直接 SVG 绘制，不使用位图生成替代矢量源。
- 编辑器：`EditorWindow` 接受可选 `initialScale`、`wheelZoom`；插件启用 Ctrl/⌘+滚轮调整 Stage scale，删除两处 CSS zoom 与相应观察器。普通应用沿用 query 和原缩放行为。
- 标题区：常规编辑页不带 Electron 的 hidden-titlebar query；PiP 灯组在独立顶行，工具区从左对齐，不出现页内 Tab 栏。PiP 通过 root dataset 接收 captureId/scale，避免回退到全局最新快照。
- 录屏：伪元素 tooltip 改为原生 title；保留 aria-label。无需额外窗口或权限，也不以预留空白伪造悬浮。
- 文件：两个 manifest、图标资源和生成脚本、截图 background/entry/lifecycle/theme、recorder popup、共享 EditorWindow、插件真机检查、相关 book 记录。

## 验证与完成条件

1. 构建插件；typecheck、lint、生产 build 全绿。
2. Chrome 独立 profile：图标可解码、popup 类型/工具区位置、PiP 灯组上下位置、明暗主题、DPR 与实际 canvas 分辨率。
3. Ctrl/⌘滚轮会增加 canvas 像素尺寸，普通滚轮不缩放；放大后绘制/撤销/裁剪/文本仍可用，复制与下载保留原图像素。
4. 录屏提示无伪元素内容和额外 scroll extent，原生 title 完整；录制/暂停/继续/音频与 MP4 回归沿用现有检查。
5. 审查只记录；更新此 Todo、父计划、简短总结与索引。Windows、宿主端到端未执行时如实保留待测。
