## 2. 范围边界

### 2.1 本阶段必须完成

**Step 0 需求简报（M）。** 背景：测试人员需要更少击键重访地址，并在指定引擎直接检索。影响范围为主窗和独立窗共用地址栏、renderer 内匹配/编辑规则、三语字典及对应产品文档。体验结果为：输入前缀看见选中的补全后缀，未精确命中引擎时 Tab 接受；输入完整引擎入口后 Tab 优先出现搜索标签，继续输入并 Enter 搜索；其他普通 Tab 留在输入框插一个 U+0009。空历史、空关键词、无激活会话、非法导航和会话切换都应有确定行为。明确排除见 §2.2，边界和失败处理见 §2.3—2.4。

交付项：

- 历史行内后缀补全与既有下拉并存；保留至少 2 字符门槛，只用当前会话历史，不把标题命中或 URL 中段命中直接当行内补全。
- 九家引擎：百度、必应、Google、DuckDuckGo、Brave Search、Ecosia、Yahoo、搜狗、360；域名、明确别名和模板采用已确认调研表，不加入单字母捷径或泛域名匹配。
- 统一 Tab/Enter/右方向键/删除/Esc/失焦语义，处理选择范围、IME、撤销、重复按键和切换作用域。
- 搜索标签置于 input 外的同一地址栏容器，保留 28px 高、原有融合外框和完整锚点；用当前 Chrome 区主题 token。标签窄窗可截断，关键词输入区域仍可见、可编辑，读屏可感知所选引擎。
- 三语文案覆盖简中/繁中/英文。失败沿用地址栏行内无效状态，不新增 toast、Modal 或引导段落。
- 实施证据、手动验收、审查记录及 book 写回；具体完成标准纳入步骤 4，不能以“代码已写”代替阶段完成。

### 2.2 本阶段明确不做

不新增默认引擎普通文字搜索、联网关键词联想、OpenSearch 自动发现、自定义引擎设置、Chrome 搜索配置导入、历史管理页；不改变 Cookie/partition/代理、历史 schema、跨窗口 Tab 转移和网页内 Tab 行为。不重写原生建议子窗、全局 ARIA 架构或通用 URL 解析，不更换编辑器，不引入依赖。输入框图标不是独立交付项，必要时仅复用现有图标资源。

### 2.3 本阶段数据原则

- 历史与最终页面事实由主进程持有；renderer 仅持当前会话镜像与临时编辑状态。搜索最终仍走来源窗口当前会话的 navigate，不单独调用全局 fetch，不共享登录态。
- 原始输入、展示后缀、补全完整目标和搜索词分开。匹配不使用追加后的展示值；提交不从去 scheme/www 的字符串反推完整 URL，保留路径大小写、query 与已编码字符。
- 新状态属于窗口实例内 `(sessionId, activeTabId)`，切会话/Tab、失焦或卸载即清理；输入法组合中不追加补全、不切搜索模式、不提交。晚到候选/导航响应不得回写新作用域。
- 没有历史不伪造补全；引擎模式空关键词 Enter 不导航；零会话/无 Tab 延续原禁用态；网络失败与网站验证码如实呈现，不宣称搜索成功。
- 普通导航首尾空白沿用 trim；中间真实 U+0009 阻止提交并走既有行内无效提示，已编码 `%09` 不拦截。搜索关键词中的 U+0009 作为参数值编码，不能静默删除或转空格。
- 权限：不新增权限和 sender 规则；通知：不新增完成提示，导航错误保留现有反馈。无数据迁移；引擎表为只读配置，无缓存失效或写盘事务。竞态沿用作用域和导航回执守卫，新增选区恢复也必须复核作用域与输入版本。

### 2.4 交互与接口核对（Phase 1/2 输出）

用户最新反馈要求完整引擎输入优先于历史补全；按原始 draft 判断全部引擎，以下表为当前执行依据。

| 当前状态 | 普通 Tab | Enter |
| --- | --- | --- |
| IME 组合输入中 | 不改组合文本或切模式；先验证候选处理后焦点仍留地址栏 | 仅确认候选，不提交 |
| 导航模式，原始输入精确命中引擎入口（含有历史后缀） | 优先进入引擎模式，显示标签，关键词置空，不导航 | 沿用普通访问与历史建议选择，不自动切搜索 |
| 导航模式，原始输入未命中引擎，有待接受的行内补全 | 接受补全，光标到末尾，不导航、不插字符 | 有可见明确高亮行则访问该行，否则访问当前行内完整目标 |
| 导航模式，无待接受补全，也无引擎入口 | 在光标或用户选区插入 U+0009 | 有可见明确高亮行则访问该行，否则提交输入；含中间 Tab 时阻止提交 |
| 引擎模式 | 在关键词光标/选区插入 U+0009 | 非空关键词构造结果页并搜索；空词保持模式 |

示例：已有 `https://www.baidu.com/` 历史，输入 `bai` → `bai[du.com]` → Tab 接受为 `baidu.com` → 再 Tab 进入“搜索 百度” → 输入 `接口测试` → Enter 打开结果页。若无历史，直接输入 `baidu.com` 后一次 Tab 即进入搜索。`b` 没有明确补全目标时不猜引擎，Tab 插字符。补全接受后解除 pending-completion 标志，避免下一次 Tab 又接受相同后缀。

其他按键和事件：

- 右方向键可接受行内补全；普通 caret 移动/中间编辑不抢光标。Backspace/Delete 先移除自动后缀并抑制立即补回，删除、粘贴、组合输入及用户主动选区时不自动追加；下一次正常尾部输入再评估。
- 引擎模式关键词为空时 Backspace 退出，恢复进入前已接受草稿。Esc 在引擎模式先退出；导航模式首按取消补全并收下拉、保留原始输入，再按恢复真实 URL。
- Shift+Tab 保留反向焦点退出；Ctrl/Meta/Alt 修饰快捷键不被普通 Tab 处理吞掉。按键 repeat 每个事件只执行当前状态的一次动作，不在单个事件里先接受又入搜索。
- 精确匹配解析后的 hostname/明确别名；根 URL 仅允许 http/https、无凭据、无非默认端口、根路径且无 query/hash。伪装后缀域名、带路径测试地址、带参数地址不触发引擎；Google 地区域名未经配置不自动支持。
- 搜索模式关闭普通历史建议，保证 Enter 只提交搜索词。构造 URL 仅编码参数值一次；`& + # %` 和中文不能增加额外参数或被双重编码。

数据流：输入事件 → renderer 本地候选/引擎判定 → 编辑状态与选区 → 既有原生建议展示；Enter → 补全完整目标或编码后的搜索 URL → 既有 `submitUrl` → store.navigate → preload → 主进程当前会话 Tab → 导航快照与历史采集。无新增 IPC。

建议文件范围：

| 文件 | 处理 |
| --- | --- |
| `src/renderer/src/components/browser/omniboxSuggest.ts` | 复用既有排序，增加前缀候选到显示选区/真实目标的安全映射；不更换排序权重 |
| `src/renderer/src/components/browser/searchEngines.ts`（新增） | renderer 本地类型、九家引擎常量、精确匹配与 URL 构造；不导入 shared 传输类型 |
| `src/renderer/src/components/browser/Toolbar.tsx` | 编辑状态、键盘入口、composition 与 selection 生命周期、搜索标签和提交分流；只抽取该功能必需逻辑，不泛化为新编辑器 |
| `src/renderer/src/assets/app.css` | 地址栏容器与标签局部样式，保持原生下拉锚点与融合态 |
| `src/shared/i18n/locales/{zh-CN,en-US,zh-TW}/browser.ts` | 搜索标签与无障碍名称；仅字典键，不改变共享 IPC/业务类型 |
| `book/docs/requirements/PRD.md`、`PRODUCT.md`、`DESIGN.md` | PRD 新交互、产品能力与局部设计事实同步，不改写历史阶段文档 |
| `book/docs/architecture/项目骨架.md` | 新增文件职责与地址栏数据流的相关条目同步，不顺手重写其遗留章节 |

renderer 内部类型可定义候选 `{displayText, selectionStart, selectionEnd, targetUrl}` 与引擎 `{id, hosts, aliases, labelKey, buildSearchUrl}`，不要扩大到三进程共用接口。原生子窗无需显示引擎候选，`OmniboxSuggestItemPayload`、共享通道、preload 签名保持现状。

### 2.5 反馈轮：完整引擎输入优先（2026-11-06）

分级 M，延续当前地址栏任务。Step 0：用户输入完整 `bing.com` 后，历史可能自动追加路径，Tab 仍必须一次进入搜索；覆盖全部九家引擎及现有域名/别名。范围仅 Toolbar 的按键分流与相应需求/验收记录，不修复前轮原生撤销菜单或无关 CSS 问题，不改 IPC、持久化和视觉样式。

Phase 1：当前 Tab 分支先接受 completion，导致完整引擎输入仍被历史后缀截获。Phase 2：用原始 draft 先调用既有 matchSearchEngine，精确命中则进入搜索；未命中再接受补全；最后插制表符。输入 `bi` 或非引擎仍沿用原行为，绝不从自动展示的 URL 猜测用户已输入完整引擎。搜索模式内 Tab 插字符不变。

验收：先复现带历史路径的 bing.com 冲突，再验证九家引擎逐字输入完整域名/别名/根 URL 时一按 Tab 进入正确引擎，部分前缀仍补全、伪装域名/带路径地址不误触发。typecheck/lint 通过，完成反馈差异审查并写回；前轮 open 审查保持 open。

## 3. 分步实施

### 步骤 1：冻结交互与验证编辑原语（Phase 1/2 门禁）

1. 复核基线与分支，在最新 dev 开功能分支；第一笔功能提交的 motive 写明 M 级、原因和验证方式。保留本次确认记录，不重新要求用户批准已经明确的范围。
2. 将 §2.4 写入 PRD 地址栏章节，并在 PRODUCT/DESIGN 局部引用；明确 Tab 接受补全、引擎入口与字符插入的先后，保留普通网址回车访问。按 impeccable 的现有 Operate 表面做 scoped shape，UI 编辑前加载 craft-floor，不开启新视觉世界流程。
3. 用开发态最小验证核实受控 input 的选区恢复、真实 U+0009、IME 与 Ctrl/Cmd+Z；记录如何区分自动选区与用户选区、输入版本与作用域。验证代码不作为额外正式功能落库。若技术上无法可靠保留撤销/IME，在此记录实证和受影响方案，不通过后续步骤掩盖。
4. 复核无需共享契约/主进程修改，冻结九家引擎表和 renderer 内部数据形状；若触及 L 级边界，先重分级、补门禁再继续。

验收：PRD 与计划按键表一致；`bai → Tab补全 → Tab引擎 → 关键词 → Enter` 与非引擎字符插入均有开发态验证记录；IME/选区/撤销有明确可行实现方式。无未决交互或数据形状冲突才进入 Phase 3；平台无法实测的项目标记未验证，不伪造通过。

### 步骤 2：实现本地补全与搜索规则（Phase 3，规则层）

1. 在 `omniboxSuggest.ts` 保留匹配排序，增加仅适用于安全连续前缀的行内候选推导；正确映射 scheme/www、原 URL 大小写和 query。子串/标题命中仍仅用于下拉。
2. 新增 `searchEngines.ts`，实现九家引擎配置、明确别名、根 URL 精确识别和一次性编码的结果页构造。仅使用浏览器标准 URL API，不 fetch、不读取 Node。
3. 为规则验证列出预期结果，使用仓库现有构建工具做临时断言或开发态核对并记录；不新增测试框架、不新增只镜像代码的永久测试。覆盖合法/伪装域名、2 字符门槛、保留原目标 URL、中文和特殊字符编码、真实 Tab 与 `%09`。
4. 同步项目骨架的新文件与职责表，防止新增源码而目录说明缺项。

验收：`npm run typecheck`、`npm run lint` 通过；规则样例结果可查：`baidu.com.evil.test`、`https://www.baidu.com/s?wd=x` 不触发引擎；`a&b+c#d%中文` 保持单一查询值；仅标题/中段命中不产生行内后缀，完整导航目标保留 scheme/path/query。骨架与新增文件一致。

### 步骤 3：接入编辑状态、键盘与标签（Phase 3，界面层）

1. 在共用 Toolbar 接入原始草稿、行内候选、已接受状态和引擎模式；候选检索保持 renderer 本地。用 composition、输入类型和选区事件区分输入、删除、粘贴、移动光标，按步骤 1 验证的方法恢复选区并维持撤销。
2. 将所有普通 Tab 决策放在同一入口，先用原始 draft 精确判断全部引擎，再处理补全/插字符，严格按 §2.4 一次处理一个动作；Enter 与 Esc/Backspace 分流。普通导航中间 Tab 拦截放在地址栏提交路径，不改通用 `normalizeInput`。搜索模式关闭历史下拉。
3. 选区恢复、异步提交和瞬态复位都带作用域/版本检查；在输入仍聚焦时切换会话或同名 Tab，也不残留补全文本、标签、候选、pending 或错误状态。保持原来的 canPresent 可见高亮提交规则。
4. 完成标签与三语文案，容器承载整条外框与融合几何，原生子窗锚点保持整框宽度。按 incumbent token 处理 focus/invalid/disabled/亮暗/窄窗；标签不进入输入复制文本，不写中文引导占位语。

验收：`npm run typecheck`、`npm run lint` 通过；`npm run dev` 在主窗和独立窗逐行验证 §2.4，Tab 不误导航或抢焦点，Enter 搜索无历史候选劫持；快速输入/删除/粘贴/选择/切会话不发生光标跳动或旧数据回填。280px 地址栏可用空间下标签截断而关键词仍可编辑，亮暗三语与面板融合无错位。

### 步骤 4：完整验证、审查与写回（Phase 4 → 5 → 6 顺序执行）
