## 1. 当前基线

- **执行模式判定说明**：虽为 6 步，但步骤间文件高度重叠（`shared/settings.ts`、preload 两文件、`main.tsx`、`app.css` 多步骤共写），不存在「两个以上互不相干的大块实现同时开工」的并行收益——主会话顺序直通执行，并行开销大于收益。
- **阶段一/二 + 侧栏双栏重构已合并 main（55008a0）**：设置窗侧栏双栏五版面全量静态渲染——外观三段受控只读（value 绑 appearance 镜像、无 onChange，`PaneGeneral.tsx`）、语言展示态选择框、主页纯本地输入（`PaneBrowsing.tsx`）、关于版本占位「—」+ 数据目录静态值「打开」（`PaneAbout.tsx`）、快捷键占位演示值 6 行（`PaneShortcuts.tsx`）。
- **外观域链路已全量存在且天然支持联动**：`src/shared/appearance.ts` 三通道（getState/setMode/changed）+ `src/main/appearance.ts` 控制器（setMode 落盘 preferences.json + nativeTheme.themeSource + syncSnapshot 对 `BrowserWindow.getAllWindows()` 逐窗广播 changed——设置窗创建后自动纳入广播）+ `src/renderer/src/stores/appearance.ts`（先订阅后拉取、setMode 以主进程快照为准、setting 串行队列防连点）。设置窗角色 `main.tsx` 已初始化该 store（阶段二兑现）。**外观对接只需给 Segmented 接 onChange，板头与设置窗双向同步零新增通道。**
- **设置域契约现状**：`src/shared/settings.ts` 仅 `SETTINGS_WINDOW_ROLE` + `SETTINGS_CHANNELS.open` + `OkResult`；preload settings 命名空间仅 `open()`。`settings.json` v1 空骨架（`src/main/settings.ts` 的 `StoredSettings` 仅 version；`loadSettings` 末尾「阶段二起此处改为按键构造完整对象」注释为首个真实键预留——本计划兑现）。
- **关于信息无任何通道**：版本三元组（`app.getVersion()` / `process.versions.electron` / `process.versions.chrome`）、数据目录路径（`app.getPath('userData')`）、打开目录动作（`shell.openPath`）全部只在主进程侧可得（renderer 禁 Node）。`settingsWindow.ts` 的 `registerSettingsIpc` 现仅一条 open 通道且 sender 白名单 = 主窗；`SettingsWindowController` 接口（open/dispose）未暴露设置窗引用——新通道 sender 判据需扩接口。
- **快捷键单源现状**：`src/shared/browserShortcuts.ts` 共 8 条键位（reload: r 与 F5 双键、new-tab: t、close-tab: w、focus-address: l、find: f、toggle-devtools: F12、close-devtools: Escape），修饰键语义（macOS meta / 其他平台 ctrl）由 `matchBrowserShortcut` 解释。`PaneShortcuts` 占位 6 行硬编码与单源无关联；键帽修饰键显示（⌘/Ctrl）需平台事实，renderer 无 `process`——经新通道带回 `platform` 单源派生（不自建 `navigator` 推断副本）。
- **主页按钮现状**：`src/renderer/src/components/browser/Toolbar.tsx` 硬编码 `onClick={() => navigate('about:blank')}`（disabled = 无激活 Tab）；`BLANK_URL = 'about:blank'` 是 manager 常量（新建 Tab 缺省地址）——即 PRD 3.8.2「留空维持既有默认起始页」的既有语义。Toolbar 为主窗与独立窗共用（BrowserFrame / IndependentWindowFrame 同构消费），对接一处双窗生效。
- **URL 规范化单源**：`src/main/browser/url.ts` 的 `normalizeInput`（scheme 白名单 http/https/file/about + 缺省补 https:// + `new URL` 解析失败返 null）——纯函数无 electron 依赖。「跨 IPC 边界的运行时守卫在 main 侧落实」是仓库纪律（骨架 3.5 节）：renderer 不自建第二套校验规则，行内红显由 invoke 拒绝驱动。
- **值域通道先例**：`src/main/appearance.ts` 是「存储 + 控制器 + IPC」同文件模式（getState/setMode 守卫 + changed 全窗推送，无 sender 白名单）；preload 订阅方法 `onChanged` 返回退订函数。设置值域通道对齐该模式。
- **renderer 角色初始化现状**：`main.tsx` 三分流——settings 角色（appearance 只读镜像）、omnibox-suggest 角色（纯渲染端，不初始化业务 store）、主窗/独立窗（主窗 `sessions.init` 完成后再 `browser.init` 的串行约束，独立窗只 `browser.init`）。主页偏好与快照守卫无耦合，settings 镜像 init 可与 browser.init 并行、不进该串行链。
- **DESIGN.md「设置窗口」条目（侧栏双栏定稿版）已载明四处「阶段三」注记**：外观行「受控只读（阶段三点亮）」、版本行「占位，真实值随阶段三接入」、键位表「占位演示值……阶段三对齐 browserShortcuts 键位表单源」、数据目录「静态值『打开』，阶段三点亮」——本计划兑现后逐处修订；主页行现为「可输入纯本地无行为（阶段四接入）」待改写为真实交互口径。
- **文档现状**：`book/docs/architecture/项目骨架.md` 已含设置域全部文件行（`stores/` 现为 4 store，无 settings store）；`book/notes/summary/2026-11/legacy-process.md` 阶段三、阶段四两行「未开始」。

### 2.3 本计划数据原则

- 版本三元组为 `process.versions` / `app.getVersion()` 真实值（dev 态 appVersion 即 package.json 的 1.0.0，如实显示不伪造）；数据目录为主进程 `userData` 真实路径（`MSB_USER_DATA` 隔离态随之指向隔离目录，验证断言以此为据）
- 键位速查单源派生自 `BROWSER_SHORTCUTS`，版面组件内不硬编码第二副本键位（中文文案映射与展示形状除外）
- `homepageUrl` 落盘值恒为规范化绝对 URL 或空串（原始输入不落盘）；非法输入零落盘零推送零 changed；主页按钮消费主进程快照的 renderer 镜像，不在 renderer 二次规范化
- open-data-dir 与 set-homepage 失败如实回传（中文提示），不静默吞错；读侧坏值回退告警如实输出（`[settings]` 前缀既有风格）
- 验证一律走 `MSB_USER_DATA` 隔离目录，落盘断言以隔离目录 `settings.json` 为据，截图为真实运行态

### 2.4 契约核对（编码前冻结）

1. **五通道一次冻结**：`SETTINGS_CHANNELS` 增 `get-app-info: 'settings:get-app-info'`、`open-data-dir: 'settings:open-data-dir'`、`get: 'settings:get'`、`changed: 'settings:changed'`、`set-homepage: 'settings:set-homepage'`；`SettingsAppInfo { appVersion: string; electronVersion: string; chromiumVersion: string; platform: 'darwin' | 'win32' | 'linux' }`（platform 用自持字面量联合而非 `NodeJS.ProcessPlatform`——shared 文件被 web 工程编译，Node 全局命名空间在 renderer 侧不可依赖，guards.ts 自持类型同风格；主进程 `process.platform` 赋值处类型自然兼容）；`SettingsSnapshot` 与 `SetHomepagePayload` 入 shared（renderer 消费的快照形状单源）。存储形状 `StoredSettings` 留在 `src/main/settings.ts`（主进程私有，与 sessions 域 StoredSession 同口径）。同步 `src/shared/settings.ts` 头注释阶段状态。
2. **白名单裁决**：`open-data-dir` 是唯一触发 OS 级外部动作的通道，sender 白名单 = 设置窗 webContents（经 `SettingsWindowController` 新增的 `getSettingsWindow()` 判据，closed 自清既有）；`get-app-info`（无害信息）与值域三通道不设 sender 白名单（对齐 appearance 域 getState/setMode/changed 全无白名单的先例，入参值守卫承担）。
3. **changed 订阅矩阵**：主窗 shell、独立窗 shell、设置窗订阅（各自 settings store init）；omnibox-suggest 角色不初始化不订阅；推送侧 `BrowserWindow.getAllWindows()` 全推（appearance 先例，子窗收到无消费无害）。
4. **返回值形状**：`set-homepage` 返回 `SettingsSnapshot`（对齐 setMode 返回快照先例，renderer 以主进程返回为准更新受控值）；`changed` 推送 `SettingsSnapshot`；`set-homepage` 守卫链（isRecord + string + trim 长度上限 2000 对齐 history URL 上限惯例 + `normalizeInput`：空串直存 `''`、非空规范化落盘、null 抛「无效的主页地址」）。
5. **基准文档**：DESIGN.md「设置窗口」条目四处「阶段三」注记兑现 + 浏览版面主页行交互口径改写（提交时机、规范化回填、错误态、空语义）。

完成标志：shared 契约 + preload 两文件三处对齐落盘且 `npm run typecheck` 通过；`grep` 五通道字符串仅存在于 shared 常量与 preload 消费点。
