# 截图与录屏插件开发计划（会话2：双插件）

分级L：涉及双端媒体采集、编辑器复用改造与特权桥消费，命中always-L。本计划由独立会话执行，会话内只做两个插件本体，不实现宿主运行时/安装管理（会话1范围）。

## Step 0（结构化需求简报）

| 项目 | 约定 |
| --- | --- |
| 背景 | 协议v1已冻结（2026-11-10）；用户决策两会话并行，本会话承担截图与录屏两个插件 |
| 使用者与场景 | 两个插件在普通Chrome与本项目宿主双端运行：截图带全套编辑器，录屏带当前Tab音频与独立audio开关 |
| 需求输入 | [协议v1](../docs/api/插件宿主协议草案.md)、前置编辑夹具与媒体夹具、生产编辑器组件 |
| 影响范围 | extensions下的screenshot与recorder目录、编辑器复用改造（captureEditor共享组件适配层） |
| 排除项 | 宿主运行时/安装管理（会话1）、代理兼容层、商店公开发布、Windows实机（挂起） |
| 数据和权限 | 插件只经协议v1桥请求宿主能力；不暴露任意文件路径读写或完整window.api |
| 成功与失败 | Chrome真机与前置夹具先行验收；宿主端到端待会话1的M1；契约变更必须与会话1同步 |
| 回收与退出 | 证据与总结归book；不删除原截图/录屏入口，原版插件样本不改 |

## Phase 1 影响与风险

- 端到端依赖会话1宿主M1；此前用普通Chrome真机与前置工具夹具验证，不阻塞开发。
- 编辑器复用改造由本会话独占；不改原截图/录屏入口行为，原版插件样本不修改。
- 录屏独立audio开关对应Chromium“Tab静音仍录入音轨”的语义，开关语义按前置结论实现。
- 生产settle迁移由会话1的E执行；本会话按协议v1的finalizing模型消费状态，不自行改生产index.ts。

## Phase 2 设计（里程碑）

| 线 | 内容 | 先行验证 | 里程碑 |
| --- | --- | --- | --- |
| C 截图插件 | manifest与结构、captureVisibleTab（Chrome）与宿主capture桥（Electron）、编辑器复用（getEditImage/editCopy/editDownload）、复制/下载 | 普通Chrome真机与前置编辑夹具 | M1 Chrome真机功能完成；M2 大图分块与宿主桥适配；M3 宿主端到端 |
| D 录屏插件 | tabCapture/offscreen/MediaRecorder（Chrome）、宿主采集器桥（Electron）、状态订阅/finalizing、暂停排除、独立audio开关、取消 | 前置媒体夹具 | M1 Chrome真机功能完成；M2 宿主桥适配；M3 宿主端到端 |

## 与会话1的协同

- 共享契约：协议v1（frozen）。任何字段/语义/错误码变更必须同步协议文件、check-protocol、check-schema与真实IPC夹具，并通知会话1。
- 文件边界：本会话独占extensions/{screenshot,recorder}与编辑器复用改造；不碰src/main/extensions、src/main/index.ts、shared、preload、i18n。
- 集成点：会话1 M1后接入宿主端到端；会话1 M3接线时插件正式入口可用。
- 建议本会话使用独立worktree/分支（从当前分支切出），合并顺序与会话1协调。
