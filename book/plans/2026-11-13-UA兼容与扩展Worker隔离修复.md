# 默认 UA 与扩展 Worker 隔离修复计划

任务分级：**L**。扩展 preload 注入、Service Worker sender 与会话隔离属于始终 L 的权限边界。首次提交的 motive 须记录此分级与原因。

当前阶段：Phase 2 设计草案；本次只准备工作区与计划，不进入实现。更新时间：2026-11-13（Asia/Shanghai）。

依据：[修复方案调研](../notes/learn/2026-11/20261113172953-UA兼容与扩展Worker隔离修复方案调研.md)、[排查记录](../notes/issue/2026-11/20261113170129-网站频繁验证码与浏览器身份排查.md)、[网站 SW 误注入问题](../notes/issue/2026-11/20261113171922-普通网站ServiceWorker误注入扩展桥.md)。调研探针是历史证据，不能算本工作区验收。

## Step 0：需求简报

### 背景与体验目标

飞书表格内嵌豆包聊天发送消息后频繁出现图片选择、拖拽验证，Cookie 正常。已复现默认 UA 中文应用名在主文档与 fetch 中编码不同，以及普通网站 Service Worker 被注入扩展兼容桥。修复这两项环境缺陷，并保留同账号、同出口、同聊天路径的人工对照，判断挑战频率是否改善。应用安装名称、Dock/任务栏名称及现有登录态保持原样。

### 范围与边界

- 影响：主进程启动时默认 UA；各分区扩展运行时的 preload 生成、注册与启动屏障；必要的激活入口失败处理；相关诊断夹具和文档。
- 排除：自定义 UA 设置、新 UI、共享 IPC 或持久化 schema、新标签来源修复、代理策略、Cookie 导入/清理、随机指纹与网站安全脚本改写。
- 全局 UA 只共享字符串，不共享 Session；继续使用独立 `persist:sess-<id>`。不反复覆盖 DevTools 设备模拟选择。
- 首次生效以正常完整退出并重启为边界，不销毁用户进行中的录屏、扩展任务或聊天，不删除网站 SW 注册及存储。
- 网站仍可能要求验证；字段一致、桥隔离与真实聊天结果分别验收。

### 行为要求与待决项

1. 所有普通网页默认采用本应用真实 Chromium 主版本、运行平台对应的 ASCII Chrome 格式 UA，不依赖本机是否安装 Chrome，产品展示名继续使用原规则。
2. 兼容 preload 与宿主 shim 只进入扩展上下文；保留插件按权限执行的 content scripts、scripting 和消息链路。
3. 主进程对可信 SW scope、实际已加载扩展 ID、Session 的鉴权继续独立生效。
4. **待决：Client Hints。** 原调研尚未获得用户对“保留原生品牌与平台信息”的确认。本计划推荐保留真实 UA-CH，不伪造 Google Chrome 品牌；UA 字符串缩减版本与 UA-CH 完整真实版本分别核验。实施前需解决该策略，不能把本轮创建计划视为批准。
5. 权限不扩大；不新增成功通知。初始化错误沿现有日志/原生错误反馈路径呈现，保留原始原因，不用吞异常换取表面兼容。

## Phase 1：影响与风险

| 入口 | 已核对的当前行为 | 计划影响 |
| --- | --- | --- |
| `src/main/index.ts` | ready 回调用本地化名称 `app.setName`，未设默认 UA | 最早安全启动点设置 `app.userAgentFallback`，早于首个 Session/窗口/扩展 |
| `src/main/browser/userAgent.ts`（新增） | 尚无集中构建入口 | 从运行时 UA、应用 token 与真实 Chromium 版本构建兼容字符串 |
| `src/main/extensions/runtime/preload-guard.ts` | 先异步生成再替换库注册，仅保留 id/type/filePath；宽泛放行 SW | 分离生成与同步安装，保留约束并限定扩展来源，收紧内部守卫 |
| `src/main/extensions/runtime/index.ts` | 先构造库引擎，再 await 守卫生成；引擎先进入 Map | 生成先完成，构造与受限替换同一同步段；成功后才公布可用引擎 |
| `src/main/browser/registry.ts` | `prepareActivation` 捕获扩展挂载错误后仍可 `commitSwitch` | 核验失败清理后再决定可否继续；不得携裸注册启动网页 |
| `src/main/extensions/shims.ts` | SW handler 使用 scope 与 Session 等权威身份 | 保留鉴权并做正反例验证，原则上不改协议 |

风险：持久分区 SW 可能早于挂载恢复；并发挂载、初始化失败和重试可能留下裸注册或半初始化引擎；过滤可能误伤插件后台与合法网页内容脚本；UA 构建可能误删平台字段；现场频率可能受账号、出口和时间变化影响。启动时序与失败隔离必须有运行证据，不能只靠代码中“没有 await”判定安全。

## Phase 2：设计

### UA 数据流

运行时默认 UA + 应用产品 token + `process.versions.chrome` → 小型纯构建函数 → 启动早期 `app.userAgentFallback` → 各分区网页与后台请求。平台沿用运行时合法平台部分，Chrome 使用真实主版本加 `.0.0.0`；构建失败应保留可诊断原因，禁止写入半成品或硬编码本机版本。具体异常策略随构建输入测试定稿。名称与打包配置无需修改。

### 扩展注入与启动顺序

1. 在库引擎构造前完成生成文件及锚点校验；失败不创建库裸注册。
2. 同一同步段中构造引擎、识别本库 frame/SW 注册、替换为守卫文件及 `includeGlobs: ['chrome-extension://*/*']`，成功才进入可用引擎 Map；不影响其他 preload。
3. 保留 id/type 和已有过滤约束。已有 includeGlobs 与扩展来源必须按交集语义处理，不能简单拼接形成 OR 放宽；字段组合以当前 Electron 类型和实测为准。
4. 同步替换失败时，注销本轮产生或残留的无过滤库注册、回收半初始化状态、拒绝本轮扩展挂载；重试必须重新核对两条注册。若无法证明普通站点和持久 SW 在整个窗口都不接触裸注册，停止该方案，改用调研方案 C 在依赖注册源头限制，并更新计划及交付方式。
5. 生成脚本的内部守卫与错误分支不得无条件信任 SW 类型，也不读取不可用的 `location.href` 掩盖原始异常。来源限制由原生注册执行；不引入页面自报来源握手。
6. 受限注册完成 → shim IPC 接线 → 扩展加载/恢复 → 网页创建。复用并核验现有 pending 串行与激活 generation 语义；持久恢复、其他 fromPartition 入口逐一检查。

不新增共享接口。内部函数可分为异步准备与同步安装，名称按实现确定。对两条注册数量、来源匹配、失败清理和首个上下文时序设断言；不能通过关闭网站 Worker、移除合法 content scripts 或放宽 sender 检查解决失败。

采用原生过滤而非额外来源协议属于可选架构取舍；实施定稿时补 ADR，写明备选方案、初始化不变量及失败策略。Client Hints 待决和持久 SW 时序证明未解决前，Phase 2 不标通过。

## 实施顺序

1. 解决 Client Hints 策略，固定隔离诊断站点与 MV2/MV3 夹具；先复现主文档/fetch UA 差异和网站 SW 桥对象，记录基线与引擎版本。
2. 完成 UA 构建与启动接线；验证新/已有持久分区冷启动、主文档、fetch、favicon、跨源 iframe、Dedicated Worker、SW 及扩展后台身份，再保留独立 UA 结果。
3. 完成 preload 原生过滤与启动失败隔离；分别复验普通网站环境、扩展能力，再运行组合回归。
4. 运行 typecheck、lint、build 和隔离应用验证；可执行夹具使用现有 Node/Electron 能力，不引入通用测试框架。agent 使用 `npm run dev:agent`，独立设置 MSB_DEV_PORT、MSB_AGENT_DEBUG_PORT、MSB_USER_DATA，避开其他实例。
5. 按 code-review 技能和项目清单执行 Phase 5，只记录问题到 book/notes/issue；缺陷修复另轮开展。Phase 6 更新本计划、总结、必要 learn/issue/changelog，运行 `npm run book:index`。
