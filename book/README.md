# book — multi-session-browser master index

> Generated by a script — do not edit by hand. After any book change run: `npm run book:index`.
> Every new file must carry a frontmatter `description` (one plain-language line about the content, not the genre); entries under `notes/task/` and `notes/issue/` also need a `status` (`open|done` / `open|resolved`); the build warns and exits 1 otherwise.

## How to use this book

- **AI agents**: read this file first for the full map, then follow links to what you need. Before writing any book document, read `guidelines/writing-style.md`.
- **Humans**: browse by the directory table below. Rules live in `guidelines/`, blueprints in `plans/`, experience in `notes/learn/`, architecture in `docs/architecture/`, decisions in `docs/decisions/`.
- **By time**: `changelogs/` and `notes/{summary,learn,issue}/` archive under `YYYY-MM/`; the month is a physical grouping only — do not nest deeper by feature.
- **By status**: entries in `notes/task/` and `notes/issue/` carry a frontmatter `status`; this index lists open entries first — flipping the field and rerunning is the archive step.
- **By feature**: search this index for a feature name, keyword, or frontmatter summary; `notes/learn/` entries are also searchable by their `tags`.
- **Obsidian**: open `book/` directly as a vault. Links are plain relative Markdown; if you move files, rerun the index.
