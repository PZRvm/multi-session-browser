## 2. 八项必查结论

### 2.1 重复代码

结论：发现 2 个问题

- [ ] **[中] shim 通道名单源旁路**：桥函数（生成的守卫 preload）与主进程 handler 各自维护通道字符串
  - 位置：`src/main/extensions/runtime/preload-guard.ts:84,92,101,106,110`（硬编码 'msb-ext-shim-*' 字面量）vs `src/main/extensions/shims.ts:41-45`（EXT_SHIM_* 常量）
  - 证据：两侧字符串当前一致，但无编译期关联；任一侧改名即静默断链（SW/页面 invoke 全部 No handler）
  - 建议：shims.ts 导出 EXT_SHIM_* 常量，preload-guard 生成桥模板时插值引用常量，恢复编译期单源

- [ ] **[低] 生成桥模板内重复模式**：5 处重复 `extId: globalThis.chrome?.runtime?.id`、4 处重复 `!result || result.ok !== true → throw` 信封检查
  - 位置：`src/main/extensions/runtime/preload-guard.ts:84-116`
  - 建议：桥内提 helper（invokeShim(channel, payload) 统一信封解包与 throw），顺带消掉重复 extId 读取

### 2.2 权限漏洞

结论：已查，未发现问题

- SW 路授权用 sw.scope 平台派生、页面路用 senderFrame 主 frame 校验，双路均不可由调用方伪造；分区名只进 sha256 哈希不进路径，无路径穿越面；popup/editor/offscreen/采集窗 webPreferences 均保持 contextIsolation:true、nodeIntegration:false；主世界桥 delete 失败残留见 2.6 关联项（同信任域低危）。秘密泄漏不适用（无密码/Token 业务域）。

### 2.3 竞态条件

结论：发现 1 个问题

- [ ] **[中] 分区副本换装并发竞态**：ensurePartitionExtensionCopy 无 per-key 串行化
  - 位置：`src/main/extensions/install/partition-copy.ts:66`
  - 证据：mountPartition 有 pending 串行化，但 management 的 openPopup/onRemove 走 `runtime.resolveLoadedId` → 同样调用 ensurePartitionExtensionCopy；openPopup IPC 与一次进行中的挂载换装并发时，两侧同时对同一 `${dir}.staging` 做 rm/cp/rename，轻则 ENOTEMPTY 报错、重则半成品目录被 rename 上位
  - 建议：按 dir 为 key 的 in-flight Promise 互斥表（manifest-store `locked()` 同款模式），mount 与 resolveLoadedId 共用

### 2.4 事务边界

结论：已查，未发现问题

- 副本换装 staging→rename 原子性成立（rm→rename 之间的空窗见 2.3 串行化修复后一并消除）；installed.json 经 manifest-store 原子写；卸载顺序（清单→运行时移除→目录清理）与既有约定一致。

### 2.5 通知遗漏

结论：已查，未发现问题

- loader 逐条错误进 results 且 recordPartition(false) 落清单；capture/download/contexts 失败均有 {ok,error} 信封回传扩展；换装自愈重载失败有 catch 兜底。

### 2.6 边界遗漏

结论：发现 2 个问题

- [ ] **[中] unpacked 来源 ID 推导不一致**：loader 去重与弹窗重映射对 unpacked 都退回 record.id，而实际加载 ID 是路径哈希
  - 位置：`src/main/extensions/runtime/loader.ts:50`、`src/main/extensions/runtime/index.ts:143`
  - 证据：unpacked 安装（前置验证/dev 链路）的 manifest 若无 key，实际 ID = extensionIdFromPath(origin)；退回 record.id 导致去重失效（重复 loadExtension 报错记为 failed）与 openPopup EXTENSION_NOT_LOADED
  - 建议：unpacked 也统一走 extensionIdFromPath(record.source.origin) 推导，与 crx/store 同构

- [ ] **[低] createExtensionWindow 加载失败为 unhandled rejection**
  - 位置：`src/main/extensions/dev-entry.ts:89`
  - 证据：`void win.loadURL(url)` 失败（目标文件缺失等）无 catch；URL 经正则校验但文件可能不存在
  - 建议：catch 后销毁窗口并 console.warn 记日志

### 2.7 复杂度

结论：已查，未发现问题（判定"可接受"并留痕）

- shims/preload-guard 复杂度确实显著上升，但属平台约束（SW ipc 逐实例注册、freeze 前注入、库源码补丁）的必要复杂度，且有锚点断言、{ok,error} 信封、串行化 pending 表等既有惯例兜底；未引入无谓抽象或新依赖。后续若库版本升级，锚点断言会显式失败引导重核验，成本可控。

结论：已查，未发现问题
