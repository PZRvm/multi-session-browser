# 恢复目标应先进入模型，再等待真实导航

1.1.2 更新适配验证中，R1 回归曾把第一个 URL 保存成 about:blank。恢复相关源码与 dev 相同，原用例预热恢复缓存，因时序不同可能通过；取消预热后稳定失败。

冷缓存补载先有一个空白占位 Tab。直接调用其 webContents.loadURL，只改变异步导航，manager 的 URL 要等 did-navigate 才更新。更新准备等待内部恢复链完成，不代表网络导航已完成，此时可能冲刷空白地址。

本次用已有 newTab 同步建立第一个目标模型，再 closeTab 删除空白占位，其余 URL 和激活位按原顺序恢复。不能先关唯一占位，因为最后留一规则会拒绝删除；也不应靠等待真实站点加载成功或延长测试时间解决。

用例固定冷缓存，仍断言两个原 URL、顺序、激活位和准备期写入禁用；修复前失败，修复后通过。此前的暖缓存通过不再代表冷缓存分支已验。
