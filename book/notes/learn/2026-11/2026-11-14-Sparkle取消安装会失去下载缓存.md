# Sparkle 取消安装后重开需要重新下载

适用：官方 Sparkle 2.10.1 的自定义 SPUUserDriver，临时签名应用通过 EdDSA 验证更新包。

原先要求普通退出不安装，同时重开还保留就绪缓存。原型在 ready 后回复 Skip，等取消完成再退出，两次运行各下载一次，磁盘保持旧版本；原要求未通过。
用户随后明确接受：应用未退出时可稍后安装；普通退出安全取消，重新打开需重新下载。这个规则必须反映在状态恢复、按钮和验收项中，不能将丢失缓存的版本继续显示为 ready。

源码机制：[SPUCoreBasedUpdateDriver.m](https://github.com/sparkle-project/Sparkle/blob/2.10.1/Sparkle/SPUCoreBasedUpdateDriver.m) 的 `installerDidStartExtracting` 清下载目录；`finishInstallationWithResponse` 的 Skip 调用 cancelUpdate。
Dismiss 则仍可能随应用退出安装，不能拿它替代安全取消。

探针位于 `tools/sparkle-g0/`。使用独立随机 appId、两个 90.0.1 / 90.0.2 包和临时测试密钥，不读取正式数据，也不向钥匙串写入密钥。
SDK 已按计划摘要验真。Cocoa、Electron 45.3.0 arm64 和 Rosetta x64 原型各七场景通过：显式许可后才请求归档、错误签名被拒绝、模拟保存拒绝零安装、确认后替换并重启到 90.0.2。
实际产品两架构另各通过八场景，最终证据见[迁移计划](../../../plans/2026-11-14-macOS更新迁移Sparkle.md)；Apple Silicon 上的 x64 是 Rosetta 验证，不代替 Intel 实机。

测试私钥必须使用工具支持的格式：本轮使用 Node 生成 Ed25519 seed，将 32 字节 seed 的 Base64 写入 0600 临时文件，由官方 sign_update 签名；不能将 seed32 + public32 拼成伪 64 字节扩展私钥。

真实坏签名测试补充：SDK 的 SUSignatureError 为 3001，SUValidationError 为 3002；4005 是通用安装错误。桥接按 SUSparkleErrorDomain 和 underlying error 链识别 3001/3002，避免把坏签名显示成下载失败，或把通用安装失败显示成签名失败。

原生编译必须显式设 `-mmacosx-version-min=13.0`，与 Electron 应用当前 LSMinimumSystemVersion 对齐。本机默认 clang 产物曾为 minos 15.0；SDK 框架自身最低为 12.0。只在本机能加载，不能证明模块能在声明的最低系统上运行。SDK 清单固定 deploymentTarget，归档生成检查应用的最低版本；升级 Electron 时重新验证。

中文应用名的 ZIP 不能依赖系统 unzip 的 `-Z1` 文本再拼命令：本机输出曾转成乱码，导致后续 `-p` 找不到文件。归档检查复用已有 adm-zip 读取条目和二进制，plist 值由系统 plutil 解析。
