# 网址分类要在实际渲染端复验

审查修复放行显式下划线主机时，本地 Node `new URL('https://bad host')` 抛错，而 Electron 39.8.10 的 renderer 原生 URL 接受并得到 `hostname=bad%20host`。只在 Node 中执行分类纯函数会漏掉该差异；实际 Enter 路由回归发现了它。

HTTP(S) 主机校验同时检查序列化后的百分号/空白，再保留显式合法 URL 的语法。`https://bad%20host` 拒绝；`https://%65xample.com` 的 hostname 已正常解码为 example.com，应放行；路径和用户信息中的合法编码不受主机检查影响。域名下划线也不因此回退为旧 DNS 标签限制。

原生编辑菜单测试另有时序边界：设置窗先等 React 挂载，网页先等本次唯一 URL 与完成标记，不能对仍在替换的旧文档断言 redo。WebContentsView 的 DOM 聚焦与 macOS 系统焦点不同。定向菜单回调使用焦点夹具，实体菜单和真实快捷键另由 CUA 验证，分别记录证据。
