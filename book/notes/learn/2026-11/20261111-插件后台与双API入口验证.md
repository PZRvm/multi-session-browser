# 插件后台必须从实际包与错误栈判断

Dark Reader 4.9.135 的两个磁盘副本都是 manifest_version=3，background.service_worker=background/index.js。旧排查把它当 MV2，因此 getBackgroundPage=NULL、没有独立 backgroundPage 都不能证明后台没启动。

生产 preload 守卫移除了库的 frame/service-worker 两种注册，只异步补回 frame。worker 缺少 windows.onRemoved，初始化中断；保留两种注册并 await 文件生成、注册后再加载，生产 popup 恢复37个控件，真实 On/Off 改变网页。

该版本 popup 的 loader--complete 会把文字设为 rgba(233,108,76,0)，容器 pointer-events:none。首次绘制前完成初始化时 transitionend 可能不发生，innerText仍含Loading。要保留原始文本证据，另读实际可见文本、截图及真实操作；不能仅凭字符串宣称仍卡住。

uBO Lite 2026.1103.1743 使用 self.browser || self.chrome。兼容库4.10只补chrome，故核查两入口而不只看chrome是否存在；功能验收应查广告请求ERR_BLOCKED_BY_CLIENT及开关对照。翻译popup空文本也不能以“不含Loading”判通过。


沉浸式翻译1.34.4还在原生内容脚本中使用storage.sync。Electron42没有该存储区，兼容库在popup/worker把它别名local也覆盖不了内容脚本。45.3原生实现可用后，守卫副本须保留原生sync/managed，避免一个插件在两种上下文读到不同区域。实际操作验证sync/local同名键互不覆盖，A/B分区互不共享。

工具栏入口另有独立错误：management原先固定mounted[0]，必须按IPC sender窗口→registry当前Tab→该Tab的session解析。popup本身是子窗口不构成隔离问题；绕开工具栏自行建popup却会漏测这个分区选择错误。新会话也应在registry激活前挂载，不能轮询启动时的一份会话快照。

沉浸式翻译预渲染popup-presentation--inert，按钮ID与真实页面相同。等待第一个translate-button存在/未disabled不足以证明能操作；须等待非inert容器中的按钮，再检查原本纯英文的页面产生扩展译文节点。失焦关闭的生产popup测试应先确保应用和窗口获焦。
