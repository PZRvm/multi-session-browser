# 渲染弹层压不过原生层：路线选型与踩坑

## 现象与根因

浏览器区页面由主进程 `WebContentsView` 原生视图承载（`useBrowserBounds` 上报矩形定位），它在窗口合成层的**原生层级**恒高于 shell renderer 的 DOM——任何 shell 弹层（`position: fixed`、`z-index` 再大、antd Modal/Popover）只要延伸到浏览器区就被原生层盖住。这不是 CSS 问题，DOM 无法跨过原生视图边界。

**白屏变体（更隐蔽）**：为了让 DOM 弹层可见走 `overlayDepth` 整页收起路线（弹层登记 `openOverlay` → `BrowserContentAnchor` 上报零矩形 → 主进程收起 WebContentsView）——弹层确实可见了，但**页面区域整个消失**（shell 该区域无内容，视觉上全白/全空），且 `useBrowserShortcuts` 冻结快捷键。2026-11-11 用户实测扩展面板唤出全白即此因（该面板是 overlayDepth 最后一个登记方）。`shared/omniboxSuggest.ts` 头注对此有权威记载："旧 overlayDepth 整页收起方案以『页面白屏』为代价（评审 L8 取舍），已由本方案取代"。

## 四条可行路线（按场景选型）

| 路线 | 机制 | 适用 | 先例 |
| --- | --- | --- | --- |
| **原生子窗池** | 主进程透明无框 `BrowserWindow(parent: 宿主)`，懒建/隐藏复用/宿主 move-resize 跟随；数据 shell 经 show 全量推送，子窗纯渲染零自治 | 需要浮在页面上方的丰富面板（列表/交互），页面须保持可见 | 地址栏建议（`main/browser/omniboxSuggest.ts`）、截图反馈条、工具栏气泡 tooltip、扩展面板（`main/extensions/panel.ts`，2026-11-11） |
| **原生 OS 级弹层** | `Menu.popup()` / 原生模态框 | 菜单、确认框——OS 级绘制天然盖过一切 | SessionRow 右键菜单（曾踩遮挡+盲操作三轮迭代后迁移）、WorkspaceSwitcher 重命名 |
| **停靠让位** | 弹层停靠在内容区上方/下方，压缩锚点矩形，`ResizeObserver` 自动重报 bounds 原生层自行让位 | 栏条类 UI，用户可接受内容区临时变矮 | FindBar 页内查找 |
| **独立窗口锚定** | 自建 `BrowserWindow` + `parent` + 锚定定位 + blur 关闭 + preferred-size 自适应 | 扩展 action popup 这类第三方内容 | `extensions/management.ts` openExtensionPopup |

## 踩坑一：overlayDepth 收起的两个代价（勿再走）

1. **页面白屏**：收起后 shell 无内容填补该区域；除非产品接受"弹层期间页面消失"，否则禁用此路线做浏览器区弹层。
2. **快捷键冻结盲操作**：`useBrowserShortcuts` 据 overlayDepth 冻结，但页面被收起用户仍看得到地址栏，体验割裂。

例外仍合法的登记方：antd Modal 居中弹层（SessionPanel 测试地址等）自带 mask 覆盖、观感弱化，见 `stores/ui.ts` 头注的登记方清单——新增右区弹层**必须**先读该头注。

## 踩坑二：层级与遮挡的判定顺序

排查"弹层被遮住"先判定**弹层宿主在哪个渲染面**：
- shell DOM 弹层 → 必被原生层盖（走上面路线）；
- 原生子窗之间的层级 → `parent` 归属与创建顺序决定（action popup 与扩展面板都设 `parent: 宿主`，互不遮挡，谁后创建谁在上）；
- 多原生子窗叠放需求 → 复用单一子窗池（每宿主至多一个），不要并列多个同位子窗。

## 迁移成本参考（shell DOM 弹层 → 原生子窗）

一次完整迁移约 8 个面：shared 契约（角色/通道/载荷/度量常量）、主进程子窗池（建窗/定位/跟随/级联）、ipc.ts 域装配（宿主/子窗身份白名单）、index.ts 接线（建池+closed 级联）、preload 命名空间、渲染面（模块求值期订阅 data 防"推送先于订阅"竞态）、shell 编排 hook（开合/收合/pick 消费/mousedown-toggle 竞态）、CSS 承载态（body[data-role] 作用域 + 环带缩进）。扩展面板实例见 `book/plans/20261111-扩展面板原生子窗口化.md` Phase 2，全部文件可作模板。

两个易漏点：
- **blur 先于 click 的重开竞态**：面板开着时点它的触发按钮，mousedown 先令面板失焦关闭，随后 click 若按当前态 toggle 会立即重开——mousedown 时捕获"面板是否已开"快照，该次点击只关不开（Chrome 菜单语义）。
- **数据推送早于组件挂载**：子窗是 React.lazy chunk，主进程 ready-to-show 即 flush data，组件挂载更晚——订阅必须在**模块求值期**同步建立 + latest 暂存（OmniboxSuggestWindow / CaptureFeedbackWindow 两次同款缺陷先例）。
