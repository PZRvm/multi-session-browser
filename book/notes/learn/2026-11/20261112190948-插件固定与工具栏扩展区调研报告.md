# 插件固定与工具栏扩展区 功能调研报告

> 创建时间：2026-11-12 19:09（Asia/Shanghai，与文件名 14 位时间戳一致）
> 需求来源：用户原话要点——「模仿 Chrome 浏览器来做插件固定功能，就是那个钉子的 icon，并且插件区域 hover 上去也需要按照图片的样子」（附截图：圆角胶囊容器内并排多个插件图标）
> 调研单元：1 个（宿主侧 pin 状态 + 工具栏扩展区胶囊 + 面板钉子开关 + 拖拽排序动画 + 设置页开关，同一数据流强耦合一体）
> 状态：调研完成；假设 1/2/3/5 已获用户裁决（2026-11-13），假设 4 已解释并按全局同规落入设计（未实施）

## 1. 需求理解

### 1.1 功能目标

为多会话测试浏览器的工具栏扩展区补齐 Chrome 的插件固定（pin）交互：

- 扩展面板（拼图菜单）每个插件行提供**钉子开关**：点一下固定，再点取消；固定态钉子为填充样式。
- 被固定的插件以**图标按钮**形式常驻工具栏扩展区：点击图标直接打开该插件的 action popup（弹窗）或派发 onClicked，不再需要先开面板再点行。
- 扩展区视觉按用户提供的截图：固定图标与扩展按钮同处一个**圆角胶囊容器**，hover 出现底色反馈（截图形态为准，具体明暗与尺寸定稿走 impeccable 流程；用户 2026-11-13 确认）。
- 固定图标支持**指针拖拽重排**（用户 2026-11-13 裁决必做）：拖动图标跟手，邻居图标平滑滑动让位（Chrome 对齐的换位动画），释放提交新序、Esc 放回原位。
- 设置窗插件页每行也提供钉子开关（用户 2026-11-13 裁决加做），与面板钉子同语义。
- 用户是专业测试人员：固定常用插件后一键直达弹窗，效率优先，不做引导式文案。

主窗口与独立窗口同规：同一份全局 pin 状态，两窗工具栏都显示，点击在各自窗口弹 popup（PRD 3.11「安装清单全局统一，主窗口和独立窗口同规」的自然延伸）。

### 1.2 未知点清单（调研结论逐条销号）

- [x] **pin 状态存在哪、什么粒度** → 全局粒度（非逐会话）。存主进程插件清单 `installed.json`，顶层新增可选 `pins: string[]`（有序 ID 列表，顺序即显示顺序）；清单存储已有串行锁 + 原子落盘，直接复用（见 2.2）。
- [x] **Electron / electron-chrome-extensions 有无现成 pin 支持** → 无。库定位是扩展 API 宿主（chrome.* API 补齐），工具栏 pin 属浏览器 UI 层，Chrome 自己也是浏览器壳实现。官方文档确认 `chrome.action.getUserSettings()` 只向插件自身暴露 pin 状态（[What's new in Chrome extensions](https://developer.chrome.com/docs/extensions/whats-new)），宿主侧必须自建。
- [x] **工具栏如何实时得知 pin 变化** → pin 开关在原生子窗面板里操作，宿主 shell 无法直接感知。解法：主进程持久化成功后向全部窗口广播 `extensions:changed`（`settings:changed` 全窗推送先例），工具栏订阅后重取 `extensions:list`（list 恒为唯一数据源，广播零载荷，消费者自行重取）。
- [x] **面板「纯展示零自治」架构下，面板内 toggle 后数据如何刷新** → 不破架构：pick 新增 `togglePin` 语义经主进程白名单转发回宿主 shell，宿主调 `setPinned` 持久化，随后宿主侧 refreshTick 重跑 show 全量刷新面板数据（panel.ts 的 show 本就幂等全量，复显零额外机制）。
- [x] **固定图标的 popup 锚点** → 复用 `openPopup` 既有锚点机制：现读该图标按钮 rect left/top，主进程定位公式（+30/+34）按 28px 按钮调的，固定图标按钮同尺寸直接沿用，dev 态实测微调。
- [x] **胶囊容器 hover 视觉** → 交互语义明确（hover 显底色），具体明暗/尺寸属界面设计，实现时走 impeccable 技能定稿（AGENTS.md 界面设计规则）。
- [x] **拖拽排序与换位动画如何实现** → 手势机制复用 TabStrip 先例（`useTabReorder` 本地预览序/中点换位/提交语义、指针捕获状态机 armed→reordering、suppressClick、Esc 放回）；动画部分为 TabStrip 未覆盖的新机制——`.chrome-tab` 换位是瞬跳（transition 仅 background/opacity），固定图标胶囊需新写**槽位 transform 滑动动画**：非拖动钮按预览槽位差 translateX + transition（~150ms ease-out）滑移，拖动钮无 transition 跟手、释放吸附。
- [x] **设置窗插件页固定开关** → `PaneExtensions.tsx` 行结构 [图标][名称/元信息][卸载钮]，追加钉子小钮即可；`setPinned` toggle 复用，pinned 标记已在 list 回执里，切换后本地 refresh + 广播同步工具栏。

### 1.3 按单单元调研

三个面（pin 存储、工具栏胶囊、面板钉子开关）共享同一条数据流（manifest pins ↔ 广播 ↔ 消费者重取），拆开调研会重复引用同一批文件，单单元整体推进。

## 2. 调研单元：插件固定与工具栏扩展区

### 2.1 该部分要做什么

pin 状态全局持久化（manifest 增量字段）→ 变更广播 → 三个消费面接线：工具栏胶囊固定图标（点击开 popup + hover 气泡）、扩展面板行钉子开关（pick togglePin 转发）、卸载清理。不负责：拖拽排序（本期不做）、设置窗插件页加固定开关（本期不做）、逐会话 pin（违反 PRD 全局统一原则，不做）。

### 2.3 候选方案

**方案 A：manifest 增量 pins 字段 + changed 广播 + 工具栏胶囊手写（推荐）**

- 原理：pin 状态存 `installed.json` 顶层 `pins: string[]`（复用串行锁与原子落盘）；主进程持久化后广播 changed；工具栏胶囊容器渲染固定图标（点击 openPopup + TooltipSlot 气泡），面板行加钉子开关（pick togglePin 转发宿主 shell 落库）。
- 来源：全部机制为项目内成熟先例（settings:changed 全窗广播、panel.ts 幂等 show、openPopup 锚点公式、28px 圆钮 CSS 语系、manifest-store 锁与原子写）；pin 交互对照 Chrome 拼图菜单（官方文档佐证交互概念：[What's new in Chrome extensions](https://developer.chrome.com/docs/extensions/whats-new)）。
- 与本项目的适配点：主进程 management.ts 加两通道，shared 契约增量，preload 镜像，renderer 两处接线，全部在既有模块内。

**方案 B：独立 pins.json 小存储**

- 原理：pin 状态独立文件 `userData/extensions/pins.json`，仿 manifest-store 建小存储模块。
- 来源：Chrome 自己把 pin 存 Preferences（与安装注册表分离）的布局。
- 看过、不选：多一套 IO/锁/校验代码，与 manifest 的 removeInstall 收口脱节（卸载清理要跨两个文件协调），换来的隔离收益为零——pins 生命周期与安装记录严格同生死，同文件同锁反而消除一致性问题。

**方案 C：扩展 electron-chrome-extensions 库**

- 看过、不选：库定位是 chrome.* API 宿主（shims.ts 头注佐证），不含浏览器 UI 层；Chrome 的 pin 也是浏览器壳行为。改造库或提 PR 引入无关能力，收益为零。

**方案 D：@dnd-kit 拖拽库（core + sortable）**

- 原理：React 生态成熟拖拽库，自带 transform 位移动画（与槽位方案同型）。
- 看过、不选：为单个胶囊内重排引入两包依赖，而 TabStrip 手势机制项目内成熟；dnd-kit 的动画本质就是 transform + transition，自写槽位方案等价且可控（时长/缓动随 impeccable 定稿），不省事反多依赖。
- 来源：https://github.com/clauderic/dnd-kit

### 2.4 可行性分析

| 维度 | 方案 A | 方案 B |
| --- | --- | --- |
| 技术匹配 | 全部机制项目内现成，Electron 39 兼容，无新依赖 | 同左，多一套存储模块 |
| 规则冲突 | 无触碰红线；共享 IPC 契约增量按 always-L 走完整流程 | 无 |
| 成本 | 主进程 2 处 + shared 2 处 + preload 2 处 + renderer 3 处 + CSS，无新依赖 | 成本只增不减 |

### 2.5 结论与实施建议

- 结论：**完全手写（方案 A）**。无现成库可承担浏览器壳 UI，而本项目自研宿主已提供全部承载机制，手写即拼装既有先例。
- 落地路径（粒度到文件与接口）：
  1. `src/shared/extensions/management.ts`：`EXTENSIONS_CHANNELS` +`setPinned`('extensions:set-pinned')/+`changed`('extensions:changed')；`ExtensionListItem` +`pinned?: boolean`；新增 pin 载荷类型。
  2. `src/shared/extensionsPanel.ts`：`ExtensionsPanelPickPayload` kind +`'togglePin'`（携带 id 与目标 pinned 值）。
  3. `src/main/extensions/install/manifest-store.ts`：`GlobalManifest` +`pins?: string[]`（可选字段向后兼容，缺省 []）；`validateManifest` 携带 pins（逐项 [a-p]{32} 校验 + 去重）；`removeInstall` 同步清理 pins；新增 `setPins` 方法（串行锁 + 原子落盘，幂等集合语义）。
  4. `src/main/extensions/management.ts`：`extensions:set-pinned` handler（载荷校验 → manifest.setPins → 广播）；`extensions:changed` 广播（getAllWindows 全推，零载荷，消费者重取 list）；list 返回项并入 pinned 标记；install/uninstall 成功后同样广播。
  5. `src/preload/index.ts` + `index.d.ts`:extensions 命名空间 +`setPinned`/+`onChanged`。
  6. `src/renderer/src/components/browser/Toolbar.tsx`：挂载时 list 现取 + onChanged 订阅重取；渲染 `.chrome-ext-bar` 胶囊容器（固定图标组 + 扩展按钮）；固定图标 click → `extensions.openPopup(id, 按钮 rect 锚点)`；TooltipSlot 悬停气泡显插件名；**固定图标钮不随 !activeTab 禁用**（Chrome 对齐：无 tab 也可拖拽重排；点击无 tab no-op，拖拽恒可用）。
  7. 新 hook `useExtPinReorder.ts`（仿 `useTabReorder`：本地预览序/中点换位/跟手位移/commit 全序提交/Esc + pointercancel 放回），叠加**槽位 transform 滑动动画**：非拖动钮按预览槽位差 translateX + transition（时长/缓动 impeccable 定稿）；拖动钮无 transition 跟手，释放吸附；commit 回执 ok 后本地乐观落地新序再复位 transform（无跳变），失败预览清空自然滑回。
  7a. `Toolbar` 拖拽接线：固定图标钮 pointerdown 手势（armed→reordering 状态机、`DRAG_ENGAGE_RADIUS_PX` 过阈值、suppressClick 吞随尾 click 与「点开 popup」分流：未过阈值释放 = 点击开 popup，过阈值 = 重排不触发 popup）。
  8. `useExtensionsPanelWindow.ts`：onPicked +togglePin 语义（setPinned 落库 → refreshTick 重跑 show 全量刷新面板，面板不关）；开面板时 show 的 items 已含 pinned 标记。
  8a. `ExtensionsPanelWindow.tsx`：行右侧钉子开关（antd PushpinOutlined / PushpinFilled），click → pick {kind:'togglePin', id, pinned}；钉子钮不参与行 disabled（hasAction 只约束开弹窗）。
  8b. `PaneExtensions.tsx`：行加钉子小钮（同 Pushpin 图标）→ `extensions.setPinned` → 本地 refresh；广播已同步工具栏。
  9. `src/main/browser/ipc.ts`：pick 转发白名单 +togglePin（载荷校验）。
  10. i18n 三语：`browser.extpanel.pinAria` / `unpinAria` + `settings.extensions.pinAria` / `unpinAria`（固定到工具栏 / 从工具栏取消固定，两处语境一致）。
  11. CSS（`app.css`）：`.chrome-ext-bar` 胶囊容器 + 固定图标钮样式 + 槽位滑动动画 transition——**实现时走 impeccable 技能**定稿视觉与动画手感（按用户截图形态）。
  12. 验证：typecheck + lint + build + `npm run dev` 手动验证清单（面板钉子切换、图标开 popup、popup-less 派发、拖拽重排动画手感、Esc 放回、卸载联动、两窗同规、重启保留、亮暗主题 hover、设置页开关）。

## 3. 风险与开放问题

- **面板刷新路径**：面板开着时 toggle pin，刷新走宿主 shell refreshTick 重发 show——show 幂等全量机制现成，但需 dev 实测复显无闪烁（panel.ts 已有首显防闪烁机制，复显路径理论无虞）。
- **锚点公式微调**：openPopup 定位公式（+30/+34）按拼图按钮调的，固定图标按钮同 28px 尺寸理论直接沿用，需 dev 实测确认。
- **manifest 校验面**：validateManifest 重建对象丢未知字段，加 pins 必须同步改校验，否则 pins 写入后下次读取被静默丢弃——这是本功能最容易漏的坑。
- **拖拽中外部刷新竞态**：拖拽进行期间，changed 广播触发的重取会覆盖本地预览序——拖拽中抑制重取应用（数据照取但挂起或直接忽略，提交回执后重取幂等收敛）。
- **动画手感**：槽位 transform 滑动动画是 TabStrip 先例未覆盖的新写部分（Tab 换位瞬跳无动画），时长/缓动需 dev 实测按 Chrome 手感调（与用户确认的截图/浏览器体验对齐）。
