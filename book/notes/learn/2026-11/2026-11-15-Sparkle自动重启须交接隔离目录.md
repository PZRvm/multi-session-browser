# Sparkle 自动重启不能依赖终端里的隔离环境变量

2026-11-15 用户从终端启动测试包，安装后磁盘已变成 90.0.2，但自动重启报“更新测试包必须设置 MSB_USER_DATA 隔离目录”。手动用同一环境变量重开可以运行，说明失败在新进程的启动上下文，而非下载或替换。

先前产品探针只观察新 PID，然后关闭它，用带 MSB_USER_DATA 的命令手动重开校验 Cookie。这个方法可以证明替换和手动启动，不能证明自动重启正常，更不能证明自动启动使用原隔离目录。旧报告的完整重启结论已撤回。

修复只用于测试构建：严格保存后、安装许可前，将绝对隔离目录和 agent 调试参数写入私有单次记录，绑定 executable 路径与目标版本，30 分钟内有效。新版本启动必须成功校验并消费记录才可恢复；缺记录、旧版本、其他应用路径、失效时间、符号链接或不安全权限均拒绝，不能回落到默认目录。安装失败撤销后清理记录。正式构建不读写这份文件。

新探针连接更新器自动启动后的 renderer，直接读取关于版本和同一临时 profile 中的随机会话标记。只有这里读到 90.0.2 与原标记，才判自动重启通过；后续手动 Cookie 复核单列。修复与证据见[修复计划](../../../plans/2026-11-15-Sparkle测试重启隔离修复.md)。

官方 [Sparkle 安装说明](https://github.com/sparkle-project/Sparkle/blob/2.10.1/Documentation/Installation.md)描述独立的 installer / progress agent 启动链。环境是否继承必须以目标路径实测，不能从终端首次启动成功推断。
