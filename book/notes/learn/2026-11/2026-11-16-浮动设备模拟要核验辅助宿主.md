# 浮动设备模拟要核验辅助宿主和网页实际参数

macOS / Electron 45.3.0 / Chromium 156 实测：右停靠切为 undocked 后，设备按钮仍亮，但设备视图隐藏、模型变为 None，网页恢复桌面 UA、视口和触摸配置。原生 AdvancedApp 打开 `device_mode_emulation_frame.html` 的 `window.open()` 返回 null；最小 BrowserWindow 也复现，排除了本项目 Tab 管理。适用范围限于实测版本与平台。

排查顺序：看设备宿主是否存在，再读网页 innerWidth/innerHeight、navigator.userAgent、navigator.maxTouchPoints，并检查启动标识以排除重载。隐藏 agent 窗口还要关闭后台节流并等布局完成，不能读取切换当刻的旧数据；私有前端模块仅用于诊断，不能直接成为产品接口。

DevTools 链接走页面的 `devtools-open-url`，不走网页 `setWindowOpenHandler`。事件有发出、没有对应 Tab，才说明宿主接线缺失；不要因为 Network/Console 正常就判整个 DevTools 完整兼容。

本轮程序注入 F12 没有触发 DevTools `before-input-event`，真实键盘结果仍待测。原生 API 关闭、所属 Tab 销毁已验证，但不能替代物理按键和鼠标关闭按钮验收。

[排查报告](../../summary/2026-11/2026-11-16-浮动DevTools排查.md)保留环境、对照数据、正常项和未测边界。

## 宿主适配后的经验

用户授权兼容宿主后，公开 `setDevToolsWebContents` 加专用 preload 可转发内部布局消息，不必导入私有前端模块。`createWindow(options)` 必须用 `new WebContentsView(options)` 认领 Chromium 的原子页；另建 WebContentsView 会丢失 opener，并留下无导航的空白 WC。安全偏好应在 allow 的 overrideBrowserWindowOptions 阶段固定，而不是认领后才尝试修改。

DevTools 首帧 1×1 placeholder 若用于缩小真实网页，会使移动页面 visualViewport.scale 卡到 4。等待有效布局后再覆盖网页，实测可保持 390×844、scale=1，按 0.77 缩放后的原生坐标能正确点击。仅量 innerWidth 不足以发现错误缩放，必须同时读 visualViewport 并看实际像素/点击。

隐藏的浮动窗口移回主窗后可能暂缓 rAF 和 viewport 更新；脚本读取会看到旧尺寸。需要让相关原生视图以 showInactive 完成合成后再验收，并在结束后恢复隐藏，不能据隐藏中间态修补产品逻辑。窗口 root capturePage 不包含所有原生子视图，页面与设备工具栏应分别取自己的 webContents 图像。
