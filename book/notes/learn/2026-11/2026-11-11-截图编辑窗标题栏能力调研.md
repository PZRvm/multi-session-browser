# 普通 Chrome 插件不能隐藏系统标题栏或重排原生红绿灯

用户截图顶部显示「多会话截图编辑器」的一整条是系统标题栏。此前用 popup 类型无 Tab 栏来判断需求完成，只证明没有浏览器标签栏，没有去掉用户指的这条栏。用户本轮明确：窗口由普通 Google Chrome 插件打开，取消右下角浮动功能，期望三灯与工具栏同排垂直居中。

## Electron 官方方案

使用 AnySearch `code.doc`（library=electron）搜索，再读取官方自定义标题栏教程与项目锁定版本 v42.11.7 的窗口配置文档：

- `titleBarStyle: 'hidden'` 去掉系统标题栏，macOS 仍保留原生三灯；无需画假的三灯。
- `trafficLightPosition: { x, y }` 指定原生按钮位置，`hiddenInset` 只能提供固定内缩，精确对齐应使用前者。
- 原生按钮不成为 DOM 元素，网页给灯位留空；工具栏空白区 `app-region: drag`，按钮 `no-drag`。48px 行高按 16px 按钮组计算 y=16，最终需要系统窗口实测。
- `frame:false` 会去掉窗框与默认按钮，需要额外恢复原生按钮；本场景优先 hidden，减少无关窗体变化。

来源：[官方教程](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)、[v42.11.7 BaseWindowConstructorOptions](https://github.com/electron/electron/blob/v42.11.7/docs/api/structures/base-window-options.md)。AnySearch 提取的 latest 教程示例已为 45.3.0，因此用 v42.11.7 再核对实际可用选项。

## 项目实现

- `src/main/browser/captureEditorWindow.ts:106` 已使用 hidden + `{x:16,y:16}`，加载渲染页时注入 `chrome=hidden-titlebar`。
- `src/renderer/src/assets/app.css:3382` 配套设置工具栏拖动区与 84px 左让位，工具按钮 no-drag。原生三灯与 48px 工具行同排。
- `src/main/settingsWindow.ts:101` 同样隐藏标题栏，按设置页布局使用 `{x:8,y:8}`。
- `src/main/index.ts:255` 主窗也已隐藏标题栏，三灯定位 `{x:14,y:12}`，对应 40px 板头。

这些操作发生在 Electron 建窗代码中，不能通过把同名 query 或 CSS 加进 Chrome 页面来获得。

## 普通 Chrome 插件边界

AnySearch 以 library=chrome.extensions 搜索，并完整提取 [Chrome windows API](https://developer.chrome.com/docs/extensions/reference/api/windows)。createData 提供 url/type/宽高/位置/状态等参数，update 提供位置/尺寸/聚焦等参数，没有 frame、titleBarStyle、trafficLightPosition。`type:'popup'` 去掉浏览器标签栏和地址栏，不授予网页修改系统窗框的能力。

结论：只修改此 MV3 插件，不能实现独立窗口去系统标题栏并把原生三灯放进工具栏。改造项目 Electron 的原生承载可实现，但这会改变普通 Chrome 独立运行的部署方式，需要另外的原生程序或宿主接入；不把这种产品变更暗中并入本轮。

## 本轮实施决定

用户已授权调研后实施，不因技能默认的报告确认步骤再次停工。删除 Document PiP 自动尝试、浮动入口、自举桥与假三灯；编辑器直接在 Chrome popup 中工作，保留清晰缩放和复制/下载。系统标题栏仍由 Chrome 管理，这一项明确为平台限制，不能计为修复完成。Electron 项目现有原生窗口代码无需再重复修改。
