# Windows 主窗去标题栏、窗口控制移右上角 功能调研报告

> 创建时间：2026-10-30 13:01（本地时区，与文件名 14 位时间戳一致）
> 需求来源：用户原话要点——"Windows 端将顶部栏删掉，功能区域直接在右上角（现在右上角没东西），仅 Windows 调整 mac 不动；tab 页太多时不能与该区域重叠"
> 调研单元：1 个（小功能，不拆分）
> 状态：已实施（2026-10-30，分支 feature/win-titlebar-wco，计划 book/plans/20261030131247、验收 book/notes/summary/20261030131247-…/20261030134409-阶段验收.md）

## 1. 需求理解

### 1.1 功能目标

Windows 主窗去掉系统原生标题栏（当前显示"多会话浏览器"标题与系统最小化/最大化/关闭按钮的那一条），窗口控制按钮改为浮在窗口右上角（Windows 惯例位置——即 Tab 栏右端上方，该处现为空白）。去栏后窗口仍可拖动、双击最大化。边界约束：浏览器 Tab 数量多时，Tab 栏必须给右上角控制区让位，不得重叠。改动仅限 Windows 主窗：mac 分毫不动，Linux 保持系统框。

### 1.2 未知点清单（本次调研要回答的问题）

- [x] 未知点 1：Electron 有没有官方方案"去标题栏但保留原生窗口控制按钮"？→ 有：Window Controls Overlay（`titleBarStyle: 'hidden'` + `titleBarOverlay`），官方教程与 API 文档均覆盖（§2.3 方案 A）
- [x] 未知点 2：Tab 栏如何避让右上角控制区，窗口 resize/最大化时避让是否自动跟随？→ CSS 环境变量 `env(titlebar-area-width)` 由浏览器动态维护，随窗口状态自动更新（§2.3 方案 A / §2.4）
- [x] 未知点 3：去掉标题栏后窗口拖动与双击最大化怎么办？→ 项目现有拖拽带（`.board-head`/`.chrome-tabs` 空白区 `app-region: drag`）恒生效，Windows 去栏后自动成为主拖拽区，零改动；drag 区双击最大化为 Windows 系统内建行为（§2.2 / §2.3）
- [x] 未知点 4：项目所用 Electron 39 有无版本坑？→ 有：[#42409](https://github.com/electron/electron/issues/42409) ready-to-show 竞态（`show:false` + overlay + 打包后 `loadFile` 正是本项目主窗模式），39.x 未修、43.7.4+ 才修，须加 `did-finish-load` 兜底（§2.4 / §3）
- [x] 未知点 5：亮暗主题切换时系统按钮配色能否跟随？→ `win.setTitleBarOverlay()` 支持运行期改 color/symbolColor，项目外观广播链已逐窗改背景色，扩同链即可（§2.4）

### 1.3 拆分判断

单单元：主进程建窗配置 + 渲染层一处 CSS 避让，接入点集中，无跨层独立子问题。

## 2. 调研单元：Windows 主窗去标题栏 + 右上角窗口控制

### 2.1 该部分要做什么

Windows 主窗：隐藏系统标题条、以系统原生控制按钮浮层占据右上角、Tab 栏避让浮层。不负责：独立窗口（tear-off 小窗）与其他子窗（设置/建议/截图等）的形态，均保持原生标题栏；不负责 mac/Linux 任何行为。

### 2.2 项目现状

- **Windows 顶部栏的来源**：主窗建窗 `src/main/index.ts:208-224`——仅 darwin 配 `titleBarStyle: 'hidden'` + `trafficLightPosition`（三灯定位板头左端）；注释明确"Windows/Linux 不携带 query、保持系统框原形态（平台惯例沿用）"。Windows 的"顶部栏"即这条系统标题栏。
- **窗口右上角现状**：`src/renderer/src/App.tsx` MainShell 布局为左会话面板（板头 `.board-head` 40px）+ 右浏览器区；右上角即 Tab 栏（`.chrome-tabs`，40px，`src/renderer/src/assets/app.css:2098` 起）右端，栏内只有 Tab 序列 + 新建按钮，右端再无内容——用户"右上角没东西"属实。
- **Tab 溢出行为（边界情况根源）**：`.chrome-tab { min-width: 0 }` + `.chrome-tab-title { max-width: 180px; ellipsis }`（app.css:2140 段），Tab 栏无横向滚动——Tab 增多时逐个收缩、一直排满到栏右缘。若右上角叠加控制按钮，最右的 Tab 与新建钮会被遮住。
- **拖拽带已就绪（零改动）**：`.board-head`（app.css:264-268）与 `.chrome-tabs`（app.css:2117-2121）空白区 `app-region: drag` **无门控恒生效**，注释明确"Windows/独立窗冗余生效为无害增益，冻结现状不加门控"——Windows 去掉标题栏后这两条自动成为主拖拽区，无需任何改动。
- **平台门控先例**：主进程建窗注入 `winc=traffic` query（index.ts:253/261，仅 darwin），renderer 解析为 `windowTrafficControls`（`src/renderer/src/stores/browser.ts:256-257`）分流三灯占位/页内标题（`SessionPanel.tsx:216-222`）。
- **40px 顶区对齐契约**：板头与 Tab 栏均 40px 高、两线对齐（app.css:259-263 与 2107-2110 头注，2026-09-28 用户三裁决）——overlay 高度必须取 40 对齐此契约。
- **主题链挂点**：外观变化广播已 `getAllWindows` 逐窗 `setBackgroundColor`（index.ts 外观装配注释）——`setTitleBarOverlay` 同步配色可挂同链。
- **领域红线**：renderer 禁直接访问 Electron API（一切经 preload）；界面视觉改动实施时须走 impeccable 技能（AGENTS.md 界面设计节）；本功能无新增用户可见文案（不触 i18n）。

### 2.3 候选方案

**方案 A：WCO（Window Controls Overlay，系统原生控制按钮浮层）**

- 原理：`titleBarStyle: 'hidden'` + `titleBarOverlay: { height, color, symbolColor }`——标题条隐藏，最小化/最大化/关闭由 **Windows 系统绘制**浮于右上角；renderer 用 CSS 环境变量 `env(titlebar-area-width)` 得知控制区左缘位置（浏览器动态维护，resize/最大化自动更新），Tab 栏右 padding 按它避让。运行期可 `win.setTitleBarOverlay()` 换色跟主题。
- 来源：官方教程 [Custom Title Bar](https://electronjs.org/docs/latest/tutorial/custom-title-bar)、[BrowserWindow API](https://electronjs.org/docs/latest/api/browser-window)、W3C 标准 [WICG Window Controls Overlay](https://github.com/WICG/window-controls-overlay/blob/main/explainer.md)
- 与本项目的适配点：主进程建窗处加一个 win32 分支即可（mac 的 darwin 分支同款先例）；系统按钮悬停最大化钮可弹出 **Win11 原生 Snap Layouts**（系统绘制的天然能力，自绘做不到）；主题配色走既有外观广播链。

**方案 B：完全自绘窗口控制按钮**

- 原理：`titleBarStyle: 'hidden'`（不带 overlay），renderer 在 Tab 栏最右自绘三按钮，经 preload 新增 IPC 调主进程 `minimize/maximize/close`。
- 来源：官方教程 [Custom Window Styles](https://electronjs.org/docs/latest/tutorial/custom-window-styles)；双击最大化为 drag 区内建行为见 [#15163](https://github.com/electron/electron/issues/15163)
- 与本项目的适配点：按钮作为 Tab 栏 flex 子元素天然不与 Tab 重叠；但需新增 preload API + IPC + 按钮组件，且 **丢失 Win11 Snap Layouts**。项目 2026-09-20 已有"自绘窗口控制"被否、改用原生三灯的裁决（index.ts:198-204 头注），"窗口控制用原生"精神下不优。

**方案 C：`frame: false` 整窗无框**——看过不选：Windows 上与 `hidden` 效果基本等同但剥除更多系统行为（无障碍/窗控语义），且项目已有 `hidden` 先例，无增益。

### 2.4 可行性分析

| 维度 | 方案 A（WCO） | 方案 B（自绘） |
| --- | --- | --- |
| 技术匹配（Electron 39 / 需求覆盖与边界） | 15+ 支持、39 完备；`env()` 避让随最大化/resize 自动跟随，边界情况由 CSS 解决；两处已知坑均可规避（#42409 加 did-finish-load 兜底；#48193 避免 overlay 透明色） | 技术可行，避让天然（flex 子元素）；但无 API 唤起 Win11 Snap Layouts，属功能回退 |
| 规则冲突（红线 / 既有裁决） | 无；与"窗口控制用原生控件"裁决精神一致；mac 零改动（overlay 仅 win/linux 生效，且按 win32 门控注入）；须守 40px 顶区对齐契约（overlay height=40） | 无硬冲突，但需新增 preload IPC 面（renderer 不碰 Electron API 的红线要求多一层通道） |
| 成本（依赖 / 维护 / 耦合） | 零新依赖：主进程建窗一处 + 一条 CSS 避让 + 一个 show 兜底 + 主题链一处扩展 | 新增 preload API、IPC handler、按钮组件与态管理，维护面最大 |

### 2.5 结论与实施建议

- 结论：**采用现成方案（A：WCO）**——官方原生能力，实现量最小、保留 Snap Layouts、与既有"原生窗口控制"裁决一脉相承。
- 落地路径（实施时衔接 impeccable 技能做视觉细节）：
  1. `src/main/index.ts` createWindow：新增 `process.platform === 'win32'` 分支，配 `titleBarStyle: 'hidden'` + `titleBarOverlay: { height: 40, color, symbolColor }`（颜色取当前主题对应实色，对齐 40px 契约头注登记）；`ready-to-show` 显示逻辑加 `did-finish-load` 兜底（#42409 workaround，只显一次；升 43.7.4+ 后可移除并注释登记）。
  2. 外观广播链（`src/main/appearance.ts` 装配处）：外观变化时对主窗 `setTitleBarOverlay` 同步 color/symbolColor（对齐既有 setBackgroundColor 先例）。
  3. `src/renderer/src/assets/app.css` `.chrome-tabs`：右侧 padding 改为按 `env(titlebar-area-width)` 避让，形如 `padding-right: calc(10px + 100% - env(titlebar-area-width, 100%))`——未启用 overlay 的窗口（mac/Linux/独立窗）env 回退 100%，calc 结果即原 10px，行为不变，天然平台门控，无需新 query；Tab 多时既有 flex 收缩在避让线内完成，不与控制钮重叠，新建钮随避让区右移。
  4. 验收（Windows 真机）：dev 与**打包后**双验（#42409 在打包 `loadFile` 路径更易复现）；Tab 20+ 无重叠；最大化/还原/拖宽窗口避让跟随；亮暗主题按钮配色正确；悬停最大化钮弹出 Snap Layouts；HTML 视频全屏时按钮随系统全屏接管（Tab 栏亦不渲染，无冲突）；窗口拖动与双击最大化正常。

## 3. 风险与开放问题

- **#42409（必修项）**：Electron 39.x 未修，`show:false` + overlay + `loadFile` 下 ready-to-show 有概率不触发（曾报 28/33/37/38 版本均现），兜底写法见 issue 内 grovesNL 方案；升 43.7.4+ 后可撤。
- **#48193**：overlay color 用透明色（rgba(0,0,0,0)）时按钮 hover 背景渲染异常——配色必须用实色（主题 chrome-tabbar/chrome-surface 对应实色）。
- **#20070 / #15163**：drag 区双击最大化与程序化最大化的状态竞态为 Electron 老问题；本项目用 WCO（按钮系统管理、无自绘 maximize 调用），基本不触，备查。
- **env() 回退**：CSS 必须带 fallback 值（`env(titlebar-area-width, 100%)`），否则无 overlay 窗口整条 padding 声明失效。
