## 中（3 项）

### 中-1 busy 拒绝无任何反馈，PRD 验收语义回归

- 位置：`src/renderer/src/components/browser/Toolbar.tsx:79-84`（beginRecording 静默吞拒绝）；`src/main/browser/recording/index.ts:224-228`（busy → reject()）
- 问题：PRD 3.10.2/验收 37 明文「录制中再次发起（含跨窗口）被拒绝并以轻量反馈提示」。轮五清理悬停提示时把 busy 反馈的载体（title）连同整套 recBusyHint 一起删了，且未给替代通道——当前跨窗口二次发起录制时 UI 零反馈。
- 证据：beginRecording 现为 `await window.api.capture.begin(...)` 无任何拒绝分支；i18n 三语 capture.busy 键已删除（grep 0 命中）。
- 建议方向：按 AGENTS 反馈裁决补通道——独占拒绝属动作结果反馈，用主进程 information 型原生框（与录制完成框同路径，频率极低不打断）；或板面反馈条。同步回补三语 busy 键。

### 中-2 begin 内 getSessionName await 未防护，失败致「有态无采集器」卡录制

- 位置：`src/main/browser/recording/index.ts:250`（`await deps.getSessionName(...)` 无 try/catch）
- 问题：machine.begin 成功后进入 async 段，getSessionName（内部 loadSnapshot 读盘）若抛错，begin handler 整体 reject——机器停在 recording、无 collector/writer/readyTimer，UI 胶囊悬死且无任何反馈；用户可经 stop + STOP_FALLBACK 兜底恢复（finalize 零块→「开始录制失败」框），但经历一段不可理解的白等。
- 证据：loadSnapshot 直读 sessions.json（store.ts），坏 JSON 路径是否有内建回退未核；该 await 位于 generation += 1 之后、createCollector 之前的关键窗口。
- 建议方向：getSessionName 包 try/catch 回退 'session'（命名是尽力而为语义，不该让读盘失败击穿录制）；或把该 await 挪进 begin 前置预检段并整体回滚。

### 中-3 PRD 措辞与实现脱节（popover/悬停提示已废，契约未修订）

- 位置：`book/docs/requirements/PRD.md` 3.10.1（「悬停弹 popover 呈现功能名与快捷键提示」）、3.10.2（「悬停即弹 popover 呈现…暂停/继续」）、验收 37；对照实现 `src/renderer/src/components/browser/Toolbar.tsx`（无任何悬停提示、暂停/继续为常驻图标钮）与轮三/四/五用户裁决
- 问题：三轮交互裁决（Tooltip 向上、原生 title、最终整体移除悬停提示；Popover 改常驻暂停/继续钮）都记录在 DESIGN/验收文档，但 PRD 业务规则正文未按 AGENTS「实现与设计冲突先改文档」流程回改——PRD 是业务规则唯一依据，当前与实现字面冲突。
- 证据：PRD.md 与 Toolbar.tsx 现状逐条对照；DESIGN「工具栏提示终态」条目已记录终态但 PRD 未动。
- 建议方向：PRD 3.10.1/3.10.2/验收 37 按「无悬停提示（图标语义自明）+ 录制态常驻暂停/继续钮 + 胶囊点击停止」修订；或经用户裁决回改实现。属文档契约修订，非代码缺陷。

## 低（8 项）

### 低-1 partitionFor 单源旁路复制

- 位置：`src/main/browser/recording/index.ts:36`（`persist:sess-${sessionId}`）
- 证据：registry.ts:60-65 有同名私有函数（中-4 修复时对齐过前缀）；注释自称「同构」但仍是两份拼装逻辑，registry 侧未来改动（如前缀调整）不会联动。
- 建议方向：registry 导出 partitionFor（或经 deps 注入 getPartitionDir——chromeImport 已有同款注入先例），录制域改消费。

### 低-2 fileWriter 头部注释整行重复

- 位置：`src/main/browser/recording/fileWriter.ts:35-36`（「分块落盘器实例…」连续两行完全相同）
- 证据：Read 可见。
- 建议方向：删一行。

### 低-3 capture store tick 字段无消费方

- 位置：`src/renderer/src/stores/capture.ts:28`（ticker 每秒递增 tick）、`:38`（字段声明）
- 证据：全 renderer grep 仅 store 自身写入；Toolbar 轮五改用 `now` 字段驱动时长后 tick 成死字段（每秒仍触发一次无意义的 store 写）。
- 建议方向：删 tick，ticker 只更新 now。

### 低-4 采集器四通道 chunk 无大小上限

- 位置：`src/main/browser/recording/captureView.ts:128-130`
- 证据：仅校验 `instanceof ArrayBuffer`，单块大小不限（MediaRecorder 500ms timeslice 实际块很小；发送方是内置受控采集页）。
- 建议方向：纵深防御加上限（如 8MB/块拒绝），非必须。

### 低-5 recording-tmp 半截 .part 无清理策略

- 位置：`src/main/index.ts`（装配注入 userData/recording-tmp）；`src/main/browser/recording/fileWriter.ts`（失败保留语义）
- 证据：崩溃/失败保留的 .part 文件无任何清扫路径，长期使用会缓慢累积。
- 建议方向：应用启动时清扫 recording-tmp 下全部 .part（无并发录制方，启动期恒安全）。

### 低-6 begin 成功后无即时广播，胶囊出现延迟至采集器 ready

- 位置：`src/main/browser/recording/index.ts:265-272`（首次 broadcast 在 onReady）；Toolbar 渲染态仅由 stateChanged 驱动（begin 返回值被忽略）
- 证据：实测点击录屏钮后胶囊出现有 1-8s 延迟（采集页加载 + getDisplayMedia 握手时长）。
- 建议方向：begin 受理后立即 broadcast(recording)（现返回值即含该态，加一行）；或 renderer 乐观态。属体验打磨。

### 低-7 采集器窗口在应用退出时的收尾路径未验证

- 位置：`src/main/browser/recording/captureView.ts:117-120`（closed → onError）；`src/main/browser/recording/index.ts`（settle → showInfoBox）
- 证据：应用退出（Cmd+Q）时所有窗口关闭 → 采集器 closed → onError → settle → showInfoBox 可能弹在退出过程中，阻塞或闪烁；录制中的行为未实测。
- 建议方向：app before-quit 挂钩子静默中止录制（不弹框），或实测确认无碍后记录豁免。

### 低-8 state.ts RECORDING_BUSY_MESSAGE 导出无消费方 + 头注过时

- 位置：`src/main/browser/recording/state.ts:18`（导出常量）、头注「装配点以 RECORDING_BUSY_MESSAGE 识别后映射 i18n capture.busy 文案」
- 证据：grep 全仓无消费方（begin 的 catch 不区分错误类型）；capture.busy i18n 键已在轮五删除。
- 建议方向：删导出与头注过时段落，或随中-1 补 busy 反馈时恢复消费。
