## 2. 八项必查结论

### 2.1 重复代码

结论：发现 2 个问题。

- [ ] **[低-1]** `escapeHtml` 旁路主进程转义单源
  - 位置：`src/main/browser/toolbarTooltip.ts:9-10`
  - 描述：新文件自带本地 `escapeHtml`（数字实体写法），而 `src/main/browser/html.ts:14-16` 是主进程自绘 HTML 插值面的转义单源，其头注明令"改转义规则只改此处，禁止各持实现（审查低-1 收敛）"。tooltipHtml 的 label/keyText 插值正是该单源定义的消费场景（renderer 可控字符串进 innerHTML）。
  - 证据：`html.ts` 头注："dragPreview 虚影卡与 manager 错误卡两处消费——页面可控输入…进 innerHTML/模板串前一律转义…禁止各持实现"；toolbarTooltip.ts:9 `const escapeHtml = (value: string): string => value.replace(/[&<>"']/g, (char) => \`&#${char.charCodeAt(0)};\`)`。
  - 建议方向：删除本地实现，改 `import { escapeHtml } from './html'`（同目录 manager.ts 先例），并顺带更新 html.ts 头注的消费方清单。

- [ ] **[低-2]** 气泡视觉规格双份维护、无单源约束
  - 位置：`src/renderer/src/assets/app.css:2461-2478`（`.chrome-tools-pop` 测量层）与 `src/main/browser/toolbarTooltip.ts:13-36`（tooltipHtml 渲染层）
  - 描述：气泡的度量配方（字体栈 `-apple-system,…,'Segoe UI',sans-serif`、12px/1.4、padding 5px 10px、gap 6px）在 renderer 测量层与主进程渲染层各写一份，当前逐值一致所以测量准确；但两份之间无编译期/单源约束，任一侧单独改动即漂移，症状是原生子窗气泡尺寸错位（裁字或空腔）且难排查。字体栈还与 app.css:161-162 的 body 全局栈第三份同值。
  - 证据：app.css `.chrome-tools-pop` 保留 `font-size: 12px; line-height: 1.4; padding: 5px 10px; gap: 6px; white-space: nowrap`（注释"本 DOM 只精确测量文字与键帽尺寸"）；tooltipHtml 内联 `font:12px/1.4 -apple-system,…` + `.tip` padding 5px 10px + gap 6px。
  - 建议方向：参照 omniboxSuggest 四度量常量与 CSS 同源配对的先例（DESIGN.md:327"四个度量常量与 .chrome-omnibox-suggest 系 CSS 同源配对（shared/omniboxSuggest.ts 单源，改一处必改另一处）"），把字体串与关键度量收敛进 `shared/toolbarTooltip.ts` 导出常量，两侧消费；至少补交叉引用注释互为对账。

结论：已查，未发现问题。

### 2.3 竞态条件

结论：发现 1 个问题。

- [ ] **[低-3]** 悬停中点击按钮时气泡闪断一次
  - 位置：`src/renderer/src/components/browser/Toolbar.tsx:234-255`（useLayoutEffect cleanup 调 hide、effect 体调 show）
  - 描述：悬停期间点击工具栏按钮（span 槽的 onMouseEnter 已示泡，点击使内层 button 获焦又触发 onFocus → showToolsPop）→ 300ms 后 setToolsPop 生成新对象 → effect 重跑：cleanup 先 `toolbarTooltip.hide()`（原生子窗立即隐藏）再 show（loadURL 完成后才 showInactive）——异步间隙气泡消失再重现，视觉闪断。toolsPopLabel 变化（刷新↔停止切换）同理重跑，但那是预期跟随；同值重发属无谓闪断。
  - 证据：effect 依赖 `[toolsPop, toolsPop, toolsPopLabel, toolsPopKeyText]`（对象恒新），cleanup 无条件 `hide()`；主进程 revision 守卫只防"迟到回调复活气泡"，不防"主动 hide 后同值重 show"。
  - 建议方向：show 前对上一次已发 payload 做同值短路（label/keyText/坐标未变则跳过本次 show+hide 对），或将 hide 从 cleanup 挪到 toolsPop 变 null/卸载时发送。

- 其余竞态面已查无问题：revision 守卫正确（迟到的 loadURL resolve 不复活气泡；被顶替的 loadURL 以 ERR_ABORTED 拒绝，catch 内 revision 不匹配即静默，不误 hide）；owner 的 blur/resize/move dismiss + closed dispose（解监听 + entries 删除 + win.destroy）完整，dispose 幂等可重入；300ms 延迟计时器卸载清理；entries 惰建复用、isDestroyed 重建路径一致；无轮询/重复注册。
