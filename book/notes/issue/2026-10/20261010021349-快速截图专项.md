## 发现的问题

### 中-1：「加速键串 → 平台化键帽」存在双源实现

- 严重程度：中
- 位置：`src/renderer/src/components/settings/PaneShortcuts.tsx:81-93`（accelKeyGroup）与 `src/shared/settings.ts:130-148`（shortcutDisplay）
- 问题描述：同一逻辑（CmdOrCtrl→⌘/Ctrl、Shift→⇧、字母大写、平台派生）两处实现——Toolbar 悬停 popover 消费 shared 单源 `shortcutDisplay`，PaneShortcuts 键帽回显/冲突文案消费组件内私有 `accelKeyGroup`。措辞或键帽规则演进时两处漂移。
- 证据：`accelKeyGroup` 返回 `string[]`（`['⌘','⇧','C']`）、`shortcutDisplay` 返回拼接串（macOS 无分隔符 `⌘⇧C`）——仅输出形态不同，派生规则逐行同构。
- 建议处理方向：shared 增 `shortcutKeyGroup(accel, platform): string[]`（数组形态），`shortcutDisplay` 与 PaneShortcuts 均从它派生；组件删私有实现。

### 低-1：反馈子窗池与建议子窗池约 200 行结构性同构复制

- 严重程度：低
- 位置：`src/main/browser/captureFeedbackWindow.ts:84-217` 与 `src/main/browser/omniboxSuggest.ts:97-230`
- 问题描述：懒建复用池的五段机制代码（existing 复用 / follow 跟随挂摘 / closed 清池 / render-process-gone / ready-to-show flush + loadURL 双路径）逐段同构，仅 computeBounds、数据通道与 focusable 差异。
- 证据：两文件的 `show` 函数体结构对照（池 Map、ChildEntry 形状、move/resize 监听对）。
- 建议处理方向：可抽 `createLazyChildWindowPool` 共享工厂（泛型化 entry 数据与 bounds 计算）；但仓库现状 settingsWindow/workspacePickerWindow 也各自持窗，属既有惯例，抽取可在录屏专项引入第三个子窗时一并做（三处再抽象更划算）。

### 低-2：反馈条显示期间宿主 resize 后条宽不跟随

- 严重程度：低
- 位置：`src/main/browser/captureFeedbackWindow.ts:137-141`（follow 回调用缓存 anchor 重算）
- 问题描述：follow 只以缓存锚点（anchorWidth 为显示时刻值）重算位置——宿主变宽后条不满宽、变窄后右侧溢出。反馈条生命周期 ≤6s 且 resize 时通常不在意反馈条，实际影响小。
- 证据：`follow = () => win.setBounds(computeBounds(owner, entry.anchor))`，anchorWidth 是 show 时刻快照。
- 建议处理方向：resize 事件（区别于 move）时按宿主内容区现宽 clamp/重算，或 shell 侧 resize 监听重发 show-feedback；或接受并注释声明。

### 低-3：danger 反馈条无自动隐藏，切换会话/窗口后可能残留陈旧反馈

- 严重程度：低
- 位置：`src/renderer/src/stores/browser.ts`（showCaptureFeedback——danger 不排定时器）
- 问题描述：danger 持续至下一次截图动作是定稿语义，但用户不再截图而切换会话/关闭窗口时，反馈子窗仍悬于新内容上方（内容为通用错误文案，无会话指向，误导性低）。
- 证据：`if (kind !== 'danger')` 才排 6s 定时器；applySnapshot 会话漂移路径无 hideFeedback 调用。
- 建议处理方向：applySnapshot 检测 sessionId/window 漂移时 fire-and-forget `hideFeedback()`（与查找栏切 Tab 即关的先例同语义）。

### 低-4：反馈子窗页面加载失败完全静默

- 严重程度：低
- 位置：`src/main/browser/captureFeedbackWindow.ts:185-192`（loadURL/loadFile 的 `.catch(() => undefined)`）
- 问题描述：子窗建出但页面加载失败（本地文件损坏等低概率）时无任何日志，症状为「点截图无任何反馈」，不可追溯。与建议子窗同款静默（先例一致），但反馈条是唯一结果通知面，静默代价更高。
- 证据：`.catch(() => undefined)` 两处。
- 建议处理方向：catch 内 `console.warn('[capture-feedback] 子窗加载失败:', error)`（保留静默不弹错，只补留痕）。

### 低-5：骨架文档顺手修正 locales 命名空间计数（越界备注）

- 严重程度：低
- 位置：`book/docs/architecture/项目骨架.md:105`（七命名空间→八，补 chromeImport）

- 证据：`git diff book/docs/architecture/项目骨架.md` 中该行与本专项无直接关联。
