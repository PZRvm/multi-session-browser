### 2.2 权限漏洞

结论：发现 1 个问题（低）。

  - 描述：任何持 preload 桥的 webContents（独立窗口/sheet 子窗）可对任意格式合法的会话 id 请求弹出原生菜单。危害分析：菜单纯 UI 无数据面；点击动作推回发起者后 renderer 按 `payload.id === session.id` 过滤（SessionRow.tsx:215-218），幻影 id 无行匹配即忽略——实际可利用性趋零。但对照同仓库 dialog:show 的 sender 白名单惯例（workspacePickerWindow「拒绝非主窗来源」）是同类缺口。

  - 建议方向：对齐 dialog:show 先例加 sender 白名单（主窗 shell）；顺带在组装菜单前查一次快照存在性（幻影 id 直接静默返回）。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 2 个问题（低）。

- [x] **[低]** popup handler 坐标只校验非负有限、无上界（2026-10-20 复核勾销：`sessions.ts:917-918` 坐标 clamp 进窗口内容尺寸，同日修复轮已落）
  - 位置：`src/main/sessions.ts:863-874`
  - 描述：x/y 接受任意大数值（如 1e9），Menu.popup 会把菜单定位到远超屏幕的位置；macOS 对越界菜单的表现未验证（可能自动 clamp 到屏内，也可能不可见）。跨 IPC 载荷不可信任口径下宜收紧。
  - 证据：守卫链仅 `Number.isFinite(x) && x >= 0`，无上限。
  - 建议方向：clamp 到发起窗口内容尺寸（win.getContentBounds()）内再交 Menu.popup。
- [x] **[低]** ⋮ 按钮在行内编辑态点击静默无响应（2026-10-20 复核勾销：编辑态可弹口径已落 `SessionRow.tsx:182-186`——批量态才拦、右键另有编辑态 gate，静默路径已消；同日修复轮已落）
  - 位置：`src/renderer/src/components/SessionRow.tsx:180-183`
  - 描述：requestRowMenu 守卫 `mode !== 'none'` 直接 return——旧 DOM ⋮ 菜单在编辑态可用（重命名/克隆/删除），现在编辑态点 ⋮ 无任何反馈也无菜单，行为收窄未提示。
  - 证据：requestRowMenu 首行守卫；⋮ 按钮渲染条件仅 `!batchMode`，编辑态仍可见可点。
  - 建议方向：接受收窄并补注释声明（编辑态语义互斥），或编辑态点击先退出编辑再弹菜单——取一即可，关键是消除「点了没反应」的静默。
