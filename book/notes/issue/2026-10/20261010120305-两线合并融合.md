### 2.1 重复代码

结论：发现 2 个问题。

- [x] **[低]** app.css `.chrome-tools-pop` 规则系两份并存（合并冲突各留一份）（2026-10-10 修复轮闭环）
  - 位置：`src/renderer/src/assets/app.css:2377-2407`（截图线版，注释「反馈五定稿」）与 `src/renderer/src/assets/app.css:2661-2691`（录屏线版，注释「轮六」）
  - 描述：两线各自实现了逐字同构的自绘 tooltip（录屏线提交语自述「与截图线逐字同构以便合并」），同名类各自成块；自动合并把两份都保留。规则体当前字节等价，视觉无差，但 CSS 后者覆盖前者——任何后续只改其中一份的维护行为都会被另一份静默覆盖或并存分歧，属「改一处必忘另一处」陷阱
  - 证据：`grep -c` 基座选择器 4 处（2 份 `.chrome-tools-pop` + 2 份 `::after`）；`git show 8efb230:...app.css` 与 `git show e31ebba:...app.css` 各有一份；全文件重复选择器扫描仅此一族
  - 建议方向：删一份（保留位置更合理者，建议保留 2377 处紧邻 `.chrome-tools` 主块的那份），注释合一注明两线同构来源；顺带评估融合中被删的 `.chrome-tools > span` 触发槽规则（`.chrome-tools` 为 flex 容器、span 作为 flex 项自动包裹按钮，功能无碍，但其「disabled 钮不派发鼠标事件、span 槽承接 hover」的知识注释随之丢失——可在保留份注释中补一句）

- [x] **[低]** 「会话名清洗 + 时间戳 + 同名序号」文件名纯函数跨线重复且行为分歧（2026-10-10 修复轮闭环）
  - 位置：`src/main/browser/capture.ts:63-134`（sanitizeFileNameSegment / formatCaptureStamp / resolveUniqueCapturePath）与 `src/main/browser/recording/name.ts:30-104`（sanitizeSessionName / formatRecordingTimestamp / resolveDownloadPath）
  - 描述：两线各自为「下载目录内按会话名落盘」实现了同一域的三组纯函数，行为有分歧：非法字符替换为空格 vs 下划线；同名序号上限 1000 vs 100；存在性探测对非 ENOENT 错误重抛（capture pathExists）vs 一律按不存在（name fileExists）；空名回退 'capture'/'session' 两套。时间戳格式逻辑（YYYYMMDD-HHmmss 补零拼装）完全相同
  - 证据：两文件并排比对（本审查通读）；时间锚点语义不同（截图=保存时刻、录屏=开始时刻）是合理的业务差异，但清洗/序号/探测无业务理由分歧
  - 建议方向：抽共享纯模块（如 `src/main/browser/downloadNaming.ts`）单源清洗与序号探测，替换字符、序号上限、探测错误策略作参数或统一裁决；两处调用方保留各自时间锚点语义

### 2.2 权限漏洞

结论：已查，未发现问题。

- preload 白名单无扩张：capture 命名空间为两线方法并集，`electronAPI` 仍不暴露（preload 尾部收口注释在位）；采集器桥 `__msbCapture` 物理隔离于多入口产物，不进 UI 白名单（electron.vite.config.ts rollupOptions.input 双入口）
- display-capture 双门核过：check/request 两处全局放行（`permissions.ts:280/323`）仅越过询问环节，真门在分区 session 的 `setDisplayMediaRequestHandler`（`captureView.ts:88-106`：请求方须为采集器顶层 frame + frameToken/URL 双保险 + file://，目标 frame 现取存活，页面自身请求一律 `callback({})` 拒绝）；未注册 handler 的分区回到 Electron 默认拒绝（destroy 显式置 null，`captureView.ts:160`）
- 'media' 免询问放行有身份门：`permissions.ts:336-342` 要求 `isRecordingCollectorUrl`（file:// + capturePage*.html）且 `collectorGate.webContentsId === webContents.id`，伪造同名页不可命中；gate 登记于建窗（`captureView.ts:79`）、清场于 destroy 带身份比对（`captureView.ts:162`）
- 采集器窗 webPreferences 无削弱：nodeIntegration false、contextIsolation true（sandbox:false 为多入口共享 chunk 所需，对齐主窗先例并有头注）
- 反馈子窗 sender 白名单：feedback-action 经 `resolveOwnerOf` 只认池内子视图（`capture.ts:312-324`）；showFeedback/hideFeedback 经 resolveSenderScope 作用域解析
- 路径穿越：无用户可控路径拼接——文件名清洗两套均覆盖 Windows 保留集 + 控制符 + 码点截断；sessionId 经 SESSION_ID_RE（begin 载荷守卫 `recording/index.ts:232-239`）
- 会话隔离不变量：截图纯读零分区触达；录屏采集器建在被录分区、授予目标为被录 Tab 的 WebFrameMain，无跨分区串味
