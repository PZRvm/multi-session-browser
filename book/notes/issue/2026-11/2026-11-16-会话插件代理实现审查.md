# 会话插件代理实现审查

范围：216a444 后本轮代理实现与临时关闭接线。按 review-checklist 十一项检查：

- 重复代码：代理原生应用和恢复由 browser/proxy 单源执行。
- 授权：原生来源、Session、proxy 权限与暂停/退休检查；发现 R1，见下方。
- 竞态：原生设置和文件事务串行；挂载排空、卸载事件等待及重载间隙阻断已回归。
- 事务：原生失败不提交文件，落盘失败恢复旧原生状态；损坏文件拒绝覆盖。
- 通知：有效值去重广播，错误事件隔离，失败 callback 的 lastError 有界。
- 边界：配置、端口、URL、字节数、请求数、scope、超时与权限验证。
- 复杂度：PAC 尾标是 mandatory 失败关闭所需；未加入第二代理引擎。
- 需求追溯：原版代理主流程与生命周期；未加入网站反检测。
- 体验：手动优先来自用户裁决，原生页面同 Session，agent 模式不抢焦点。
- 范围：没有 renderer 视觉修改、版本变更或发布操作。
- 分级：L，已有 Step 0 与设计，不降级。

R1：shims 在入队前验证扩展权限；异步读取安装清单和代理队列期间，扩展可能卸载。队列执行时应再检查原生已加载且具 proxy 权限；否则旧调用可能重新保存孤立记录。此阶段只记录，不在审查中修改。下一轮按下方定向修复执行。

## R1 定向修复计划（L）

Step 0：仅修复过期调用写入风险；不改配置语义、IPC 结构或界面。目标是卸载后旧排队请求明确失败，宿主管理清理仍可执行。

Phase 1：异步清单读取与队列是两处身份时差；Session 存活不代表扩展仍加载。
Phase 2：在代理引擎锁内、所有 get/set/clear 前复验 native getExtension 与 proxy 权限；宿主卸载路径只允许内部 hostRemoval 跳过。新增卸载身份单元断言；通过后独立复核。

Phase 3/4：引擎锁内增加原生已加载/权限复验，内部宿主清除保持可用；卸载身份拒绝、缺失持久扩展阻断、扩展资源放行、mandatory 超时取消及文件0600单元断言通过。typecheck与lint通过（零错误、316既有警告）；前述生产构建和真实矩阵结果保持有效，新增检查只拒绝失效身份。

Phase 5 复核：检查调用点仅主进程内部可传 hostRemoval，IPC 不接受该字段；复验发生在锁内、任何读取/写入配置之前。未发现新增阻断问题。Phase 6：本记录、开发计划、ADR/PRD、实现快照、任务表、经验与报告已同步；平台待验继续保留。R1关闭。
