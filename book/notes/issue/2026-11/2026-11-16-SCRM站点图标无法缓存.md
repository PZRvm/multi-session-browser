# SCRM 站点图标无法缓存

用户反馈页面：`https://scrm.office.foreunit.com:8086/manage/auth/login?redirect=/manage/greeting-rules`。2026-11-16 在 feature/history-favicon 的 135c720 实现上只读排查，未改产品代码。

- 页面声明 `/xingqun-gravity-icon.png`，实测为有效 PNG、512×512、96,024 字节、HTTP 200；historyIcons.ts 的 MAX_BYTES=65,536，原图在落盘前被拒绝。
- `/favicon.ico` 返回 HTTP 200，但内容是 3,220 字节 HTML，与登录页响应哈希相同。无图标地址的旧历史没有其他候选；已有原图地址的历史也会在超限后回退到这里。
- 对当前模块注入两份真实响应字节，分别以原图 URL、null 图标地址连续调用两次 resolve，结果均为 null，落盘文件数为零。第二次命中 60 秒失败冷却，不再发请求；超过冷却仍会遇到同样的拒绝原因。

建议修复：区分原图下载上限与缓存大小，获取后缩小图像再落盘；对原地址缺失且根 favicon 不可用的旧历史，按真实页面的 link rel=icon 补充候选。保留会话网络身份、超时、并发、解码失败兜底与下载体积保护。不得用移除大小限制或接受 HTML 冒充图标的办法处理。

## 用户确认后的修复范围

用户选择仅允许较大图标、保留合理上限；已将 MAX_BYTES 提高到 256 KiB，不做缩图或页面发现。真实 96,024 字节响应经实际模块成功缓存，重复读取与重建服务读盘只调用一次下载；256 KiB 接受，超出 1 字节拒绝。11 项回归、typecheck 和 lint 通过，见 [上限修正计划](../../../plans/2026-11-16-历史图标体积上限修正.md)。

原图超限部分已修复。null 图标旧历史且根 favicon 返回 HTML 的部分仍 open，需重新访问页面取得图标地址，或后续补充页面发现；本轮不关闭整项 issue。
