## R1：构造失败后同一 Session 的引擎无法重新构造（中）

位置：`src/main/extensions/runtime/index.ts:67`、`:69`；固定依赖补丁作用点 `scripts/patch-extension-preloads.mjs:10`。依赖 CJS 4.10.0 补丁后 `index.js:2710` 先 `sessionMap.set(session2, this)`，`:2711` 再创建路由，后面还有各 API 构造与监听注册。

宿主 catch 只撤销本轮新增 preload，未清理库内部 WeakMap/已注册监听；宿主 `engines` 尚未写入，下次挂载会重新调用构造器，被库拒绝。普通网页仍可打开，受影响分区的插件要完整重启进程才能恢复。受限注册保证没有因此留下裸注入，但计划中“构造失败可重试”的要求尚未完全达成。

只读故障注入：读取已安装 CJS 的真实构造器，在 Node VM 中令 ExtensionRouter 首次构造抛出错误（没有改依赖文件，没有模拟为实际 Electron 异常）。结果：

```text
attempt=1 error=INJECTED_ROUTER_FAILURE dependencySessionRetained=true
attempt=2 error=Extensions instance already exists for the given session dependencySessionRetained=true
```

处理方向：单独修复库构造事务，建立可靠的失败清理或显式要求重启的状态；补齐构造器中段抛错后重试的验证。不能仅移动宿主 Map 写入位置声称已恢复。此处按 Phase 5 规则不修复。
