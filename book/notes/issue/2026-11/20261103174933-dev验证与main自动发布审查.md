## 2. 八项必查结论

### 2.1 重复代码

### 2.2 权限漏洞

已查，未发现问题。默认 contents: read，只有发布任务 contents: write；checkout 不保存凭据。发布不使用 pull_request_target，不执行未合并 PR 的发布代码；来源限制同仓 dev。PR 数据通过 env 传入 shell，版本与仓库标识白名单校验，外部命令采用 execFileSync 参数数组。

### 2.3 竞态条件

已查，未发现问题。全链路固定 merge_commit_sha；相同 PR 与相同版本发布各有互斥分组；创建远程标签后再次核对目标提交，不覆盖异提交标签。Latest 通过 make_latest=legacy 按语义版本确定，避免不同版本并发完成时强行将较早版本置顶。

### 2.4 事务边界

已查，未发现问题。三系统全部构建成功才进入发布；所有上传发生在草稿内，逐个核对数量、名称、字节数、SHA-256 后才公开。上传失败草稿可重试；已公开 Release 不更换附件。package 与 lockfile 版本同步。

### 2.5 通知遗漏

已查，未发现问题。版本冲突、构建失败、意外附件、网络错误和摘要不一致均失败退出并记录中文日志；不误报发布成功；签名与真机验收限制进入发布说明及文档。
