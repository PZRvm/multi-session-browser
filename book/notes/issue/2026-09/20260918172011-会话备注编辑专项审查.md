### 2.3 竞态条件

结论：发现 1 个问题（高——事件传播缺陷导致功能错误，为本轮核心发现）。

- [ ] **[高]** 行内编辑态 Enter/Space 冒泡至行级 onKeyDown：吞空格字符 + 顺带切换激活会话
  - 位置：`src/renderer/src/components/SessionPanel.tsx:200-203`（行级普通态分支，无 `e.target !== e.currentTarget` 守卫）、`src/renderer/src/components/SessionPanel.tsx:244-254`（备注 Input 未 stopPropagation；重命名 Input :224 同病，既有问题）
  - 描述：普通态行 onKeyDown 对 Enter/Space 一律 `preventDefault() + selectSession(session.id)`，且不检查事件来源。备注/重命名 Input 内的按键沿 DOM 冒泡到 li：① **空格**被行级 preventDefault 吞掉（字符无法输入）并触发 selectSession；② **Enter** 提交备注/名称的同时切换右侧浏览器到被编辑会话。因 `selectSession` 对已激活会话短路（`if (prev === id) return`），重命名活跃会话时从未暴露；但备注的典型用法恰是编辑**非激活**行，必现。
  - 证据：`@rc-component/input/es/Input.js:114-119` 的 `handleKeyDown` 仅回调 `onPressEnter(e)` / `onKeyDown?.(e)`，无 stopPropagation（链路闭合）；活体实验（隔离实例种子双会话「甲-激活/乙-编辑」，CDP 对乙行备注 Input 派发一次冒泡空格 keydown）：基线激活=甲，单次空格后激活行漂移为乙（`AFTER_SPACE {"activeNow":"乙-编辑"}`）。违反 PRD 验收 29「备注编辑态……不触发选中切换」与本计划步骤 3 验收⑤。
  - 建议方向：行级普通态分支补 `if (e.target !== e.currentTarget) return`（镜像批量态分支的既有守卫惯例），一处守卫同时覆盖重命名/备注两个编辑态；或对两个编辑 Input 的 onKeyDown 做 Enter/Space stopPropagation。重命名侧同病建议同轮一并修复。

- Enter/blur 双提交路径无竞态：Enter 提交后 Input 随条件渲染卸载，DOM 移除不派发 blur，无二次 IPC（与 rename 同构）；`mutateSnapshot` 临界区内完成存在性校验与写入，无 check-then-act 窗口。
