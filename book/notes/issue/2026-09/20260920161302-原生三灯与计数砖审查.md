## 2. 八项必查结论

### 2.1 重复代码

结论：已查，未发现问题。

- CountTiles 替换 FlapCounter 为替换非复制（静态裸数字 vs 翻牌动画砖，结构不同）；`flap-*` 旧类系 CSS 已随删除全净（grep 无残留）；themeSystems 的 `tileSeam` token 三处（接口/数据/映射）全净，全仓 grep `tile-seam|tileSeam` 零残留。
- 外观弹层覆写 `.appearance-menu`（app.css 950 行起）与组件 `className` 对应 ✓，无第二份同语义覆写。

### 2.2 权限漏洞

结论：已查，未发现问题。

- 本批次**净删除**了一条半成品 IPC 域（window:minimize / window:toggle-full-screen + preload 两方法 + windowControls.ts）——自绘方案废弃后这些通道已无消费方，删除后攻击面收窄而非扩大；grep 全仓无 `WINDOW_CHANNELS|windowControls` 残留。
- 建窗 query `winc=traffic` 仅 darwin 主窗携带（renderer 不经 navigator 推断平台，单源纪律与设置窗一致）；该 query 只门控渲染占位，不授予任何能力。
- 原生三灯为系统绘制与接管，不扩大 renderer 可达面。

### 2.3 竞态条件

结论：已查，未发现问题。

- `windowTrafficControls` 模块加载时解析一次（query 运行期不变），无时序面。
- CountTiles 为纯静态渲染（value clamp 到 pad 上限），无动画/定时器/监听器。
- 板头 drag 带与 TabStrip drag 带并存不冲突（各自独立行）。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题（本批次零落盘；i18n 键改名 flapCounter→countTiles 三语 + 消费方四处全同步，typecheck 的缺译硬门禁通过即无缺译）。

### 2.5 通知遗漏

结论：已查，未发现问题。

- CountTiles 容器 `aria-label`（`sessions.countTiles.aria`，`{n} 个会话`）三语落库、数字 span aria-hidden——读屏语义不因视觉降级丢失。
- 外观下拉 `placement="bottom"`（弹层居中于图标，用户反馈修正）：弹层 132px 在面板 [220, 420] 全宽区间内均有正余量，无翻转/裁切路径。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 0 个新问题（1 条既有耦合记录为低-2）。

- CountTiles：`value` clamp 到 `10^pad - 1`（99 上限），`pad` 缺省 2；负值不可达（length ≥ 0）。
- `winc` query 缺失（Windows/Linux/独立窗）→ spacer 不渲染、页内标题保留、原生标题栏并存——三形态（mac 主窗 / 非 mac / mac 独立窗）行为各自自洽。
- 遗留耦合留痕（低-2）：`trafficLightPosition {x:14, y:15}` 与板头实测高度 47px 强耦合（y = (47−16)/2），板头内容高度变化需再校准——注释已记录推导，建议后续板头高度调整时连同校验。

### 2.7 复杂度是否增加

结论：已查，未发现问题。

- 净方向是**减法**：删 3 个文件（FlapCounter/windowControls/window 契约）、删一条 IPC 域、删 6 条自绘钮 CSS 规则与翻牌动画 keyframes；CountTiles 18 行静态组件替代 60 行动画组件。
- 分层未破坏：平台门控单源在主进程建窗 query，renderer 只消费；`windowTrafficControls` 与 `windowIdentity` 同址解析（窗口身份语义内聚）。
