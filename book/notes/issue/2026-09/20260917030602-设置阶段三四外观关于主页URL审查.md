## 2. 八项必查结论

### 2.1 重复代码

结论：已查，未发现问题。

- `readableIpcError`（stores/settings.ts:12）全仓唯一（grep「Error invoking」仅此一处；外观域 setMode 失败路径不剥包装前缀，无既有同类实现可复用）。
- `broadcastSettingsChanged`（main/settings.ts:144）与外观域 `syncSnapshot` 的窗口遍历循环形似，但「分域并行、两域队列互不耦合」是 PRD 4.9 与两文件头注释的明文惯例，不属应收敛的重复。
- `normalizeHomepageInput` 复用浏览器域 `normalizeInput` 单源（scheme 白名单 + 缺省补全不在本域重写）；键位表经 `BROWSER_SHORTCUTS` 单源派生（PaneShortcuts 无键位第二副本，仅文案映射与行序）；快捷键中文文案与既有 UI 同词核对：刷新 = Toolbar title「刷新」、新建/关闭标签页 = TabStrip aria-label、开发者工具族 = Toolbar title（「打开或关闭开发者工具」为速查表语境的合理变体），页内查找/聚焦地址栏为无既有 UI 词的新定文案。

### 2.2 权限漏洞

结论：已查，未发现问题。

- 白名单分级与裁决一致：`settings:open` 白名单 = 主窗（既有）；`settings:open-data-dir` 白名单 = 设置窗 webContents（settingsWindow.ts:160-169，null/destroyed/异源一律拒绝并告警，冒烟实证主窗来源被拒）；get-app-info 无害信息不设白名单（对齐 appearance.getState 先例）；值域三通道不设白名单（对齐 appearance 先例，入参值守卫承担）。
- `setHomepage` 载值守卫：isRecord + homepageUrl typeof string（main/settings.ts:161-163）；URL 规范化经浏览器域白名单（http/https/file/about），renderer 拿到的值无法引导非白名单 scheme。
- 落盘路径固定（`userData/settings.json`），homepageUrl 不拼接任何文件路径/分区名，无穿越面；preload 新增五方法与 shared 常量一一对应，无绕契约暴露。

### 2.3 竞态条件

结论：发现 1 个低危问题（见 Todo 1）。

- 主进程 setHomepage 读-改-写的跨调用交错（两笔并发后写胜出）已在实现注释显式文档化，与外观域 setMode 同语义——有意裁决，不记问题。
- changed 推送在落盘成功后发起，拒绝路径零推送（冒烟计数实证）；广播对 isDestroyed 双重防御。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题。

- 写盘唯一入口 `saveSettings` → `atomicWriteJson` 单源（tmp+rename+失败清理），无旁路直写；串行队列只吞排错不吞调用方结果（`saveSettingsQueue = result.catch(...)` 模式与外观域一致）。
