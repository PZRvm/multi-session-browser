### 2.3 竞态条件

结论：发现 1 个问题

- [ ] **[高]** registerShellIpc 在 createWindow 内注册，macOS 关窗重开时二次注册抛异常
  - 位置：`src/main/index.ts:196`（注册点，位于 `function createWindow(): void`（154-247）函数体内）；`src/main/shell.ts:11`（ipcMain.handle 固定通道名）
  - 描述：macOS 关窗不退出，Dock 点击走 `activate → if (!mainWindow) createWindow()`（`src/main/index.ts:527-531`）重入 createWindow → 对同通道二次 `ipcMain.handle` 抛 "Attempted to register a second handler" → createWindow 中断，主窗无法重建。收起态下用户走「自绘关闭点关窗 → Dock 重开」即 100% 触发。此外被替换前注册的旧 handler 闭包持有已销毁的旧 win 引用，即使不抛也有 destroyed-object 风险。
  - 证据：`src/main/index.ts:529` `if (!mainWindow) createWindow()`；`registerShellIpc(win)` 实参为局部 `win`；Electron `ipcMain.handle` 同通道重复注册抛错为框架行为。
  - 建议方向：仿 `registerSettingsIpc(settingsWindowController, { getMainWindow: () => mainWindow })`（`src/main/index.ts:378`）的惰性取用模式——`registerShellIpc({ getMainWindow: () => mainWindow })` 移出 createWindow、放进 whenReady 一次性注册块（与 registerDialogIpc 同位）；handler 调用时现取主窗判空，sender 白名单判据随之用现取引用。
- [ ] **[中]** 收起态收起/展开切换在 setState updater 内发起 IPC 副作用
  - 位置：`src/renderer/src/App.tsx:78-88`
  - 描述：`setCollapsed((prev) => { ...window.api.shell.setNativeWindowButtonsVisible(...)... })`——updater 函数内含网络副作用，破坏「updater 必须纯」约定；main.tsx:58 起全局 StrictMode，dev 下 updater 双调用使每次切换发两条相同 IPC（现载荷幂等无实害，但属隐形地雷：后续换非幂等载荷即炸）。
  - 证据：StrictMode 确认于 `src/renderer/src/main.tsx:3,58`；updater 体含 `window.api.shell...` 调用。
  - 建议方向：handler 体内用当前渲染闭包的 `collapsed` 先算 `const next = !collapsed`，顺序执行 `setCollapsed(next)` 与 IPC 调用（onToggleCollapse 由点击事件驱动，闭包值即最新值）。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 1 个问题

- [ ] **[中]** tipOpen / plusTipOpen 在 Tooltip 无 unmount 回调路径下可能滞留 true，overlay 计数滞留
  - 位置：`src/renderer/src/components/SessionRow.tsx:178,243-247`（tipOpen）、`src/renderer/src/components/SessionPanel.tsx:162-167`（plusTipOpen）
  - 描述：overlay 登记依赖 antd `onOpenChange(false)` 复位，但 Tooltip 因触发器卸载而消失时（展开切换使行从 collapsed 分支切走、foot 从图标钮切回全宽钮）**不触发** onOpenChange(false)——tipOpen/plusTipOpen 停留 true，overlay 计数滞留 ≥1，页面视图持续收起不恢复。常规鼠标路径下离开行 0.2s 后会先复位，可绕过；程序化/快捷路径（如悬停中触发 HTML 全屏——panel-left 卸载则 SessionPanel 整体卸载走 effect cleanup 可自愈；但「展开切换」场景 SessionPanel 存活、仅行分支翻转，无 cleanup）会滞留。
  - 证据：`onOpenChange={setTipOpen}`（SessionRow）/ `onOpenChange={setPlusTipOpen}`（SessionPanel）；antd Tooltip 无 unmount 通知。
  - 建议方向：登记 effect 的键改用派生活动值——行级 `const tipActive = tipOpen && collapsed`（渲染期派生，React 认可的模式），SessionPanel 级 `const plusActive = plusTipOpen && collapsed`；或 collapsed 翻转处显式复位两个开关。
- 其余边界已查未发现问题：48px 轨道经 `.panel-left-collapsed` 解除 220/420 钳制；空视野轨道空白分支存在（emptyText=null 实测）；cloning 态在收起行保留 loading 语义；main/shell.ts 拒非布尔载荷；SessionRow 收起分支 onKeyDown 无内层控件故缺 target 守卫不构成缺陷。
