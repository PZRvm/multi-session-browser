## 2. 八项必查结论

### 2.1 重复代码

结论：已查，未发现问题。

- `newUserTab` 唯一实现在 manager（`newTab(opts.getHomepageUrl() || undefined, windowId)`）；registry 侧一行薄委托，与其 newTab/closeTab 等命令兼容面委托同构（既有惯例非重复）。
- 主页地址单源：newUserTab 只读注入的 `getHomepageUrl`（缓存），renderer 不传默认地址，无第二套规则。

### 2.2 权限漏洞

结论：已查，未发现问题。

- 无新增 IPC 通道与 payload 面；getHomepageUrl 为只读内存值注入（依赖注入风格沿 getWindow 先例，不跨域直接 import）。
- newTab 的 loadURL 目标仍受 setHomepage 写侧守卫链约束（scheme 白名单 + 长度）；settings.json 路径固定无穿越面。

### 2.3 竞态条件

结论：已查，未发现问题。

- `initHomepageCache` 在 whenReady 内建窗前 await，先于一切 newTab / applyRestore 可能路径。
- 缓存更新在 `saveSettings` 落盘成功之后（先盘后缓存），与 changed 广播同序；两笔并发 setHomepage 的后写胜出语义与阶段四一致。setHomepage 在途时新建 Tab 读旧值属可接受的最终一致（Chrome 同语义）。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题。

- 缓存与盘面无多文件事务：极端时序（落盘后、缓存更新前崩溃）最多缓存滞后一拍，下次启动经 initHomepageCache 重读盘收敛。
- 恢复径（applyRestore 恢复集非空逐条 newTab(url)）与 window.open（newTab(openUrl)）零改动——冒烟 B 轮与 A 轮第 5 项实证。

### 2.5 通知遗漏

结论：已查，未发现问题。

- `initHomepageCache` 不抛错（loadSettings 全路径容错回默认骨架：ENOENT 静默、坏 JSON/非对象/未知 version 中文告警），不会阻断 whenReady 启动链。
- 主页非法拒绝路径沿用阶段四红显链，无新增静默失败面。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：1 个低危注记（见 Todo 1，属上轮遗留交集）。

- 缓存空串 → `|| undefined` → 空白 Tab（冒烟「清空主页后新建回空白」实证）；file/about scheme 直通（冒烟 C 实证）。
- 读盘原值未经写侧规范化即入缓存（手改 settings.json 场景）——见 Todo 1。

### 2.7 复杂度是否增加

结论：已查，未发现问题。

- 语义分流以一个新方法 + 三处调用替换实现，未加标志位或分支参数；TabManager/SessionBrowserRegistry 接口各增一成员（registry 经 extends 自动获得）；注释密度与仓风一致。
- 分层未破坏：renderer 零改动（仅一行文案）；主进程内 settings → registry → manager 单向注入。

### 2.8 作用域外的改动

结论：已查，无新增越界。

- 全部改动映射计划任务（含契约文档同步）；与阶段三/四同工作区叠加为已声明的执行前提（计划头部 + 验收文档），提交时需按特性分批——组织性提醒，非代码缺陷。
