### 2.1 重复代码

结论：发现 1 个问题。

- [ ] **[低]** 300ms 菜单延迟兜底在两处重复实现、魔数无单源
  - 位置：`src/renderer/src/components/SessionRow.tsx:200-202`（deferWhileMenuCloses helper）、`src/renderer/src/components/WorkspaceSwitcher.tsx:314-319`（内联 `window.setTimeout(action, 300)`）
  - 描述：同一「先让菜单动画走完再挂窗口模态弹层」的 workaround 及其理由注释在两个组件各写一遍，300ms 魔数无单源；将来调整延迟或改机制（如 motion 关闭）需两处人肉同步，漏一处即卡显缺陷复发。
  - 证据：两处代码结构相同、注释语义相同（SessionRow「先让菜单动画走完再挂弹层」/ WorkspaceSwitcher「先让菜单动画走完再挂弹层」）。
  - 建议方向：提为共享工具（如 renderer dialogs.ts 或 components 层小模块）导出 helper 与 300ms 常量，两调用点收敛。

### 2.3 竞态条件

结论：发现 1 个问题。

- [ ] **[低]** 菜单延迟回调无卸载清理，组件卸载后仍会挂出弹层
  - 位置：`src/renderer/src/components/SessionRow.tsx:200-202、213、220-224`；`src/renderer/src/components/WorkspaceSwitcher.tsx:314-319`
  - 描述：菜单项点击后 300ms 窗口期内若组件卸载（视野切换/下拉面板关闭/会话删除），setTimeout 回调仍执行 → 挂出 sheet 或原生确认框。用户已确认该动作、主进程守卫兜底（工作区已消失 → cancelled），无错误状态；但属「卸载后回调仍执行」模式，且行为可感知（菜单已消失却弹出弹框）。
  - 证据：两处 setTimeout 均无 cleanup 句柄，无 mounted 判据。
  - 建议方向：接受现状则注释写明「已确认动作跨卸载有效」语义；严格化则记录句柄、卸载时 clear。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 2 个问题。

- [ ] **[低]** rename 场景 pick 守卫未强制禁传 workspaceId
  - 位置：`src/shared/dialog.ts:141-147`（WorkspacePickerPickPayload 注释「重命名场景禁传」）vs `src/main/workspacePickerWindow.ts:263-270`（rename 分支只校验 name）
  - 描述：show 通道做了「彼此禁传字段出现整单拒绝」，pick 通道对 rename 的 workspaceId 只在类型注释声明禁传、运行时不拒。sheet 是受控渲染端不会传，属防御深度口径不一致（契约注释承诺强于实现）。
  - 证据：pick rename 分支无 workspaceId 缺省检查；对照 show 的 parse 三分支均有禁传校验。
  - 建议方向：rename 分支补 workspaceId 缺省拒绝，或将注释降格为「忽略」与实现对齐。
- [ ] **[低]** rename 场景 payload 拉取失败时的兜底 UI 语义错位
  - 位置：`src/renderer/src/components/WorkspacePickerWindow.tsx:59、106-110、208-211`
  - 描述：context 为 null（payload 拉取失败/无在途请求）时统一渲染选择列表分支空态 + titleFallback「移动到工作区」族文案——rename sheet 若发生该防御路径，窗口会显示移动选择的标题与「暂无可选工作区」空态，语义错位。正常路径不可达（sheet 仅由主进程在途请求创建、payload 通道必中）。
  - 证据：isRename 分支以 `context?.kind` 判定，context null 时走列表分支兜底。
  - 建议方向：loadFailed 空态按上下文区分，或 rename 失败兜底渲染最小「关闭」形态。
