## 2. 八项必查结论

### 2.1 重复代码

结论：发现 2 个问题

- [ ] **[低]** `isRecord` 三处同构副本
  - 位置：`src/main/store.ts:25`、`src/main/sessions.ts:53`、`src/main/appearance.ts:27`
  - 描述：同一类型守卫在主进程三个模块各持一份私有副本；本专项新增第三处后达到可收敛阈值。
  - 证据：`rg -n "function isRecord" src/` 三处命中，函数体逐字相同。
  - 建议方向：收敛到 `src/shared/` 或主进程公共 utils；三处调用点等价替换。可作为专项后小重构，不阻断本专项。
- [ ] **[低]** 亮暗窗口背景色常量与 CSS token 双源同值
  - 位置：`src/main/appearance.ts:13-14`（`LIGHT_BACKGROUND '#f6f4ee'` / `DARK_BACKGROUND '#101418'`）对照 `src/renderer/src/assets/app.css:10`（`--board-bg: #f6f4ee`）与 `app.css:50`（`--board-bg: #101418`）
  - 描述：主进程 `BrowserWindow.setBackgroundColor` 必须与 renderer 板底 token 同值，否则启动首帧窗口背景与 UI 底色闪差。两处靠人肉对账，当前一致，DESIGN.md frontmatter 已记录两值；缺一处机械同步或显式交叉引用。
  - 证据：两文件字面量对照；`DESIGN.md` colors 段 `board-bg`/`board-bg-dark` 同值。
  - 建议方向：最低成本是在两处字面量旁互加“与 app.css --board-bg / appearance.ts 常量保持同步”注释；或在 DESIGN.md 标注该值的单一事实源地位。

### 2.2 权限漏洞

结论：已查，未发现问题

- preload 仅新增 `window.api.appearance` 三方法：get/set 经 invoke、`onChanged` 包装 listener 剥离 `IpcRendererEvent`、退订用同一 listener 引用精确 `removeListener`；无 `nativeTheme`/`ipcRenderer`/任意通道暴露。
- 主进程 `registerAppearanceIpc` 对 set-mode payload 以 `isRecord` + `isAppearanceMode` allowlist 校验，非法值拒绝且不改盘不改主题（验收 D3 实证）；`appearance:changed` 仅主进程 send。
- 无路径拼接用户输入（`preferencesPath()` 固定自 `app.getPath('userData')`，且 `MSB_USER_DATA` 重定向发生在 app ready 前）；无秘密泄漏；无新运行时依赖（package.json 零 diff）。

### 2.3 竞态条件

结论：已查，未发现问题（1 项理论路径裁决记录）

- `setMode` 以模块级 Promise 队列串行化，`this.setModeQueue = result.catch(() => undefined)` 防队列断链；同值幂等早退。
- 广播以 `{mode, resolvedTheme}` 完整 snapshot 去重（`lastPublishedSnapshot`），setMode 返回与 `nativeTheme.updated` 双入口不会产生重复推送；窗口列表 `BrowserWindow.getAllWindows()` 现取并带 `isDestroyed()` 守卫。
- 落盘先于 `themeSource` 赋值（计划第 3 节契约点 5 的既定顺序）：若赋值瞬间异常，磁盘已是新值而运行时停留旧值，重启自愈——理论路径（themeSource 赋值实际不抛），契约即此语义，裁决建议接受、无需改动。
- renderer store：`initialized`/`initializing` 模块级守卫防 StrictMode/HMR 重复注册，失败路径先退订再复位；HMR `import.meta.hot.dispose` 精确清理。`setMode` 以 `setting` 防重复提交、失败恢复提交前快照。
- `src/main/index.ts`：`await appearanceController.init()` 先于菜单安装与 `createWindow()`，activate 重建窗口读 controller 当前状态，窗口 `backgroundColor` 每次构造取实时 snapshot。

### 2.4 事务边界

结论：已查，未发现问题

- `preferences.json` 写入：唯一 tmp 文件（pid+时间戳+随机）+ `rename` 原子替换，失败路径 `unlink(tmp)` 补偿；独立于 sessions `mutateQueue`，两文件生命周期互不影响（验收 D1/D2 实证坏偏好不清会话）。
- 无跨资源事务需求；appearance 模块不 import registry/sessions。

### 2.6 边界遗漏

结论：已查，未发现问题

- `isAppearanceMode` 枚举闭集校验（shared 单一实现，主/预两端共用）；`version` 严格 `=== 1`；根节点对象校验；非法 mode/坏 JSON/未知版本/读失败四路均回退 system。
