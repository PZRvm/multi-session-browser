## 问题清单

### 中

**[中-1] dry-run/execute 失败弹框正文可能穿透英文 FS 错误，违反域内「错误口径 i18n 中文」约定**
- 位置：`src/main/browser/chromeImport/index.ts:226-232`（dry-run catch showResultDialog(body=err.message)）、`:322-328`（execute 同款）、`src/main/browser/chromeImport/siteData.ts` dryRun 目标侧 `cp(targetLeveldb, targetCopy, { recursive: true })`（无 wrapLock 映射）
- 证据：siteData 对「源侧锁」有 wrapLock → chromeLocked 中文；但 dry-run 目标侧拷贝（中-1 修复引入）与 execute 的还原路径失败、historySource 非 EBUSY/EPERM 的 fs 错误（EACCES/ENOSPC/EMFILE）原样上抛 → 主进程弹框 detail 直出英文 `Error: EACCES: permission denied, open '/tmp/...'`——用户可见口径与域内全部中文文案不一致；en/zh-TW 界面下反而「歪打正着」，zh-CN 下露英文
- 建议方向：在 chromeImport/index.ts 的失败弹框出口对 message 做一层兜底映射（fs 错误统一转 chromeImport.errors.failed 或按 code 细分中文文案），保留 logFailure 的完整原始错误留痕

### 低

**[低-1] 结果框与 keepOpen 加载态 sheet 的关闭存在短暂呈现时序**
- 位置：`src/main/browser/chromeImport/index.ts:319`（execute handler 内 showResultDialog 先于 invoke resolve）；`src/renderer/src/components/SessionPanel.tsx:271`（closeWorkspacePicker 在 execute 返回后调用）
- 证据：结果框（主窗模态）在 execute handler 内同步弹出，sheet 的关闭要等 invoke 响应回到 renderer 再经 close 通道往返——数十毫秒窗口内「导入中…」sheet 与结果框并存；macOS sheet 挂主窗顶部、信息框居中主窗，两者不重叠；Windows/Linux message box 居中可能短暂覆盖 sheet 区域
- 建议方向：可接受（窗口期极短）；若要消除，可把 keepOpen sheet 的关闭从 renderer 编排移到主进程 execute 完成点直调（架构微调，编排职责微调需过计划）

**[低-2] quiesce 内克隆互斥的 busy 文案与实际原因不符**
- 位置：`src/main/browser/registry.ts:683`（runImportQuiesced 入口 `cloningIds.has(id)` 抛 `t('chromeImport.errors.busy')`「该会话正在导入中，请稍后再试」）
- 证据：触发条件实为「该会话正在克隆中」，弹框文案会让用户去找不存在的导入
- 建议方向：增补 errors.cloningBusy 三语键区分，或文案泛化为「该会话正忙，请稍后再试」

**[低-3] chromeDetector 双实例**
- 位置：`src/main/workspacePickerWindow.ts:79`（chromeDetector 单例）与 `src/main/browser/chromeImport/index.ts`（detector 单例）
- 证据：同一 createChromeDetector 工厂被两个模块各自实例化（均无状态、行为一致，无害）；单源精神下探测入口宜收敛一处
- 建议方向：chromeImport/index.ts 导出 detector 单例供 workspacePickerWindow 复用，或接受双实例并注释说明

**[低-4] showResultDialog 的 detail 未设长度上限**
- 位置：`src/main/browser/chromeImport/index.ts:380-396`
- 证据：body 来自 summarizeResults（计数插值，定长）或 error.message（fs 错误可能含长路径）；主进程自身产出无跨 IPC 攻击面，但极端错误文本会撑高弹框
- 建议方向：detail 按 500-1000 字符 clamp（dialogs.ts DISPLAY_NAME_MAX 先例）

**[低-5] deps.getMainWindow 返回类型用 import('electron') 内联**
- 位置：`src/main/browser/chromeImport/index.ts:160-162`
- 证据：`getMainWindow: () => import('electron').BrowserWindow | null`——可改为顶部 `import type { BrowserWindow } from 'electron'`，与 registry.ts 的 import type 风格一致
- 建议方向：风格统一，随手改

**[低-6] MSB_CHROME_USER_DATA 指向非目录（文件/权限异常）时 listProfiles 非 ENOENT 错误静默收敛 cancelled**
- 位置：`src/main/workspacePickerWindow.ts:173-176`（buildContext select 分支）→ show handler catch → cancelled
- 证据：测试后门路径（非用户功能面）下，detector 上抛的权限类错误被 show handler 按组装失败收敛，用户只看到 sheet 消失无原因——正常用户路径不可达
- 建议方向：可接受（后门路径）；如需改善，cancelled 前留 warn 已有（logFailureAsync + 组装失败 warn）

**[低-7] 骨架 dialogs.ts 行未记 dialogIconForDarwin 导出与 information 型弹框职责**
- 位置：`book/docs/architecture/项目骨架.md` 3.1 dialogs.ts 行
- 证据：2026-09-30 图标反馈轮将 dialogIconForDarwin 从模块私有改为导出（chromeImport/index.ts 复用），骨架该行职责描述仍停留在「破坏性确认 + 会话处置三选」
- 建议方向：骨架 dialogs.ts 行补一句「dialogIconForDarwin 导出（darwin 项目图标，导入结果框等信息型弹框复用）」
