### 2.5 通知遗漏

结论：发现 1 个低级问题。

- **[低] 页内链点击的失败加载日志归零**（消噪副作用）
  - 位置：`src/main/warnings.ts:20`（吞掉条件）与 `src/main/browser/url.ts:40-42`（日志面）的组合覆盖面
  - 描述：`logLoadFailure` 只挂在应用的 4 处 `loadURL` 调用上（地址栏导航、恢复、克隆、newTab）；用户在页面内点击死链导致的失败导航不经过 `loadURL`，原本唯一记录就是被吞掉的 C++ 警告，现在主进程侧零日志。用户侧行为不变（Chromium 内建错误页照常呈现），仅 dev 排查追溯面收窄——「页面打不开」类问题在地址栏路径有单行日志、链点击路径无痕。
  - 证据：`grep -rn 'logLoadFailure' src/main` → 4 个调用点全部为 `wc.loadURL(...).catch`；页内导航无对应挂点。
  - 建议方向：若需保留追溯面，可在 manager 层挂 `did-fail-load`（isMainFrame 且非 ERR_ABORTED）补一条同样的单行日志；若判定「链点击失败属正常操作无须留痕」则在 url.ts 注释把该取舍写明，防后来者误当遗漏。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 1 个低级问题。

- **[低] ERR_ABORTED 静默判定用子串匹配存在误伤面**（预存缺陷，本次触碰函数内）
  - 位置：`src/main/browser/url.ts:40`
  - 描述：`error.message.includes('ERR_ABORTED')` 做静默判定，而 message 内含目标 URL 原文——若 URL 路径/查询串恰好含 `ERR_ABORTED` 字样（测试环境构造 URL 并非不可能），真实的连接失败会被误静默。reject 的 Error 对象实际携带 `code`/`errno`/`url` 结构化字段（用户日志实测可见 `{errno: -102, code: 'ERR_CONNECTION_REFUSED', url: …}`）。
  - 证据：`url.ts:40` 当前实现；loadURL rejection 字段结构见 2026-09-20 用户终端输出（含 code 字段的完整对象）。
  - 建议方向：改用 `(error as NodeJS.ErrnoException).code === 'ERR_ABORTED'` 精确匹配（保留子串匹配作兜底亦可），顺带消除对 message 文本的依赖。
