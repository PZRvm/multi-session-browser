## 2. 自动回归的具体结论

- 合并A保存中→主窗点击B：四方最终都为B。
- 选择B保存中→提交合并A：四方最终为更新的合并A。
- 合并保存中连续点B/C：最后成功选择C生效。
- 合并期间切工作区B：视野/激活会话与落盘一致。
- 后续选择保存失败：不发布失败状态，维持成功归并A。
- 合并期间会话/工作区乐观排序：各自保存后列表与磁盘顺序一致。
- 主窗录制或暂停态：归并改变激活页后状态机idle，原因auto。
- 来源子窗录制：tab-moved自动停止。
- 同会话另一未变化子窗录制：不误停，原窗/原Tab保持。

## 3. 从零启动与手动操作

1. 仓库根目录使用全新的空隔离目录运行：`MSB_USER_DATA=/tmp/msb-merge-review-manual-001 MSB_DEV_PORT=6194 npm run dev -- --inspect=9411 --remoteDebuggingPort=9412`。若旧测试实例仍占端口先关闭它；每次回归改隔离目录后缀。Windows PowerShell先设置同名环境变量，再运行npm run dev及对应参数。不要用真实userData目录。
2. 等待主窗口出现。终端运行 `node /tmp/msb-merge-check/repair-verification.mjs`，脚本在当前实例创建A/B/C与工作区，输出12条PASS与TOTAL12。脚本会临时替换当前测试进程的rename并在结束时恢复；全部仅作用于隔离数据。此脚本使用实际store/IPC与状态机，未向产品代码加入测试桥。
3. 鼠标验收：创建A和B，在A开两个Tab，拖出其中一个形成独立窗口。主窗口选B；独立窗口点最右侧「合并回主窗口」，同时在主窗快速点击B或C。全部命令完成后，检查左侧选中名、Tab列表、地址栏及显示页面属于同一会话。可再次切换工作区、拖拽会话/工作区排序，最终列表与重启后的顺序一致。确定性保存交错以步骤2的屏障检查为准。
4. 目标主窗录屏：同一会话A中，主窗显示页面M，独立窗口显示S。在主窗开始录屏并操作M，然后到独立窗点「合并回主窗口」。预期主窗显示S，录屏停止并保存M此前内容；录屏胶囊退出，原生信息框报告保存位置，MP4可播放。暂停后重复应同样结束。
5. 来源窗录屏：在独立窗S开始录屏，录几秒后点合并，预期录屏停止并保存，S按原页面状态回主窗，无第二次录制。
6. 其他子窗录屏：同会话开两个独立窗K/S，在K开始录屏，然后将S合并。预期K保持打开，录屏继续；手动停止K后文件可播放。此项确保只响应发生变化的来源/目标窗口。
7. 切换三语言、亮暗主题，悬停合并钮，确认已交付的箭头对齐与8DIP边距仍保留。本轮未改视觉相关代码；原功能验收见notes/accept/20261106131016-独立窗口合并回主窗口开发计划/。
