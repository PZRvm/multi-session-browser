# 浮动 DevTools 排查

后续：用户已授权兼容宿主，R1/R2 的修复与本机验收见[修复报告](2026-11-16-浮动DevTools修复.md)。以下保留修复前的排查记录。

2026-11-16，在 dev 的 `6c45905`、应用 1.1.5 上排查。宿主为 macOS，实际运行 Electron 45.3.0 / Chromium 156.0.8078.96。本轮只排查与登记问题，没有修改产品代码、依赖或用户数据，也没有执行发布。

## 设备按钮为何无效

用户截图中的按钮是“Toggle device toolbar”。它在浮动状态下会亮起，但设备模拟没有生效。对照结果如下，页面带有 viewport meta：

| 项目 | 右侧停靠，开启设备模拟 | 切为 undocked |
|---|---|---|
| 按钮状态 | 开启 | 仍显示开启 |
| 设备视图 | 显示，模型为 Responsive | 不显示，模型为 None |
| 网页 innerWidth × innerHeight | 390 × 844 | 999 × 740 |
| UA | Android 16 / Pixel 10 / Mobile | macOS 桌面 Chrome |
| navigator.maxTouchPoints | 1 | 0 |
| 页面启动标识、输入和 LocalStorage | 原值 | 保留，无重新加载 |

浮动状态下再次点击按钮也不能创建设备视图。因而从停靠切到浮动还会让原来有效的设备模拟退出，不能以按钮蓝色判断当前 UA 或触摸状态。

项目在 [manager.ts](../../../../src/main/browser/manager.ts) 的 `openTabDevTools()` 直接调用 `wc.openDevTools()`。运行时检查原生前端发现：

1. `AdvancedApp.openToolboxWindow()` 在转为 undocked 时调用 `window.open()`，目标为 `devtools://devtools/bundled/device_mode_emulation_frame.html`。
2. 实际返回 `null`；`toolboxWindow`、`toolboxRootView` 均未创建。
3. `updateForUndocked()` 隐藏主设备区域，缺少辅助宿主后设备视图无处挂载；`DeviceModeView.willHide()` 将模拟模型复位为 None。

同一实例中另建 `new BrowserWindow({ show: false })`，不经过项目的 Tab 管理、会话 partition 或页面 `setWindowOpenHandler`，也复现相同的 `window.open() → null`、按钮开启而模型为 None。根因已定位到本版本 Electron 原生 DevTools 对浮动设备视图的宿主集成，不能通过调整工具栏点击事件解决。本轮没有将问题外推到其他 Electron 版本或平台。

原生前端机制可对照 [Chrome DevTools AdvancedApp](https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/panels/emulation/AdvancedApp.ts)；本次结论以运行中的内置模块和最小窗口实测为准，上游 main 仅作阅读参考。

## 其他发现

**链接打开缺口。** 从浮动 DevTools 调用原生“打开新标签页”宿主入口，目标页面收到了 `devtools-open-url`，但页面、Tab 数量均未变化。项目没有处理该事件。Electron [事件文档](https://www.electronjs.org/docs/latest/api/web-contents#event-devtools-open-url)将其用于点击链接和右键 Open in new tab；现有网页 `setWindowOpenHandler` 不接收这条路径。浮动模式已实测；停靠模式共用该缺失接线，仍应在修复时单独回归。

**切换后旧调试窗仍绑定旧页。** A 打开浮动 DevTools 后切至 B，原 DevTools 仍读取 A 的 URL、LocalStorage 和启动标识，B 的工具栏显示未打开。切回 A 后其开关恢复为开启；同会话新建 A2 时，A 的 DevTools 也保留。本轮确认没有串数据，但行为不满足 PRD 3.3.2“切换会话后 DevTools 同步切换对应环境数据”的直观要求。后续应明确浮动窗是否随激活页切换可见性，继续保持每个工具只调试自己的 webContents。

详见[问题登记](../../issue/2026-11/2026-11-16-浮动DevTools问题.md)。

## 验证范围

测试使用 `MSB_USER_DATA=/tmp/msb-devtools-investigation-20261116`、`MSB_DEV_PORT=6191` 和 `npm run dev:agent`。本地 HTTP 夹具监听 6192；9222 用于 renderer CDP，9231 用于只读主进程检查及临时夹具。DevTools 开启使用临时 `activate:false` 包装并隐藏测试应用；关闭后台节流后等待布局更新再读取对照数据，避免隐藏窗口尚未渲染造成误判。没有将这些测试设置写入产品。

| 检查项 | 结果与证据 |
|---|---|
| Console 求值 | 正常，经浮动 DevTools 的运行时代理读取到 A 页标识和输入值 |
| Elements DOM | 正常，经 DevTools DOM 代理取到目标文档及 HTML 节点；未验证鼠标拾取覆盖层 |
| Network | 面板可打开；实际请求抓到 HTTP 200 |
| Network 断网 | 经 DevTools 网络模型设为 Offline 后 fetch 返回 TypeError，抓包标记 failed；已恢复 No throttling |
| Application 存储 | DevTools DOMStorage 代理读到 `probe=?A`，B 同源页面为 `probe=?B` |
| Sources | 面板可打开；`debugger; 6*7` 触发暂停，恢复后得到 42 |
| DevTools 内 Escape | 打开原生 Console drawer，工具保持开启，符合现有代码的焦点分工 |
| 原生关闭与重新打开 | `closeDevTools()` 后快照变为 false，再开变为 true，并创建新 DevTools webContents |
| 关闭所属 Tab | 页面 webContents 和它的 DevTools 均销毁，其他会话及最小对照窗口保留 |
| 切换 Dock side | 右停靠与 undocked 可切换，不刷新页面；设备模拟存在上文故障 |

这些是定向检查，不代表所有面板已完整验收。未测：真实键盘 F12、鼠标原生关闭按钮、Performance 录制、Memory 快照、第三方 DevTools 插件、多显示器/窗口几何恢复、Tab 跨应用窗口转移、Windows/Linux。隐藏模式下两种程序注入的 F12 都未触发 `before-input-event`，不能据此判定用户实际 F12 正常或失败。

临时证据保存在 `/tmp/msb-devtools-evidence/`：`docked.png`、`undocked.png`、`evidence.json`。JSON 同时保留探索过程的中间状态，不将其全部列作通过证据；最终 390×844 对照以本报告表格为准。临时文件可被系统清理，复现步骤和关键数据已保留在 book。

## 后续方向

目前设备模拟可先用已验证的右侧停靠。正式修复先验证 Electron 上游修补或候选版本能否创建浮动设备宿主，再考虑是否需要原生层补丁；仅强制 `mode: 'undocked'` 不能解决，因为故障就是该状态下复现的。运行时检查用到的私有前端模块不能直接成为产品依赖。

链接事件可在页面所属 manager 接入，目标 Tab 仍归事件来源会话和窗口，不能误用当前激活会话。浮动窗跟随策略须兼顾 PRD 和固定目标绑定。后续实现至少按 M 分级；涉及共享契约、跨窗口或 webContents 生命周期时按 always-L 执行 Step 0 及完整流程。本轮没有开始修复。
