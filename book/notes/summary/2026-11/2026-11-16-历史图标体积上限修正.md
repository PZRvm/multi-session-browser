# 历史图标体积上限修正

SCRM 图标为有效的 96,024 字节 PNG，原 64 KiB 上限会在写缓存前拒绝。用户确认允许较大图标但保留上限，本次改为 256 KiB；长度声明、流式读取、内联图片和磁盘缓存校验使用同一常量。每会话仍至多 128 项，图片数据理论上限从 8 MiB 提升至 32 MiB，不含 Base64 与 JSON 开销。

先增加接受边界回归，在旧上限下确实失败；修改后 11 项全通过。恰好 256 KiB 的有效 PNG 可缓存，超出 1 字节的声明长度和流式响应均被拒绝。使用重新获取的真实图标字节运行实际模块，首次、重复读取和重建服务读盘均一致，只调用一次下载、落盘一个文件。typecheck、lint 和差异检查通过。没有重跑原生界面或跨平台验收。

审查未发现新增问题。当前分支 feature/history-favicon，未合并或推送。旧历史没有图标地址且 /favicon.ico 返回 HTML 的情况不在本次上限调整范围内，[原 issue 保留该部分](../../issue/2026-11/2026-11-16-SCRM站点图标无法缓存.md)。
