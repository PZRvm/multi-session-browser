# 历史建议图标缓存

启动后历史建议原来只用灰圆点兜底：记录保存的是图标地址，默认 Session 的弹窗重新联网加载；Chrome 导入历史没有图标地址。

现在先显示搜索图标，主进程优先读会话缓存，再沿对应会话的 Cookie 和代理获取原图，失败尝试站点 /favicon.ico。旧历史无需重新导入。只向弹窗传图片数据，保留现有列表布局、排序、键盘和点选行为；Tab 栏不改。

缓存每会话 128 项、单图原为 64 KiB，后按用户确认[提高到 256 KiB](2026-11-16-历史图标体积上限修正.md)，4 路并发、单次下载 4 秒；七天后尝试刷新，离线可用旧图。识别 PNG/JPEG/GIF/WebP/AVIF/ICO/SVG 的文件签名，兼容错误 MIME，拒绝登录 HTML；最终获取或解码失败显示 SearchOutlined。克隆、删除、更新准备和退出沿既有生命周期排空在途请求。

验证：`node scripts/history-icons-regression.mjs` 十项通过；`npm run typecheck`、`npm run lint`、`npm run build` 通过。macOS 隔离 dev:agent 中，同 URL 随 A/B Cookie 返回并显示不同图标；404、无图标旧历史、搜索兜底、亮暗主题、解码失败换源、上下选择与 Esc 通过。停止服务并重启后仍显示缓存。仅经本地代理可访问的 .invalid 站点成功显示图标；伪造地址不请求，子窗仅加载 data URL。窗口池的旧查询、跨会话、隐藏、销毁及双宿主回填使用原模块与模拟原生窗口验证；未执行独立原生窗口端到端或 Windows/Linux 实机验收。

Phase 5 按十一项检查完成；[两项非阻断后续边界](../../issue/2026-11/2026-11-16-历史图标展示缓存回收.md)已记录：展示 Map 未限容量、离线旧图的刷新间隔偏长，未在审查阶段修改。未改版本、未合并、未推送。
