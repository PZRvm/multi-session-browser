# sandbox 与 SVG 告警的根因和修复选项

> 2026-11-10后续：用户已授权两项处理，根Electron现为42.11.7，独立React修复版双端实测通过；以下保留此前验证时点。最新范围、结果及未验项见[升级与修复结果](20261110125000-Electron升级与React图标修复.md)。


**有具体修复路线，但不能把临时实验说成正式项目已修复。** 正式依赖仍为Electron39.8.10，原版插件不变。用户正在确认是否放开原计划的引擎升级/第三方修改边界；未确认前不应用正式改动。

## sandbox

同一最小程序对照：无插件的Electron39没有该错误；只加载原版React8、完全不加载兼容库，仍出现sandbox_bundle的null iterable错误。42.11.7隔离引擎中同场景消失。上游[42.11.7发布记录](https://github.com/electron/electron/releases/tag/v42.11.7)及[修复PR54175](https://github.com/electron/electron/pull/54175)明确修复DevTools过早附着空文档导致的sandbox初始化误报。

升级不能只改版本号。直接把现有兼容层放进42.11.7，会出现 Cannot define property devtools, object is not extensible：兼容preload把子frame的chrome对象冻结，妨碍原生DevTools增加API。临时适配仅在顶层扩展页/service-worker注入兼容API，让DevTools子frame使用原生API。修正后，三款固定插件加载、Dark Reader开关、Cookie增改删与隔离、React属性和Profiler检查通过；没有关闭sandbox/contextIsolation。

此为候选组合验证，未完成正式应用全部回归和跨平台测试。Electron42包要求开发Node≥22.12，现有CI已用Node22；本机命令行Node20需调整开发环境。升级涉及根依赖/锁文件和宿主preload适配，仍需完整build/dev及截图录屏回归，不在本次临时实验中冒称完成。

## SVG

实际错误path的React props.d是一个React元素对象，类型g，包含3个polygon和1个path，浏览器将其转为[object Object]，因而图标路径无效。来自React DevTools8.0.0自己的ButtonIcon，不是会话或渲染截图服务。对照[上游ButtonIcon.js](https://github.com/facebook/react/blob/main/packages/react-devtools-shared/src/devtools/views/ButtonIcon.js)也可看到将pathData放入d的实现。

修复思路：React.isValidElement(pathData)时直接渲染该节点；字符串继续渲染path.d。针对实际错误对象的离线源码思路检查已通过：重现无效路径、修复后保留g/3个polygon/path、普通字符串路径输出不变。**这不是修复版插件的装载实测，原版插件没有被修改。**

若维护修复版，需要从对应源码构建并单独标注版本/来源/哈希/许可证，保留原版商店包做兼容对照；不能悄悄替换样本。也可保持原版并等待插件官方修复，该图标问题不会因升级引擎自动消失。
