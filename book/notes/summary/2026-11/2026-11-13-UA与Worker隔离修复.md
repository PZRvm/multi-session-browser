# UA 与 Worker 隔离修复

频繁人机验证的排查发现两项环境缺陷：中文默认 UA 在请求间编码不同，普通网站 SW 收到扩展桥。此次在 `fix/site-human-verification`（dev@61f835f，端口 6176）修复它们，按 L 级管理。

网络 UA 在任何 Session/窗口前初始化，平台与 Chromium 主版本来自运行时；产品名称仍为多会话浏览器，Client Hints 保留真实信息。宿主先生成再受限注册两个 preload，然后构造扩展引擎。固定 4.10.0 的源码补丁取消依赖的裸注册，npm 安装和 Vite 启动/构建都会校验。没有新增 npm 依赖。

验证中还发现 IPC 会接受网页自报的扩展 ID，已在 Phase 4 改为原生 frame/SW scope 与 Session 鉴权。没有改变代理、Cookie、存储 schema 或共享 IPC，也没有清理用户站点数据。
