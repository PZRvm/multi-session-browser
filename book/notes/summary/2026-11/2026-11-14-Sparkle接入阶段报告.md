# Sparkle 接入阶段报告

旧 Mac 更新器能下载临时签名包，但 Squirrel.Mac 拒绝安装。用户暂不购买 Apple Developer 证书，本轮按已确认的计划改用官方 Sparkle 2.10.1 和 EdDSA 更新签名，Windows 保留 electron-updater / NSIS。工作发生在 feature/app-update worktree，未合并、推送或发布。

主进程继续独占更新状态和安装许可。发现版本及查看日志不下载，用户点下载才消费原生许可；包经过验证后自动弹既有原生重启确认。录制检查、严格保存和版本复核成功后才安装。进程内“稍后”保留 ready；普通退出提交取消，等待原生周期完成后再退出。用户已接受退出后重新下载，不能把失效缓存继续显示为 ready。

交接 60 秒无结果会先撤销安装许可；取消超过 20 秒则保留应用和写入门禁，收到迟到取消回执后才恢复。检查和下载停滞各 30 秒走有界取消。测试中修正了坏签名的错误分类、取消后残留 ready，以及原生模块默认只支持 macOS 15 的编译目标；模块现在明确对齐应用的 macOS 13 声明。

发布包嵌入固定公钥，私钥经 CI Secret 传给官方 sign_update 的 stdin。免费 EdDSA 可以验证更新来源，不能替代 Apple 公证；首次分发仍有 Gatekeeper 限制。正式公钥和私钥尚未配置，本轮只用隔离测试密钥。首个 Sparkle 版本必须手动安装，之后才走 Sparkle 升级。

## 版本日志必须和同版本 Release 绑定

版本号是唯一绑定键：package.json / lock 的 X.Y.Z → 唯一的 `book/changelogs/YYYY-MM/release-notes-vX.Y.Z.md` → Tag `vX.Y.Z` 和该 Tag 的 GitHub Release。月份只负责归档；改版本时同步准备同版日志，不覆盖已发布版本。

`release-notes.cjs` 剥离 frontmatter 并校验正文。Release 正文和 Windows `latest.yml.releaseNotes` 使用相同内容；Mac 生成同内容的 `release-notes-vX.Y.Z.md` 附件，两份架构 appcast 的 releaseNotesLink 都指向该 Tag 下的附件。运行时 Mac 由 Sparkle 读取这份附件，经主进程归一化后显示；应用不读取本地仓库，也不抓取 Release 网页。缺失、重复、空白、超过 12000 字符或平台正文不一致均拒绝发布。

规范已同步到 [项目骨架](../../../docs/architecture/项目骨架.md)、根 AGENTS.md、PRD、ADR 和 `.github/RELEASING.md`。Mac 资源门禁验证归档实际版本、架构、公钥、feed、最低系统要求及 EdDSA；Windows 保留 SHA-512 校验，所有附件先在 draft 对账后才公开。

## 验证边界

33 组定向验证已通过，涵盖原 Windows 流程回归与 Mac 取消、超时、迟到事件、候选变化和禁用策略。lint 为 0 错误、316 条既有警告，类型检查和生产构建通过。Cocoa、Electron arm64、Rosetta x64 的原生七场景探针通过；实际产品最终隔离包在 arm64、Rosetta x64 各通过八个场景：网络失败重试、日志失败、截断包、坏签名、真实保存故障拒绝安装、普通退出取消、替换重启、更新后读取原测试 Cookie。最终产物证据统一记在[当前计划](../../../plans/2026-11-14-macOS更新迁移Sparkle.md)。

完整门禁仍停在 Phase 4：[既有 R1](../../review-todo/20261113200900-应用更新本地审阅快照.md) 恢复集覆盖风险没有在本轮修复，继续阻断真实用户数据安装验收、合并和发布。Intel 实机、Windows 实际升级、macOS 13/14 运行及真实录制组合仍待验证。正式 Phase 5 审阅与 Phase 6 收口没有标完成；本报告是进度返写。
