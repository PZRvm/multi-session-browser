## 三、人工验收清单（合成输入可靠性边界，需真人操作）

以下流程需要鼠标点击菜单/弹层，合成键盘在本机不可靠（与前两阶段记录一致）。在隔离目录按步骤执行：

### 用例 A：克隆保真（PRD 3.1.2，核心）

1. `MSB_USER_DATA=/tmp/<目录> npm run dev`，建会话 S1 并激活，导航到 `https://the-internet.herokuapp.com/login` 登录（或任意可留 Cookie 的站点）
2. S1 行悬停 →「...」菜单 →「克隆会话」→ 预期：行状态字短暂「克隆中…」，数秒后新行「<S1 名> 副本」入列且**自动激活**，右侧为其浏览器并自动加载 S1 的上次打开页
3. 克隆会话按 F12 → Application → Cookies / Local Storage → 预期：与 S1 登录态一致（同账号已登录）
4. 在克隆会话退出登录 → 切回 S1 → 预期：S1 仍登录（两者互不影响，隔离未稀释）
5. S1 切回时按 lastUrl 重载（克隆的已知代价：源会话活页面状态不保留，如实核对）

### 用例 B：克隆元数据与零异常边界

1. 克隆带备注/自定义名的会话 → 预期：note/pageTitle/lastUrl 复制、名称「XX 副本」超长截断
2. 克隆从未激活过的会话（无分区目录）→ 预期：不报错，产物为空白环境（1 个新标签页）

### 用例 C：批量打开测试地址（PRD 3.1.3）

1. 板头「批量操作」进入批量模式 → 勾选 ≥3 会话（含从未激活的）→「打开测试地址」
2. 弹层输入 `example.com` → 确定 → 预期：各会话均新建 Tab 加载该地址；激活会话立即可见；后台会话状态灯如实转「加载中」再回「空闲」
3. 输入非法地址（如 `not a url`）或列表外场景 → 预期：整单拒绝（错误提示），无部分打开
4. Esc 或再点板头钮退出批量模式 → 预期：复选清空、恢复单选激活语义（Esc 在焦点位于输入框/弹层开启时不应退出——核对豁免）

### 用例 D：批量关闭全部（PRD 3.1.3）

1. 批量模式 →「关闭全部会话」→ 确认框文案核对（「将永久删除全部 N 个会话及其全部本地数据，且不可恢复。」）→「全部删除」
2. 预期：列表清空、右侧「尚无会话」空态、`MSB_USER_DATA` 目录下 `Partitions/sess-*` 全部消失（可 `ls` 核查）
3. 空列表时批量入口钮禁用；批量态中删光后入口仍可点（退出不死锁）

### 用例 E：回归

1. 阶段 1—4 全回归：单条增删改选/重命名（菜单现为三项，重命名与删除会话行为不变）、切换保活、F12/ESC、状态灯、重启恢复、零会话空态
2. 批量模式与单选模式互斥：批量态下行菜单隐藏、单击不激活；退出后一切恢复
3. 弹层悬挂：URL 弹层与确认框打开时原生页面层收起（右区不被遮挡）

### 用例 F：隔离不变量

1. 任意操作后 `ls $MSB_USER_DATA/Partitions/` → 每个存活会话恰一个 `sess-<id>` 目录，无共享无残留
