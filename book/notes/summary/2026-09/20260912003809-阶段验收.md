## 三、人工验收清单（无法自动驱动的交互项）

以下项需要真人操作验证。合成键盘导航受平台限制（焦点序含行内「...」菜单按钮、鼠标合成 click 在本机不可用），按步骤逐项执行：

### 用例 A：绑定切换保真（PRD 4.2 / 验收标准 2）

1. 启动应用，点击会话 A（左侧任意会话行）
2. 在地址栏输入 `https://example.com` 回车；页面加载后，在页面任意输入框（如搜索框）输入文字 `marker-a`，滚动页面到中部
3. 点击会话 B → 预期：右侧瞬时切换为 B 的浏览器（B 首次激活显示 1 个「新标签页」），A 的页面消失
4. 点击回会话 A → 预期：Tab 仍为 example.com、输入框 `marker-a` 仍在、滚动位置保留、无重新加载白屏（webContents 保活，非重载）
5. 会话 A 按 F12 打开 DevTools 并展开 Console 抽屉 → 切到 B → 预期：DevTools 消失（B 无 A 的调试数据）→ 切回 A → 预期：DevTools 复现且抽屉态保留

### 用例 B：多账号隔离（PRD 4.1 / 验收标准 1）

1. 会话 A 登录某测试站点账号甲（或用 `https://the-internet.herokuapp.com/login` 等演示站）
2. 会话 B 登录同一站点账号乙
3. 预期：双向切换互不踢线、两边登录态并存；A 的 DevTools → Application → Cookies 与 B 的互不相同
4. 重启应用后两边登录态仍各自保留（分区持久化）

### 用例 C：状态灯与后台加载

1. 会话 A 地址栏输入慢速 URL（如 `https://httpbin.org/delay/5`）回车，立即切到会话 B
2. 预期：A 的会话行状态点/状态字保持「加载中」（琥珀脉冲）直到加载完成转「空闲」——后台会话真实状态如实驱动
3. 加载期间 B 的浏览不受影响

### 用例 D：删除会话清分区数据（PRD 3.1.2）

1. 新建会话 C（左栏底部「新建会话」），激活并浏览任意站点产生数据
2. 记录 `~/Library/Application Support/multi-session-browser/Partitions/` 下 C 的目录名（`sess-<C 的 id>`）
3. C 行悬停 →「...」菜单 →「删除会话」→ 确认框（文案「将永久删除……及其全部本地数据」）→ 点「删除」
4. 预期：右侧级联切到剩余首项会话；C 的分区目录消失；主进程日志无清除失败告警
5. 删除当前唯一会话后 → 预期：右侧呈现「尚无会话」空态（灰阶文字），tab 栏空、地址栏与新建 tab 按钮禁用

### 用例 E：DevTools 跟随会话（PRD 3.3.2）

1. 会话 A 开 DevTools 查看 Network，刷新页面产生请求记录
2. 切到会话 B 开 DevTools → 预期：B 的 Network 无 A 的请求记录；Elements 显示 B 的 DOM
3. 切回 A → 预期：A 的 DevTools 数据（含此前的 Network 记录）保留

### 用例 F：回归与生命周期

1. 阶段 1：会话新建/重命名/删除/点选；重启后会话列表/名称/备注保留
2. **新建会话即激活**（code-review H1 修复项）：点击左栏底部「新建会话」→ 预期：新行立即琥珀选中、右侧切换为新会话的浏览器（1 个「新标签页」）；主进程 sessions.json 的 activeId 同步为新会话 id；再点其他会话再点回均正常（不再有"死会话"）
3. 阶段 2：多 Tab 增删切、地址栏跳转、前进/后退/刷新/停止、Cmd+T/W/L/R
4. 阶段 3：F12/ESC 双向、设备模式（DevTools 工具栏切设备后页面视口联动）、关闭开着 DevTools 的 Tab
5. macOS：关闭窗口后点 Dock 图标重开 → 预期：当前会话的浏览器页面重挂显示
6. 窗口 resize 与左栏拖拽后切会话 → 预期：新会话页面矩形正确跟随布局
