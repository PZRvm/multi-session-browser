# 多会话测试浏览器工具 PRD 产品需求文档

## 1\. 文档概述

### 1\.1 产品名称

多会话测试浏览器工具（测试专用多账号隔离浏览器）

### 1\.2 产品定位

面向软件测试人员的**桌面端专用测试工具**，基于Chromium内核实现多独立浏览器会话并行管理。核心解决测试场景中多账号登录、多角色权限测试、频繁切换浏览器/账号/缓存环境的低效问题，所有会话登录态、缓存数据完全隔离，支持原生浏览器操作及开发者调试能力，大幅提升多账号场景测试效率。

### 1\.3 需求背景

日常软件测试中，多账号、多角色并行测试场景高频出现，传统浏览器存在环境互通、Cookie共享、登录态互踢、需频繁清除缓存/切换浏览器的痛点，操作繁琐、测试效率低、易出现环境干扰问题。因此开发一款专属测试多会话隔离浏览器，实现一键切换独立账号环境、无需重复登录、支持完整调试能力。

### 1\.4 目标用户

软件测试工程师、接口测试人员、前端测试人员、权限场景测试人员

### 1\.5 文档目的

明确产品整体功能、界面布局、交互规则、核心能力、版本规划，为开发、测试、迭代提供统一需求依据。

## 2\. 整体产品架构

### 2\.1 客户端形态

Windows/Mac 桌面端独立客户端，无需依赖第三方浏览器，独立安装运行。

操作系统展示名（macOS Dock/菜单栏、Windows 任务栏 hover 等）随操作系统语言自动切换三语言短名：简中「多会话浏览器」/ 繁中「多會話瀏覽器」/ English "Multi-session Browser"（2026-09-18 增补，契约单源 `src/shared/appDisplay.ts`）；应用内产品名仍为「多会话测试浏览器」（菜单与关于页，随应用界面语言）。macOS dev 态限制：Dock 名来自未打包的 Electron 二进制，运行期不可改，打包后由 bundle 本地化元数据生效。

### 2\.2 界面整体布局

固定左右分栏布局，比例可自适应调整，永久固定结构：

- **左侧**：浏览器独立会话列表面板（核心：多环境管理；板头下方提供工作区切换框，见 3.1.5）

- **右侧**：标准Chrome风格浏览器主面板（核心：页面浏览、交互、调试）

## 3\. 详细功能需求

### 3\.1 左侧：会话列表面板功能

所有会话为**完全隔离的独立浏览器环境**，互不共享Cookie、LocalStorage、Session、缓存、登录态、IP代理配置。

#### 3\.1\.1 会话基础信息展示

单条会话展示内容：会话自定义名称、账号备注、当前页面标题、会话状态（空闲/加载中）；备注未填写时行内显示「未填写备注」占位

#### 3\.1\.2 会话单条操作功能

- 新建会话：创建全新空白独立隔离环境

- 删除会话：永久删除当前会话及所有本地缓存数据。删除前经二次确认（2026-09-18 修订：确认框改用主进程 Electron 原生对话框，不再用渲染层绘制的 Modal——渲染层弹层开启需隐藏页面视图，曾致弹框期间浏览器区变白）：标题「删除会话」，正文列明将永久删除「会话名」及其全部本地数据且不可恢复，按钮「删除」「取消」；弹框存续期间右侧浏览器区内容保持原样可见，交互由原生窗口模态阻塞；业务规则见 4\.10

- 重命名会话：支持自定义名称，区分管理员/普通用户/测试账号等角色

- 编辑备注：为会话写入账号备注（账号用途、环境说明等测试语境信息），行菜单「编辑备注」进入行内原位编辑，Enter 或失焦提交、Esc 放弃；备注上限 200 字符，清空提交即清除备注并恢复「未填写备注」占位；备注行内截断时悬停经 Tooltip 展示全文，Tooltip 不被右侧页面遮挡（未截断文本与未填写占位均不触发，2026-09-18 增补）；克隆会话时备注随环境一并复制（2026-09-18 增补：数据层已就位，本条补齐编辑入口）

- 克隆会话：复制当前会话所有环境配置、页面状态，快速生成同款新隔离环境

- 启动/唤醒会话：点击会话列表，右侧浏览器实时切换对应环境

- 拖拽排序会话：按住会话行拖动即可调整列表顺序，供测试人员按测试计划或账号重要度组织会话；重命名、备注编辑态下不可拖拽，拖到列表外释放或按 Esc 取消均不改变顺序（纯重排业务规则见 4.7）

#### 3\.1\.3 批量操作功能（已于 2026-10-23 退役）

2026-10-23 用户裁决：批量多选功能整体退役删除——板头批量入口、行级勾选、批量关闭选中会话、批量打开指定 URL、批量移动到工作区与「打开测试地址」输入弹层不再提供。按集合删除会话的能力由删除工作区的「删除全部会话」处置继续承担（见 3.1.5 工作区管理）。

#### 3\.1\.4 会话持久化能力

软件重启后，保留所有会话列表（含用户拖拽调整后的排列顺序）、自定义名称、账号备注、上次打开页面、工作区列表（含拖动调整后的工作区顺序，2026-09-21 增补）与会话归属（3.1.5）、上次激活的工作区视野（含该工作区内上次激活的会话），无需重新创建配置。

#### 3\.1\.5 工作区（下拉切换与聚焦）

工作区是会话的组织维度，解决多项目并行测试时会话列表过长、跨项目会话互相干扰的问题。会话归属为独占制：每个会话同一时刻只属于一个工作区，或不属于任何工作区（「未分组」）。

- **切换框形态**：左侧板头下方一枚工作区切换框（下拉形态），收起时显示当前视野（「全部会话」或工作区名）；未创建任何工作区时界面与既有版本完全一致（默认态零噪音）

- **下拉交互**：点击展开下拉面板，顶部提供过滤输入——键入文字即按名称过滤定位工作区，↑↓ 键盘导航、Enter 选中、Esc 关闭；过滤词无匹配工作区时出现「新建工作区」快捷行（输入名称后回车即建即切入，为新建工作区的唯一入口）。「未分组」为固定末位的视野行（2026-09-21 增补：仅存留未分组会话的视野；零工作区时不渲染——零噪音基线）；面板内支持按住工作区行拖动更换顺序（2026-09-21 增补）：「全部会话」「未分组」两个视野哨兵行均不可拖不可落，放下即提交完整顺序并持久化；有过滤词时暂停拖拽（重排业务规则见 4.8）

- **切换语义（视野 + 激活位）**：切换到某工作区后，会话列表只显示该工作区的会话，右侧浏览器切换到该工作区内上次激活的会话（无记忆则会话列表首项，空工作区为右侧空态）；「未分组」视野只显示未分组会话，右侧级联到全序首个未分组会话（无记忆位，空则右侧空态）；「全部会话」视野显示全部会话（未分组会话带归属标记）且不改变当前激活会话

- **会话归属操作**：会话行菜单提供「移动到工作区」（独占归属，移出即入未分组），目标选择经原生模态框承载（4.11，2026-09-21 修订：原渲染层 Modal 退役——渲染层弹层需收起右侧页面视图，弹框期间浏览器区不可见）；新建、克隆会话落入当前工作区视野对应的工作区（「全部会话」视野下落入未分组），仍追加列表末尾

- **工作区管理**：右键下拉列表中的工作区项可重命名、删除；删除工作区时若其中含会话，弹原生对话框由用户选择会话处置（2026-09-24 增补）：「删除全部会话」连同会话与分区数据彻底删除，或「保留会话」全部移入未分组（会话数据与隔离环境不受影响）；空工作区维持删除确认；删除工作区的确认框口径同 4\.10（2026-09-18 增补）

- **排序的作用域**：拖拽排序的全序语义不变（4.7），工作区视野内的拖拽仅调整该工作区可见会话在全序中的相对位置（批量勾选/全选/关闭选中已于 2026-10-23 随批量多选退役）

#### 3\.1\.6 侧边栏收起（已于 2026-10-23 退役）

2026-10-23 用户裁决：侧边栏收起功能整体退役删除——板头收起钮、48px 窄轨、收起态状态点列表、自绘关闭点与窗口壳域通道（shell:set-native-window-buttons-visible）不再提供，左栏宽度回归可拖调宽单源形态（收起态原为 2026-09-28 增补功能）。

### 3\.2 右侧：浏览器主面板功能

完全复刻Chrome原生浏览器操作体验，单会话内支持完整浏览器能力，适配测试使用场景。

#### 3\.2\.1 顶部导航栏

包含前进、后退、刷新按钮、可编辑地址URL输入框，支持回车跳转、地址自动展示（工具栏主页按钮已于 2026-10-30 用户裁决退役删除）。

地址栏输入瞬态与会话强绑定（2026-10-28 专项增补）：网址草稿、待导航文本、无效提示与建议选中状态归属当前窗口中的会话与 Tab——新建会话或切换会话后地址栏不残留旧会话的任何输入与建议（含已提交未落地的待导航文本），旧会话的页面与历史数据不受清空动作影响；已配置主页的新会话先清空旧输入，页面导航落地后只展示该会话自己的 URL，不改写主页配置。

历史建议展开时输入框与建议面板融合为连续整体（2026-10-28 专项增补，Chrome 对齐）：面板紧贴输入框下沿零间距，输入框下角与面板上角取消圆角、接缝单线无重复边框与分离底色；收起后输入框恢复四角圆角。主窗口与独立窗口、亮暗主题、缩放与窗口移动下均保持贴合；屏幕下方空间不足时面板保持锚定并收窄高度，无可呈现区域时不显示并恢复输入框独立形态。

#### 3\.2\.2 Tab标签栏

- 单会话支持多Tab页面管理

- 支持新建Tab、关闭单个Tab、切换Tab页面

- Tab状态跟随当前独立会话，切换会话时Tab列表同步切换

- Tab 间以竖直分隔线区分（Chrome 对齐，2026-09-18 修订）：分隔线仅在相邻两个 Tab 均为非选中态时呈现于其间，选中 Tab 的左右两侧不呈现分隔线；亮暗双主题下分隔线取 Chrome 灰系发丝线，不做阴影与渐变

- 同一会话内支持拖拽调整 Tab 顺序（2026-09-18 修订）：在 Tab 栏内水平拖动已按下的 Tab 即实时换位预览，释放即生效并持久于本次运行（不落盘，与 Tab 列表不持久化口径一致）；拖动离开 Tab 栏区域则自动进入既有拖出独立窗口手势——重排与拖出两种意图由拖动方向自动区分，无需修饰键；重排与拖出共用同一张键位与手势体系，跨窗口转移规则不受影响（重排仅限本窗口作用域内）

#### 3\.2\.3 网页渲染区域

完整渲染网页，支持鼠标点击、表单输入、文件上传、弹窗交互、JS执行、图片加载等所有原生浏览器能力，和Chrome行为完全对齐。

网页 HTML 全屏（视频全屏按钮等 Fullscreen API 路径）与 Chrome 行为对齐：进入全屏时窗口进入操作系统原生全屏、视频铺满整屏，应用壳层（左侧会话面板、Tab 栏、工具栏）暂时隐藏，壳层不做鼠标移近浮现；按 Esc 或网页全屏按钮退出后窗口与壳层恢复原状。全屏态挂窗口：切换 Tab 后窗口保持全屏布局（激活页面占满整屏），关闭或拖出全屏中的 Tab 时恢复窗口布局。HTML 全屏期间页内查找栏不可达（见 3.7.3）；主窗口与独立窗口同规则支持。

页面加载失败（2026-10-20 增补）时内容区呈现自绘错误卡而非白屏：可读失败原因（错误码经确定性映射的当前语言短句，未映射码回退通用标题，不伪造具体原因）与引擎错误码原样并列展示，附失败目标 URL 与「重新加载」钮（重试失败的原导航）；错误卡文案与配色在注入时取当前界面语言与亮暗主题（已显示的错误卡不随后续翻转更新，重试或新导航后自愈）。加载中维持既有信号（Tab 图标位加载指示 + 刷新钮转停止加载），不以假进度误导。错误卡为纯展示层，不产生导航历史、不写 pageTitle、不触碰会话数据。

### 3\.3 核心新增能力：F12开发者工具（关键需求）

适配测试调试场景，支持原生完整DevTools能力，会话完全隔离。

#### 3\.3\.1 触发规则

- 选中当前浏览器会话页面，按下 **F12 快捷键** 唤起开发者工具

- 支持 ESC 快捷键快速关闭开发者工具

#### 3\.3\.2 隔离规则

每个会话的DevTools**完全独立**，仅展示当前会话的页面DOM、网络请求、存储数据，切换会话后DevTools同步切换对应环境数据，无数据串扰。

#### 3\.3\.3 支持完整DevTools面板

兼容Chrome原生所有调试能力：Elements元素调试、Console控制台日志、Network网络抓包、Application存储查看（Cookie/LocalStorage/Session）、Sources源码、Performance性能调试等。

#### 3\.3\.4 交互规则

开启DevTools不影响页面正常交互、不清除登录态、不破坏当前会话环境。

### 3\.4 应用外观模式

- 提供“跟随系统”“白天”“黑夜”三种应用级外观模式，首次启动默认“跟随系统”

- “跟随系统”模式下，操作系统明暗主题变化后应用无需重启即可同步；显式选择白天或黑夜后不再跟随系统变化

- 用户选择保存到独立的应用偏好文件，软件重启后保持原选择；偏好文件缺失、损坏、版本未知或模式非法时安全回退“跟随系统”，不得影响会话数据

- 外观切换覆盖应用壳、Electron 原生界面和原生 DevTools；支持 `prefers-color-scheme` 的被测页面按 Chromium 当前主题响应，不向网页注入强制暗色样式

- 应用壳覆盖范围含浏览器区 WebContentsView 页面首帧前的兜底底色：随当前亮暗取 Chrome surface 族色并在切换时同步存量视图；兜底底色不改变页面自身画布默认色，不向页面注入任何样式

- 左侧到发信息板与右侧 Chrome 风格浏览器区均提供完整亮、暗配色；入口位于左侧板头，在零会话与普通会话状态下均可使用

- 切换外观不得刷新页面、重建 Tab、切换会话、清除 Cookie/LocalStorage/缓存/登录态、改变 DevTools 绑定或破坏一会话一分区的隔离规则

### 3\.5 测试辅助扩展功能（二期迭代）

- 网页截图：快速截取当前会话页面，绑定会话备注（已交付：2026\-10\-09 增补，细化方案抽入 3\.10 快速截图与快速录屏并已并入主分支，「绑定会话备注」由该专项定稿为文件名锚定会话名；快速录屏为该专项扩展能力，非二期原列项）

- 独立代理：单会话配置单独代理IP，支持多IP测试（2026\-10\-15 增补，细化规则见 4\.14 独立代理规则，验收见 40）

（2026\-10\-10 裁决：弱网模拟、数据可视化、日志记录三项裁撤，不做——弱网模拟与数据可视化由 3\.3 原生 DevTools 覆盖（Network 面板节流/断网模拟、Application 面板存储查看），日志记录经评审暂不投入。2026\-10\-23 裁决：UA 自定义裁撤，不做——原生 DevTools 设备模拟已覆盖 UA 修改（3\.3 每会话可独立唤起 DevTools），不再单独立项。二期清单至此全部闭环：网页截图、独立代理已交付，其余项均裁撤。）

### 3\.6 多窗口浏览：Tab 拖出独立窗口与跨窗口转移（一期后增量）

会话内任意 Tab 可拖出主窗口成为独立浏览器窗口，用于双屏比对、多页面并行测试；Tab 可跨窗口转移，但严格限定同一会话，环境隔离规则不受影响。

#### 3\.6\.1 拖出与独立窗口形态

- 从主窗口或独立窗口的 Tab 栏**拖拽单个 Tab** 离开 Tab 栏区域释放，即创建该会话的独立窗口（2026-09-25 修订：原「拖到窗口外空白处释放」，调整为 Chrome 对齐的「拖离 Tab 栏即可拖出」——释放在源窗/他窗内容区同样建窗，仅落在某窗口 Tab 栏上时走放回/并入/拒绝三态）；一次拖拽只移动一个 Tab，不做多选批量拖

- 拖拽过程有明确拖拽状态反馈：源 Tab 半透明；悬停反馈仅在可接收该 Tab 的同会话窗口的 Tab 栏上呈现（高亮与插入指示），释放在不可接收（异会话）窗口的 Tab 栏上时拒绝并回弹，Tab 不丢失

- 独立窗口为完整浏览器窗口：顶部 Tab 栏 + 导航栏（地址栏、前进、后退、刷新等），无左侧会话面板；**窗口标题显示会话名称**（会话重命名后同步更新），Tab 标题维持页面原标题

- 拖出/转移为页面原样迁移：滚动位置、表单输入、登录态、会话分区、DevTools 绑定全部保留，页面不重载

#### 3\.6\.2 Tab 跨窗口转移规则

- 独立窗口工具栏提供「合并回主窗口」图标钮（2026-11-06 增补，两窗与向内箭头；三语气泡与无障碍名称；气泡距窗口右缘至少 8px，小箭头始终对准图标中心）。点击将本窗全部 Tab 按当前顺序追加到主窗同一会话末尾，源窗激活页跟随；保留原页面实例、表单、滚动、登录态与 DevTools 绑定，全部迁移后关闭本窗。主窗缺席时重建、最小化时还原，切换到源会话并聚焦；工作区视野隐藏源会话时切到其所属工作区（未分组则切未分组）。其他独立窗口不受影响。失败用主进程原生信息框反馈，保存失败不转移，未迁移的 Tab 不因合并失败而关闭。

- 转移目标限定**同一会话**：主窗口浏览区与该会话的全部独立窗口之间可双向互转，独立窗口之间也可互转；跨会话（异 session）一律拒绝

- 主窗口仅当前激活会话的浏览区可作为转移目标；主窗口 Tab 栏是合法转移源

#### 3\.6\.3 独立窗口生命周期

- 一个会话允许同时存在多个独立窗口

- 关闭独立窗口即销毁其中全部 Tab（不回主窗口）

- 独立窗口的最后一个 Tab 允许关闭，关闭后窗口自动销毁；Tab 全部转移走后窗口自动销毁

- macOS 下关闭主窗口（应用不退出）时独立窗口继续存活；应用退出时全部独立窗口随应用销毁

#### 3\.6\.4 重启恢复

- 重启后不恢复独立窗口；退出时各会话的全部 Tab（含独立窗口中的）按 URL 归入主窗口对应会话下恢复，页面运行态不还原（与既有"上次打开页面"恢复口径一致）

- 会话持久化在上次打开页基础上扩展为每会话 Tab 列表（URL 与顺序、激活位）

### 3\.9 导入 Chrome 浏览数据（2026\-09\-30 增补；2026\-10\-28 扩四类型）

面向测试人员的本机数据复用：把电脑上 Google Chrome 某个 profile 的浏览历史、localStorage、Cookie 与 IndexedDB 站点数据一次性导入指定会话，免去测试前的手工数据准备。入口为会话行右键/⋮ 菜单「导入 Chrome 数据…」；选择与冲突裁决由主进程原生模态子窗口承载（同 4\.11 机制），导入结果与失败反馈为主进程原生对话框（信息型，渲染层不参与）。

#### 3\.9\.1 范围与边界

- 导入内容四类（勾选粒度，引擎就绪一类开放一类，未接入不显示可选）：**浏览历史**（成为该会话地址栏建议数据源，不新增任何历史列表界面）、**localStorage**（站点前端数据随导入延续）、**Cookie**（普通 Cookie 含 HttpOnly，登录态承载的主要数据面）、**IndexedDB**（站点结构化存储完整快照，含 Blob 等关联文件）。密码、支付方式、书签、扩展均不在导入范围；sessionStorage 不做（用户裁决 2026-10-28）；Chrome 扩展导出路线后续另立项
- 数据来源：仅 Google Chrome 官方默认安装位置的用户数据目录；支持多 profile 选择（Default / Profile N，显示名来自 Chrome），不做自定义目录与其他 Chromium 系浏览器；源路径由主进程探测白名单解析，renderer 不提交任意文件路径
- 一次性动作：导入为显式触发的一次性复制，不做持续同步；再次同步 = 再次执行导入；用户放弃裁决或流程失败即释放暂存（不等待有效期自然过期）
- 未检测到 Chrome（未安装或从未运行）：对话框如实提示「未检测到 Google Chrome」并禁用导入，不提供引导文案与自定义路径
- Cookie 支持矩阵（以步骤 1 技术验证为准，按记录实态执行不虚构）：源库有效明文记录直接导入；Mac 平台经系统钥匙串授权取得解密密钥后导入受支持格式的已加密记录（授权弹窗由用户处理，拒绝或超时如实反馈为不可解密计数）；Windows 应用绑定加密记录与非 Mac 平台加密记录当前不支持，如实分类计数、不伪造成功率；CHIPS 分区 Cookie 不降级为普通 Cookie，单列不支持；已过期 Cookie 跳过并计数
- IndexedDB 支持矩阵：以站点存储完整快照（\.leveldb + \.blob 成对目录）为单位，源快照 schema 版本不高于目标引擎支持版本方可导入（版本过新的源站点整站点拒绝并如实反馈——Chromium 对不兼容库会静默重置，引擎必须预校验拒绝）；不做任意版本间通用转换与原始记录拼接；源 Chrome 须已退出（可靠一致快照前提），不强制结束用户 Chrome 进程、不修改源数据

#### 3\.9\.2 合并与冲突裁决

- 合并语义：与目标会话已有数据按类型**合并而非覆盖**（IndexedDB 快照替换例外见下）
- 浏览历史：静默合并（同网址访问次数取大、最后访问时间取新、标题/图标保留非空新值），无冲突概念、不弹窗；沿用会话历史上限（每会话 2000 条，超限按最后访问时间淘汰最旧）
- localStorage / Cookie：记录级合并；目标缺失直接新增，同名同作用域（localStorage 同站点同键、Cookie 同名同域同路径）且值不同视为冲突
- IndexedDB：以站点存储快照为裁决单位——目标不存在该站点快照则整体导入；已存在且无法可靠判同即构成冲突，由用户选择整份**保留目标**（session，目标快照完整不动）或**以 Chrome 快照整体替换**（chrome，该站点快照单位内目标专有数据被移除，其他站点、其他类型、其他会话不受影响；替换影响范围在提交前的裁决摘要中可辨识）；不做同一底层库内两侧记录混合
- 冲突裁决为会话级一次二选一（不按站点分组、不逐条裁决）：同次导入全部冲突类型共用「以 Chrome 为准 / 以当前会话为准」一个结论
- 结果反馈：导入结果与失败反馈为主进程原生对话框（信息型，单「确定」钮），按内容类型与计数单位（条数/站点数）汇总新增/合并/冲突处置/不支持/跳过计数；部分成功、整类不支持、失败与还原失败分别如实呈现，不以「全部成功」掩盖部分完成；失败如实报错（Chrome 文件被占用提示关闭 Chrome 后重试）

#### 3\.9\.3 隔离与安全

- 导入只写目标会话分区，零跨会话触达；导入写入窗口期该会话的切换、克隆、删除被拒绝，窗口期结束自动恢复；确认写入前对目标零写入，确认后目标状态漂移（如被并发修改）则拒绝按旧摘要扩大写入、要求重新探测
- 只在用户显式点击导入后读取 Chrome 数据（只读探测属导入动作的一部分），不静默读取；读取范围 = 勾选项；Cookie 与 IndexedDB 源文件要求处可靠快照态（源 Chrome 已退出），复制为固定副本后执行，探测与写入消费同一份数据
- 不修改源 Chrome 数据与其加密保护；Cookie 原值与解密密钥只在主进程内存流转，不落日志不写临时文件；localStorage 合并为字节保真移植；IndexedDB 写入前完整备份受影响快照，复制/校验/重开失败自动还原（还原失败独立报告，不等同普通导入失败，且不继续写同一损坏目标）；临时资源（源副本/备份）在完成、取消、过期与退出时清理

#### 3\.10\.2 快速录屏

- 入口与行为：浏览器工具栏图标钮，与截图钮并列置于开发者工具按钮左侧（自左向右为截图、录屏、开发者工具）；悬停即弹 popover 呈现功能名与当前状态（空闲／录制中含累计时长／已暂停）；点击即开始录制当前激活 Tab 的连续画面（录制页面画布本身，不含应用壳与左侧面板）；录制中按钮呈录制态（红点＋累计时长），再次点击停止

- 录制锚定发起时的会话与 Tab：录制期间切换 Tab、切换会话、关闭被录 Tab、拖出被录 Tab 成独立窗口或删除该会话，均自动停止并保存已录内容后反馈；同 Tab 内页面导航不中断录制（跨页连录为默认语义）
- 截图与录屏是会话作用域的运行态能力：不落盘进会话快照、不触碰会话分区数据，不改变会话隔离与 DevTools 绑定；录制状态为主进程运行态，不持久化，重启恢复空闲
- 页面 HTML 全屏（3\.2\.3）期间应用壳隐藏、工具栏入口不可达，截图/录屏随入口不可达而不可发起（原截图快捷键全屏口径随 2026\-10\-29 快捷键退役移除）

## 4\. 核心业务规则（关键）

### 4\.1 环境隔离规则

所有浏览器会话**100%环境隔离**，Cookie、缓存、本地存储、登录态、调试数据完全独立，实现：多账号同时在线、互不挤下线、数据互不串扰，完美适配多角色权限并行测试。

### 4\.2 会话切换规则

点击左侧任意会话，右侧浏览器瞬间切换对应环境，保留该会话所有Tab页面、登录状态、缓存数据、调试配置。

### 4\.3 DevTools绑定规则

开发者工具与浏览器会话强绑定，一对一对应，不存在跨会话调试、数据混淆问题。

### 4\.4 外观模式规则

应用外观是全局偏好而非会话属性。持久化的是用户选择的模式，不是某一时刻解析出的明暗结果；“跟随系统”的实际主题每次启动及系统变化时重新计算。外观偏好与 `sessions.json`、会话分区数据分别存储、独立读写，任一侧损坏或删除都不得连带影响另一侧。

### 4\.5 Tab 跨窗口转移规则

Tab 拖出与跨窗口转移不改变其所属会话：页面 webContents 原样迁移，分区恒为该会话的 `persist:sess-<id>`，禁止跨会话转移。转移到异会话窗口的请求一律拒绝且源 Tab 保持原位不丢失。

### 4\.6 页内查找规则

页内查找作用于当前会话当前 Tab 的页面内容，是运行态交互：不落盘、不进快照、主进程不持查找开关状态。查找命令按来源窗口作用域路由（与浏览器命令同规），禁止跨窗口、跨会话触发；切 Tab/切会话即终止查找并清除高亮，残留高亮不得跨激活位留存。

### 4\.7 会话列表排序规则

排序是纯元数据重排：只改变会话在列表中的顺序，不切换激活会话，不触碰会话分区、页面运行状态、Tab 集与 DevTools 绑定。列表顺序的唯一持久化事实是 sessions 数组顺序：新建、克隆会话仍追加到列表末尾；删除激活会话后级联指向按当前顺序的剩余首项。排序指令必须提交当前全部会话的完整顺序，主进程整单校验——id 格式非法、重复、缺项、多项或未知时整单拒绝且磁盘不变，界面回到主进程事实顺序；拖拽中的源行、插入位等瞬态不落盘、不进 IPC。工作区视野（3.1.5）是该全序上的过滤视图，不另存顺序。

### 4\.8 工作区规则

工作区是纯组织维度：只管理会话的归属与列表视野，不改变会话隔离（每会话仍是独立分区）、不产生跨会话共享数据、不承载环境配置。归属为独占制：一个会话同一时刻只属于一个工作区或未分组。切换工作区是视野与激活位的变化，不销毁、不重建任何会话页面，右侧切换遵循 4.2 会话切换规则。删除工作区时其中会话的处置由用户在删除弹窗中选择（2026-09-24 增补）：「删除全部会话」则会话与分区数据彻底删除，或「保留会话」则全部移入未分组、会话数据不动；取消零副作用。（批量移动选中会话到工作区已于 2026-10-23 随批量多选功能退役删除，会话移动仅保留行菜单单条入口。）未创建任何工作区时，一切行为与无工作区能力的既有版本一致。

工作区列表顺序是纯元数据全序重排（2026-09-21 增补）：下拉面板内拖动放下即提交完整工作区 id 排列，主进程整单校验拒绝制（同 4.7 口径——重复、缺项、多项、未知 id 或格式非法任一不满足整单拒绝、磁盘顺序不变）；重排只改下拉展示序，不动视野（activeWorkspaceId）、激活会话、激活记忆与会话归属，拖拽中的源行、插入位等瞬态不落盘、不进 IPC。「全部会话」（首位）与「未分组」（末位）是固定视野哨兵项，不属于排序集合。

### 4\.9 设置规则

设置是全局偏好而非会话属性（与 4.4 外观同规）：设置偏好与 `sessions.json`、会话分区数据分别存储、独立读写，任一侧损坏或删除不得连带影响另一侧。设置窗口的打开与关闭不得影响浏览器页面状态、会话切换、会话隔离与 DevTools 绑定。主题色是纯视觉层偏好：只改写信息板与右侧 Chrome 区的表面色彩系统 token（信号色与底色族；右侧表面随主题同族换色为 2026-10-30 修订，墨阶恒中性），不触碰会话数据、不向被测网页注入任何样式。恢复出厂设置必须经主进程原生警告确认框确认（2026-10-31 修订，原两步确认退役）方可执行，执行中任何失败都如实提示并中止，不得静默半途失败。

### 4\.10 破坏性确认框规则（2026-09-18 增补）

删除类不可逆操作（删除会话、删除工作区）的二次确认使用主进程 Electron 原生对话框（`dialog.showMessageBox`），不使用渲染层绘制的 Modal。页面视图可见性是硬性约束：弹框存续期间右侧浏览器页面（WebContentsView）必须保持可见且内容原样，禁止为让弹层可见而隐藏、清空或移出页面视图——弹框期间浏览器区变白即为事故；原生对话框自身是窗口模态，天然阻塞主窗口交互，无需遮挡页面。样式按当前产品风格对齐到原生对话框的能力边界：亮暗跟随应用当前主题（复用既有 nativeTheme 同步链路）、弹框图标使用项目图标（2026-09-18 增补：macOS warning 弹框的角标在 dev 态显示 Electron 包图标，传项目图标整体替换；Windows 保留 warning 盾形原生语义）、标题/正文/按钮文案经 i18n 单源随界面语言、「取消」为安全默认按钮（Enter 与 Esc 均等同取消，防误触不可逆删除）；删除工作区确认扩为会话处置三键选择（2026\-09\-24 增补）：含会话工作区呈「取消 / 保留会话 / 删除全部会话」三键、结论按三态返回（语义仍以 defaultId/cancelId 为准绳），空工作区维持「删除 / 取消」两键；原生对话框不支持注入主题色与自绘样式，不得为改色退回渲染层弹框或自绘子窗口。输入类弹层「打开测试地址」曾为本条唯一例外（维持渲染层弹层机制），已于 2026-10-23 随批量多选功能退役删除——渲染层弹层例外至此清零（2026-09-21 修订：工作区重命名不再属输入类保留项，同日起迁主进程模态子窗口承载，规则见 4\.11）；选择类弹层「移动到工作区」（单条入口）2026-09-21 起迁主进程模态子窗口承载，规则见 4\.11。

### 4\.11 原生模态框规则（2026\-09\-21 增补，同日扩围工作区重命名；2026\-09\-30 扩围导入 Chrome 数据；2026\-10\-15 扩围独立代理设置）

「移动到工作区」的目标选择（会话行菜单单条入口）与「工作区重命名」（工作区下拉右键操作条入口，2026\-09\-21 扩围——原渲染层 Modal + overlay 登记退役，弹层开启需收起右侧页面视图的缺陷同前）以及「导入 Chrome 数据」的 profile 选择、内容勾选与 localStorage 冲突裁决（2026\-09\-30 扩围，渲染层 antd Modal 版退役——用户裁决模态框用原生框）以及「代理设置」（会话行菜单入口，2026\-10\-15 扩围——协议/地址/端口/账号/密码表单与出口 IP 检测，细则见 4\.14）使用主进程模态子窗口（BrowserWindow 以主窗为 parent 且 modal）承载：macOS 呈原生 sheet（窗口模态，挂主窗顶部滑出），Windows/Linux 呈系统框模态对话框窗口。页面视图可见性是同 4\.10 的硬性约束：模态存续期间右侧浏览器页面（WebContentsView）必须保持可见且内容原样，禁止为弹层隐藏、清空或移出页面视图，不经 overlay 悬挂登记收起页面——模态阻塞由窗口系统承担（原生 sheet 为窗口模态，天然阻塞主窗输入）。

载荷只带数据参数（kind + 会话标识/工作区 id），工作区列表、当前归属、预填现名等展示数据由主进程从权威快照现取组装，不经 IPC 传展示用字符串；文案由模态窗口页面经 i18n 字典随界面语言。确认与执行两段解耦：模态框只返回结论（目标工作区 / 移出未分组 / 新名称 / 取消），移动执行仍由既有 workspaces:move-session 通道闭环，重命名执行仍由既有 workspaces:rename 通道闭环；取消（Esc/关闭弹框）零副作用；选择后执行失败时模态框不保持开启，按既有失败反馈惯例呈现、可从入口再次发起（一次性模态，对齐 4\.10 删除确认框的口径）。工作区重命名场景（2026\-09\-21 增补）：输入框预填当前名称且全选，保存（或 Enter）提交、空名时保存钮禁用且 Enter 不提交（UI 面），新名称经 trim 非空与长度上限的主进程守卫（契约面，跨 IPC 载荷防御惯例）后才作为结论返回；重名与超长等非法输入由既有 workspaces:rename 通道按既有规则拒绝并反馈。样式对齐原生窗口能力边界：亮暗随应用当前主题（nativeTheme 同步链路）、选项行/输入行按板面语系渲染（抬升层/发丝线/无阴影）、不得为注入主题色退回渲染层弹框。

### 4\.12 导入 Chrome 数据规则（2026\-09\-30 增补；2026\-10\-28 扩四类型）

- 导入是会话级操作，数据只写入目标会话分区（历史 JSON + 分区存储），不产生任何跨会话共享；导入窗口期目标会话禁止切换/克隆/销毁，窗口期结束自动恢复
- 历史导入复用会话历史域的上限与合并规则（2000 条 / 同址访问数取大、时间取新）；localStorage 记录级合并，目标分区缺失的站点数据整体移植、冲突键按用户裁决处置
- Cookie 记录级处置（2026-10-28 增补）：源值须为有效明文或受支持格式解密后方可写入（密文不得当原值导入），经目标分区 Cookie API 写入并保留作用域（host-only/domain、路径）与受支持属性（Secure/HttpOnly/SameSite/过期时间），同名不同路径不混淆；会话 Cookie 仅导入源快照中实际存在者，不伪造过期时间；不支持与解密失败项独立计数
- IndexedDB 站点快照处置（2026-10-28 增补）：以站点存储完整快照为最小单位（不拆分同一底层库），导入前校验源 schema 版本兼容（不兼容整站点拒绝，不将未校验数据交给引擎打开）；冲突按用户裁决整份保留或整体替换（替换只影响该站点快照单位，其他站点/类型/会话不动）；写入前备份、失败还原、还原失败独立报告
- 密码、支付方式、书签、扩展均不在导入范围（IndexedDB 已于 2026-10-28 从「后续可选增量」转为正式范围；sessionStorage 经用户裁决不做）

### 4\.13 快速截图与录屏规则（2026\-10\-09 增补）

截图与录屏是会话作用域的运行态取证动作：始终作用于当前激活会话的当前激活 Tab，不跨 Tab、不跨会话，同一时刻全应用至多一个进行中的录制。截图是单帧纯读动作，不写会话数据与分区、不改变页面状态；录制锚定发起时的 Tab，切 Tab/切会话/关被录 Tab/拖出被录 Tab/删除该会话时自动停止并完整保存已录内容，不产生半截文件。录制数据只在应用内存内流转编码，不持久化、不进快照；图片与视频仅按用户动作写文件，落点恒为系统下载目录（不弹另存对话框），文件名锚定会话名，会话更名不影响已生成文件。录屏画面为被录 Tab 页面画布本身（不含应用壳、左侧面板与 DevTools），不得引入桌面级或跨会话画面采集。（原截图快捷键应用级偏好句——默认未设置、经设置界面自定义与清除、冲突拒绝、即时生效持久化——已于 2026\-10\-29 用户裁决随截图快捷键退役删除，截图不再有应用级快捷键偏好。）

### 4\.14 独立代理规则（2026\-10\-15 增补）

- 代理是会话级配置：作用于该会话分区的一切网络流量（页面、下载、Service Worker，含该会话的独立窗口视图），未配置的会话保持直连；不改动系统代理，不影响其他会话
- 配置含协议（HTTP/SOCKS5）、服务器地址、端口与可选账号密码；账号密码明文随会话元数据落盘（userData/sessions\.json，与登录态数据同文件同机），不做加密，界面不得宣称安全隔离
- 代理在分区首个页面请求前应用（新建、切换、克隆、重启恢复四条路径均保证时序）；会话中途修改或清除后，新连接走新配置，既有 keep\-alive 连接被关闭收尾；不自动刷新已打开页面（Chrome 惯例，防丢表单态），生效确认由「检测」与用户手动刷新承担
- 出口 IP 检测是会话作用域只读探测：按表单当前草稿值经该会话分区发起探测请求，不保存、不改变当前生效配置；结论如实三态分类——连不上代理 / 认证失败 / 探测失败，不伪造「代理生效」
- 克隆会话携带代理配置（环境同款复制语义）；删除会话随整条删除链连带清理；清除代理即回直连
- PAC 脚本、自定义绕过规则（bypass）、WebRTC 防泄露不在范围（Chromium 对 localhost 等本机地址已有隐式旁路）

## 5\. 技术约束与选型

### 5\.1 技术栈选型

Electron \+ Playwright \+ Chromium 原生内核

### 5\.2 技术优势说明

- 无需自研浏览器内核，复用成熟Chromium能力，兼容性强

- Playwright天然支持多BrowserContext隔离，完美实现会话环境独立

- 原生支持F12 DevTools唤起，无需二次开发调试面板

- Electron快速实现桌面端UI、分栏布局、本地持久化存储

### 5\.3 需求边界（不做功能）

- 不做远程分布式浏览器，所有会话本地运行

- 不自定义改造DevTools原生能力，完全复用官方调试面板

- 一期不做自动化测试脚本，仅保留手动测试、手动调试能力

- 不做主题自由取色与主题市场，全局强调色仅限设置页预设色板（见 3.8.2）

1. 创建多个会话，不同会话登录不同账号，账号状态互不冲突、互不踢下线
