# 独立窗口合并回主窗口 功能调研报告

> 创建时间：2026-11-06 13:10:16（Asia/Shanghai）
> 需求来源：独立窗口全部 Tab 合回主窗口并关闭，确定文案/icon 并执行开发计划
> 调研单元：1 个
> 状态：调研完成；用户本轮明确授权制定并执行，继续落地

## 1. 需求理解
### 1.1 功能目标
测试人员结束多窗口比对时，一次点击收回本窗所有 Tab，保持页面运行态，回到主窗口继续工作。
### 1.2 未知点清单
- [x] 页面实例是否能复用：manager.ts 已有 WebContentsView 挂摘与归属更新，见 2.2。
- [x] 如何表达与处理主窗缺席：复用工具栏气泡，文案「合并回主窗口」；主窗重建及会话激活由主进程完成，见 2.5。
### 1.3 拆分判断
作为一个端到端小功能调研单元，不另引组件库或进程。

## 2. 调研单元：全部 Tab 归并与入口
### 2.1 该部分要做什么
新增独立窗专属按钮与可信 IPC，按序转移原有页面到同会话主窗，全部迁移后关闭源窗。
### 2.2 项目现状
- src/main/browser/manager.ts：moveTabToWindow 迁移同一实例，逐次激活/发快照；需要批量版本避免中途激活和关窗。
- src/main/browser/registry.ts：管理每会话 manager、空窗收口、生命周期通知和激活会话；现有单 Tab 跨窗入口要求主窗当前会话相同。
- src/main/index.ts：createWindow 重建主窗并挂现有 view；src/main/store.ts 的 mutateSnapshot 为会话元数据串行写盘入口。
- src/main/browser/ipc.ts：sender 白名单；preload 双文件与 shared/browser.ts 为通信契约。
- src/renderer/src/components/browser/Toolbar.tsx：TooltipSlot 与原生气泡可直接复用；app.css 灰阶 28px 图标钮为视觉依据。
- docs/PRD.md 3.6 与阶段 7—10：会话隔离、原页面实例转移、空窗销毁；Electron ^39.2.6 / React ^19.2.1。
### 2.3 候选方案
**方案 A：批量迁移既有 WebContentsView**
- 以现有摘挂/归属修改机制，批量更新后一次发快照；官方 View 提供 addChildView/removeChildView，IPC 验证 sender。
- 来源：[View](https://www.electronjs.org/docs/latest/api/view)、[IPC sender 校验](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages)。当前项目已实际使用相关 API。
**方案 B：读取 URL 后在主窗新开并关闭原窗**
- 可用 webContents.loadURL 重建页面，但丢表单、滚动和调试运行态，不采用。
- 来源：[webContents](https://www.electronjs.org/docs/latest/api/web-contents#contentsloadurlurl-options)。
### 2.4 可行性分析
| 维度 | A | B |
| --- | --- | --- |
| 技术匹配 | 现有迁移机制可复用 | URL 能重开，运行态无法保持 |
| 规则冲突 | 同会话原实例，符合 PRD | 违反页面不重载原则 |
| 成本 | 无新依赖，批量原语与编排 | 代码少但用户数据风险不可接受 |
### 2.5 结论与实施建议
**借鉴思路手写**：复用现有迁移机制增加批量原语；registry 编排、IPC 单飞与原生失败框、preload 窄桥、Toolbar 独立窗门控。impeccable 继承既有工具栏世界，图标两窗加向内箭头，文案明确目标主窗，避免「关闭」误读为销毁页面。三步直通计划记录于 notes/plans/20261106131016-独立窗口合并回主窗口开发计划.md。

## 3. 风险与开放问题
异步元数据保存期间源窗可能关闭/会话删除，迁移前须复验；主窗口显示其他会话时须先摘旧 view；录制中的 Tab 迁移须发生命周期通知。Windows 原生观感需实机验收。

用户已授权设计与执行；默认采用末尾追加、源窗激活页跟随、主窗自动重建与切换源会话，均在实施前告知。无阻塞假设。
