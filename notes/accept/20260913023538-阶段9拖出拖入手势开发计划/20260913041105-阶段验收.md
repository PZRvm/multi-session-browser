## 三、macOS 真实手势人工清单（合成输入平台限制，需用户执行）

CDP 只能合成 DragEvent（无真实鼠标按住拖动），以下四组按历阶段同口径转人工。逐项操作步骤与预期：

1. **源窗内释放（stayed）**
   - 操作：按住某 Tab 在本窗口 Tab 条范围内小幅拖动后松手。
   - 预期：拖动中该 Tab 半透明；松手后 Tab 原位恢复不透明，无新窗口、无位置变化。
2. **空白处拖出建新窗**
   - 操作：按住 Tab 拖出窗口到桌面空白处松手。
   - 预期：新独立窗口在松手位置附近出现（水平居中、垂直偏上），页面滚动/输入/登录态原样；源窗 Tab 减一（主窗可至 0 Tab 空态）。
3. **拖入既有同会话独立窗**
   - 操作：保持该会话激活，把 Tab 拖到该会话已存在的独立窗口上方。
   - 预期：悬停时目标窗 Tab 栏整条高亮一档；松手 Tab 并入目标窗末位并激活；拖回主窗同理（主窗 Tab 栏高亮）。
4. **拖到异会话窗口拒绝回弹**
   - 操作：左侧切换激活会话使其与拖拽源会话不同（或把 Tab 拖到另一会话的独立窗上）松手。
   - 预期：目标窗不高亮（悬停广播只达同会话窗口）；松手 Tab 原位水平回弹一下，不丢失、不转移。

另有两项体验性核对（不阻塞）：拖拽中悬停高亮随光标进出目标窗即时亮灭（16ms 轮询，仅变化广播）；拖拽后立即再拖另一 Tab 无状态残留（半透明/高亮均已清）。

## 七、验收后修订：手势引擎替换（HTML5 DnD → 指针捕获自绘）

> 修订时间：2026-09-13（用户实测反馈：「拖出去松手后，Tab 先回到原来的会话再跳转到对应位置」，期望松手直接进入/创建目标窗口）

**根因**：HTML5 原生拖放在窗外（桌面空白或另一窗口上方）释放时，松手位置下方的窗口未「接受投放」，macOS 先播放系统级拖影飞回原位动画；随后我们的异步裁决（建窗/搬移）才生效——两段叠加即「先回原位再跳走」。该飞回动画是 OS 行为，HTML5 DnD 无法抑制。

**修订**：TabStrip 手势引擎换为指针捕获自绘（pointerdown 捕获 → 位移过 5px 阈值成拖拽 → pointerup 直接上报落点裁决）。无 OS 拖影、松手即结果；跨窗事件送达由指针捕获保证（光标出窗仍收 move/up，经 CDP 真鼠标事件窗外释放实测验证）。附带升级：Esc 由「按坐标裁决（空白处建窗）」改为「放回源窗」（capture 阶段吞键，避让 close-devtools 快捷键）。主进程裁决链（dragging.ts/IPC/store 契约）零改动。

**复验（CDP Input 域真鼠标事件，/tmp/msb-s9-ptrdrag.mjs，隔离目录 /tmp/msb-s9-ptr）：9/9 全过**——T1 点击切换无误触 / T2 源窗释放 stayed（拖拽中半透明 true→false）/ T3 空白建窗 + 保活（哨兵 + scrollY=500）/ T4 并入既有窗（moved + 激活位正确）/ T5 Esc 放回（清态留原窗、释放无二次结算）/ T6 异会话拒绝（落主窗独占区 + 回弹类实测）/ T7 关闭钮不受手势影响。

**环境受限转真实鼠标人工项（新增 2 项）**：① 拖拽中目标窗 Tab 栏高亮随真实光标进出即时亮灭（悬停管线由主进程轮询真实 OS 光标驱动，CDP 注入事件不移动真实光标，注入环境不可驱动；管线代码未改动）② 松手瞬间无任何「飞回原位」的 OS 动画（本次修订的目标效果，需真实手势确认体感）。

**修订追加（同日，用户报错闭环）**：自绘手势首版上线后实测出现 `[browser] browser:switch-tab 失败: 标签页不存在`——pointerup 后浏览器仍会派发随尾 click（HTML5 原生拖拽压制它、自绘手势不会），拖拽结束后紧随的 click 对已移出作用域的 Tab 触发 switchTab 被守卫正确拒绝；源窗内小拖释放（stayed）也会误激活被拖 Tab。修复：拖拽收尾（finishDrag 唯一出口）置吞 click 标志，click 消费一次即复位、新一轮 pointerdown 清残留。强化版复验 10/10（T2 改拖非激活 Tab 断言激活位不变 + 新增 T8 全程主进程日志零 switch-tab 失败，/tmp/msb-s9-ptrdrag.mjs）。

**修订追加二（同日，虚影补齐）**：用户反馈自绘手势拖动中"鼠标上没有 Tab 虚影"。补齐跟随虚影（Chrome 同款手感）：主进程透明置顶小窗（新增 src/main/browser/dragPreview.ts，floating 层 + setIgnoreMouseEvents + showInactive 不抢焦点 + skipTaskbar）渲染与源 Tab 同尺寸圆角卡片（chrome-tab-active 亮暗配色、favicon 仅收 https、标题转义，data URL 内联自包含样式），锚定按下点在卡内偏移、由拖拽控制器既有 16ms 光标轮询逐帧 setBounds 跟随（零新增定时器），生命周期严格锁拖拽窗口期（dragStart 建 / 释放、过期、接管即销毁，endSession 统一收口）。契约：TabDragStartPayload 增可选 preview 子对象（TabDragPreviewPayload：度量/抓取点/标题/favicon/主题），ipc 层结构守卫（垃圾按命令口径拒绝），通道数不变（17）。复验 11/11（新增 T9：拖拽中 data: 预览 target 存在、释放后销毁；macOS 全屏 OS 截屏目视确认悬浮白卡「新标签页」+ 阴影与源 Tab 半透明并存；T1—T8 全保持，含日志零 switch-tab 失败）。虚影跟随的真实光标驱动属真实手势体感项（注入事件不移动 OS 光标），随第四节人工清单一并确认。
