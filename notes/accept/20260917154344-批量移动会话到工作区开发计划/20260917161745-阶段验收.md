## 三、计划偏离记录（主会话采信，理由如下）

1. **载荷字段 `sessionIds` → `ids`**：与 delete-batch/batch-open-url/reorder 批量家族字段名一致，并直接复用 `parseNonEmptyStringIds` 守卫（计划原文 sessionIds；契约冻结时消费方为零，改名零成本）。
2. **重复 id 去重容忍（非整单拒绝）**：对齐 batch 家族既有语义（reorder 才整单拒绝重复）；计划步骤 2 原文「重复检测」按家族先例收敛为去重。
3. **响应式阈值 300 → 340**：最宽文案「取消全选」态下第一行排布实测 340 为容纳线（demo 只目检了 340/280 两档），DESIGN 已按 340 落盘。

## 四、需人工执行的验收项（如实标注，未自动化）

1. **失败 danger 反馈条的 UI 渲染**：勾选集与 store 状态同源，`moveSessionsToWorkspace` 返回 null 的路径从 UI 实际不可达（通道级整单拒绝已由 A11—A13 覆盖）；danger 形态转代码复核（app.css `.batch-feedback-danger` 已落）。
2. **单会话行菜单「移动到工作区…」回归**：本阶段对该路径纯增量未触碰（typecheck 守护），行菜单 DOM 驱动成本高，建议人工点一单验证。
3. **Windows 平台**行为（无 Windows 机器，沿项目转人工惯例）。
4. **真实手感**：Tooltip 出现时机、反馈条淡出节奏、拖拽分隔条跨越 340px 的形态切换（CDP 已断言语义与终值，手感留人工）。
