## 二、已验证项（自动化证据）

### 1. F12 唤起底部停靠 DevTools（PRD 3.3.1，用例 A 主链路）✅

- 操作：dev 启动后（shell 聚焦态）按 F12。
- 实测（pid 34263，窗口捕获截图 + AX 树）：底部出现原生 DevTools（Console 面板激活，显示 about:blank 页面的开发态 CSP 安全警告），高度为内容区 40%（默认），页面上方区域同步缩小；中间 1px 灰阶分隔条可见。
- AX 证据：工具栏开关按钮 `checkbox 开发者工具 = 1`（aria-pressed 随状态翻转）；分隔条元素 `调整开发者工具高度`（中文 aria-label）出现；DevTools 完整 AX 子树（Elements/Console/Sources/Network 面板 radio、Console panel、设置等 100+ 元素）可访问。
- 链路含义：shell keydown（useBrowserShortcuts）→ zustand store → IPC `browser:toggle-devtools` → manager.toggleDevTools → 宿主 view 挂入 + 快照推送 → renderer 双锚点布局，全链打通。

### 2. 开关按钮双向切换（PRD 3.3.1 辅助路径）✅

- 操作：AX 点击工具栏「开发者工具」按钮两次（关→开→关）。
- 实测：第一次点击后停靠区出现（`= 1`）；再次点击后停靠区消失、页面区恢复全高（`= 0`，AX 与截图双重证实）。按钮无激活 Tab 时禁用态由阶段 2 既有 disabled 模式承担。

### 3. 每 Tab 独立实例：切换 Tab 时停靠区收起/复现，实例状态保留（PRD 3.3.2 / 4.3，用例 B）✅

- 操作：DevTools 开着（tab-1）→ 点「新建标签页」按钮切到 tab-2 → 点 tab-1 切回。
- 实测：
  - 切到 tab-2：停靠区立即收起（`开发者工具 = 0`，DevTools AX 树消失，页面区全高）；tab-2 为全新 about:blank，无任何 DevTools 痕迹（无数据串扰的可见面）。
  - 切回 tab-1：停靠区复现（`开发者工具 = 1`），DevTools 面板结构与**内部抽屉状态**（`Tool drawer` / `Drawer shown`）原样保留——证明 tab-1 的 DevTools webContents 在非激活期间存活、状态持续，与"每 Tab 一对一实例"的设计一致。
- 阶段 2 回归（同轮证实）：新建 Tab 后地址栏自动聚焦（focus-address 推送正常）、tab radio 选中语义正常、导航四键禁用态正常。

### 4. DevTools 数据正确性（PRD 3.3.3；冒烟轮已证）✅

- 证据（阶段 3 步骤 1 冒烟，process.md 有记录）：对 example.com 开启 DevTools，Elements/Styles 面板显示的正是该页实际样式（`body { background: #eee; width: 60vw; margin: 15vh auto; font-family: system-ui, ... }`）；Network/Console/Sources 面板可切换（AX radio 组）。DevTools 为 Chromium 原生面板本体（`devtools://devtools/bundled/devtools_app.html`，`can_dock=true`），零自定义改造（PRD 5.3 红线合规）。

### 5. DevTools 聚焦态 ESC = 抽屉切换（Chrome 原生行为，计划设计如此）✅

- 实测：DevTools 聚焦态发 ESC，DevTools 内部 Console 抽屉被切换（AX 出现 `Tool drawer` / `Drawer shown` / `Close drawer`），DevTools 本体不关闭——与 Chrome 行为一致（ESC 在 DevTools 内属于抽屉快捷键），符合键位表头注"DevTools 自身 webContents 内 ESC 不劫持"的设计。

## 三、需人工执行项（真实键盘/鼠标操作，附步骤与预期）

以下项依赖真实焦点路由或破坏性操作，后台自动化无法安全驱动。逐项 10 秒内可完成：

- [ ] **A1 页面聚焦态 ESC 关闭**：DevTools 开着时，鼠标点一下页面内容区（焦点进页面），按 ESC。预期：DevTools 关闭、页面区恢复全高、按钮态变未按下。（代码路径：page webContents before-input-event → close-devtools，`src/main/browser/manager.ts:239`）
- [ ] **A2 omnibox 编辑态 ESC 豁免**：DevTools 开着时，点地址栏输入任意文字，按 ESC。预期：仅地址栏草稿还原，DevTools 保持开启。（代码路径：useBrowserShortcuts 的 omnibox 豁免分支）
- [ ] **A3 页面聚焦态 F12 关闭**：DevTools 开着、焦点在页面时按 F12。预期：DevTools 关闭。
- [ ] **C1 开启 DevTools 不影响页面交互（PRD 3.3.4）**：打开 example.com 并开 DevTools，页面滚动、点击链接、输入框键入。预期：全部正常，无卡顿错位。
- [ ] **C2 登录态不破坏（PRD 3.3.4）**：任一需登录站点登录后，反复开关 DevTools。预期：登录态保持。
- [ ] **D1 关闭开着 DevTools 的 Tab**：对非最后一个 Tab 开 DevTools 后点其关闭钮。预期：Tab 与其 DevTools 一并消失、无崩溃、无残留黑块（代码路径：disposeTabDevTools）。
- [ ] **D2 停靠区分隔条拖拽**：拖动分隔条上下移动。预期：DevTools 高度实时跟随、clamp 生效（不能拖到小于 80px 或挤没页面区）、松手后布局稳定。
- [ ] **D3 macOS 关窗重开**：Cmd+W 关窗后点 Dock 图标重开。预期：DevTools 若开着则随 attachToWindow 重挂，布局正确。
- [ ] **D4 重启复位**：退出应用重开。预期：回到单个新标签页、DevTools 关闭（浏览器状态不持久化，设计如此）。
- [ ] **E1 dev 态 F12 不再打开 shell 自身 DevTools（AGENTS.md 坑点闭环）**：`npm run dev` 下 shell 聚焦按 F12，右侧出现的必须是浏览器页面的 DevTools 而非应用 UI 自身的 DevTools。（本验收第 1 项已间接证实：F12 打开的是带 Console 警告的页面 DevTools；人工复核一次即可）
- [ ] **E2 prod 守卫**：`npm run build:unpack` 启动产物，shell 聚焦按 Cmd/Ctrl+R 与 F5。预期：shell 不重载（页面 DevTools 不闪断）；F12 正常开关页面 DevTools。
