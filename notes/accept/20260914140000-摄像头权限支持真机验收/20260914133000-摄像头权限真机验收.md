# 摄像头权限支持真机验收

> 落盘时间：2026-09-14 13:23（Asia/Shanghai）
> 分支：codex/camera-access-support
> 范围：会话网页摄像头站点授权 broker（src/main/browser/permissions.ts 新增 + registry 接线）+ macOS 打包 entitlements/用途声明 + dev 态二进制签名治理
> 证据截图：站点询问弹窗-会话A.png（本目录）

## 一、实现要点（验收对应）

- 站点层：`setPermissionRequestHandler` / `setPermissionCheckHandler` 挂在每个会话分区（persist:sess-\<id\>）的 Electron Session 上，按「会话 + 安全 origin + 纯 video」维护仅本次运行有效的授权；音视频混合、纯音频、非安全 origin、未知权限一律拒绝
- 系统层：macOS 走 `systemPreferences.getMediaAccessStatus` / `askForMediaAccess`（TCC），拒绝时给出中文引导弹窗（当前状态 + 系统设置路径）；Windows 读状态但不在站点层误拒 unknown
- 会话删除先 `disposeSession` 封死 handler 再销毁分区，防止销毁窗口期回落 Electron 默认自动批准；克隆临时会话不走删除分支，源会话授权保留
- 打包：entitlements 增 `com.apple.security.device.camera`；Info.plist `NSCameraUsageDescription` 改为中文文案（麦克风描述移除——产品仅允许视频）

## 三、过程中发现并修复的缺陷

1. **系统层拒绝被缓存**：原实现把 TCC 拒绝也 `cache:true`，导致用户在系统设置放行后，同源重试被旧决定静默封死整个运行期。修复：只缓存用户显式拒绝与放行，系统层拒绝 `cache:false`（重试重走完整询问）；系统阻止路径补 console.warn。
2. **dev 态 TCC 全链排障结论**（不属代码缺陷，已固化治理措施，见 scripts/sign-electron-dev.sh 与 AGENTS.md 坑点）：
   - dev 二进制（node_modules/electron/dist/Electron.app）官方分发即 ad-hoc 签名，TCC 对其授权弹窗/记录极不可靠（秒拒、弹窗时有时无）→ 用仓库证书重签真实签名后可靠
   - 终端子进程的摄像头请求按 TCC 归责到宿主应用：ZCode 内置终端起 dev 会静默失败；iTerm 正常。与代码无关，属环境因素

## 四、已知边界

- 系统层拒绝弹窗中的「当前状态：denied」为代码写死文案（askForMediaAccess 返回 false 分支），非实时读取值
- 每次 `npm install` 会把 Electron 二进制换回 ad-hoc 版，需重跑 `bash scripts/sign-electron-dev.sh`（未自动挂 postinstall，避免影响非 darwin 环境）
- macOS 关窗不退出（模板行为）下弹窗宿主窗销毁时回退应用级弹窗，授权判据不放宽（代码注释已述）
