## 三、执行中发现并修复的阻塞缺陷（超出计划字面范围，如实记录）

**采集页末块竞态**：`capturePage.html` 的 `ondataavailable` 原实现 `cap.saveChunk(await e.data.arrayBuffer())` 为未 await 的浮动 Promise。MP4 封装把数据缓冲到 stop 时冲刷，末块与 `onstop → cap.reportStopped()` 竞速——主进程 settle 见 stopped 即 drain+finalize，晚到的末块落空即「录制没有任何内容」报错。静态页面下全部分块都在 stop 冲刷，竞态必输（本次改动首轮真链路复现）；webm 时代因 VP8 按周期出块 + WebM 容忍截断而未暴露——属录屏线潜在时序缺陷，被 MP4 化暴露。

**修复**：页内 `chunkChain` 串行链（每块 append 到链尾、await saveChunk），`onstop` 改为 `chunkChain.then(() => cap.reportStopped())`——分块恒先于 stopped 到达主进程（渲染进程 IPC FIFO 保序），链内错误已转 reportError 故链自身永不 reject。修复后两轮真链路（含静态页最坏情况）全过。

诊断过程另证：分块 IPC 的 ArrayBuffer 过 contextBridge 桥完好（探针 16 字节 ArrayBuffer 到达主进程 handler），授予链（权限 broker → display handler → callback({video: frame})）在健康实例上全部正常。

## 四、转人工验收项（GUI 目检，无法自动化，如实标注）

1. **录制全链目检**：左栏新建会话 → 地址栏打开任一页面 → 工具栏点录屏钮（截图旁）→ 按钮变红点胶囊 + mm:ss 计时递增 → ~10s 后再点停止 → 原生信息框「录屏已保存：<路径>.mp4」→ 打开该文件可播放（QuickTime/系统预览）、画面为被录 Tab 内容、时长≈录制时长。
2. **暂停/恢复**：录制中点暂停钮 → 红点停脉、时长冻结 → 点继续 → 计时续走 → 停止后文件时长 = 总时长 − 暂停时长（暂停段不落帧）。
3. **自动停止三路抽验**：录制中 ①切到另一会话 ②关闭被录 Tab ③拖出被录 Tab——均自动停止并保存已录内容（本次改动未触碰生命周期编排，按计划回归抽验）。
4. **重名序号**：同名会话连续录两次，第二份落 `-2` 序号。
5. **三语言 × 亮暗**：录制态胶囊/popover/原生框文案随语言切换；暗色主题下录制态可读。
6. **Windows 抽查**：H.264 编码为平台编码器路径，Windows 真机录一段验证可播。

## 五、执行期环境插曲（如实记录，非代码缺陷）

跨日重启后隔离实例出现「CDP 可连但 Runtime 永不响应」：根因为**上一日实例的孤儿 Electron 主进程仍占 9224 端口**（pkill 模式只杀了 helper 与 electron-vite，主进程命令行不含 userData 串未被命中），新实例 `bind() failed: Address already in use / Cannot start http server for devtools`（dev 日志判据），CDP 流量实际打到孤儿进程、其渲染层已被杀。处置：`pkill -f '…/Electron.app'`（主进程）+ `lsof -ti :9224` 确认端口释放后重启，恢复。期间用三组最小 harness（BrowserWindow 目标 / WebContentsView 目标 / 复刻权限 broker）全部授予成功，排除 Electron 39.8.10 层回归。
