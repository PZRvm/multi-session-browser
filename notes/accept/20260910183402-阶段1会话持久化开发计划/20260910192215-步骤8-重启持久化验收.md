## 已实测通过（真实应用 + 真实落盘文件）

### 链路一：新建 → 重命名 → 落盘 → 重启 → 恢复

1. 启动应用（`npm run dev`），用户在界面实际操作：点击左栏底部「+ 新建会话」，再将会话重命名为「管理员界面」
2. 查看落盘文件（`cat sessions.json`），实际内容：

   ```json
   {
     "version": 1,
     "sessions": [
       { "id": "sess-mtvfkwzn-1", "name": "管理员界面", "note": "", "pageTitle": "未打开页面" }
     ],
     "activeId": null
   }
   ```

   → 主进程生成 id（`sess-` 前缀）、重命名已写穿落盘
3. 完全退出（kill 进程）后重新 `npm run dev` → UI 列表恢复显示「管理员界面」（截图存于波次 4 执行记录）→ **load 链路端到端成立**

### 链路二：重启后再次新建 → 落盘

1. 重启后的应用中点击「+ 新建会话」
2. 落盘文件变为两条：`管理员界面` + `会话 1`（主进程默认命名）→ **create 链路写穿成立**

### 链路三：坏数据回退（主会话实测）

1. 向 sessions.json 注入 `{"version":1,"sessions":"oops"}` 后启动 → 控制台输出 `[store] 会话快照校验失败（sessions 不是数组），已回退空快照`，应用正常启动，文件被写回合法空结构（详细日志见波次 2 验收文档）
2. store 层 29 用例转译桩测试（波次 3）覆盖：非法 JSON/空串/BOM、根非对象、version 异常、元素缺字段/类型错/重复 id、activeId 悬空/类型错、多余字段剔除、.tmp 残留不污染——全部 pass
