## 二、人工验收清单（需手动执行）

启动方式：正式终端执行 `npm run dev`（如遇摄像头/权限类异常与本项目无关，本功能不涉摄像头）。

### A. 核心链路（本机 Clash 即可完成，关闭 Clash「系统代理」开关保持对照组干净）

1. **入口与表单**：左侧会话行右键（或 ⋮ 菜单）→「代理设置…」→ 弹出原生 sheet（macOS 从主窗顶部滑出），表单预填当前配置（未配置时协议 HTTP、五字段空）。
2. **保存与徽标**：填 Clash 混合端口（如 127.0.0.1:7890，协议 HTTP）→ 保存 → sheet 关闭、会话行出现「代理」灰阶小徽标，悬停显「HTTP · 127.0.0.1:7890」。
3. **出口 IP 变化**：该会话打开 https://ip.sb（国外站避免 Clash 分流直连）→ 显示节点 IP；另建一个未配代理的会话打开同站 → 显示真实 IP；两行来回切换互不串线。
4. **检测按钮**：代理设置 sheet 内点「检测」→ 检测中态 →「代理可用，当前出口 IP：x.x.x.x」；在 Clash 切换节点再检测 → IP 跟变；把地址改成 127.0.0.1:19999 检测 →「连不上代理」；错密码（若用 mitmproxy --proxyauth 或代理商凭据）→「认证失败」。
5. **重启恢复**：重启应用 → 徽标仍在、代理配置保留、恢复的页面仍走代理（ip.sb 复核）。
6. **中途修改不自动刷新**：已打开页面时修改/清除代理 → 页面不重载（表单态保留），手动刷新后新配置生效。
7. **克隆携带**：克隆配了代理的会话 → 新会话行也有徽标，出口同代理。
8. **清除**：代理设置 →「清除代理」→ 徽标消失、出口回真实 IP。
9. **登录态不受影响**：走代理登录某网站 → 重启仍保持登录；F12 DevTools 正常绑定。
10. **失败反馈**：（可选，需人为制造失败——如临时改坏 sessions.json 或断网保存）保存失败时面板底部出现 danger 反馈条（「保存代理失败，请重试」）。

### B. 视觉与文案（目检）

11. 亮暗主题：sheet 表单、徽标、检测结果四态在两种主题下清晰可读（徽标全灰阶零琥珀）。
