## 七、用户验收反馈修复轮（2026-09-14）

用户实测反馈「有独立窗时退出重开，只剩主窗 Tab」。诊断结论两层：

1. **主因（数据已不可逆）**：用户退出的实例启动于阶段 10 改动之前——退出那一刻跑的还是旧主进程代码，独立窗 Tab 未归并落盘即丢失；重开后的新代码只是如实恢复旧盘面（时间线：当前实例 PID 22333 启动于 00:03:59，晚于全部改动落盘）。
2. **实锤一个真实缺陷并修复**：退出链冲刷是异步写盘，进程在写落定前退出——撕出/导航后 500ms 去抖窗口内退出丢最后一次改动；且 SIGTERM 信号路径不触发 before-quit（此前所有"SIGTERM 退出"验证的去抖均已提前落盘，从未真正覆盖冲刷路径，属验证盲区，如实记录）。修复：flushAll 汇合在途写盘返回 promise；before-quit preventDefault 拦首次退出、等写盘落定（1s 上限防 fs 挂死）再关窗真正退出；SIGTERM 统一转 app.quit() 走优雅链（src/main/index.ts + registry.ts + persistence.ts）。复测：撕出中间位 Tab 后立即 Browser.close（≈Cmd+Q 路径）与立即 SIGTERM 双双 PASS（落盘保留撕出 Tab、归并序正确）；typecheck/lint/build 复跑全绿。

给用户的复核方式：确认 dev 实例为新代码（重启 `npm run dev`）后，拖 Tab 出独立窗 → Cmd+Q → 重开，全部 Tab 应回主窗。

## 八、用户验收反馈修复轮 2（2026-09-14）：地址栏加载期清空

反馈：输入网址回车后，加载等待期间地址栏被清空。根因（Toolbar.tsx 既有逻辑，阶段 2 代码）：提交成功即 setDraft(null) 回归显示主进程快照 URL，而此刻导航刚开始、Tab url 仍是旧值（新标签页为 about:blank → 显示空串），加载落地前文本框空白。修复：提交成功后锁定显示提交文本（pending 记录「提交文本 + 当时快照 URL 基线」，渲染期比对基线判断是否仍在加载——快照 URL 离开基线即导航落地/重定向，无需 effect 清理；切换 Tab 同样使基线失配而过期；聚焦编辑取当前显示值；加载失败保留提交文本与 Chrome 同款）。验证：本地 2s 延迟服务器隔离实例实测——加载期间 9 个采样点地址栏恒显示提交文本零清空，落地后自动切换最终 URL；typecheck/lint 复绿。
