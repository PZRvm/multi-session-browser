# 阶段开发计划：截图快捷键退役、工具栏图标气泡与 Tab 融合

> 创建时间：2026-10-29 19:15:50（Asia/Shanghai）
> 需求来源：`notes/steps/feature-工具栏图标气泡与Tab工具栏融合.md`
> 执行模式：直通
> 实施范围：截图自定义快捷键整体退役；导航四键气泡 + 刷新/主页/停止自绘图标；选中 Tab 改色融合工具栏（含下角圆润衔接）。不含工具栏背景改动、主题色三系改动与新窗口形态。
> 目标结果：设置页无截图快捷键行、全局无截图快捷键通道；四键悬停出气泡（刷新带键帽）、图标观感统一改小；选中 Tab 与工具栏连成同色连续面、下角圆润，亮暗主题与双窗一致。
> 当前进度：步骤 1—4 均未开始

## 1. 当前基线

- 工具栏（`src/renderer/src/components/browser/Toolbar.tsx`）：`.chrome-nav` 四键 = 后退/前进（自绘 NavChevron，2026-10-23）+ 刷新（antd ReloadOutlined）+ 主页（antd HomeOutlined），加载态原位切停止（antd CloseOutlined）；四键用原生 `title` 提示。截图/录屏钮已有自绘气泡机制：`showToolsPop`/`hideToolsPop`（300ms 延迟、resize 即隐、span 槽 hover/focus 接线），样式 `.chrome-tools-pop`（app.css），截图钮气泡消费 `shortcutDisplay(screenshotShortcut, platform)` 键帽槽。
- 截图快捷键链路（全部现存，本阶段整体拆除）：
  - renderer：`settings/PaneShortcuts.tsx` 录入行与录制捕获；`browser/useBrowserShortcuts.ts` shell 聚焦分支（matchConfiguredShortcut 命中直调 capture）；`stores/settings.ts` screenshotShortcut 镜像与 setScreenshotShortcut；`stores/browser.ts` 的 `capture.onRequest` 接线（页面聚焦态推送汇流）。
  - 主进程：`main/settings.ts`（StoredSettings 字段、readScreenshotShortcut、cachedScreenshotShortcut、getScreenshotShortcut、setScreenshotShortcut、set-screenshot-shortcut IPC）；`main/browser/manager.ts` before-input-event 内 matchConfiguredShortcut 分支 + `capture:request` 定向推送。
  - shared：`settings.ts`（快照键、通道、validateShortcut/SHORTCUT_KEY_RE/SHORTCUT_CONFLICT_SET/ShortcutValidation、shortcutDisplay——shortcutKeyGroup 为速查表与键帽共用单源）；`browserShortcuts.ts` 的 matchConfiguredShortcut；`capture.ts` 的 request 通道。
  - preload：`index.ts`/`index.d.ts` 的 settings.setScreenshotShortcut 与 capture.onRequest 桥。
  - i18n：三语 `settings.screenshotShortcutRow.*` 键族与 `errors.invalidShortcut`/`invalidShortcutParams`/`shortcutConflict`。
- Tab 栏（`src/renderer/src/assets/app.css`）：`.chrome-tabs`（高 40px）带 `border-bottom: 1px solid var(--chrome-line)`；`.chrome-tab` 30px 底对齐、圆角 `8px 8px 0 0`；`.chrome-tab.active` 仅改背景色无下角衔接；非激活邻接对的分隔线已占用 `::before`（active 自身的 ::before/::after 空闲）。Token：亮色 `--chrome-tab-active: #ffffff` / `--chrome-toolbar: #f1f3f4` / `--chrome-tabbar: #dee1e6`；暗色 tab-active 与 toolbar 同值 `#292a2d`。
- 主题结构：chrome-* 全族为全局常量，不随琥珀/雾蓝/苔绿主题色三系；亮暗两块（`:root` 与 `@media (prefers-color-scheme: dark)`），外观三态（跟随系统/白天/黑夜）经主进程 `nativeTheme.themeSource` 统一驱动同一暗色块——改动只要走 token 即双主题自动适配。
- 双窗共用：Toolbar/TabStrip 为主窗与独立窗口共用组件，CSS 改动全体生效。
- PRD 现状：`docs/PRD.md` 多处载有截图快捷键契约（3.8.2 快捷键增补条 255 行、3.10 截图行为 299/300/316 行、4.x 偏好存储段 378 行），退役须同步修订。

## 2. 范围边界

### 2.1 本阶段必须完成

- 截图快捷键全链退役（PRD/DESIGN 修订 + shared/main/preload/renderer/i18n 拆线），截图按钮保留。
- 刷新/主页/停止自绘图标（NavChevron 同语言）+ 四键气泡（复用 .chrome-tools-pop 机制），刷新键帽单源派生。
- 选中 Tab 改色 #f1f3f4、Tab 栏接缝去线、下角反向圆角衔接，全走 token。
- typecheck/lint 通过，`npm run dev` 亮暗 × 主窗/独立窗手验，feature 文档待办勾选。

### 2.2 本阶段明确不做

- 工具栏背景色不动（用户裁决：融合由 Tab 侧改色承担）；主题色三系不涉及（chrome 侧全局常量）。
- 后退/前进图标不动（已自绘）；录屏线气泡机制与文案不动。
- 不为退役做旧配置迁移清理；不引入 Tab 切换动画/过渡新动效。
- 不增删源码文件、不改文件职责边界——`docs/项目骨架.md` 同步不适用（纯内部实现改动）。

### 2.3 本阶段数据原则

- 旧 `settings.json` 残留 `screenshotShortcut` 键：读侧不再消费、写侧不再产出，容忍残留不告警不清理。
- 快捷键退役后气泡不得显示假键帽——截图钮气泡只显功能名；刷新键帽只来自 BROWSER_SHORTCUTS 真实键位。
- 融合态颜色一律引用既有 token，不硬编码色值（双主题适配的执行纪律）。

1. **SettingsSnapshot 删 `screenshotShortcut` 键**、SETTINGS_CHANNELS 删 `set-screenshot-shortcut`：同步 `src/shared/settings.ts`、`src/main/settings.ts`、`src/preload/index.ts` + `index.d.ts`、`stores/settings.ts`。

3. **shared 校验函数退役**：validateShortcut 族（含 ShortcutValidation/SHORTCUT_KEY_RE/SHORTCUT_CONFLICT_SET）与 matchConfiguredShortcut 删除；shortcutKeyGroup/shortcutDisplay/ShortcutPlatform 保留（速查表 + 刷新键帽新消费方）。
4. **DESIGN.md**：colors 块 `chrome-tab-active` 亮色 `'#ffffff'` → `'#f1f3f4'`（components 条目随动核对）。
5. **docs/PRD.md**：删除/修订截图快捷键相关条目（3.8.2 增补条、3.10 快捷键与键帽行为、HTML 全屏快捷键口径、4.x 偏好存储段），标注 2026-10-29 用户裁决退役——依 AGENTS「实现与设计文档冲突先改文档」，本条在步骤 1 首任务落地。

完成标志：上述契约点全部落盘且 `npm run typecheck` 通过；`grep -rn "screenshotShortcut\|matchConfiguredShortcut\|set-screenshot-shortcut\|capture:request\|screenshotShortcutRow\|invalidShortcut\|shortcutConflict" src/` 零命中（shared 保留函数除外）。
