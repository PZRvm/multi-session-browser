- **Ant Design 主题固定**：`src/renderer/src/App.tsx` 顶层 `ConfigProvider` 只设琥珀主色和字体，没有 algorithm；`SessionPanel.tsx` 内层固定 `theme.darkAlgorithm`。Modal、Dropdown、Input、Checkbox 等控件若只改 CSS 会出现主题不一致。
- **现有视觉契约明确**：`DESIGN.md` 要求“左侧到发信息板 / 右侧 Chrome 原生语法”两个世界、琥珀只作稀缺信号、行式栅格、1px 发丝线、全应用零阴影、右侧不使用琥珀。亮暗扩展必须保留这些规则，而不是替换视觉世界。
- **技术栈已满足需求**：Electron `^39.2.6`、React `^19.2.1`、antd `^6.6.3`、zustand `^5.0.15`；不需要新增运行时依赖。当前本地未安装 `@ant-design/cli` 可执行文件，执行时不能把 CLI 命令冒充现有验收命令，Ant Design API 只用当前版本官方文档确认过的公开能力。
- **官方方案调研结论**：Electron [`nativeTheme`](https://www.electronjs.org/docs/latest/api/native-theme) 明确将 Follow OS / Dark / Light 映射到 `themeSource = system/dark/light`，并通过 `shouldUseDarkColors` 与 `updated` 提供实际主题和变化通知；[Dark Mode 教程](https://www.electronjs.org/docs/latest/tutorial/dark-mode) 推荐 renderer 使用 `prefers-color-scheme`；[BrowserWindow 文档](https://www.electronjs.org/docs/latest/api/browser-window) 建议即使使用 `ready-to-show` 也设置匹配背景色以减少首屏闪烁；[Ant Design 主题文档](https://ant.design/docs/react/customize-theme/) 支持 `ConfigProvider` 动态切换 `defaultAlgorithm/darkAlgorithm`。
- **主题作用域的关键事实**：`nativeTheme.themeSource` 是 Electron/Chromium 全局设置，会同步原生菜单、窗口框架、DevTools，并改变 WebContents 中 `prefers-color-scheme` 的匹配结果。因此支持该 media query 的被测页会响应主题；不支持的网页保持原样。本专项不向网页注入 CSS，也不把普通浅色网页强制反色。
- **验证纪律**：仓库无测试框架；验收手段是 `npm run typecheck`、`npm run lint`、`npm run build` 与 `npm run dev` 手动验证。所有运行时验证必须通过 `MSB_USER_DATA=<临时目录>` 隔离真实 `sessions.json` 和 `Partitions/`。

## 2. 范围边界

### 2.1 本阶段必须完成

- **三态与默认值**：`AppearanceMode = 'system' | 'light' | 'dark'`；首次启动默认 system；保存的是用户选择的 mode，不是当时计算出的明暗结果。
- **主进程唯一事实源**：用 Electron `nativeTheme` 应用三态，用 `shouldUseDarkColors` 生成 `resolvedTheme: 'light' | 'dark'`，用 `updated` 处理系统主题实时变化。
- **独立偏好持久化**：新增 `userData/preferences.json` v1，只存应用级外观偏好；缺文件、坏 JSON、未知版本或非法 mode 安全回退 system，不能阻止应用启动或影响会话数据。
- **类型化 IPC 与 preload**：新增 appearance 共享类型、get/set/changed 三通道和 `window.api.appearance` 白名单；renderer 不直接 import Electron。
- **renderer 状态镜像**：新增 Zustand appearance store，先订阅后拉取，StrictMode/HMR 防重复初始化；切换失败恢复主进程真实状态。
- **入口与可访问性**：左侧板头新增紧凑外观按钮，菜单提供“跟随系统 / 白天 / 黑夜”三个单选项；零会话、普通会话、批量模式下均可使用，支持键盘与明确的 `aria-label`。
- **完整双主题**：左侧信息板和右侧 Chrome 壳都有亮、暗 palette；Ant Design 顶层/板面层 algorithm 随 resolvedTheme 切换；窗口背景、空态、Tab、Toolbar、地址栏、弹层、错误/禁用/焦点状态都与当前主题一致。
- **首屏与运行时一致**：偏好在第一个 BrowserWindow 创建前加载；BrowserWindow `backgroundColor` 匹配 resolvedTheme；切换无需重启且不出现明显闪白/闪黑。
- **业务零回归**：主题切换不得导航/刷新、创建/关闭 Tab、切换会话、销毁 WebContentsView、清理 Cookie/缓存/LocalStorage、改变 DevTools 与页面的绑定。
- **文档与验收**：同步 `docs/PRD.md`、`PRODUCT.md`、`DESIGN.md`、`notes/process.md`，在 `notes/accept/20260912140057-应用外观三模式开发计划/` 落真实验收文档并用项目 `code-review` 技能收尾。

### 2.2 本阶段明确不做

- 不做每会话、每 Tab、每站点的独立外观设置；三态是应用级全局偏好。
- 不向被测页注入暗色 CSS，不使用滤镜强制反色，不改写网页自己的主题开关；网页只按其原生 `prefers-color-scheme` 支持情况响应。
- 不新增完整设置页、快捷键、定时切换、自定义颜色、主题下载或主题市场。
- 不自定义 DevTools 样式、停靠方式或生命周期；只使用 Electron/Chromium 原生主题能力。
- 不改会话快照 schema、不改 partition 字符串、不改 Tab/DevTools 快照、不把 theme 放入 `sessions.json`。
- 不引入 Playwright、单元测试框架或新的运行时依赖。
- 不借本专项整理/重编号用户正在修改的 `notes/steps/step-06~08`。

### 2.3 本阶段数据原则

- **保存意图，不保存偶然结果**：system 永久保存为 system；每次启动及系统变化时重新计算 resolvedTheme，禁止把 system 偷换成 light/dark。
- **应用偏好与会话数据分离**：`preferences.json` 与 `sessions.json`/`Partitions/` 生命周期互不影响；删除全部会话不能清除外观偏好，偏好损坏不能清空会话。
- **主进程为准**：renderer 的 mode 和 resolvedTheme 都是镜像；IPC 保存失败不得继续显示未落盘的虚假选择。
- **坏数据宽容、非法请求严格**：磁盘坏数据告警后回退 system；renderer 传入非法 payload 必须拒绝且不改盘、不改主题。
- **切换不伪装为页面功能**：被测页是否变色取决于页面自身对 `prefers-color-scheme` 的支持；验收不得宣称“所有网页都会变成暗色”。
- **界面纯中文**：菜单与失败反馈使用“跟随系统 / 白天 / 黑夜 / 外观模式”等中文文案；代码类型和值保持英文稳定枚举。
- **真实用户数据零触碰**：运行时测试只使用显式的 `MSB_USER_DATA` 临时目录，不以真实 userData 做重启或坏文件验证。

## 3. 开始编码前的契约核对

以下契约必须在步骤 1 冻结。任何实现偏离都要先更新本节、`notes/steps/feature-应用外观三模式.md` 和相关设计文档，禁止边写边猜。

1. **共享类型与通道**（新增 `src/shared/appearance.ts`）：
   - `AppearanceMode = 'system' | 'light' | 'dark'`
   - `ResolvedTheme = 'light' | 'dark'`
   - `AppearanceSnapshot { mode: AppearanceMode; resolvedTheme: ResolvedTheme }`
   - `SetAppearanceModePayload { mode: AppearanceMode }`
   - `APPEARANCE_CHANNELS = { getState: 'appearance:get-state', setMode: 'appearance:set-mode', changed: 'appearance:changed' }`
   - 导出单一 `isAppearanceMode(value: unknown)` allowlist 校验，主进程不得仅靠 TypeScript 类型信任 renderer。
2. **preload 表面**：`window.api.appearance.getState(): Promise<AppearanceSnapshot>`、`setMode(payload): Promise<AppearanceSnapshot>`、`onChanged(callback): () => void`；changed listener 剥离 `IpcRendererEvent`，退订使用注册时的同一个 listener。
3. **持久化格式**：`userData/preferences.json` v1 固定为 `{ "version": 1, "appearanceMode": "system|light|dark" }`；写入串行化，使用唯一临时文件 + rename；文件不存在静默 system，其余坏数据中文告警回退 system。
4. **主进程控制器表面**（新增 `src/main/appearance.ts`）：`init(): Promise<void>`、`getSnapshot(): AppearanceSnapshot`、`setMode(mode): Promise<AppearanceSnapshot>`、`registerAppearanceIpc(controller)`；初始化和失败回退均保证 controller 可用。
5. **应用顺序**：`app.whenReady()` 后先 await appearance init，再安装/注册既有功能并创建窗口；appearance 独立于 `sessions.init() → browser.init()` renderer 顺序。显式 set-mode 成功落盘后再修改 `nativeTheme.themeSource`，同值设置幂等。
6. **事件与去重**：`nativeTheme.updated` 是 system 实时变化和显式覆盖后的统一更新入口；广播前对 `{mode,resolvedTheme}` 去重，避免 setMode 返回与 updated 产生无意义重复渲染。广播窗口用 `BrowserWindow.getAllWindows()` 现取，不缓存已销毁窗口。
7. **主题作用域**：本计划采用 Electron 全局三态，因此支持 `prefers-color-scheme` 的被测页面会响应显式 light/dark；这属于已声明的产品行为。若用户在编码前决定“只改外壳、绝不影响被测页”，必须停止执行并重写此契约，不能在同一实现里暗中混用两种语义。
8. **UI 契约**：板头 `board-head-right` 在批量按钮前加入 20×20 外观按钮；菜单 `placement="bottomRight"`，键值与 mode 同名，顺序“跟随系统 / 白天 / 黑夜”，`selectedKeys` 反映 mode，按钮 title/aria-label 显示当前选择；popup 保持在最小 220px 左栏内，不进入右侧 WebContentsView 覆盖区。
9. **设计契约变更**：当前 DESIGN 固定“左暗右亮”，本专项改为两个视觉世界各有 light/dark 变体。琥珀稀缺、左右色域不互串、反白选中、数字翻牌、1px 发丝线、无阴影、右侧 Chrome 尺寸全部保留；`DESIGN.md` 必须在 UI 编码前记录该扩展。

完成标志：`docs/PRD.md` 与 `DESIGN.md` 已写入上述产品/视觉契约；`src/shared/appearance.ts` 与 preload 类型/包装逐项一致；`npm run typecheck` 通过；`rg -n "appearance:(get-state|set-mode|changed)" src` 只显示共享常量定义和经常量引用的接线，无散落手写通道。

5. 保持 `src/main/store.ts`、`src/main/sessions.ts`、`src/main/browser/**` 零改动；appearance 模块不得读取/枚举 session partition。

### 步骤 3：接入 renderer 外观镜像与 Ant Design 动态算法

任务：

1. 新建 `src/renderer/src/stores/appearance.ts`：初始 resolvedTheme 同步读取 `matchMedia('(prefers-color-scheme: dark)')` 以保证首帧；init 先订阅 changed 再 getState，使用 in-flight Promise/initialized/unsubscribe 防 StrictMode 与 HMR 重复注册。
2. store 同一 `applySnapshot` 同时处理 push 与 invoke 返回；`setMode` 以主进程结果为准，暴露 setting 状态防连续提交，失败回到旧 snapshot 并中文 console.error，不阻塞 sessions/browser 初始化。
