- 会话元数据持久化：会话列表（顺序）、自定义名称、账号备注、页面标题（pageTitle）、当前选中项（activeId），完全退出重启后完整恢复
- 主进程唯一写入者：electron-store（或其等价退路，见步骤 2）封装为 `src/main/store.ts`，schema 带版本号
- IPC 契约与桥：`window.api.sessions.*` 五个方法（list/create/rename/delete/set-active），`ipcMain.handle` + `invoke` 请求-响应式

- 健壮性：坏数据/缺字段回退空列表不崩溃；status 为运行时状态不落盘，重启后一律 idle

### 2.2 本阶段明确不做

- session 分区（`persist:sess-<id>`）与浏览器数据隔离——阶段 2（浏览器嵌入时落地）
- Tab 结构与"每个 Tab 的 URL"持久化——阶段 2（本阶段 pageTitle 由前端占位维护）
- 窗口尺寸/位置、分栏宽度持久化——PRD 未要求，推到有真实需求时
- 会话数据加密、多窗口并发写——单窗口阶段无此需求
- 测试框架引入——验证手段仍为 typecheck + lint + 手动验证（沿用 AGENTS.md 约定）
- Apifox 同步——判定：本计划不涉及任何 `backend/` 代码（本项目无后端），Apifox 同步要求整体不适用

### 2.3 本阶段数据原则

- `userData/config.json`（electron-store 默认落盘文件）是唯一事实源；主进程是唯一写入者；renderer 只是它的视图，禁止任何直写
- 禁止伪造：主进程加载失败或 handler 缺失时，如实呈现空列表 + 控制台错误，不得兜底演示数据
- `status` 是运行时状态，不落盘；`pageTitle` 落盘（对应 PRD"上次打开页面"）；`activeId` 落盘（对应 PRD 验收 4"页面状态可正常保存"的最低实现）

## 3. 开始编码前的契约核对

本项目无 `docs/architecture/` 骨架文档，契约以 `src/shared/sessions.ts` 文件 + `src/preload/index.d.ts` 类型为冻结载体；以下变更编码前必须冻结：

1. **持久化数据模型**：`StoredSession = { id: string; name: string; note: string; pageTitle: string }`；`status` 不在其中（运行时）。`SessionItem = StoredSession & { status: 'idle' | 'loading' }`（renderer 运行时类型）。id 由**主进程**在 create 时生成，规则沿用现状 `sess-<Date.now()base36>-<自增seq>`，renderer 不得自行造 id。
2. **store schema 与版本**：`{ version: 1, sessions: StoredSession[], activeId: string | null }`；`version` 字段为后续迁移预留，本阶段不做迁移逻辑，读到不认识的 version 时按坏数据回退（见步骤 7）。
3. **IPC 通道五条**（`ipcMain.handle`/`invoke`，禁用 `send`/`on` 单向通道）：
   - `sessions:list` → `{ sessions: StoredSession[]; activeId: string | null }`
   - `sessions:create` `{ name?: string; note?: string }` → `StoredSession`
   - `sessions:rename` `{ id: string; name: string }` → `StoredSession`（id 不存在时抛错）
   - `sessions:delete` `{ id: string }` → `{ ok: true }`（id 不存在时抛错）
   - `sessions:set-active` `{ id: string | null }` → `{ ok: true }`（id 不存在时抛错）
4. **preload 类型**：`src/preload/index.d.ts` 的 `api: unknown` 改为具体 `sessions` API 接口（含上述五方法签名）；该文件归步骤 3 独占，后续步骤不得再改。
5. **共享文件位置与引用方式**：类型与 channel 常量放 `src/shared/sessions.ts`；main/preload 以相对路径引用（`../shared/sessions`），**不新增 electron-vite 别名配置**（避免动构建层）。

完成标志：`src/shared/sessions.ts` 与 `src/preload/index.d.ts` 按上述落地，`npm run typecheck` 通过。

## 10. 主要风险与控制

| 风险 | 控制方式 |
| ---- | -------- |
| electron-store@11 纯 ESM 在 CJS 主进程加载失败（ERR_REQUIRE_ESM / 具名导出缺失） | 步骤 2 第一个任务即冒烟验证；失败当场切退路 A（手写 fs JSON，同接口，波次 3+ 不受影响）或 B（降级 electron-store@8）；决策记入 process.md |
| dev 模式误验：renderer HMR 或 Cmd+R 只重载渲染层，误判"持久化生效" | 步骤 8 验收统一"Cmd+Q 完全退出 → 重跑 `npm run dev`"，并以 `cat` 落盘文件前后对比为铁证；AGENTS.md 已注明 F12/Cmd+R 被 optimizer 接管 |
| renderer 多入口并发触发写，落盘竞态 | 唯一写入口收敛在主进程 handlers（2.3 数据原则）；electron-store 同步写天然串行；renderer 只按 IPC 返回值更新 |
| 手工编辑/损坏的落盘文件导致启动崩溃 | 步骤 7 坏数据矩阵逐项回退 + `console.warn`，永不让主进程因数据崩 |
| 移除「演示数据」签后 DESIGN.md 与实现漂移 | 步骤 9 文档同步列入验收（grep 断言）；DESIGN.md 本就注明"接入持久化时该签应移除" |
| 范围蔓延：顺手做分区/Tab/窗口状态持久化 | 2.2 明确不做清单 + code-review 八项第 8 条（作用域外的改动）拦截 |
