## 1. 契约冻结点

1. **快照字段（无新通道）**：`BrowserSnapshot` 增 `htmlFullscreen: boolean`（通道数不变，事实随既有 `state-changed` 推送）——窗口级 HTML 全屏态（Chrome 语义：挂窗口，切 Tab 保持）；零会话空态（`registry.emptySnapshot`）与落盘视角（`persistence.composePersistView`，重启后无页面处于全屏）恒 false；renderer 壳层（Tab 栏 / 工具栏 / 主窗左栏 / FindBar）据此隐藏，内容锚点扩满窗口、bounds 沿既有上报链路跟随。
2. **manager 内部面（非 IPC 契约）**：`TearOffTabManager` 扩展面增 `hasHtmlFullscreen(windowId?)`——registry 切会话编排专用查询。槽位表 `htmlFullscreenByWindow: Map<windowId, tabId>`（manager 内部，仿 `suspendedByWindow` 分槽先例）：
   - `enter-html-full-screen`（激活位守卫）：置槽位 + 激活 view 立即扩整窗（`getContentSize()` 现取）+ `emitChange`；
   - `leave-html-full-screen`（只清自己置位的槽位）：清槽 + 恢复缓存矩形 + `emitChange`；
   - 全屏期间 `setBounds` 上报**只应用不写缓存**（防整窗矩形污染布局缓存）；`currentRect` 优先级：悬挂收起 > HTML 全屏整窗 > 缓存布局；
   - 槽位释放收口：`closeTab` / `tearOffTab` / `moveTabToWindow` 在改写归属前经 `releaseFullscreenSlot` 精准释放（wc 销毁不保证补发 leave 事件）；`destroyTabsInWindow` 无条件清理。
3. **权限放行范围**：`permissions.ts` 的 request 与 check 两 handler 白名单各增 `fullscreen`（浏览器语义权限，与 `clipboard-sanitized-write` 同款无条件放行）；摄像头询问链与销毁期全拒绝（含 fullscreen）不动。
4. **registry 切会话收口**：`switchSession` 摘旧 view 前，旧会话 manager 持主窗全屏槽位时 `win.setFullScreen(false)`（槽位在 = 窗口全屏源于网页全屏而非用户自主，退出不误伤）——消除「窗口钉在 OS 全屏 + 新会话壳层全显」矛盾态（review 20260918125417 中 1 的定案：选「主动退出」而非文档冻结；旧会话 DOM 全屏态保留，Chromium 是否联动清槽位以实测为准，两分支行为均自洽）。
5. **快捷键口径**：HTML 全屏期间页内查找不可达（PRD 3.7.3 既有口径）——manager `before-input-event` 对 `find` 吞键前置放行、renderer `useBrowserShortcuts` 的 `openFind` 守卫，双侧同口径。
6. **PRD 修订链**：`docs/PRD.md` 3.2.3「网页渲染区域」增 HTML 全屏验收段（2026-09-18 修订：进 OS 全屏 + 壳隐藏不浮现 + Esc/网页按钮退出恢复 + 切 Tab 保持全屏布局 + 关闭/拖出恢复窗口布局 + 全屏期查找不可达 + 主窗/独立窗同规则）。`docs/` 在 .gitignore 内不进版本库，本文档即修订链的唯一在库记录。

## 2. 验收口径（手动，待跑）

- bilibili / YouTube 点全屏按钮：窗口进 OS 全屏、视频铺满、壳层（左栏/Tab 栏/工具栏）消失；Esc 退出后窗口与布局复原——主窗与独立窗各一遍，亮暗两主题
- 全屏中切 Tab：窗口保持全屏布局、新页面占满；切回原 Tab 全屏保留
- 全屏中拖出该 Tab / 关闭该 Tab：窗口布局恢复正常
- 全屏中切会话：窗口退出 OS 全屏、新会话正常呈现（本计划第 1.4 条定案行为）；切回旧会话观察全屏态走向（两分支均自洽，记录实测分支）
- 全屏中 Cmd+F：不唤起查找栏、按键留给页面（PRD 3.7.3）
- DevTools 开启时进出全屏：记录表现，异常再立专项
