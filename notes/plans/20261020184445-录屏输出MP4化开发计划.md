# 录屏输出 MP4 化 开发计划

> 创建时间：2026-10-20 18:44:45（Asia/Shanghai）  
> 需求来源：用户 2026-10-20 反馈——录屏保存的文件是 WebM（用户口述"webp"），要求改为 MP4、用最简便方式产出（关联 `notes/steps/feature-快速截图与快速录屏.md` 录屏线，PRD 3.10.2 现行"编码为 WebM"条款为本次变更对象）  
> 执行模式：直通  
> 实施范围：录制封装从 WebM 切换为 MP4（MediaRecorder 原生 MP4 封装，零转码、零新依赖），落盘扩展名同步 `.webm`→`.mp4`，PRD 与骨架文档同步。不做：webm 回退、转码管线、音频采集、格式配置项  
> 目标结果：停止录制后下载目录产出真实的 `.mp4` 文件（ISO Media 容器，QuickTime 等系统播放器可直接播放），既有录制生命周期（暂停/恢复/五路自动停止/重名序号/原生框反馈）行为不变  
> 当前进度：步骤 1—3 均未开始

## 1. 当前基线

- **录制管线（录屏线 A' 架构，计划 20261009231903 已交付）**：被录分区 WebContentsView 内的采集页 `src/main/browser/recording/capturePage.html` 发起 `getDisplayMedia`（video only，audio: false）并承载 `MediaRecorder`，当前固定 `mimeType: 'video/webm;codecs=vp8'`（capturePage.html:54），500ms timeslice 分块经 preload 桥上行。
- **落盘链**：`fileWriter.ts` 逐块 append 到临时区 `<随机名>.webm.part`（fileWriter.ts:58，惰性建目录 + promise 链序列化），finalize 经 `name.ts` 同名序号探测改名进下载目录 `${清洗会话名}_${YYYYMMDD-HHmmss}.webm`（name.ts:25、name.ts:46，硬编码 `.webm`）；零块 finalize 如实抛错、abort 删临时件，语义不变更。
- **启动期清扫**：`recording/index.ts:107` 只清 `*.webm.part` 孤儿——切 `.mp4.part` 后旧后缀残留将永不清扫，需双后缀兼容一轮。
- **MP4 可行性（已实测，本机 2026-10-20 探针）**：项目 Electron 39.8.10（Chromium 142），`MediaRecorder.isTypeSupported` 实测 `video/mp4`、`video/mp4;codecs=avc1`、`video/mp4;codecs=avc1.42E01E` 均 `true`。Chromium 126 起 MediaRecorder 原生支持 MP4 封装（H.264），Electron 39 远在其后——**最简便方案成立：换 mimeType 即得真 MP4，无需 ffmpeg/转码/新依赖**。
- **契约现状**：本次零共享类型变更、零 IPC 通道变更、零 preload 暴露面变更（`shared/capture.ts` 通道与载荷、`preload/index.d.ts` 均不动）；i18n 三语字典无格式字样（完成文案 `{file}` 插值，不涉后缀）。
- **文档记载**：PRD 3.10.2 出口条款与验收 37 明文"编码为 WebM/后缀 .webm"（PRD:311、PRD:477）——实现改 MP4 即与 PRD 冲突，按 AGENTS.md 纪律先改文档；`docs/项目骨架.md` name.ts 行载".webm 扩展名"（骨架:161）；`downloadNaming.ts:11` 头注释载".webm"（序号探测单源，注释级）；DESIGN.md 无格式记载；`notes/steps/feature-快速截图与快速录屏.md:8` 载"输出单个 WebM"（历史阶段文档，不追溯改写）。

## 2. 范围边界

### 2.1 本阶段必须完成

- 采集页 `MediaRecorder` mimeType 切换 `video/mp4;codecs=avc1`（显式声明 codec，确定性优先于容器默认）。
- 落盘扩展名链同步：临时件 `.mp4.part`、最终件 `.mp4`（buildRecordingFileName 与 resolveDownloadPath 两处）。
- 启动期清扫兼容双后缀：`.mp4.part` 与遗留 `.webm.part` 都清（一次性迁移兼容）。
- 相关注释与文档同步：fileWriter/name/downloadNaming/recording/index 四文件头注与行注、PRD 3.10.2 出口条款 + 验收 37、`docs/项目骨架.md` name.ts 行。
- 手动验证 MP4 容器真实性（`file` 命令输出 ISO Media，QuickTime 可播）——证明扩展名与容器一致，非改名伪造。

### 2.2 本阶段明确不做

- 不做 webm 回退分支：若某环境 MediaRecorder 不支持 avc1，构造即抛 NotSupportedError，走既有 reportError →「开始录制失败」原生框路径如实报错。理由：回退需把所选容器上行到主进程同步扩展名（ready 载荷扩容），违背本次"最简便"裁决；Electron 39/Chromium 142 桌面端实测支持，如未来某平台真不支持，另立专项。
- 不做 ffmpeg/转码管线、不新增任何依赖。
- 不做音频采集（audio: false 维持）、不加格式配置项、不改暂停/恢复/自动停止等生命周期语义。
- 不改 `notes/steps/` 历史文档（历史记载不追溯）；用户下载目录中已生成的 `.webm` 旧文件不迁移不处理。

### 2.3 本阶段数据原则

- 文件如实即所写：`.mp4` 扩展名内必为 MP4 容器（MediaRecorder 原生封装，非改扩展名伪造），验收以 `file` 命令输出与系统播放器可播为准。
- 沿用既有诚实语义：零块不产出空文件、失败不产半截文件、临时件失败保留供排查——全部不动。
- 录制数据仍只在应用内存内流转直写落盘，不重编码、不驻留整段。

### 2.4 契约核对

本阶段无共享类型/IPC 通道变更，但涉及基准文档与实现的一致性，编码前先落文档（AGENTS.md：实现与文档冲突时先改文档）：

1. **PRD 3.10.2 出口条款**（PRD:311）："停止后编码为 WebM 直接落系统下载目录（……后缀 .webm）" 改写为 MP4 口径（后缀 .mp4）；**验收 37**（PRD:477）"停止自动编码 WebM 落系统下载目录" 同步改 MP4。其余生命周期措辞（自动停止/原生框反馈/无半截文件）不动。
2. **`docs/项目骨架.md`** name.ts 行（骨架:161）：".webm 扩展名" → ".mp4 扩展名"；fileWriter 行无格式字样，不动。
3. **代码注释四处**：name.ts 头注/行注、fileWriter.ts 头注、recording/index.ts 清扫注释、downloadNaming.ts 头注中 `.webm` 措辞随代码同步改写。

完成标志：`grep -rn "webm" src/ docs/PRD.md docs/项目骨架.md` 仅命中 index.ts 双后缀清扫的兼容分支与 steps 历史文档（如保留 .webm 字样处均为迁移兼容注释）；`npm run typecheck` 0 错误。
