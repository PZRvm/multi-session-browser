## 1. 当前基线

- **窗形态（反馈轮一落地，未提交）**：`src/main/browser/captureEditorWindow.ts:122` darwin `titleBarStyle:'hidden'` + `trafficLightPosition:{x:8,y:8}`（settings 同款位——但 settings topbar 高 28px 与编辑窗 48px 不同源，**8px 在 48px 工具条上贴顶**，用户截图实证）；CSS `.chrome-capture-editor-chrome-custom .chrome-capture-editor-topbar`（drag 区 + padding-left:78px）。
- **笔迹现状**：`AnnotationStage.tsx` 画笔（`BrushAnnotation` Line）与马赛克画笔（`MosaicBrushAnnotation` MosaicBrushNode）均 `draggable` + `commitPointsShift` 位移平移——用户裁决改定型不可拖（马赛克**选区**模式 `MosaicAnnotation` 可拖性不动：上轮「标注画后可拖动」批复范围以其为准）。
- **文字缺陷现状**：文字工具点击落点开 DOM textarea（`openTextEdit`/`textSession` effect 聚焦），用户实测「打不上字」。根因未定位——嫌疑面：①EditorWindow window keydown（无依赖数组每次渲染重挂）在 textarea 聚焦前后抢先处理？该 handler 仅在 ⌘/Ctrl+Z 与 Escape 分支 preventDefault，字母键应穿透；②topbar drag 区（`-webkit-app-region: drag`）若因层叠误覆盖画布区会吞点击——但 drag 只声明在 topbar 元素本身；③`textSession` effect 聚焦与 Stage mousedown blur 时序。**实现时先复现定位（CDP 或人工），修到中文可输入、Enter 落版为止，不许猜测式改**。
- **裁剪现状**：确认钮 `.chrome-capture-editor-cropbtn.is-primary` 背景 `var(--accent-ink)`（#221a00 深褐——用户看到的非主题色）；取消钮 `.is-danger` 红字；Esc 双段语义（清选区留裁剪态→再按退出）；取消钮仅清选区栈留裁剪态。主题色底 token 已核实在位：`--accent-strong`（:root，#ffc133 琥珀缺省；雾蓝/苔绿主题系统自动换色）。
- **文档现状**：PRD 3.10.1 编辑小节与验收 39（反馈轮一口径）；DESIGN.md「截图编辑器」段；上轮验收增补篇（20261014163509）§2 人工步骤含本轮回归面。

## 2. 范围边界

### 2.1 本阶段必须完成

- `trafficLightPosition` y 8→16（48px topbar 垂直居中；x:8 不变，CSS 让位 78px 不动）——模块头注与注释同步裁决（编辑窗 48px 工具条与 settings 28px 拖拽带不同源，不复用其 8px 位）。
- 画笔/马赛克画笔笔迹落版定型：`draggable` 移除（Line 与 MosaicBrushNode 两处）、`commitPointsShift` 改为仅供裁剪平移复用或移除、相关头注更新（微信涂抹语义，用户 2026-10-14 反馈轮二裁决）。
- 文字工具输入修复：先复现定位根因再修，验收=中文 IME 输入、Enter 落版、双击重编辑全链人工可过。
- 裁剪确认钮 `background: var(--accent-strong)` + `color: var(--accent-ink)`（hover/focus 保持同底微降透明度）。
- 裁剪取消钮/Esc 直接退出：`cancelCrop` 语义改「清栈 + 退出裁剪工具」（EditorWindow Esc 分支不再双段；取消钮 onClick 同语义）；工具条裁剪锁定（cropLocked）随退出自然解除。
- i18n：无新键（五条均为行为/样式）；PRD 3.10.1 与验收 39、DESIGN 编辑器段增量句同步。
- 收尾：三命令 + build 分包核对 + `npm run dev` 人工清单（§3 步骤 3）+ 验收增补篇落盘 + process 行更新。

### 2.2 本阶段明确不做

- 笔迹选中态/二次编辑/橡皮擦。

- 裁剪选区手柄（八向缩放）、比例锁定。
- 快捷键体系变更（⌘/Ctrl+Z 系维持反馈轮一裁决；裁剪态 Ctrl+Z 撤框选逻辑不动——只改取消/Esc 出口语义）。

### 2.3 本阶段数据原则

- 零新增数据面：全部为交互/样式层，单槽与产出链（edit-copy/edit-download）不触碰。
- 笔迹定型后「撤回」唯一路径 = 撤销（⌘/Ctrl+Z），删除标注能力本就未建（与上轮一致，不做 del）。

### 2.4 契约核对

- 无 IPC/载荷/preload 变更；i18n 无新键。
- 基准文档增量：PRD 3.10.1 编辑小节（笔迹定型语义、裁剪取消/Esc 直退、确认钮主题主色）与验收 39 对应句；DESIGN.md 编辑器段（红绿灯 48px 居中位裁决、笔迹锁定、accent-strong 供色）。

## 3. 分步实施

### 步骤 1：红绿灯居中与裁剪配色/出口

任务：

1. `captureEditorWindow.ts`：`trafficLightPosition` 改 `{ x: 8, y: 16 }`；头注差异②补一句「y=16 = 48px 工具条垂直居中（(48−16)/2），与 settings 28px 拖拽带的 8px 位不同源，不复用」。
2. `AnnotationStage.tsx`：`cancelCrop` 语义改「清裁剪栈与草稿并返回 'exit'」或简化为 `exitCrop()`（清栈，返回 void）；EditorWindow Esc 分支改 `exitCrop(); setTool('rectangle')` 无条件退出；裁剪浮层取消钮 onClick 同语义（清栈 + 通知父层退出——经新 prop `onCropExit` 或复用 onToolChange 通路，实现取最简并在注记说明）。
3. `app.css`：`.chrome-capture-editor-cropbtn.is-primary` 背景 `var(--accent-strong)`、`color: var(--accent-ink)`（hover/focus 同底 opacity 0.88 微降）。
4. PRD/DESIGN 增量句（2.4 列明处）。

验收：`npm run typecheck` 0 错误 / `npm run lint` 0 error（7 存量不增）；`npm run dev` 人工——红绿灯垂直居中于工具条；裁剪确认钮呈琥珀/雾蓝/苔绿主题色（三主题切换各验一次）；取消钮与 Esc 均一键退出裁剪回矩形工具；裁剪态 Ctrl+Z 撤框选仍工作（回归）。

### 步骤 2：笔迹锁定与文字输入修复

任务：

1. 笔迹锁定：`AnnotationStage.tsx` 画笔 Line 与 `MosaicBrushNode` 移除 `draggable`/`onDragEnd`；`commitPointsShift` 若无其他消费方则连同 `applyCropFrame` 的折线平移（保留——裁剪仍需）一起核删冗余；模块头注补微信涂抹语义裁决。
2. 文字输入修复（根因定位优先）：`npm run dev` 复现「打不上字」→ 以 CDP 或断言缩小（textarea 是否出现/是否聚焦/keydown 是否被拦截/是否被遮挡）→ 修复 → 中文 IME 输入 + Enter 落版 + 双击重编辑全链人工过。常见嫌疑按序排查：window keydown 抢占、`textSession` effect 聚焦时序、CSS 层叠遮挡（topbar drag 区/层叠上下文）。
3. `npm run dev` 人工：画笔/马赛克（双模式）涂上即定型——拖拽笔迹不产生移动；选区马赛克仍可拖（回归）；矩形/椭圆/箭头/文字仍可拖（回归）。

验收：三命令全绿（typecheck 0 / lint 0 error·7 存量 / build 成功且 konva 仍独立 chunk、主包零 Konva）；`npm run dev` 人工清单全过；PRD 3.10.1/验收 39/DESIGN 增量句落盘；验收增补篇落 `notes/accept/20261014134249-截图编辑器开发计划/`；process 行更新；审查清单无新增问题或如实记录。
