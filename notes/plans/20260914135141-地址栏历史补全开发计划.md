## 2. 范围边界

### 2.1 本阶段必须完成

- 契约：新增 `src/shared/history.ts`（类型 + 2 通道 + 常量），preload `api.browser` 增两方法，`index.d.ts` 同步。

- 采集：manager 增 onVisit 回调面（did-navigate / did-navigate-in-page 主 frame / page-title-updated / page-favicon-updated 四事件上抛 `{ url, title, faviconUrl }`，about:blank 不入史），registry ensureManager 接线 `history.recordVisit`。

- 视觉：下拉面板走 impeccable scoped 流程定稿（chrome 灰阶、无阴影、亮暗 token），DESIGN.md 增条目。
- 文档：`docs/项目骨架.md`（新文件 + 通道数 + 职责）、`notes/process.md` 阶段表同步；验收文档落 `notes/accept/`。

### 2.2 本阶段明确不做

- 历史管理页（查看/搜索/删除单条历史）——后续如有需求另立专项。
- 跨会话全局历史、历史导出/导入、历史同步。
- 搜索引擎建议、书签建议、Tab 补全（输入 Tab 键采纳首选）、输入内联自动完成（只做下拉建议，不改输入框文本）。
- URL 去 query 规范化（测试场景靠 query 区分环境，调研定案不学 Min 此项）；拼音/模糊音匹配。
- Web Worker / utilityProcess 检索迁移（量级不需要；`omniboxSuggest` 保持纯函数，未来可整体迁移，接口不变）。
- 访问过的页面全文索引（Min 的 fullTextPlaces 一类）。

### 2.3 本阶段数据原则

- 历史属会话数据：按会话隔离是硬边界——镜像与推送都以 sessionId 守卫，主窗切会话即丢旧会话镜像，杜绝跨会话串建议。
- 主进程是历史唯一事实源：renderer 只镜像不造条目；建议检索纯本地（编辑期零 IPC），满足「不阻塞主进程」为结构性保证而非性能余量。
- 诚实性：历史文件损坏按 store.ts 同款回退空史并中文告警——丢历史不丢会话（sessions.json 互不影响）；favicon 加载失败走灰阶占位不伪造；无匹配不弹面板，与现状无异。
- 容量纪律：每会话 2000 条、URL 截断 2000 字符（与 LAST_URL_MAX 同值）；淘汰只按 lastVisitedAt 最旧。
- about:blank 不入史；`file://` 入史（白名单内）；`data:` 已被 `isOpenableUrl` 白名单挡在门外。

### 步骤 2：主进程历史模块

任务：

1. 新建 `src/main/browser/history.ts`：`createBrowserHistory(deps)` 返回模块面——
   - 内存 `Map<sessionId, Map<url, HistoryEntry>>`；`ensureLoaded(id)` 单飞行 promise 懒加载（读 `userData/history/<id>.json`，ENOENT 静默空史，坏 JSON/缺字段/版本不认识回退空史并中文告警，照 store.ts 容错口径）；
   - `recordVisit(id, entry)`：URL 截断（超长不入史并告警）、about:blank 跳过、同 URL upsert（visitCount+1、lastVisitedAt=Date.now()、title/faviconUrl 非空才覆写——导航先到、标题后补的真实时序）、超 2000 条按 lastVisitedAt 淘汰最旧、500ms trailing 去抖落盘（tmp+rename 原子写，照 store.ts）、成功落盘后触发 `onEntryChanged` 回调（供 IPC 推送）；
   - `getEntries(id)`（ensureLoaded 后返回数组拷贝）；`cloneHistory(srcId, dstId)`（复制落盘文件 + 内存未加载则只复制文件）；`dropHistory(id)`（删文件 + 清内存 + 清去抖定时器）；`flushAll()`（冲刷全部待写并封笔，照 persistence.ts sealed 模式，返回汇合 promise）。

3. 一次性验证脚本（放 /tmp，不入库）：临时 Electron 入口或 node 断言脚本跑 upsert/淘汰/截断/坏数据回退四路，验证后删除。
