## 2. 范围边界

### 2.1 本阶段必须完成

- `StoredSession` 增 `tabs: StoredTab[]`（`{ url: string }`）与 `activeTabIndex: number`，写盘恒出 v3，v1/v2 读取迁移（tabs 由 lastUrl 派生单元素、activeTabIndex=0）。
- `flushReport` 落全量 Tab 列表（顺序、URL 截断、激活位），lastUrl 与 `tabs[activeTabIndex]` 同源计算保持一致；before-quit 冲刷覆盖。
- `ensureManager` 按 tabs 列表多开 Tab 恢复（逐条白名单校验、坏值跳过告警、全坏回退空白 Tab），激活位恢复；缓存未命中补载路径同步改造。
- clone 元数据与 createSession 初始条目补 v3 字段。
- `DESIGN.md`、`src/shared/sessions.ts` 头注释、`notes/process.md` 状态行同步。

### 2.2 本阶段明确不做

- 独立窗口的一切形态与拖拽（阶段 7—10）。
- 窗口宿主模型重构（阶段 7）：本阶段不碰 manager 数据结构与快照语义。
- Tab 运行态（滚动/表单/SPA 内部态）与 DevTools 开关态的持久化——PRD 3.6.4 明确 URL 级恢复。
- renderer 任何改动、IPC 通道/暴露面变更、BrowserSnapshot 结构变更。

### 2.3 本阶段数据原则

- 恢复是 URL 级，运行态不还原且不做任何"看起来恢复"的假象（空白 Tab 如实空白）。
- 坏 url（白名单不过/超长截断后仍非法）跳过并如实告警，不静默吞掉也不整包丢弃。
- lastUrl 与 tabs[activeTabIndex] 由同一快照同源计算，禁止两处独立维护出现分歧。
- 落盘 URL 逐条截断 `LAST_URL_MAX`，与既有 lastUrl 截断同口径。

### 步骤 2：registry 写侧——Tab 列表随上报落盘

任务：

1. `src/main/browser/registry.ts` `flushReport`：在既有 pageTitle/lastUrl 之外，从 `manager.getSnapshot()` 计算并写 `tabs`（快照 tabs 顺序，url 逐条截断 `LAST_URL_MAX`，about:blank 原样保留）与 `activeTabIndex`（activeTabId 在列表中的序号，找不到取 0）；lastUrl 取同一快照的激活 Tab url，保证与 `tabs[activeTabIndex]` 一致。
2. 上报去抖判据（`reported` 缓存）扩展为 `{ url, title, tabsKey }`（tabsKey = URL 列表 + 激活位指纹），激活位切换、增删 Tab 均能触发落盘。
3. `src/main/sessions.ts`：createSession 初始条目补 `tabs: [], activeTabIndex: 0`；clone 的 `cloned` 元数据复制增 `tabs`/`activeTabIndex` 随行（源条目取自最新落盘值，与既有 pageTitle/lastUrl 同路）。

验收：`npm run typecheck` 通过；`npm run dev` 打开会话开 3 个 Tab、切到中间 Tab，退出后 `sessions.json` 该会话条目 tabs 长度 3、顺序正确、activeTabIndex = 1、lastUrl 与激活项一致；克隆会话产物条目含相同 tabs。

### 步骤 3：registry 读侧——按 Tab 列表恢复

任务：

1. 预读缓存升级：`lastUrls` 值类型从 `string` 改为恢复描述符 `{ tabs: { url: string }[]; activeTabIndex: number; lastUrl: string }`（`preloadLastUrls` 与两处消费点同步），语义为"该会话下次激活的恢复集"。
2. `ensureManager` 恢复逻辑：tabs 空 → 单空白 Tab（现状不变）；非空 → 逐条 `isOpenableUrl` 校验，合法项按序 `newTab(url)`、坏值跳过并告警，全部非法回退单空白 Tab；末尾按 activeTabIndex `switchTab`（钳制到有效范围）。恢复 Tab 数为 0 且原列表非空时告警。
3. 补载路径（`pendingBackfill`）同步改造：缓存未命中现读落盘后按同一恢复集逻辑多开；`openUrlInSessions` 的空白 Tab 复用判据不变（恢复后初始 Tab 非 blank 时自然不命中）；R1 的"复用路径先撤销补载资格"守卫语义保留。
4. `openUrlInSessions` 对刚懒创建会话的复用分支在多 Tab 恢复后的行为复核（恢复集非空 → 不复用，新建 Tab 加载，语义不变）。

验收：`npm run typecheck` 通过；`npm run dev` 用例——① 重启后激活有多 Tab 的会话：Tab 数/顺序/激活位正确，页面为 URL 级加载（滚动位置不还原）；② v2 老文件（手改 version=2）重启迁移为单 Tab lastUrl 恢复；③ 落盘 url 填 `javascript:alert(1)` 的坏值重启：该 Tab 跳过且控制台告警，其余 Tab 正常；④ 克隆产物激活后 Tab 集与源一致。
