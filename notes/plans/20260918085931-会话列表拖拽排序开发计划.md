## 2. 范围边界

### 2.1 本阶段必须完成

- 契约与白名单桥：新增 `sessions:reorder`、`ReorderSessionsPayload { ids: string[] }` 与 `window.api.sessions.reorder(payload)`，shared、preload 实现和全局类型三处一致；会话域通道总数 10 → 11。
- 主进程排序：只接受当前全部会话 ID 的无重复全序；格式非法、重复、缺项、多项或未知 ID 时整单拒绝且磁盘不变；合法时仅按入参顺序重排 `snapshot.sessions`，`activeId`、会话字段与浏览器编排均不改变。
- renderer 排序动作：校验本地全序后乐观换序，只提交一次 IPC；失败时重拉主进程快照恢复权威顺序并保持运行时状态，向用户显示中文失败反馈。
- 会话行拖拽：普通模式下鼠标拖动排序；行内重命名、菜单、复选框等交互起点不得误触拖拽；批量模式和重命名编辑态禁用拖拽；列表外、右侧网页、窗口外释放或按 Esc 取消均不移动且无残留指示。
- 拖拽反馈：源行、拖影和前/后插入位清晰可辨，激活态仍属于原会话 ID，亮暗主题与 220—420px 左栏宽度均可读；所有视觉决策遵循信息板发丝线、无阴影与琥珀稀缺规则。
- 文档与验收：同步 `docs/PRD.md`、`DESIGN.md`、`PRODUCT.md`、`docs/项目骨架.md`、`notes/process.md`，并在本计划对应 `notes/accept/` 目录记录隔离环境的运行时证据。

### 2.2 本阶段明确不做

- 不做跨列表、跨窗口或向右侧浏览区的会话搬移；会话分区 `persist:sess-<id>`、WebContentsView、Tab 拖出/拖入与 DevTools 绑定逻辑全部不动。
- 不做批量模式下排序；进入批量态即无 draggable 行，退出后恢复。
- 不做键盘拾取、方向键移动、读屏排序播报或移动端/触控排序；既有 Enter/Space 激活与批量勾选键位保持原样。
- 不引入 dnd-kit、@hello-pangea/dnd、pragmatic-drag-and-drop 或其他依赖；不实现多容器、树形排序与定制自动滚动算法，先使用 Chromium 的列表拖拽自动滚动。
- 不升级 sessions.json schema，不新增 order/index 字段，不改变新建/克隆追加末尾及删除后的级联首项规则。
- 默认不因拖拽收起右侧 WebContentsView；只有真机验证能稳定复现拖拽态无法结束时，才暂停实现并修订方案，不直接加入会让网页区闪退式消失的 overlay 兜底。

### 2.3 本阶段数据原则

- `sessions.json` 内 `sessions` 数组顺序是唯一持久化顺序；renderer 不另存 order，不维护第二份索引事实。
- IPC payload 必须是完整排列而非“from/to”增量；主进程在 `mutateSnapshot` 同一互斥期内比较当前 ID 集合，消除校验后再写盘的竞态窗口。
- 排序是纯元数据重排：会话 ID、activeId、名称、备注、页面恢复集、运行状态、分区数据和各 webContents 身份全部不变。
- 拖拽中的源 ID、候选插入位、拖影节点都是 `SessionPanel` 本地瞬态，不进 zustand 持久事实、不经 IPC、不落盘；只有有效 drop 生成一次全序提交。
- 乐观 UI 不冒充落盘成功：IPC 失败须回到主进程返回的列表顺序；若重拉也失败，则按未被其他操作改写的条件回滚并保留错误日志/中文提示，不静默维持未落盘顺序。
- 运行时验证必须使用独立 `MSB_USER_DATA` 临时目录，禁止读取、覆盖或清理用户真实会话数据。

### 2.4 契约核对（编码前冻结）

1. **通道与 payload（10 → 11）**：`SESSIONS_CHANNELS` 增 `reorder: 'sessions:reorder'`；新增 `ReorderSessionsPayload { ids: string[] }`。同步修订 `src/shared/sessions.ts` 头部契约说明，并在 `notes/plans/20260912201534-阶段6会话Tab列表落盘与恢复开发计划.md` 第 2.4 节追加本专项历史修订记录；schema v3 与 `StoredSession` 零变更。
2. **preload 暴露面**：`src/preload/index.ts` 增 `sessions.reorder(payload: ReorderSessionsPayload): Promise<OkResult>`，`src/preload/index.d.ts` 同步类型导入和方法签名；renderer 禁止直接 invoke 通道。
3. **主进程拒绝制**：payload 必须为 record，`ids` 必须是非空 string 数组；每个 ID 通过 `SESSION_ID_RE`；`new Set(ids).size === ids.length`；在 `mutateSnapshot` 内与 `snapshot.sessions.map(id)` 做长度和集合相等校验。任一失败抛中文业务错误、整单不写；成功以 ID → StoredSession 映射按 ids 重建数组，返回 `{ ok: true }`，不触发任何 `SessionIpcDeps` 回调。
4. **renderer 动作**：`reorderSessions(ids): Promise<boolean>` 只接受与当前本地列表相同 ID 集合的全序；无变化直接返回 true；有效变化乐观重排现有 `SessionItem` 对象。失败先调用 `sessions:list`，以快照顺序映射当前 SessionItem 保留 `status`，缺失项按 `idle` 补齐，并以快照 `activeId` 为准；重拉也失败时仅在当前 ID 顺序仍等于本次乐观结果时回滚原顺序，返回 false。
5. **拖拽提交语义**：`dragstart` 记录源 ID、设置 `effectAllowed = 'move'`、清空默认 dataTransfer 后只写应用自定义 MIME；交互控件起点直接取消。`dragover` 仅在本列表的有效源存在时 `preventDefault`，按目标行垂直中点计算 before/after；`drop` 生成一次完整新序并调用 store；`dragend` 无条件清空源 ID、插入位与临时拖影。相邻无位移、拖回原位和列表外释放不得发 IPC。
6. **需求与设计文档**：`docs/PRD.md` 在 3.1 补普通模式拖拽排序、3.1.4 补列表顺序持久化、4.x 补纯重排业务规则、验收标准追加一条；`DESIGN.md` 在会话行附近新增排序条目并说明与 Tab Drag 的边界差异；`PRODUCT.md` 会话管理能力补“拖拽排序”。

完成标志：上述签名、拒绝语义与文档口径一致，`npm run typecheck` 和 `npm run lint` 均通过后才进入手势实现。
