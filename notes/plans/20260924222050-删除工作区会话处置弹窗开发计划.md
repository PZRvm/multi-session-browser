### 2.2 本阶段明确不做

- 不做主进程「删会话 + 删工作区」原子合批通道——复用既有两通道由 renderer 编排（确认与执行两段解耦先例，4.11 同口径）；不做 workspaces:delete 载荷扩展。
- 不动 workspaces:delete 主进程「降级未分组」语义（「保留会话」路径原样）；不动删除会话（session-delete）与批量关闭（sessions-batch-close）两处确认及其契约。
- 不做「不再询问」checkbox、自绘无边框子窗口、按钮主题色注入（PRD 4.10 既有裁决）。
- 不动 picker 三通道（move-single/move-batch/rename）与 `useDeferredMenuAction` 接线；独立窗口无工作区入口不涉及。

### 2.3 本阶段数据原则

- 弹窗通道是纯 UI 辅通道：主进程只弹框返回三态结论，不落盘、不触碰会话快照与分区；执行由 sessions:delete-batch / workspaces:delete 既有通道闭环，确认与执行两段解耦。
- 结论语义诚实：`cancel` 覆盖 取消钮 / Esc / 关框 / 宿主窗缺失 / 入参守卫失败 / invoke 异常（薄封装吞错 warn），不伪造 delete-all/keep；delete-all 仅当用户按下「删除全部会话」（空工作区两键框按下「删除」亦返回 delete-all，此时无会话可删与既有行为等价）。
- delete-all 失败不静默、不部分执行：delete-batch 整单拒绝 → 工作区不删 + 行内失败反馈，可从入口再次发起。
- 执行时现取数据：会话 id 集在弹窗结论后从 store 现取（`useSessionsStore.getState()`），不用弹窗触发时刻的闭包旧值。
