## 1. 当前基线

- **阶段一已交付（本阶段直接基线）**：独立设置子窗 + 板头齿轮 + 菜单「设置… ⌘,」双入口、`settings:open` 单通道（sender 白名单主窗）、`settings.json` v1 空骨架、renderer 第四角色 `?role=settings` 惰性 chunk、外观三段阈值 390。设置窗当前渲染**空窗态分组标题骨架**（`SettingsWindow.tsx` 三组 `<section><h2>`，无控件行）。
- **设置窗主题与 store 现状**：`main.tsx` settings 分支**不初始化任何 store**——壳体主题走 CSS 媒体查询（`app.css` 暗色 token 经 `prefers-color-scheme` 随主进程 `nativeTheme.themeSource` 翻转，阶段一分流注释明确「阶段二接入真实设置项时再议 store 初始化」——本阶段兑现该备注：为「外观行显示当前真实模式」，settings 分支需增 `useAppearanceStore.init()`（先订阅后拉取 + in-flight 防重入的既有实现，`stores/appearance.ts`），只读消费 `mode`/`resolvedTheme`，不调用 `setMode`）。
- **DESIGN.md 现行契约**：「设置窗口（Settings Window）— 设置专项阶段一新增」条目定义了窗口度量（420×320 / min 380×260 / max 600×680 可拉伸）、空窗态（三组标题 11/500 次墨 letter-spacing 0.04em、组间距 20px、组内标题下 8px 接控件行、36px 行高发丝线分隔——**控件行度量已预定义，本阶段直接兑现**）、板面双世界 token、无卡片无阴影、阶段六前零琥珀。本阶段需把「空窗态」段落扩写为全量内容契约，并新增危险区与两步确认弹层的视觉语言（危险色域在板面世界的用法——`--danger` token 既有：亮 #d4380d / 暗 #ff7875，历久经 antd danger 供色先例）。
- **色板候选资产**：两案候选色值已在访谈中定稿待校（甲「航显霓虹」/乙「陶墨低语」，每色 base/deep/ink/press/strong 一组 token；终值与逐对对比度校验明确留阶段五）。本阶段色板以**候选色值渲染**（建议先取一案的 6 色圆点，选中态=默认琥珀），阶段五点亮时再定案。
- **契约现状（本阶段零变更）**：`src/shared/settings.ts` 仅 `SETTINGS_WINDOW_ROLE` + `SETTINGS_CHANNELS.open`；preload 五命名空间不变；外观域三通道既有（getState/setMode/changed）——settings 窗 init appearance store 复用 `getState` + `changed` 订阅，**不新增任何通道、不动 schema**。
- **renderer 依赖现状**：设置窗经共享 index chunk 已加载 antd 全图（阶段一 build 实证 SettingsWindow chunk 仅 1.11 kB、antd 在主 index chunk）；设置窗是独立 OS 窗、**无 WebContentsView 原生层遮挡问题**——antd Modal/弹层在此窗口内可正常浮起（与主窗 shell 的弹层约束不同）。
- **文档现状**：`docs/项目骨架.md` 已含四新文件行与五命名空间；`notes/process.md` 阶段表已重排为七阶段（本计划对应阶段二行「未开始」）。

## 2. 范围边界

### 2.1 本阶段必须完成

- impeccable scoped 设计定稿 + DESIGN.md「设置窗口」条目扩写：语言选择器形态、主页 URL 输入框、关于区三行布局与占位值口径、危险区（恢复出厂按钮 + 后果说明）与两步确认弹层（含「antd Modal 自带阴影 vs 板面无阴影规则」的形态裁决——自绘或 Modal token 去阴影，二选一定稿）；控件行度量兑现阶段一预定义（36px 行高、发丝线分隔、label 左 + 控件右）
- **主题色行本阶段不渲染（2026-09-16 执行中用户裁决）**：色值先经示例网页选案（notes/demo/ 两案各一页、多 subagent 并行绘制），色板行随阶段五色板定案后与功能一起入窗——「全量内容」其余部分不变
- `SettingsWindow.tsx` 全量内容渲染（全部受控只读/无行为）：
  - 通用：外观三段（Segmented 受控只读，value 绑 appearance store 镜像、无 onChange——板头切换实时同步显示，设置内点选不生效）；语言选择器（展示「中文（简体）」，形态按设计定稿，选择不生效）；**主题色行缺席（用户裁决留空，见 2.1）**
  - 浏览：主页 URL 输入框（可输入、placeholder 按设计定稿，无持久化无行为）
  - 关于：版本行（占位值）、快捷键速查行、打开数据目录行（后两行为静态行/链接样式，点击无行为）
  - 危险区：恢复出厂按钮（danger 视觉）+ 两步确认弹层（本地 state：第一步后果清单 + 取消/下一步；第二步「输入重置」受控输入 + 输入等于「重置」时点亮确认钮；确认与取消均仅关闭弹层，零清理执行）
- `main.tsx` settings 分支增 appearance store 初始化（只读镜像，兑现阶段一预留备注）；`app.css` 增全量内容样式（行/色板/选择器/危险区/弹层，亮暗双主题）
- `docs/项目骨架.md` 同步（SettingsWindow 职责行、main.tsx 角色注释微调）；`notes/process.md` 状态更新
- 验收：三命令全绿 + CDP 冒烟（全内容渲染断言 / 亮暗双主题 / 两步确认走形 / 控件只读断言）+ impeccable detector + code-review 轮

### 2.2 本阶段明确不做

- **任何功能**：外观切换（阶段三）、语言切换与 i18n（阶段六）、主题色生效与 token 化（阶段五）、主页 URL 持久化与工具栏对接（阶段四）、真实版本号/快捷键速查内容/打开数据目录（阶段三）、恢复出厂清理（阶段七）——控件一律无行为，文案不写「待实现」类引导语（PRODUCT 禁，静默即可）
- `settings.json` 任何键扩展与 get/changed/set 通道（首个真实键归阶段四）
- `src/shared/`、`src/preload/`、`src/main/` 任何改动（零契约变更、零主进程改动——两步确认的「零清理」使其无需主进程参与）
- 色板终值定案与对比度校验（阶段五；本阶段用候选色值渲染）

### 2.3 本阶段数据原则

- 占位值如实标注设计语义（版本行占位以设计定稿口径渲染，不伪造真实版本号）；外观行显示的是真实当前模式（只读镜像，非伪造）
- 两步确认输入框为纯本地瞬态（不落盘、不进 IPC）；色板选中态为组件本地 state
- 验证一律走 `MSB_USER_DATA` 隔离目录；截图为真实运行态

### 2.4 契约核对（编码前冻结）

本阶段**零共享契约变更**：不新增/修改 IPC 通道、不动 schema、不改 preload 暴露面（复用既有 `settings:open` 与外观域只读订阅）。唯一基准文档变更为 DESIGN.md「设置窗口」条目扩写（空窗态段落 → 全量内容契约 + 危险区/两步确认视觉语言），随步骤 1 设计定稿一并落盘——属 feature 文档既列明的 impeccable 产出。

完成标志：DESIGN.md 条目扩写完成且与既有规则零冲突（无阴影、零琥珀至危险区前、图标走 @ant-design/icons）；`git status` 确认 `src/shared/`、`src/preload/`、`src/main/` 零改动。
