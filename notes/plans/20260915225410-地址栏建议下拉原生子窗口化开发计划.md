### 2.2 本阶段明确不做

- 不改建议语义：匹配算法/排序/阈值/上限、历史数据层（`shared/history.ts` 与 `main/browser/history.ts`）、键盘状态机行为（↑↓ 环形/Enter 高亮优先/Esc 两段）逐字不变。
- 不做子窗内键盘交互：键盘恒在宿主 shell 输入框（子窗 `focusable: false` 结构性保证），子窗纯指针（hover/click）。
- 不做宿主失活（blur）自动收起：与 Chrome 的已知差异如实接受——窗口失活时子窗随宿主失去激活仍可见，回焦点后原样保持（若实测造成困扰再立修订，本阶段记录为已知差异）。
- 不做 Chrome 的输入内联自动补全（inline suffix）、搜索引擎联想、多列/分组建议；无任何网络请求新增。
- 不动 overlayDepth 机制本体与其余登记方（antd Modal/Dropdown 弹层语义原样）；不动 `useBrowserShortcuts` 冻结逻辑（对建议面板自然解冻即可）。
- 不改 PRD/PRODUCT（承载机制是实现细节，需求事实未变；DESIGN.md 承担全部记录）；零新增依赖；不碰会话隔离链路（分区/WebContentsView 挂摘/DevTools 绑定/拖拽/快照契约零变更——子窗是 BrowserWindow 不进 contentView，与 WebContentsView 无涉）。

### 2.3 本阶段数据原则

- 无持久化：子窗纯瞬态（不落盘、不进任何快照、重启无恢复语义）；数据仅存于宿主 shell 的既有镜像与子窗内存，生命周期 = 面板开合。
- 会话隔离不变量：子窗数据只由宿主 shell 推送（当前作用域会话的历史镜像子集，≤8 条），子窗零拉取零持有；favicon 加载行为与现状一致（内联面板同走默认会话网络栈，无回归）。
- 状态单源：建议状态机（draft/suggestions/activeIndex/dismissed）唯一在宿主 shell；子窗是纯渲染端（只收 data 推送），hover/pick 只上报不自治——杜绝双端状态分叉。
- 运行时守卫制：新通道入参一律先过结构守卫（`createIpcGuards` 惯例）；sender 身份白名单校验（show/hide 仅认宿主 shell webContents，hover/pick 仅认池内子窗 webContents），伪造来源拒绝。
- 诚实性：无匹配不弹面板（不显示空面板）；点选导航失败时编辑态保留 + 行内错误提示与现状一致；页面保持可见是结构事实（子窗悬浮于页面上方，原生层零触碰），不依赖任何「收起/恢复」时序。
