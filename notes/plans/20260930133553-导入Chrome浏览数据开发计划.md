### 2.2 本阶段明确不做

- **Cookie 导入**（用户 2026-09-30 批复移出；调研报告单元 B 保留备续）。
- 持续同步 / Chrome 数据变更监听（一次性动作，再导一次即再同步）。
- 自定义 Chrome 用户数据目录的手动路径选择（仅默认目录 + `MSB_CHROME_USER_DATA` 测试覆盖，后者不属用户功能面）。
- IndexedDB / 密码 / 书签 / 扩展导入（IndexedDB 与 LS 同机制，列为后续可选增量）。
- 历史冲突弹窗（历史按既有规则静默 upsert，无冲突概念——调研报告 5.1 已定）。
- 逐条/逐站点冲突裁决（会话级一次二选一，已批复）。

### 2.3 本阶段数据原则

- 读取 Chrome 数据只在用户显式点击「导入」后发生（dry-run 属导入动作的一部分），绝不静默读取；读取范围 = 勾选项。
- 导入只写目标会话分区（历史 JSON + 分区 LS 目录），零跨会话触达；导入条目如实反映 Chrome 数据（visitCount 合并取 max、时间取新），不伪造计数。
- 每一步失败如实报错（探测失败 / 文件锁 / 暂存过期 / 合并失败），失败路径恢复原状（LS 备份还原、历史不动已导入部分如实计数），不产生「看似成功」。
- 冲突计数如实 dry-run 实测得出，不由 renderer 估算。

### 步骤 2：Chrome 探测与数据读取侧（detect.ts + historySource.ts + history.importEntries）

任务：

1. `detect.ts`：三平台默认目录解析；`MSB_CHROME_USER_DATA` 环境变量整体覆盖根目录（dev/冒烟 fixture 用，头注释声明非用户功能面）；`Local State` 解析 `profile.info_cache` 取 `{dir → 显示名}`（坏 JSON/缺键告警回退枚举 `Default`/`Profile N` 子目录）；`listProfiles()` 返回 `{detected, profiles}`。
2. `historySource.ts`：拷贝 `History`（含 `-journal` 若存在）到 `fs.mkdtemp` 临时区 → `node:sqlite` 只读打开 → `SELECT url, title, visit_count, last_visit_time FROM urls ORDER BY last_visit_time DESC LIMIT 2000` → 过滤（仅 http/https、`HISTORY_URL_MAX` 内）→ WebKit 纪元换算 ms → `HistoryEntry[]`（faviconUrl 恒 null）；临时目录用后清理。
3. `history.ts` 增 `importEntries`（第 3 节契约点 3，合并规则与 parseStored 同源）。
4. 三模块不 import electron（deps 注入路径，照 history.ts 先例），配一段临时断言脚本（ELECTRON_RUN_AS_NODE 下对本机真实 Chrome 只读枚举与读取，输出条目数后删除脚本）。

验收：`npm run typecheck`、`npm run lint` 0 error；断言脚本实测——本机 Chrome 未运行与运行中两种状态均可枚举 profile、读取历史条目数 > 0（无 Chrome 环境则用 fixture 目录验证 detected=false 与空列表路径）。

### 步骤 3：localStorage 记录级合并引擎（siteData.ts）

任务：

1. 读侧：拷贝 Chrome profile `Local Storage` 整目录到临时区 → classic-level 打开（buffer 编码）→ 全量迭代分类三类记录（`META:<origin>` / `METAACCESS:<origin>` / `_<origin>\x00\x01<key>`），值 Buffer 原样持有不解码。
2. 冲突检测（dry-run 入口）：classic-level 只读打开目标分区 `Local Storage/leveldb`（分区须已静默；目录不存在 = 全新增零冲突）→ 同 origin 同 key 值不同计冲突（键数 + 涉及 origin 数），返回冲突摘要与新增/合并计数。
3. 合并执行（execute 入口，入参 policy 'chrome'|'session'）：先整体备份分区 LS 目录到临时区 → 非冲突数据键与缺失 origin 整体移植（batch put，值字节原样）→ 冲突键按 policy（chrome=put / session=skip）→ close 落盘；任一步失败：关闭句柄 → 还原备份（rm 现目录 + 备份移回）→ 上抛。
4. 复制源与目标全程不触碰活库（调用方保证分区静默，模块头注释声明该前置契约）。

验收：`npm run typecheck`、`npm run lint` 0 error；fixture 冒烟（用本项目某分区目录充当「Chrome 侧」源，对另一分区执行 dry-run → execute 两种 policy）——合并后 classic-level 重读目标与预期一致、冲突计数正确、人为注入损坏记录后 execute 失败且分区 LS 目录与备份前逐字节一致（还原路径生效）。

### 6.2 并行波次

- **波次 1（串行先行）**：步骤 1。理由：契约、i18n 键与依赖是后续全部步骤的编译与接口前提。

波次 2 达标：三个执行单元文件集合两两不相交（chromeImport/detect.ts+historySource.ts+history.ts ∣ chromeImport/siteData.ts ∣ renderer 组件+store+i18n 消费），且每个预计远超 5 分钟。波次 1、3 不达门槛（串行依赖/装配红线），合并执行。

## 10. 主要风险与控制

| 风险 | 控制方式 |
| ---- | -------- |
| LS 记录级手术格式错误致分区站点数据损坏 | 值字节原样移植（不解码不重编码）+ 有改写先例；每次 execute 前整体备份、失败还原（步骤 3 任务 3）；fixture 冒烟含人为损坏注入验证还原路径 |
| Chrome 运行中文件锁 / 数据不一致 | 拷贝后读临时副本（SQLite/LevelDB 均崩溃安全回放）；拷贝失败如实报「Chrome 文件被占用，请关闭 Chrome 后重试」 |
| classic-level 打包（原生模块进安装包） | N-API prebuilds 随 npm 包内置、免下载免 rebuild；批次 A 即在 Electron 运行时内验证加载；批次 D `npm run build` 验证构建链 |
| dry-run 暂存过期造成用户困惑 | 60s TTL + 过期中文错误 + 对话框回到勾选态可原地重试（步骤 4 任务 5） |
| 导入窗口期与克隆/切换竞态污染分区 | `importingIds` 守卫照 `cloningIds` 先例四处入口拦截（步骤 5 任务 2）；CDP 冒烟专验（步骤 5 验收） |
| Modal 弹层遮挡右区原生层盲操作 | `useOverlayWhenOpen` 登记 overlay（步骤 4 任务 2），手动验收含「页面区可外点收起」 |
| node:sqlite 实验标记告警噪音 | 仅主进程 console 一次性 ExperimentalWarning，无害不处理（调研已实测）；若 lint/构建链报错再评估迁移 better-sqlite3（决策留 process.md） |
