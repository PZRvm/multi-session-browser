## 2. 范围边界

### 2.1 本阶段必须完成

- 方案 A 采集管线 spike 先行验证（时间盒）：跨 frame 授予真实生效、无 macOS TCC 授权、帧连续可录。
- 共享契约：`src/shared/capture.ts`（`CAPTURE_CHANNELS` ＋ 录制状态机类型 ＋ 载荷）＋ preload `api.capture` 命名空间（index.ts / index.d.ts 对齐）。
- 主进程 `src/main/browser/recording/`：全局单实例状态机（idle/recording/paused，非 idle 时 start 拒绝）＋ 分块追加写 ＋ finalize 落下载目录 ＋ 会话名清洗/时间戳命名/同名追加序号（纯 Node 模块，不 import electron）。
- 五路生命周期自动停止：`switchSession`、会话内 `switch-tab`、`closeTab`、`moveTabToWindow`（拖出/跨窗）、`destroySession`/`closeSession`——命中被录 Tab/会话即停止并 finalize 已录内容。
- renderer：录屏钮接线（点击开始/停止）＋ 录制态（红点＋累计时长）＋ popover 状态段 ＋ 暂停/继续控件（形态走 impeccable 定稿）＋ 完成原生信息框 ＋ i18n 三语。
- 文档同步：DESIGN.md 条目、`docs/项目骨架.md`、`notes/process.md`。

### 2.2 本阶段明确不做

- 截图线全部内容（capturePage/剪贴板/截图反馈条/截图快捷键——兄弟 worktree 进行中）。
- 音频录制（handler 只授予 video track，不采集页面声音）。
- 录屏快捷键与全局快捷键（本期录屏仅工具栏入口）。
- 录制预览/播放、断点续录、自定义保存目录、区域裁剪、录制中画面水印。
- 录制状态持久化（主进程运行态，重启恢复空闲）。

### 2.3 本阶段数据原则

- 录制只在用户显式点击录屏钮后开始；不写会话分区、不进任何快照，录制数据只在应用内存与目标文件间流转。
- 落盘文件如实：显式停止 finalize 成功才算完成；中断/失败路径把已收块如实落盘并反馈「已自动停止保存」，绝不伪造完整文件，也不静默丢弃。
- 采集零越权：handler 只响应 UI renderer 发起的请求（核对请求方 frame），页面分区的 `getDisplayMedia` 一律拒绝；CDP 冒烟专验。
- 时长如实：popover 时长由主进程状态时间戳推导（暂停段不计），不由 renderer 估算起步值。

## 3. 开始编码前的契约核对

本阶段涉及共享契约和基准文档的以下变更，必须在编码前冻结并同步文档（依据 AGENTS.md：实现与设计文档冲突时先改文档；**步骤 1 spike 已完成并修订本节为 A' 架构**）：

1. **`src/shared/capture.ts`（新）**：`CAPTURE_CHANNELS = { begin: 'capture:record-begin', pause: 'capture:record-pause', resume: 'capture:record-resume', stop: 'capture:record-stop', chunk: 'capture:record-chunk', stateChanged: 'capture:state-changed' }`（独立常量对象，`BROWSER_CHANNELS` 先例；chunk 仅采集器桥使用，不经 UI preload 暴露）。状态契约：`CaptureStatus = 'idle' | 'recording' | 'paused'`；`CaptureState = { status, sessionId?, tabId?, startedAt?, pausedAccumMs?, pauseStartedAt? }`（idle 态仅 `{status:'idle'}`；时长口径单源 `elapsedMs(state, now)` 于本文件导出——进行中暂停段由 `pauseStartedAt` 现扣，暂停段不计；步骤 4 实现期发现契约缺口补 `pauseStartedAt` 字段，renderer ticking 与主进程状态机共用同函数）。**A' 采集时序（主进程编排，renderer 只发意图）**：`invoke(begin)` → 主进程预检（独占/激活位）→ 建采集器 view（partition = 被录会话分区，专用 preload 桥）→ 分区 session 注册 handler（授予被录 Tab mainFrame，核对请求方 frame = 采集器 frame）→ 采集页 `getDisplayMedia` → MediaRecorder 分块 → chunk 经 `capture:record-chunk` 直达主进程（不经 UI window.api）；`getDisplayMedia` 失败由主进程编排感知（采集器桥上报）并整体回滚到 idle。
2. **preload（UI 侧）**：`api.capture = { begin(target), pause(), resume(), stop(), onStateChanged(cb) }`（无 chunk——采集数据不经 UI renderer）；`index.ts` / `index.d.ts` 同步增 `capture` 命名空间（三处对齐），命名空间数 8→9。
3. **采集器专用桥（主进程自持，不经 shared 白名单）**：`recording/capturePreload.ts` 暴露 `__msbCapture`（采集页消费：指令下行 onCommand + chunk 上行 saveChunk + 错误上报）；采集器页 `recording/capturePage.ts`（HTML+JS 内联资源）承载 MediaRecorder 逻辑，pause/resume 直接映射 `MediaRecorder.pause()/resume()`（编解码器保证暂停段不落帧不计时长）。
4. **handler 注册域（安全契约，A' 修订）**：handler 仅注册于**被录会话分区 session**（`session.fromPartition(partitionFor(id))`），授予时核对「请求方 frame = 采集器 view 的 mainFrame ＋ 目标 = 该分区激活 Tab 的 mainFrame」，录制结束置 null 注销；UI 所在 defaultSession **不注册** handler——页面分区自身的 `getDisplayMedia`（页面代码发起）在录制窗口期之外无 handler 默认拒绝、窗口期内因请求方 frame ≠ 采集器 frame 同样拒绝。
5. **文件命名规则**：`${sanitize(sessionName)}_${YYYYMMDD-HHmmss}.webm`；清洗 = Windows 非法字符与控制符替换为 `_`、去首尾点空格、空名回退 `session`、超长截断；同名在尾部追加 `-2`/`-3` 递增，绝不覆盖既有文件；落点 `app.getPath('downloads')`，不弹另存框。
6. **i18n 新命名空间 `capture`**：`src/shared/i18n/index.ts` Dictionary 类型增命名空间 ＋ `locales/{zh-CN,en-US,zh-TW}/capture.ts` 三语文件；键集（实现期可增删、三语同步）：状态提示（录制中/已暂停）、暂停/继续控件、完成反馈（{file} 插值）、自动停止反馈（切走/关 Tab 场景）、失败（开始失败/写入失败/下载目录不可写）、独占拒绝（busy）。
7. **需同步更新的文档**：`DESIGN.md`（录制态按钮与暂停/继续控件形态条目，步骤 4 impeccable 定稿后回填）；`docs/项目骨架.md`（`browser/recording/` 目录行（含采集器页与专用桥）、`shared/capture.ts` 表行、preload 九命名空间、Toolbar.tsx 与 stores 职责行修订）；`notes/process.md`（当前阶段行，含 spike 结论）。PRD 3\.10 已定稿；A' 属实现路径修订（UI 发起改为主进程编排、画面来源不变），PRD 表述「录制页面画布本身」零偏离，无需回改。

完成标志：契约类型落入 `src/shared/capture.ts`、preload 三处对齐、i18n 三语键齐，`npm run typecheck` 通过。

| handler 泄漏：录制结束后分区 handler 残留，页面自身 getDisplayMedia 被误授 | 停止/回滚路径统一注销（置 null）；CDP 冒烟专验「录制结束后页面分区 getDisplayMedia 被拒」 |
