## 2. 范围边界

### 2.1 本阶段必须完成

- **克隆会话（主进程）**：`registry.closeSession(id)`（关闭该会话全部 webContents、保留分区数据与元数据；关后切换回该会话由 ensureManager 重载 lastUrl 恢复）+ `registry.clonePartition(srcId, dstId)`（closeSession(src) → `fs.cp` 分区目录，排除 Cache/GPUCache/Code Cache 缓存类目录 → 异常如实告警失败上抛）；`sessions:clone` 通道（生成新 id、元数据复制：name 加「副本」后缀并 clamp、note/pageTitle/lastUrl 原样复制，经 deps 调 clonePartition 完成后才落盘返回）。
- **克隆会话（renderer）**：行菜单增「克隆会话」项（重命名与删除之间）；克隆期间按钮/行给出进行中反馈（分区复制可能数秒）；成功后新会话入列并**激活**（addSession 同款乐观 + setActive + 失败回滚模式，H1 教训入任务）。
- **批量关闭所有会话**：`sessions:delete-all` 通道（原子清空快照：sessions=[]、activeId=null）+ registry 编排（switchSession(null) + 逐会话 destroySession 清分区）；renderer 批量模式操作栏「关闭全部会话」+ `modal.confirm` 明示"删除全部会话及其全部本地数据，不可恢复"（PRODUCT 原则 1：影响范围明确感知）。
- **批量打开指定 URL**：`sessions:batch-open-url` 通道（payload { ids, url }，运行时守卫：url 过 normalizeInput 白名单、ids 全部存在否则整单拒绝——测试工具要确定性）+ registry `openUrlInSessions(ids, url)`（逐会话 ensureManager + newTab(url)，激活会话立即可见、后台会话保活后台加载）；renderer 批量模式操作栏「打开测试地址」+ URL 输入弹层（板面 antd，antd 暗色嵌套层）。
- **批量模式 UI**：板面多选交互（进入/退出批量模式、行复选、已选计数、全选），设计走 impeccable 技能 new-work 路径（AGENTS.md 前端设计硬规则），约束预冻结见 2.4；批量模式下单击行 = 勾选（不再激活），退出恢复单选激活。
- **契约扩展与文档同步**：sessions 通道 7 → 10 + 三 payload + preload 三方法；DESIGN.md（会话行菜单四项、批量模式新条目、Not Yet 更新）与 process.md 同步；`notes/accept/` 验收文档落盘；code-review 收尾。

### 2.2 本阶段明确不做

- **会话拖出独立窗口**：阶段 6（process.md 阶段表已列，其 steps 文件尚不存在——编号重整属用户决策）
- **克隆源会话的"活页面状态"保真**：克隆以最后一次落盘的分区数据为准（Cookie/LocalStorage/IndexedDB 等持久数据全保真）；源会话当前 Tab 结构、表单草稿、滚动位置不进入克隆（Tab 结构本就不持久化，2.3 数据原则声明）
- **克隆的目标会话免打断源会话**：为保证分区副本一致性必须先关闭源会话 webContents（活库 cp 不一致，见风险表）；克隆后源会话切回时按 lastUrl 重载——此代价如实呈现，不隐藏
- **批量重命名 / 批量删除选中项 / 按组管理**：PRD 3.1.3 仅列关闭全部与打开 URL 两项，其余不发明
- **批量打开 URL 的逐会话失败重试与部分成功语义**：ids 全存在才执行（整单校验），加载失败由 Chromium 错误页如实呈现（与单会话导航同规）
- **Tab 列表持久化 / 克隆时复制 Tab 结构**：重启单值恢复边界不变（阶段 4 既定）
- **二期功能**（截图/弱网/UA/代理/可视化）：`step-08`
- **测试框架引入**——沿用 typecheck + lint + 隔离目录手动验证

### 2.3 本阶段数据原则

- **克隆保真的边界如实呈现**：克隆复制的是源会话**持久化的环境数据**（登录态、Cookie、LocalStorage、IndexedDB 等）+ 元数据（备注/页面标题/上次打开页）；"页面状态"落在 lastUrl 单值恢复语义上。UI 文案与验收结论不得宣称"完整复刻当前打开的所有页面"。
- **隔离边界不因克隆稀释**：克隆目标必是新 id + 新分区（`persist:sess-<newId>`），复制完成后源/克隆互不影响（验证用例）；禁止任何"共享分区"捷径。
- **批量关闭即彻底删除**：与单条删除同一标准（销毁 webContents + clearStorageData + 删分区目录），确认框明示"全部本地数据不可恢复"；部分失败逐会话如实告警，不静默。
- **批量打开 URL 的确定性**：入参整单校验（ids 全存在、URL 过白名单），不满足即拒绝整单——不出现"部分会话打开、部分静默跳过"的模糊结果。
- **不造假状态**：克隆进行中的耗时如实以进行中反馈呈现；后台会话批量打开后的加载态由状态灯如实驱动。
- 界面文案纯中文（新增：克隆会话 / 副本 / 批量操作 / 打开测试地址 / 关闭全部会话等）。

## 10. 主要风险与控制

| 风险 | 控制方式 |
| ---- | -------- |
| 活库复制不一致（LevelDB/Cookies journal 未落盘） | clonePartition 强制先 closeSession 源（销毁全部 webContents 触发 flush）再 cp；close 的销毁机制复用 destroySession 已验证代码；接受"源会话切回重载"的代价并如实写入 UI/验收文案 |
