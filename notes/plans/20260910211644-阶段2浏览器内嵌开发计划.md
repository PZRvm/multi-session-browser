## 2. 范围边界

### 2.1 本阶段必须完成

- 主进程 Tab 管理器：每个 Tab 一个 `WebContentsView`，固定 `persist:browse` 分区，挂到主窗口 `contentView`，按 renderer 上报的内容区 rect `setBounds`；未激活 Tab 的 view 脱离 contentView 但 webContents 保持存活（切回时页面状态不丢）
- Tab 管理：新建（默认 about:blank 新标签页）、关闭（最后一个 Tab 的关闭按钮禁用）、切换；Tab 栏如实展示标题 / favicon / loading 态
- 顶部导航：后退 / 前进（按 canGoBack / canGoForward 启停）、刷新（加载中变停止）、主页（定义为回到新标签页 about:blank）、可编辑地址栏（回车跳转、URL 自动展示、非 http(s)/file 输入自动补 `https://`）
- 完整网页交互：真实 Chromium 渲染，表单输入、文件上传、JS 弹窗（alert/confirm）、`target=_blank` / `window.open` 转为本浏览器新 Tab（`setWindowOpenHandler` deny + 建新 Tab）；加载失败由 Chromium 内建错误页如实呈现
- 契约与桥：`src/shared/browser.ts`（类型 + `BROWSER_CHANNELS` 常量）、`api.browser` 命令方法 + `onStateChanged` 状态订阅（preload）
- 状态推送：主进程是唯一事实源，tab 列表 / 激活项 / url / title / favicon / loading / canGoBack / canGoForward 变化统一推 `browser:state-changed`
- 最小快捷键集（Chrome 对齐）：页面聚焦时经 `before-input-event` 处理 Cmd/Ctrl+R 与 F5（刷新）、Cmd/Ctrl+T（新建）、Cmd/Ctrl+W（关闭）、Cmd/Ctrl+L（聚焦地址栏）；shell 聚焦时由 renderer keydown 处理同一集合
- 移除 BrowserFrame 全部占位文案（phase2Tip、「会话浏览器引擎 · 阶段 2 接入」、右侧翻牌砖空态）

### 2.2 本阶段明确不做

- **DevTools**：F12/ESC 唤起、与会话绑定——阶段 3（本阶段不碰 `optimizer.watchWindowShortcuts`，不处理 AGENTS.md 提到的 F12 冲突）
- **会话与浏览器绑定**：`persist:sess-<id>` 每会话独立分区、点击会话切换浏览器环境、切换保留 Tab/登录态——阶段 4。本阶段浏览器是**未绑定任何会话的单例**，UI 与状态均不得暗示绑定
- **浏览器状态持久化**：Tab 列表 / URL 不落盘，重启后回到单个新标签页；会话 `pageTitle` 不由浏览器写入（写入即伪造绑定）——阶段 4 随绑定一起做
- **会话状态灯 loading 驱动**：浏览器 loading 只作用于 Tab 与工具栏视觉，不驱动左侧会话状态灯——阶段 4 绑定后才存在"某会话在加载"的事实
- 地址栏搜索兜底（非 URL 输入转搜索引擎）、favicon 缺省图之外的图标美化、下载管理定制、右键菜单定制、页面内查找（Ctrl+F）、缩放、权限请求管理、Tab 拖拽重排、Ctrl+Tab 切换、Ctrl+Shift+T 恢复关闭——PRD 未列为本阶段验收项，推后续打磨
- 测试框架引入——沿用 typecheck + lint + 手动验证（AGENTS.md 约定）

### 2.3 本阶段数据原则

- 主进程是浏览器唯一事实源：Tab 列表、激活项、URL、标题、loading、canGo 状态一律由主进程推送，renderer 纯镜像展示；renderer 不造 tab id、不做任何乐观状态（唯一例外：地址栏输入框在编辑期间显示用户正在输入的文本，失焦/回车后回归主进程 url）
- 用户输入如实加载：导航失败由 Chromium 内建错误页呈现真实错误，禁止伪造"已打开"或兜底演示页
- 浏览器数据（Cookie/缓存/存储）落 `persist:browse` 分区，与左侧会话零耦合：会话的增删改选不影响浏览器，浏览器的浏览不影响会话；两侧不得出现任何数据通路
- 所有界面文案中文，面向专业测试人员，无引导式提示文案（PRODUCT.md 原则 4）

## 3. 开始编码前的契约核对

以下变更编码前必须冻结（依据 AGENTS.md：实现与设计冲突时先改文档；本节即本阶段的文档修订记录）：

1. **新增 `src/shared/browser.ts` 契约**（本文件是阶段 2 的冻结载体，修改需先修订本节）：
   - `BROWSER_CHANNELS = { getState: 'browser:get-state', newTab: 'browser:new-tab', closeTab: 'browser:close-tab', switchTab: 'browser:switch-tab', navigate: 'browser:navigate', back: 'browser:back', forward: 'browser:forward', reload: 'browser:reload', stop: 'browser:stop', setBounds: 'browser:set-bounds', stateChanged: 'browser:state-changed', focusAddress: 'browser:focus-address' }`
   - `BrowserTabState = { id: string; url: string; title: string; faviconUrl: string | null; loading: boolean; canGoBack: boolean; canGoForward: boolean }`；`BrowserSnapshot = { tabs: BrowserTabState[]; activeTabId: string | null }`
   - tab `id` 由主进程生成（`tab-<自增seq>`），renderer 不得自造；除 `navigate { url }`、`closeTab/switchTab { id }`、`newTab { url? }`、`setBounds { x, y, width, height }` 外，命令均作用于当前激活 Tab、无 payload
   - 推送通道两条：`state-changed`（BrowserSnapshot 全量）与 `focus-address`（无 payload，主进程要求 renderer 聚焦地址栏，服务于 Cmd/Ctrl+L 与新建空 Tab）
2. **`src/preload/index.d.ts` 归本计划步骤 1 独占**：阶段 1 计划第 3 节的独占声明随阶段 1 完成失效；步骤 1 落地 `api.browser` 十方法 + 两条订阅（`onStateChanged(cb) → unsubscribe`、`onFocusAddress(cb) → unsubscribe`），步骤 2 及以后不得再改该文件。
3. **renderer CSP 放宽（安全边界声明）**：`src/renderer/index.html` 的 `img-src` 由 `'self' data:` 放宽为 `'self' data: https:`——Tab 栏 favicon 是远程 https 图片，现 CSP 会拦截；`script-src 'self'` 与其余指令保持不动，此放宽仅此一处，code-review 需复核。
4. **对 DESIGN.md 的两处显式修正**（收尾步骤 8 落盘）：①「loading 态已设计、未触发——阶段 2 接真实加载事件时直接驱动」改为"loading 视觉阶段 2 只驱动 Tab/工具栏，会话状态灯的驱动推迟到阶段 4 会话绑定时"（阶段 2 浏览器与会话无绑定，驱动会话灯即伪造绑定事实）；②「右侧 Chrome 框架是占位」条目改写为真实现状，并记录**右侧翻牌砖与会话空态撤场**——内容区被 WebContentsView 覆盖，会话信息只留在左侧信息板（"翻牌砖跨界信使"概念右侧退场）。Tab 栏/工具栏/地址栏的既有度量与灰阶全部沿用（符合 DESIGN"替换时保留既有度量"的要求）。
5. **sessions 契约零变更**：`src/shared/sessions.ts`、`src/main/sessions.ts`、`src/main/store.ts`、SessionPanel 一律不动；阶段 1 的验收能力（重启恢复会话列表）是本阶段回归基线。
6. **文档事实修正**（收尾步骤 8 落盘）：`notes/process.md` 阶段表中 `step-02.md`、`step-05.md` 引用改为现文件名；根目录无 `PRD.md` 的事实仅在本计划与 process.md 执行决策中记录，AGENTS.md 的修订属用户决策、不在本阶段擅动。

完成标志：`src/shared/browser.ts` 与 `src/preload/index.d.ts` 按上述落地、CSP 行改毕，`npm run typecheck` 通过。

### 步骤 5：renderer 浏览器状态 store

任务：

1. 新建 `src/renderer/src/stores/browser.ts`：zustand store 镜像 `BrowserSnapshot`（tabs/activeTabId 原样存主进程推送，不加工）；`init()` 按"先订阅 onStateChanged/onFocusAddress、再 invoke getState 拉初始快照"顺序执行，沿用 sessions store 的防重入模式（模块级 initialized 标志 + 失败复位可重试），避免推送与拉取竞态

### 6.2 并行波次

- **波次 1（串行先行）**：步骤 1。理由：shared 契约、preload 类型、CSP 是后续全部并行的输入；main/renderer/preload 三侧都消费它。
- **波次 2（可并行）**：步骤 2、4。理由：都只消费波次 1 契约，分别落 `main/browser/manager.ts` 与 `preload/index.ts`，文件集合不相交；各自工作量均超 5 分钟（manager 是本阶段最重模块）。
- **波次 3（可并行）**：步骤 3、5。理由：步骤 3 消费波次 2 的 manager，步骤 5 只需波次 1 的类型即可通过 typecheck；`main/browser/ipc.ts + main/index.ts` 与 `renderer/stores/browser.ts` 不相交。步骤 5 的运行时验证推迟到波次 4 一并做。
- **波次 4（独占）**：步骤 6。理由：同时组合步骤 3/4/5 的产物，独占 BrowserFrame 与 browser/ 组件目录。
- **波次 5（独占）**：步骤 7。理由：跨 main 与 renderer 两端改文件，且需在真实 UI 上逐键验证。
- **波次 6（收尾，独占）**：步骤 8。理由：验收期间代码必须冻结，文档内容以验收结论为准。

### 6.3 并行门槛

- 波次 2：2 个步骤、文件不相交、各约 30—60 分钟——达标，开并行。
- 波次 3：2 个步骤、文件不相交、各约 20—40 分钟——达标，开并行。
- 波次 4—6：均单步骤，无并行对象，串行执行（无门槛问题）。

### 6.4 不可并行的红线

- `src/shared/browser.ts`、`src/preload/index.d.ts`、`src/renderer/index.html` 仅归步骤 1；其余步骤不得触碰（防契约漂移、CSP 被顺手扩大）
