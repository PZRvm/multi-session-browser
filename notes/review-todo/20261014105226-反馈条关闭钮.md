## 2. 八项必查结论

### 2.1 重复代码

结论：已查，未发现问题。

- `onDismissRequest` 订阅样板（`src/preload/index.ts:400-410`）与 `onRequest` / `onDownloadRequest` 逐字同构——属仓库既有 IPC 订阅惯例（三处先例同形），不构成需收敛的重复。
- 反向收益：`hideCaptureFeedback`（`src/renderer/src/stores/browser.ts:153-156`）把原先散在 6s 定时器（:207）与会话漂移分支（:393）的两处收起序列收敛为单函数，本轮 dismiss 回程（:504）第三处复用，净消除重复。

### 2.2 权限漏洞

结论：已查，未发现问题。

- `dismiss` 动作仍受 `resolveOwnerOf` sender 白名单约束（`src/main/browser/capture.ts:262-270`）：伪造页/非池内视图发 `feedback-action` 一律 `invalidCaptureParams` 拒绝，与 `download` 同门，未放宽。
- 新通道 `dismiss-request` 为主进程 → 宿主 webContents 定向推送（`captureFeedbackWindow.ts` sendToHost，owner 销毁/destroyed 判空 no-op），renderer 侧无新增能力暴露；preload 仅增只读订阅。
- 未触及分区、路径拼接、`webPreferences`、导航与权限 broker；无秘密泄漏面（本项目无密码/Token 业务域）。

### 2.3 竞态条件

结论：发现 1 个问题。

- [x] **[低]** 迟到的 dismiss 回程可收起新一轮反馈条（毫秒窗微竞态）
  - 位置：`src/renderer/src/stores/browser.ts:503-505`
  - 描述：`onDismissRequest` 回调无条件执行 `hideCaptureFeedback()`。若用户点击关闭钮后、dismiss-request 在途的毫秒窗内又有新截图完成（`showCaptureFeedback` 重建编排并显示新条），迟到的 dismiss 会把**新**条连编排一起收起。对照：6s 定时器路径无此问题——`showCaptureFeedback` 首行 `teardownCaptureFeedback()` 会清掉旧定时器，新条挂新定时器。
  - 证据：触发需两次用户动作落在 <10ms 的 IPC 往返窗内（点关闭钮 + 截图/快捷键），人为操作近乎不可达；记录在案备将来程序化触发（如连点脚本）。
  - 建议方向：dismiss 载荷携带所关内容的轻量指纹（如 kind+text），宿主回调比对 `captureFeedbackShown` 不匹配即忽略；或裁决接受现状并在代码注记注明。

其余竞态面已查无问题：池 `hide()` 对未就绪 show 的撤销语义（`visible=false` + `pendingData=null`）正确；`offCaptureDismiss` 订阅/退订对称（browser.ts:467/545）；组件 HMR dispose 与模块级监听集不受影响。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题。

本轮无落盘写。内存态一致性：收起 = 宿主编排态（定时器/ResizeObserver/内容镜像）与主进程池 `visible`/`pendingData` 两方同步翻转，三路收起共用同一函数保证不出现「视图已隐、观察器仍挂」的半状态（该半状态正是 resize 复活 bug 的根因，本轮设计已规避）。

### 2.5 通知遗漏

结论：发现 1 个问题。

- [x] **[低]** 交互钮嵌于 `role="status"` live region 内
  - 位置：`src/renderer/src/components/browser/CaptureFeedbackWindow.tsx:50-61`
  - 描述：`role="status"` 隐含 `aria-live="polite"`，可聚焦交互元素（「下载」钮、本轮新增的关闭钮）嵌于 live region 是可访问性反模式（区域更新时焦点语义不确定）。既有「下载」钮同病，本轮关闭钮同构新增一颗。实害极小：条内容为单帧推送无后续更新、success 6s 瞬态。
  - 证据：MDN/ARIA 作者实践：live region 不应包含可交互内容；本条为既有模式沿用非本轮引入。
  - 建议方向：后续统一把按钮组移出 live 容器（文本独占 status），或容器改 `aria-live="off"` 保留 role。

其余通知面已查无问题：dismiss 全链失败静默（`.catch(() => {})`）与既有 hide/show 反馈通道「尽力而为通知」口径一致——反馈条本身是通知性 UI，截图/落盘主链路结果不依赖它；用户点关即期望条消失，失败时条仍在视野外（或稍后被 6s 定时器/下一次动作收敛），无误导性状态。danger 态无定时器，若 dismiss 失败条会持续显示——可见即为诚实状态，不构成静默失败。
