## 2. 八项必查结论

### 2.1 重复代码

结论：发现 1 个问题（低）

- [ ] **[低]** 三处调用点的「confirm→catch→warn→按取消处理」Promise 样板重复
  - 位置：`src/renderer/src/components/SessionRow.tsx:209-214`、`src/renderer/src/components/SessionPanel.tsx:229-242`、`src/renderer/src/components/WorkspaceSwitcher.tsx:166-179`
  - 描述：invoke + `.catch((error) => console.warn(...))` 吞错按取消处理的包装在三个调用点各写一份；后续确认动作与失败反馈键三处各异，但异常包装语义（吞错=取消+warn）相同，第四个确认入口出现时会继续复制。
  - 证据：三段 diff 逐行同构（`void window.api.dialog.confirmDestructive(...).then(...).catch((error: unknown) => console.warn('...确认框调用失败', error))`）。
  - 建议方向：在 renderer 侧抽一个薄封装（吞错 resolve false + 统一 warn 前缀，确认后动作由调用方续接），或明确接受为调用点本地语义并在 ui.ts/骨架注记惯例；二选一，避免第三个半抽象层。

### 2.2 权限漏洞

结论：已查，未发现问题

- 通道为 UI-only：name/count 仅进弹框文案插值，不进任何文件路径、分区名、落盘键——无路径穿越面。
- 确认与执行两段解耦：本通道零落盘、零分区触碰，删除仍走既有 sessions:delete / sessions:delete-batch / workspaces:delete（整单拒绝制）。
- 无 sender 白名单：与外观/设置值域「入参值守卫承担」先例一致；建议子窗/设置窗等自家 renderer 理论上可弹框，但无数据面、窗口模态仅及 sender 窗，无越权增益。
- `BrowserWindow.fromWebContents(event.sender)` 窗口缺失返回 false，不误删。
- 会话隔离边界零触碰；无秘密泄漏域。

### 2.3 竞态条件

结论：发现 1 个问题（中）

- [ ] **[中]** 批量关闭防重入守卫在确认 promise resolve 时即释放，早于 deleteSessions 完成
  - 位置：`src/renderer/src/components/SessionPanel.tsx:224-243`（`.finally` 释放于 241）
  - 描述：`.finally` 挂在 `confirmDestructive` 的 promise 上——用户点「删除」瞬间守卫即释放，而 `deleteSessions(checkedIds)` 仍在途。此窗口内「关闭选中会话」按钮可再次点击并弹出第二个原生框（count 取当前 checked 快照），用户再确认会对在途/已删集合发起第二次删除。
  - 证据：伤害上限被既有机制兜住——sessions:delete-batch 整单拒绝制使第二次调用命中「选中会话已发生变化」行内失败反馈（`closeConfirm.failed`），无数据损坏；但与同文件 `batchMoveInFlight`（L227：整个「弹层确认+落盘」链完成后才在 finally 释放）的先例不一致。
  - 建议方向：把守卫释放在 `deleteSessions` 落定后执行（`.then` 链末尾或改 async/await 整链 try/finally），对齐批量移动先例的守卫粒度。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 1 个问题（低）

- [ ] **[低]** 显示用载荷参数无上限：name 长度、count 极值
  - 位置：`src/main/dialogs.ts:31-38`
  - 描述：守卫只校验「非空 string / 有限数 ≥0」——跨 IPC 载荷不可信任口径下，异常载荷可传 10MB name 或 `count: 1e20` 生成巨型文本弹框（原生框自行换行不崩溃，但属显示面无界）。store 上游对 name 有 NAME_MAX=50 clamp，正常路径不可达，仅异常/伪造载荷触发。
  - 证据：`if (typeof name !== 'string' || name.length === 0) throw invalid()`（31/38 行）；`if (typeof count !== 'number' || !Number.isFinite(count) || count < 0) throw invalid()`（36 行）。
  - 建议方向：显示用 clamp（如 name 截 200、count 超过会话总数或 1e6 封顶）后照常弹框；或以「载荷不可信任但 UI-only 无数据面」明确接受并注记。
