### 2.3 竞态条件

结论：发现 1 个问题。

- [ ] **[中-1]** `setTitleBarOverlay` 同步调用无抛错防护，`nativeTheme updated` 事件路径的未捕获异常可致进程崩溃
  - 位置：`src/main/index.ts:126-130`（新增调用点）；传播链在 `src/main/appearance.ts:254-256 → 277-280`
  - 描述：亮暗翻转回调内直接调 `mainWindow.setTitleBarOverlay({...})`，仅守卫了 `win32 && mainWindow && !isDestroyed()`，未包 try-catch。两条失败传播路径：① 用户经设置切外观（setMode/setThemeColor → syncSnapshot → 回调抛错）→ run() reject → IPC 拒绝 → 主题切换失败（可感知可重试，后果轻）；② **系统亮暗翻转**（`nativeTheme.on('updated', handleNativeThemeUpdated)`，appearance.ts:254-256）→ syncSnapshot → 回调抛错 → 事件处理器内未捕获异常 → uncaughtException → **进程崩溃**。Electron 对 `setTitleBarOverlay` 无"永不抛错"保证（除已规避的"无 overlay 窗口"外，原生层失败仍可抛），触发面虽窄但后果为崩溃级。
  - 证据：appearance.ts:254-256 `handleNativeThemeUpdated = () => { this.syncSnapshot(true) }`（无 catch）；index.ts:126-130 回调体无 try-catch。同文件已有防御先例：index.ts:302-307 `app.dock.setIcon` 的 try-catch + 中文告警（同为 Electron 原生 API 边界调用）。
  - 建议方向：回调内 try-catch 包裹 `setTitleBarOverlay`，失败 `console.warn` 中文告警即返回（对齐 dock.setIcon 先例；overlay 配色是纯视觉增益，不应具备阻断主题切换或崩溃进程的能力）。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题。

- 本专项零落盘变化（无新增持久化键、无多文件写）。`shown` 标志（index.ts:265-272）保证 show 幂等，`did-finish-load` 多次触发（每次导航）与 `ready-to-show` 竞达不重复显示；macOS 关窗重开走 createWindow 现取快照回填 overlay 初值，无跨窗口残留态。

### 2.5 通知遗漏

结论：发现 1 个问题。

- [ ] **[低-2]** `showOnce` 双事件皆未达的极端路径零可观测性
  - 位置：`src/main/index.ts:265-273`
  - 描述：显示依赖 `ready-to-show` 与 `did-finish-load` 二者至少其一。若主页面加载彻底失败（如打包损坏致 loadFile 的主 frame 导航失败，两个事件可能均不触发），窗口永不显示且无任何日志，现场不可追溯。#42409 兜底的排查成本会因零日志放大。
  - 证据：showOnce 函数体仅 `if (shown || win.isDestroyed()) return; shown = true; win.show()`，无任何日志分支。
  - 建议方向：showOnce 首次显示时打一条 `[main] 窗口显示（经 ready-to-show/did-finish-load）` 级日志（或记录触发事件名），成本一行，排查价值高。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 1 个问题。

- [ ] **[低-3]** 避让 136px 加剧 Tab 极限压缩，Tab 无保底最小宽度
  - 位置：`src/renderer/src/assets/app.css`（`.chrome-tab { min-width: 0 }` 既有规则 × 新增右侧避让 padding）
  - 描述：Tab 栏无横向滚动，溢出全靠 flex 收缩（Tab 可压至仅剩 favicon + 关闭钮的极限）。避让占走约 146px 后，minWidth 1080 的窗口下 Tab 可用宽度再减，20+ Tab 时 Tab 可能挤成一团（机制正确、观感存疑）。非本次引入（既有收缩行为），但避让加重了它。
  - 证据：`.chrome-tab { min-width: 0 }` 与 `.chrome-tab-title { max-width: 180px; ellipsis }`；验收文档人工项 4（15—20 Tab 压力）正覆盖此场景。
  - 建议方向：观察人工验收项 4 的实际观感；若确实拥挤，为 `.chrome-tab` 设保底 `min-width`（如 40px，favicon+关闭钮可容），Tab 超限部分自然溢出裁切（或届时再议 Tab 滚动/列表化）。
