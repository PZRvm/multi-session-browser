### 2.1 重复代码

结论：发现 1 个问题（低）。

- [ ] **[低]** `applyRectToActive` 与 `setBounds` 尾段结构重复
  - 位置：`src/main/browser/manager.ts:324-330` 与 `src/main/browser/manager.ts:704-710`
  - 描述：两处均为"解析该窗口激活 Tab → destroyed 防御 → `setBounds` 应用矩形"，仅矩形来源不同（`currentRect(windowId)` 现值 vs 上报的 `rect` 参数）。新增函数复制了既有尾段而非提取共用。
  - 证据：
    ```ts
    // applyRectToActive（manager.ts:324）
    const activeId = activeByWindow.get(windowId) ?? null
    if (activeId === null) return
    const tab = tabs.get(activeId)
    if (!tab || tab.view.webContents.isDestroyed()) return
    tab.view.setBounds(currentRect(windowId))
    ```
    ```ts
    // setBounds 尾段（manager.ts:704 起）
    const activeId = activeByWindow.get(windowId) ?? null
    if (activeId === null) return

    ```
  - 建议方向：提取 `applyRect(windowId, rect)` 私有函数，`applyRectToActive` 与 `setBounds` 尾段共用；顺带消灭两处防御逻辑的漂移风险。

其余核对：`'fullscreen'` 权限字符串在 permissions.ts 两处硬编码（266-267、302 行）与既有 `clipboard-sanitized-write` 的两处硬编码完全同构，遵循文件既有模式，不记问题；两个 Frame 组件的壳层条件渲染沿用文件头声明的"同构"关系，非新增重复。

### 2.3 竞态条件

结论：发现 0 个新问题（1 个时序边界并入 2.5 的切会话矛盾态记录）。

逐路径核查（均在 `src/main/browser/manager.ts`）：

- 进出事件与上报交错：enter 后 renderer 壳层隐藏需一帧，期间锚点只增不减，`setBounds` 全屏态旁路缓存（702 行）保证无缓存污染；leave 后壳层回归触发的过渡矩形同样只应用不落错缓存。幂等，无状态破损。
- `enter-html-full-screen`（467 行）有激活位守卫（非激活 Tab 的事件忽略）；`leave`（476 行）只清自己置位的槽位，防其他 Tab 事件误清。
- 事件监听随 wc 生命周期回收（`newTab` 内 `wc.on`），无重复注册与泄漏。
- `closeTab`/`tearOffTab`/`moveTabToWindow` 的 `releaseFullscreenSlot` 均在改写 `tab.windowId` 之前调用（槽位按归属窗口查），窗口销毁级联 `destroyTabsInWindow` 无条件清槽位。
- 权限回调异步（`RequestFullscreenPermission` → handler → callback）与快速进出的交错：enter 处理器为 Map set 幂等写，无状态机破损路径。

### 2.5 通知遗漏

结论：发现 1 个问题（中）。

- [ ] **[中]** 切换会话后窗口 OS 全屏态与壳层回显矛盾，且无用户可感知的解释通道
  - 位置：`src/main/browser/registry.ts:515`（`switchSession` 摘旧 view 处）与 `src/main/browser/manager.ts:207`（全屏槽位随 manager 保活的设计）
  - 描述：主窗口处于 HTML 全屏时切换会话：旧会话全屏 Tab 保活（wc 的全屏 DOM 态与窗口 OS 全屏态由 Electron 绑定保留），新会话快照 `htmlFullscreen=false` 令壳层全部回显、view 按内容区矩形布局——结果是"窗口仍钉在 OS 全屏、界面却带完整壳层"的矛盾态，且无任何提示告诉用户成因与出路（须切回旧会话按 Esc，或手动退出窗口全屏）。不是死锁，但属 UI 与真实状态脱节。
  - 证据：`registry.ts` switchSession 只摘 view 不触全屏态（`if (prev) detachActiveView(prev)` 后直接 `ensureManager(id); manager.attachToWindow()`）；旧 manager 的 `htmlFullscreenByWindow['main']` 槽位保留，但该会话快照不再推往主窗口。
  - 建议方向：三选一——① 切会话时主动退出旧会话激活 Tab 的 HTML 全屏（需权衡 Electron 无干净 API：`webContents.exitFullscreen` 不存在，`executeJavaScript('document.exitFullscreen()')` 违背"网页内容不可信不注入"红线，或可试 `setFullScreen(false)` 但会误退用户自主的 OS 全屏态）；② 接受现状并冻结为文档化行为（PRD 3.2.3 补一句"切换会话视同退出全屏布局"或明确矛盾态）；③ renderer 侧在"快照非全屏但窗口 OS 全屏"时给壳层加全屏化兜底。先实测 macOS/Windows 真实表现再定案。

其余核对：enter/leave 两处均 `emitChange()` 推快照，renderer 壳层显隐链路无驱动遗漏；无异步失败静默路径（本次改动无新 IPC 命令与 Promise 链）。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：已查，未发现问题。

- `fullWindowRect`（manager.ts:309）：`getWindow` 已过滤销毁窗口（registry 注入的解析器均带 `isDestroyed` 过滤），缺失时回退 `HIDDEN_RECT`，无空值路径。

- 全屏 + 悬挂（弹层）同存：`currentRect` 悬挂优先收起（弹层必须可见），防御自洽。
- 全屏态下 Cmd+F 双侧封死（manager `before-input-event` 吞键前置放行 + renderer shell `openFind` 守卫），与 PRD 3.7.3 对齐；FindBar 组件另有全屏态不渲染兜底。
- 用户本在 OS 全屏时进入 HTML 全屏：Electron `SetHtmlApiFullscreen` 的 `native_fullscreen_` 路径不动窗口，槽位接管整窗，退出时不误撤用户的 OS 全屏——上游已处理，本次实现兼容。
- 快照零会话空态 `htmlFullscreen: false` 显式落值（registry/persistence 两处），无字段缺省。
