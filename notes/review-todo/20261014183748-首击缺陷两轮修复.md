### 2.3 竞态条件

结论：发现 1 个问题（并入 2.7 前先记此处）。

- [ ] **[低]** `capturePageWithRetry` 等待期销毁竞态可吞「无标签页」语义（`src/main/browser/capture.ts` capturePageWithRetry 内 done()）
  - 描述：200ms 超时路径里 `done()` 调 `wc.off('paint', onPaint)`——若等待期 webContents 已销毁，Electron 对已销毁对象的方法调用抛 "Object has been destroyed"，异常在 Promise executor 内将等待 Promise 置为 rejected，被外层 catch 统一转「截图失败，请重试」——而按既有语义（capturePage 在途销毁 → `captureNoTab`「当前没有可截图的标签页」）应报无 Tab。极窄竞态、仅错误文案偏差。
  - 证据：helper 中 `done` 无 destroyed 守卫即调 `wc.off`；外层 `try { image = await capturePageWithRetry(wc) } catch { throw captureFailed }` 会覆盖销毁语义。
  - 建议方向：`done()` 内 `if (!wc.isDestroyed()) wc.off(...)`，与同函数内 `wc.once` 的既有守卫同款。

### 2.7 复杂度是否增加

结论：发现 1 个问题。

- [ ] **[低]** `capturePageWithRetry` 的 `paint` 监听为死路径（`src/main/browser/capture.ts:8-16`）
  - 描述：Electron `WebContents` 的 `paint` 事件**仅在离屏渲染（offscreen）启用时触发**——本项目全部在线渲染，`wc.once('paint', onPaint)` 永不回调，等待实际恒走 200ms 超时兜底。注释「等一帧 paint」与实际行为（固定 200ms 延时）不符，后来者会误以为有帧信号驱动。功能上无碍（200ms 对合成就绪足够），属误导性死代码。
  - 证据：Electron 文档 paint 事件语义（offscreen-only）；helper 代码。
  - 建议方向：删 paint 监听改纯 `setTimeout(200)` 并更正注释为「固定延时等合成」；或换用在线可触发的信号（如 `webContents.on('did-finish-load')` 不适用时保持纯延时）。
