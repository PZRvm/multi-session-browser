## 2. 八项必查结论

### 2.1 重复代码

结论：已查，未发现问题。

- 旧 `hitTest`（窗口 bounds 命中）被 `tabstripHit` 完整替换删除，无副本残留；全仓 grep 无 `hitTest` 残留引用。
- TabStrip 矩形上报复用 `useRectObserver` 共享骨架（挂载即报 + ResizeObserver + rAF 节流），未复制采集逻辑；`TabstripRectPayload` 与 `SetBoundsPayload` 结构相同但独立命名（语义分离：内容锚点布局 vs 拖拽命中布局），未做类型别名混用。
- ipc handler 的守卫结构（isRecord + 逐字段 typeof + Number.isFinite）与既有命令守卫同构，遵循文件惯例。

### 2.2 权限漏洞

结论：已查，未发现问题。

- 新通道 `browser:report-tabstrip-rect` 经 `resolveScope(event)` 按 sender 归属窗口——每个窗口只能写自己的 Tab 栏矩形，无跨窗越权写入口；页面 webContents 无 preload、无 `window.api`，网页内容不可触达此通道。
- payload 结构守卫为命令口径（结构垃圾抛错拒绝，`ipc.ts` logFailure 记录）；数值仅用于本应用内部的拖拽命中测试，异常值无安全面。
- `resolveScope` 的选择正确：`ipc.ts:216` 注释明确"空会话不在此拦——getState/setBounds 对空态合法"，零会话主窗的 TabStrip 挂载中（BrowserFrame 无条件渲染 TabStrip）可正常上报，无误拒与日志噪音。
- 窗口销毁后的迟到大报到 setTabstripRect：仅写入孤儿条目（windowId 不复用、无别名），候选集排除已销毁窗口，条目永不被消费为错误裁决。

### 2.3 竞态条件

结论：已查，未发现问题。

- 矩形缓存在无拖拽会话时也接受写入（布局通道与拖拽会话解耦），dragStart 首次悬停计算即有最新矩形可用；写入为 Map set 幂等操作，无 check-then-act 窗口。
- 悬停判定（`hoverWindowAt`）与收尾裁决（`hitAnyTabstripAt`）共用同一 `tabstripHit` 与同一缓存，无判据漂移；悬停窗切换清 hint 的既有机制不受影响（hint 匹配守卫仍以悬停窗为准，悬停已收窄到 Tab 栏，hint 上报窗口期与悬停窗口期天然重合）。
- TabStrip 卸载零矩形与在途拖拽交错：下一次 16ms 轮询悬停自然归 null 并广播清态；dragEnd 用当下缓存，最多一次"栏刚消失仍命中"的单帧陈旧，后果是该次释放并入而非建窗——与"栏在视觉上刚消失"的物理事实一致，非状态破损。
- 事件/定时器面零新增（无新轮询、无新监听器）；`useRectObserver` 的观察连接随组件卸载断开，清理完整。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：已查，未发现问题（本改动零落盘、零持久化，纯运行期内存缓存 + IPC 通道）。

- 矩形缓存生命周期 = 应用运行期，不落盘不恢复；窗口销毁不清理条目的取舍已在代码注释论证（候选集排除 + windowId 单调不复用），属自洽设计而非半状态。

### 2.5 通知遗漏

结论：已查，未发现问题。

- renderer 上报 `.catch(() => {})` 静默：与 `setBounds` 布局上报同款口径（尽力而为通道，丢失自愈——TabStrip 重挂载/resize 即重报），且 ipc 层对结构拒绝有 logFailure 日志留痕，失败可追溯。
- 行为反馈面：悬停高亮收窄到 Tab 栏后，"拖到他窗内容区"从"高亮可并入"变为"无反馈"，与"释放即建新窗"的新裁决一致，消除了旧语义下"看着能并入、整窗释放也并入"与新裁决间的误导；无 UI 与真实裁决脱节的路径。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：已查，未发现问题。

- NaN/Infinity：`Number.isFinite` 逐字段拒绝（NaN 不为 finite，覆盖）；零/负尺寸清条目（TabStrip 卸载语义）；未上报窗口（新窗首帧、上报丢失）不命中 → 释放走建窗，自愈路径已在注释冻结。
- 已验证的边界行为（符合 PRD、留痕备查）：① 拖到**零会话主窗**的 Tab 栏释放 → `hitAnyTabstripAt` 命中 sessionId=null 候选 → `adjudicateHit` 判 `rejected` 弹回——符合 PRD 3.6.2"主窗口仅当前激活会话的浏览区可作为转移目标"，且比旧语义（命中整窗即拒）更精确；② Esc 取消短路在坐标裁决之前，不受命中面变化影响；③ `getContentBounds` 异常（极端窗口态）回退不命中 → 建窗，与矩形缺失同路径。
- Windows (0,0) 陈旧上报守卫（`isStaleReport`）语义未动：修订后其后果仍是"径用轮询点裁决"，轮询点落点决定 stayed/moved/建窗，影响面不比修订前差；Windows 实测属原阶段 9 波次 3 遗留的平台验证项，本次裁决面变窄后建议一并实测（并入待办）。

### 2.7 复杂度是否增加

结论：已查，未发现问题。

- dragging.ts 净增约 40 行：一个缓存 Map + 一个命中函数替换 + 一个存储方法，形状对齐既有 `setInsertHint` 先例；四态裁决的结构与注释同步更新，无分支增殖。
- renderer 侧 TabStrip 增两组 effect（上报 + 卸载清除），复用共享骨架，未引入新状态或新渲染通道。
- 分层未破坏：布局事实源在 renderer（唯一知道 Tab 栏位置的一方），裁决在主进程，经 shared 契约通道传递；无 renderer 直访 Electron API。
