### 2.5 通知遗漏

结论：发现 1 个问题。

- [x] **[中-1] 编辑页面加载失败后静默销毁窗口，用户收不到失败信息**
  - 位置：`src/main/browser/captureEditorWindow.ts:142`；调用方 `src/main/browser/capture.ts:363`、`:387`；反馈条 `src/renderer/src/components/browser/CaptureFeedbackWindow.tsx:72`。
  - 描述：新增失败清理在页面加载拒绝时仅 console.warn，再释放条目并 destroy。open 返回 void，IPC 在页面加载完成前已成功返回，异步错误不能回到调用方。用户会看到点击编辑无反应或窗口一闪而过，无法区分未触发与加载失败。
  - 证据：
    ```ts
    const onRejected = (error: unknown): void => {
      if (created.isDestroyed()) return
      console.warn('[capture-editor] 编辑窗页面加载失败:', error)
      release()
      created.destroy()
    }
    ```
    loadURL/loadFile 的 Promise 均 catch(onRejected)，两个 IPC 入口仅调用 `open(...): void` 后返回；反馈条 `.catch(() => {})` 也没有可见错误展示。已有验证脚本第 54—55 行让 loadURL 拒绝后，`await window.api.capture.openEditor()` 仍成功，再断言窗口被移除；它验证了清理与重开，没有覆盖失败反馈。本轮结论来自静态调用链和已保存脚本，未重新运行注入。
  - 建议方向：保留条目释放，在主进程失败点提供符合现有规则的原生可见反馈，文案走三语字典；或让两个入口统一处理可等待的开窗结果。不要仅把拒绝传给当前会吞 catch 的反馈条。补“加载失败可见反馈只出现一次”的验收。
