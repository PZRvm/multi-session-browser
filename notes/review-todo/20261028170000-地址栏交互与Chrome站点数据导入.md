### 2.3 竞态条件

结论：发现 1 个问题（中-1）。

- [ ] **[中-1]** 建议面板"空间不足拒绝展示"后，follow 跟随以陈旧锚点/条目复活面板
  - 位置：`src/main/browser/omniboxSuggest.ts:127-137`（show 拒绝路径）与 `192-201`（follow）
  - 描述：show 判定 `canPresent=false` 时直接 `starved.win.hide()` 并返回，注释声明"锚点/条目不缓存——shell 的下一次 show 会携新锚点整包重发"；但 `entry.visible` 仍为 true、`entry.anchor`/`entry.itemCount` 停留在**最后一次被接受**的 show 值。此后宿主窗口 move/resize 触发 follow：`computeBounds(owner, entry.anchor, entry.itemCount)` 若空间恢复即 `setBounds + showInactive` 复活面板——复活的是陈旧锚点定位、陈旧条目数高度、webContents 内陈旧建议列表（拒绝路径未推送新 data），而 shell 侧最后一次回执为 `canPresent=false`（融合态已收回）。复活面板上的陈旧建议可被点选，`pickSuggestion` 仅以 `panelOpen`（仍 true）为闸（Toolbar.tsx:316-320），会把旧建议 URL 提交导航。
  - 证据（复现序）：①输入触发 show#1（面板呈现，entry.anchor/itemCount=首包值）；②窗口处于屏幕底部空间不足，继续输入触发 show#2 → 拒绝路径隐藏面板、entry 状态不更新、新 data 丢弃、shell presented=false；③用户把窗口拖回有空间的位置（无新输入，renderer 不重发 show——锚点为内容系坐标，纯 move 不变）→ follow 以 show#1 旧值复活面板。结果：面板可见但输入框非融合态、内容/宽度/高度均为旧值、可点选提交旧建议。
  - 建议方向：拒绝路径同步更新 `entry.anchor/itemCount`（缓存新值但保持隐藏，follow 复活即用新值重算并补发 data），或引入 `starved` 标记令 follow 在下一次 show 到达前只隐藏不复活；同时让 shell 侧在 canPresent=false 期间冻结键盘选中态（见低-6）。

其余竞态面已查无问题：dry-run/execute 的 `inFlight` 单飞判据与登记相邻无 await 穿透窗口（index.ts:281-282,399-403，注释援引上轮审查中-3）；`takeStaged` 取出即销毁 + 定时器同步清理，execute 消费后 cancel 不可能命中写盘中途（"写盘中不可取消"不变量成立，:397-403 与 cancel handler :512-527）；execute 暂存窗口期会话删除复核（:408-411，援引上轮审查中-2 已修复）；TTL 定时器 `unref` 不阻退出、will-quit 兜底清理；渲染层 `useOmniboxSuggestWindow` 请求代号（showSeq）旧回执作废与收起即失效（useOmniboxSuggestWindow.ts:58-80,101）；Toolbar `submitUrl` 在途作用域核对（Toolbar.tsx:287-301）；作用域漂移渲染期即拍清零（:221-229）；workspacePicker 的 pending 占位/迟到 pick 拒绝结构未动。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：发现 1 个问题（中-4）。

- [ ] **[中-4]** IndexedDB 冲突替换窗口内进程硬崩溃留下半迁移态，无自动恢复路径
  - 位置：`src/main/browser/chromeImport/indexedDb.ts:632-664`（replaceConflictSite）
  - 描述：冲突替换为"目标成对目录 rename 入临时备份 → 复制源 → 校验 → 清备份"多步序列。序列中途**进程硬崩溃**（断电/被杀/段错误）时：目标站点目录已被搬走（或半拷）、备份滞留 tmp 目录（`mkdtemp` 临时区），下次启动无任何检测/回卷机制——该站点 IndexedDB 对目标引擎呈现缺失或撕裂。模块对 `rollback-failed`（还原抛错）有"备份保留 + 中文告警交人工"的处置，但对硬崩溃窗口无对等交代（will-quit 不覆盖被杀场景；dispose 也不碰备份，唯一恢复副本尚在但无提示路径）。
  - 证据：替换序列任一步与下一步之间均无跨重启日志/标记文件；`restoreSitePair` 仅在进程存活的前提下方可触达。
  - 建议方向：至少补一条启动期扫描（msb-chrome-import-* 临时区残留即告警/提示人工核查），或在替换前于目标分区侧落一个事务标记文件（完成即删）；也可在模块头注如实注记硬崩溃窗口的存在与人工恢复路径，将已知风险显式化。

其余事务面已查无问题：IDB 逐站点"校验通过即原子提交、清理该站点备份、后续失败不回卷已提交站点"（partial 语义自洽，:326-333）；还原失败保留唯一备份绝不自动删除（:326-329 注释与实现一致）；Cookie apply 作用域组快照 → 排空 → 逐条重设 → 指纹对拍（`cookies.ts:497-553`，跨组重叠成员共享条目、只重设已写组、DRAIN_LIMIT 防御界）；localStorage 备份还原为既有 siteData 机制未动；sessions.json/history JSON 落盘路径未改（history 走 registry 既有 importEntries）。

### 2.5 通知遗漏

结论：发现 2 个问题（中-2、低-7）。

- [ ] **[中-2]** 快照层复制丢失锁错误的 source-busy 语义（Windows 实际可达）
  - 位置：`src/main/browser/chromeImport/sourceSnapshot.ts:228-238`（copyOne）与 `241-249`（copyTree）；对照头注承诺 `:16-17`
  - 描述：模块头注承诺"history/localStorage 维持既有两类语义（复制容错、锁错误→chromeLocked 文案）"，但 `copyOne`/`copyTree` 直接透传 `copyFile/cp` 错误——EBUSY/EPERM（Windows 下 Chrome 运行中占用文件的典型错误码）会落入 catch 的通用包装 `io-error`（:219-222），用户看到"文件系统错误"而非"请退出 Chrome 后重试"。既有 `cookieSource.ts:175-186` 的 `copyWithLockGuard`（EBUSY/EPERM → source-busy）正是为此而设，快照层作为新的复制入口未沿用。且 lsof 一致性探测仅 darwin 生效（:81-82），Windows 上历史/LS 路径完全依赖错误码映射给用户指引。
  - 证据：`copyOne` 无任何 errno 分支；dry-run 失败框正文经 `resolveDialogBody` 后 reason=io-error → `reasonText` 映射"文件系统错误"（index.ts:576-577），而 source-busy → chromeLocked 文案（:569-570）。
  - 建议方向：`copyOne/copyTree` 增加 EBUSY/EPERM → `ImportEngineError('source-busy', …)` 映射（同 cookieSource 口径），或对 history/LS 两 scope 在非 mac 平台补充存在性预检文案。

- [ ] **[低-7]** dry-run 中途失败未对已产出的引擎工件走 dispose
  - 位置：`src/main/browser/chromeImport/index.ts:370-376`（catch 只 `captured.dispose()`）
  - 描述：cookie prepare 成功、idb prepare 抛错（或反之）的半途失败路径，catch 只释放快照目录，不调用 `cookieEngine.dispose(cookieArtifacts)`——已解密的明文 Cookie 记录表只能等 GC 回收。`types.ts:16-17` 生命周期契约写明"取消、TTL 过期、失败与退出清理统一走 dispose（释放暂存资源：内存工件/临时目录）"，本路径未兑现（无落盘泄漏，纯内存面，且 handler 返回后引用即失）。
  - 证据：catch 块仅两行（快照 dispose + 弹框）；`disposeStaged` 存在但只对已入暂存（putStaged 之后）的 entry 生效。
  - 建议方向：catch 中对非空 `cookieArtifacts/idbArtifacts` 补 `void cookieEngine.dispose(...)`/`idbEngine.dispose(...)`（各自幂等、内部已 catch），对齐契约声明。

其余通知面已查无问题：execute 逐 scope 分项独立 try/catch（一类失败不中断另一类，:419-475）；失败原生框正文兜底映射防英文 fs 直出（resolveDialogBody，:659-675）；rollback-failed 独立呈现不与普通失败混同（summarizeResults :637-639）；冲突 sheet planId 未命中按取消收敛且 renderer 补发 cancel 释放暂存（SessionPanel.tsx:133-149,157-161）；取消/放弃裁决路径即时 cancel 不等 TTL（SessionPanel）。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 2 个问题（低-6、低-8）。

- [ ] **[低-6]** 空间不足拒绝展示时键盘状态机仍生效，可提交不可见建议
  - 位置：`src/renderer/src/components/browser/Toolbar.tsx:234`（panelOpen 定义）、`340-358`（键盘语义）；关联 `src/main/browser/omniboxSuggest.ts:128`（拒绝展示）
  - 描述：`panelOpen` 是 shell 本地状态机（draft 非空 + 未抑制 + 有建议），主进程 canPresent=false 只影响融合态 class 与面板可见性，不回写 panelOpen。空间不足期间：↑↓ 仍环形移动高亮、Enter 在高亮 ≥0 时仍按"选中建议优先"提交**不可见**的建议 URL（而非输入原文），aria-expanded 也仍为 true——用户按 Enter 得到意料外的导航。
  - 证据：`onKeyDown` Enter 分支以 `panelOpen && activeSuggestIndex >= 0` 判定走 pickSuggestion；`suggestPresented`（hook 返回值）未参与键盘语义与 aria。
  - 建议方向：`suggestPresented` 为 false 期间将键盘语义降级（↑↓ 吞默认但不移动、Enter 走 submitDraft、aria-expanded 随呈现态），或至少 Enter 忽略高亮提交输入原文。

- [ ] **[低-8]** 导入加载态 sheet 的 60s 兜底时长与导入实际耗时上限未对齐
  - 位置：`src/main/workspacePickerWindow.ts:90-91`（MANAGED_SHEET_FALLBACK_MS = 60_000）
  - 描述：dry-run 含钥匙串授权等待（上限 20s，cookieCrypto.ts:53）+ 全量源快照复制（IndexedDB 树可达 GB 级）+ 四类型探测，60s 内未完成即被兜底关掉加载态 sheet，而导入仍在途继续执行——用户视角"加载框消失了、稍后又弹出结果框"，反馈链断裂观感（结果框最终仍会弹，无功能损害）。
