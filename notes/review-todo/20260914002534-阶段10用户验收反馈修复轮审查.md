## 问题明细

### [中] A：quittingAfterFlush 标志放行的二次退出会截断在途写盘

- 位置：`src/main/index.ts`（`app.on('before-quit', (event) => { if (quittingAfterFlush) return; ... })`，约 :316）
- 证据：标志在冲刷**启动时**即置 true；冲刷落定前若再有第二个退出请求到来（连按两次 Cmd+Q 的第二次经 macOS 队列重入、连续两个 SIGTERM、或 dock「退出」双击），before-quit 直接放行退出——写盘未落定即退进程，丢最后 500ms 改动，等于该路径回到了修复前行为。首个退出请求被 preventDefault 后用户感知不到"正在退"，双击退出是真实存在的肌肉记忆路径。
- 建议方向：放行判据从"冲刷已启动"改为"冲刷已完成"（如两态标志 pending/done，或把二次请求也吞掉直到 flush 完成的 then 里统一 quit）；至少第二次 preventDefault 并依赖 1s race 兜底自然退出。

### [低] B：settleSession 的 flushReport 仍为 fire-and-forget，克隆恢复集缓存更新无结构保证

- 位置：`src/main/browser/persistence.ts:325-334`（settleSession 内 `void flushReport(id)`）与 `src/main/browser/registry.ts:528-533`（closeSession 冲刷前置）
- 证据：克隆读 `getRestoreSet(srcId)` 缓存，而缓存前移在 flushReport 的 mutateSnapshot `.then` 里；closeSession 随后的 killPartitionWebContents 为秒级、写盘毫秒级先行，时序事实安全，但若 fs 极慢（或未来 kill 变快）无结构保证。
- 建议方向：settleSession 返回写盘 promise，closeSession await 之（调用方均为 async，改动面小）；或维持观察并在注释标注时序依据。

### [低] C：omnibox 提交锁定未绑定 Tab 身份，同 URL 双 Tab 场景串显

- 位置：`src/renderer/src/components/browser/Toolbar.tsx:40-41`
- 证据：`pendingShown = pending && pending.baselineUrl === mainUrl ? pending.locked : null` 只比对 URL——提交后切到另一个 URL 恰等于基线的 Tab（或提交时 A Tab 与 B Tab 同 URL），锁定文本会在那个 Tab 的地址栏错显示；编辑/失焦后自愈，纯展示层。
- 建议方向：pending 增提交时的 activeTabId 参与比对（三字段均等才显示锁定）。
