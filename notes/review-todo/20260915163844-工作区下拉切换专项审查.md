### 2.3 竞态条件

结论：发现 1 个问题

- [x] **[高] workspaces 镜像的 lastActiveSessionId 永不随激活回填，乐观级联可与主进程级联分叉，且分叉时浏览器快照推送被守卫丢弃，列表高亮与右侧实际会话不一致**（`src/renderer/src/stores/sessions.ts:56-100` cascadeActiveForView / `src/renderer/src/stores/sessions.ts` selectSession、switchWorkspace 成功路径 / 对照 `src/main/sessions.ts` setActive 与 workspaceSetActive 的主进程记忆写入）
  - 描述：主进程在 setActive（同临界区）与 workspaceSetActive（级联时）会更新 `workspaces[].lastActiveSessionId` 落盘，但 renderer 的 `workspaces` 镜像只在 init / adoptSnapshot（失败重拉）时刷新——`selectSession` 成功后与 `switchWorkspace` 级联成功后都不回填镜像记忆。于是镜像记忆相对主进程事实持续陈旧。
  - 复现序列：会话 X、Z 同属工作区 A（镜像 A.memory=X₀ 旧值）。① 切到 A：主进程级联 activeId=Z 并写 A.memory=Z，renderer 镜像仍 X₀；② 切走并激活其他会话；③ 再切回 A：此时激活会话不属于 A，触发级联——renderer 按镜像旧记忆（或全序首个）乐观置 activeId=X，主进程按盘上记忆 Z 级联 activeId=Z 并 `onActiveChanged(Z)`。结果：右侧浏览器实际切到 Z，而 renderer `sessions.activeId=X`，browser store 的快照守卫把 (sessionId=Z) 的推送当过期丢弃——列表高亮 X、Tab 栏镜像停在旧会话，直到用户下一次点击才自愈。
  - 证据：`cascadeActiveForView` 读 `workspaces.find((w) => w.id === viewId)` 的镜像记忆；`selectSession` 成功路径仅有 `window.api.sessions.setActive` 调用（无 workspaces 镜像更新）；主进程 setActive handler 在 mutateSnapshot 内写 `ws.lastActiveSessionId = nextId`。既有 UI 冒烟未覆盖「级联切换后再次切回触发二次级联」的序列（Phase 2→UI6 的切回恰好走了"激活已属视野、零级联"分支），故 40/40 未暴露。
  - 建议方向：在 `selectSession` 与 `switchWorkspace` 成功路径回填镜像记忆（镜像主进程同临界区副作用——selectSession 后更新激活会话所属工作区的 memory；switchWorkspace 级联后更新目标工作区 memory 为级联结果）；或更彻底：switchWorkspace 成功后用 `sessions:list` 权威快照 adoptSnapshot 一次（代价多一次 IPC，但消灭整类漂移）。

- [x] **[低] move-session 留下源工作区指向被移会话的陈旧记忆（运行期）**（`src/main/sessions.ts` workspaceMoveSession handler）
  - 描述：移动会话归属不动任何工作区的 lastActiveSessionId（注释声明"记忆只随真实激活更新"）。源工作区记忆若指向被移走的会话，运行期残留；级联处的 `s.workspaceId === viewId` 守卫使其不致错选，重启 parse 净化（store.ts lastActiveSessionId 悬空检查）会置 null。行为正确但记忆语义上已脏。
  - 建议方向：moveSessionToWorkspace 同临界区内把「指向被移会话且属于源工作区」的记忆置 null（纯一致性清理，不违反"只随真实激活更新"——置 null 是删记忆不是造记忆）。

### 2.4 事务边界（落盘原子性与级联一致性）

结论：发现 1 个问题

- [x] **[中] clone 的归属校验后置于 clonePartition，可预期的整单拒绝路径产生孤儿分区目录**（`src/main/sessions.ts` clone handler——`resolveMembership` 在 mutateSnapshot 内执行，而 `await deps.clonePartition(srcId, newId)` 在其之前）
  - 描述：payload 带非法格式或不存在的 workspaceId 时，clone 先完成分区复制（close-then-copy：关闭源会话 webContents + 全量复制分区数据，耗时数秒），随后在 mutateSnapshot 内 `resolveMembership` 抛「工作区不存在/非法」整单拒绝——进入既有 catch 警告「目标分区目录可能残留，请手动核查」。拒绝是入参可预知的，校验本可在 clonePartition 之前用已加载的 `snapshot.workspaces` 完成（同文件 create 先例：归属校验在写副作用之前）。
  - 证据：clone handler 代码序：loadSnapshot → src 存在性校验 → `await deps.clonePartition(...)` → mutateSnapshot{resolveMembership...}。UI 不可达（renderer 只发当前视野的合法归属），故降为 中。
  - 建议方向：clone 在 `clonePartition` 之前对 membership 做与 resolveMembership 同规则的预校验（格式 + 存在性，基于已 loadSnapshot 的快照），把不可预期副作用挡在校验后。

其余核查：全部写通道落盘经 `mutateSnapshot` → `atomicWriteJson`（fs-utils 单源）,无旁路直写；delete/deleteBatch 级联新增 `clearDanglingMemory` 补齐记忆清理（单删与批量同覆盖）；activeId 不变量（指向存在会话或 null）在五个新 handler 中均保持。

### 2.6 边界遗漏（入参范围 / 空值 / 极值）

结论：发现 2 个问题

- [x] **[低] 下拉键盘导航的高亮行不滚入可视区**（`src/renderer/src/components/WorkspaceSwitcher.tsx` onSearchKeydown / ws-options 渲染）
  - 描述：`.ws-options` 为 max-height 224px 滚动容器；工作区数量超过可视行数后，↑↓ 移动的 active 行越过可视边界时容器不跟随滚动（无 scrollIntoView），键盘用户高亮在一行不可见的选项上按 Enter。
  - 建议方向：activeIdx 变化时对对应行调 `scrollIntoView({ block: 'nearest' })`（地址栏建议面板 OmniboxSuggestPanel 有同类键盘滚动先例可对照）。
- [x] **[低] 批量勾选集跨视野残留**（`src/renderer/src/components/SessionPanel.tsx` checked Set 与视野切换）
  - 描述：`checked` Set 不随视野切换清理；不可见行的勾选不计数（checkedIds 以 visibleSessions 过滤，批量指令正确），但 A 视野勾选 → 切 B 视野 → 切回 A 时先前勾选原样显现，且与全选按钮状态联动（B 视野全选后切回 A，allChecked 按 A 重算，B 的勾选仍留在 Set 里不显示）。批量指令本身不受污染（以可见交集为准），属轻微状态卫生问题。
  - 建议方向：视野切换时清空 checked（toggleBatchMode 已有先例），或在 switchWorkspace 成功回调处由面板清理。

其余核查：workspaceCreate/rename 的 name trim→空拒绝→clamp 20→重名拒绝链完整（重名排除自身）；id 格式前置 + 存在性后置双层；`workspaceId: null` 显式合法；store.ts 对 v4 缺 workspaceId/workspaces/activeWorkspaceId 字段分级告警（v1—v3 静默迁移）；WS_NAME_MAX=20 与 WORKSPACE_NAME_MAX 单源；`ws-search` maxLength=20 与契约一致。
