## 问题清单

### 中 1：show 通道 pending 检查与赋值之间存在 await 竞态窗口

- **位置**：`src/main/workspacePickerWindow.ts:150-166`（registerWorkspacePickerIpc 的 showWorkspacePicker handler）
- **严重程度**：中（竞态隐患；后果轻微，见下）
- **描述**：handler 内 `if (pending) resolveCancelled(...)` 的检查与 `pending = {...}` 的赋值之间隔着 `await buildContext(request)`（读盘 I/O）。两次 show 并发到达时（模态生效前约百毫秒窗口内的双触发，或程序化调用），双双通过检查→先后各自赋值 pending，后者覆盖前者：**首请求的 resolve 引用丢失、promise 永不收敛**，且首张 sheet 成为孤儿窗（其 pick 因 requestId/归属校验被忽略、close 因归属不符不误收敛，无数据风险；下一次 show 的防御路径会将其以 cancelled 收敛并关闭）。
- **证据**：handler 代码序——`if (pending) {...}` → `await buildContext(request)` → `return new Promise((resolve) => { pending = {...}; openSheet(...) })`；pending 为模块级单槽。
- **建议方向**：pending 槽位同步预留（先置占位 pending 再异步组装上下文），或 renderer 侧 openMoveModal/openBatchMoveModal 增在途守卫（对齐 batchMoveInFlight 先例）；二选一即可闭合窗口。

### 低 3：未分组视野下删除最后一个工作区后，视野哨兵行从下拉消失

- **位置**：`src/main/sessions.ts`（workspaceDelete handler）、`src/renderer/src/components/WorkspaceSwitcher.tsx`（allOptions 的 workspaces.length > 0 条件）
- **严重程度**：低
- **描述**：用户处于「未分组」视野时删除最后一个工作区：workspaceDelete 只在 activeWorkspaceId 指向被删工作区时回落 'all'，'ungrouped' 视野保留；但下拉的未分组行渲染条件是 `workspaces.length > 0`，此时该行消失——当前视野在下拉中不可见、无对勾指示（功能无损：零工作区时全员未分组，过滤结果等价全部会话，combobox 标签仍正确显示「未分组」）。
- **建议方向**：二选一——workspaceDelete 后若 workspaces 清零且视野为 'ungrouped' 则回落 'all'；或下拉在 activeWorkspaceId === 'ungrouped' 时恒渲染该行。

### 低 4：未分组视野的空态复用工作区文案，措辞不符

- **位置**：`src/renderer/src/components/SessionPanel.tsx`（visibleSessions 为空的分支）；键 `sessions.panel.emptyWorkspace.{title,desc}`（zh-CN/sessions.ts:53-56）
- **严重程度**：低
- **描述**：未分组视野且无未分组会话时，空态显示「该工作区尚无会话 / 新建会话将加入此工作区」——未分组不是工作区，「此工作区」指代错误（desc 的落点语义倒是对的：新建会话确实会落入未分组）。
- **建议方向**：新增一条未分组视野空态键（或文案改中性「此视野尚无会话」级），随视野条件切换。

### 低 5：sheet 单条空态的「尚无其他工作区」措辞在反馈轮后不再准确

- **位置**：`src/renderer/src/components/WorkspacePickerWindow.tsx`（emptyOther 分支）；键 `sessions.moveModal.emptyOther`
- **严重程度**：低
- **描述**：反馈轮后单条场景列表含当前归属行（current 标记），options 为空的唯一含义是**完全没有任何工作区**；而键文案「尚无其他工作区，先在工作区切换框新建一个」的「其他」是旧语义（排除当前归属）的残留。
- **建议方向**：改用 `moveModal.emptyNone`（「尚无工作区…」，与批量空态同键）或修订 emptyOther 文案。

### 低 6：parsePickerPayload 的 batch ids 无长度上限

- **位置**：`src/main/workspacePickerWindow.ts:80-90`（parsePickerPayload batch 分支）
- **严重程度**：低（防御面；正常路径 ids ≤ 会话总数）
- **描述**：ids 数组只校验非空 + 逐项格式，无长度上限；hereCount 组装为 O(ids×workspaces)。跨 IPC 载荷不可信任口径下，dialogs.ts 有 DISPLAY_NAME_MAX/DISPLAY_COUNT_MAX 显示面兜底先例，本通道缺席。
- **建议方向**：对 ids 长度设上限（如会话总数或固定常量），超限整单拒绝；或注明显示数据经 clamp 的等效兜底。

### 低 7：微小编号收敛（两处可选）
